# 반평면 교집합 (Half-Plane Intersection)

> **한 줄 요약**: 직선 하나가 평면을 둘로 나눈 한쪽(**반평면**)을 `n`개 모아 **모두 만족하는 영역**(볼록 다각형)을 `O(n log n)`에 구한다. 반평면을 **경계 직선의 방향 각도 순으로 정렬**하고, **덱**에 하나씩 넣으면서 새 반평면에 의해 쓸모없어진 직선을 앞뒤에서 뺀다. 남은 직선들이 교집합 다각형의 변이다.

## 1. 언제 쓰나 (문제 신호)

- "부등식 `a·x + b·y ≤ c` 여러 개를 만족하는 `(x, y)`의 영역 / 넓이 / 존재 여부" — 2차원 선형 계획법
- **다각형의 핵(kernel)**: 모든 점이 보이는 점들의 집합 = 모든 변의 안쪽 반평면의 교집합 (예술관 문제: 한 점에서 전체 벽을 볼 수 있는가)
- 두 **볼록 다각형의 교집합**(각 변을 반평면으로)
- **이분 탐색 + 반평면 교집합**: "볼록 다각형 안에 들어가는 가장 큰 원" — 반지름 `r`만큼 각 변을 안쪽으로 밀어 낸 반평면의 교집합이 비어 있지 않은 최대 `r`
- 점 `p`가 가장 가까운 영역(보로노이 칸): 이웃과의 수직이등분선의 한쪽 반평면들의 교집합
- 정점 수가 1천 정도로 작고 **순서대로 자르기**(서덜랜드-호지먼) `O(n²)`로도 충분하면 그것이 더 단순하다. `n`이 `10⁴` 이상이면 이 알고리즘

## 2. 핵심 아이디어

**반평면 표현**: 점 `p`와 방향 `d`로 정해진 직선의 **왼쪽**(경계 포함) `{q : cross(d, q − p) ≥ 0}`. 부등식 `a·x + b·y ≤ c`는 방향 `d = (−b, a)`, 직선 위의 점 하나로 바꾼다.

**각도 순서의 의미**: 교집합 볼록 다각형의 변들을 **반시계 방향**으로 돌면 변의 방향 각도가 단조롭게 커진다 (볼록 다각형을 한 바퀴 돌면 방향이 한 바퀴 돈다). 그래서 반평면을 방향 각도 순으로 정렬하면 교집합의 변이 되는 직선들도 그 순서로 나타난다.

**알고리즘**:

1. 반평면을 **방향 각도 순**으로 정렬한다 (외적으로 정확하게 비교: 먼저 윗반평면/아랫반평면으로 나누고 외적 부호).
2. **방향이 같은** 반평면은 가장 안쪽(제약이 센) 것 하나만 남긴다.
3. 덱을 유지한다. 새 반평면 `h`를 넣을 때
   - 덱 **뒤** 두 직선의 교점이 `h`의 (엄격히) 바깥이면 뒤 직선을 뺀다 (`h`가 그 꼭짓점을 잘라 내 마지막 직선이 쓸모없어졌다).
   - 덱 **앞** 두 직선의 교점이 `h`의 바깥이면 앞 직선을 뺀다 (한 바퀴를 돌아 앞쪽도 잘릴 수 있다).
   - `h`를 뒤에 넣는다.
4. 다 넣은 뒤, 뒤 직선이 앞쪽에 의해 잘리는지 / 앞 직선이 뒤쪽에 의해 잘리는지 한 번 더 정리한다.
5. 덱에 직선이 **3개 미만**이면 교집합이 비었거나 넓이가 0이다. 아니면 이웃한 직선끼리의 교점이 꼭짓점이다.

**유계로 만들기**: 교집합이 유계가 아닐 수 있으므로 `±bound`의 큰 정사각형 4개 반평면을 같이 넣는다. 각도가 사방으로 퍼지게 되어 알고리즘의 "한 바퀴" 가정이 성립하고, 비유계 영역은 상자로 잘려서 나온다.

**정확성**: 교점은 분수(`Fraction`)로 정확하게 구하고 정렬도 외적으로만 비교한다. 경계 위의 꼭짓점도 *엄격하게* 빼서(`side ≤ 0`) 같은 점을 지나는 여분의 직선이 꼭짓점을 중복시키지 않는다. 넓이 0인 결과(점·선분)는 정반대 방향의 평행선이 이웃하거나 직선이 3개 미만 남아 걸러진다.

## 3. 손으로 따라가기

반평면 4개: `x ≥ 0`, `y ≥ 0`, `x + y ≤ 4`, `x ≤ 3` (그리고 상자 `bound = 10`의 4개).

각 반평면의 방향(경계 직선에서 왼쪽이 안쪽):

| 반평면 | 방향 `d` | 각도 |
|---|---|---|
| `y ≥ 0` | `(1, 0)` | 0° |
| `x ≤ 3` | `(0, 1)` | 90° |
| `x + y ≤ 4` | `(−1, 1)` | 135° |
| 상자 위쪽 `y ≤ 10` | `(−1, 0)` | 180° |
| `x ≥ 0` | `(0, −1)` | 270° |

(상자의 아래 `y ≥ −10`(0°), 오른쪽 `x ≤ 10`(90°), 왼쪽 `x ≥ −10`(270°)은 방향이 같은 더 안쪽 반평면 `y ≥ 0`, `x ≤ 3`, `x ≥ 0`에 가려져 2단계에서 버려진다.)

| 단계 | 넣는 반평면 | 뒤 pop | 앞 pop | 덱 |
|---|---|---|---|---|
| 1 | `y ≥ 0` | - | - | `y≥0` |
| 2 | `x ≤ 3` | - | - | `y≥0, x≤3` |
| 3 | `x+y ≤ 4` | - | - | `y≥0, x≤3, x+y≤4` |
| 4 | 상자 위쪽 | - | - | `y≥0, x≤3, x+y≤4, top` |
| 5 | `x ≥ 0` | 뒤 두 직선 `x+y≤4`와 `top`의 교점 `(−6, 10)`이 `x ≥ 0` 밖 → `top` pop | 앞 두 직선 `y≥0`과 `x≤3`의 교점 `(3, 0)`은 안쪽 → 그대로 | `y≥0, x≤3, x+y≤4, x≥0` |

마지막 정리에서 더 빼는 직선이 없다. 꼭짓점은 이웃한 직선의 교점:
`y≥0 ∩ x≤3 = (3, 0)`, `x≤3 ∩ x+y≤4 = (3, 1)`, `x+y≤4 ∩ x≥0 = (0, 4)`, `x≥0 ∩ y≥0 = (0, 0)` → 사각형, 넓이 **15/2**.

- **빈 교집합**: `x ≤ 0`과 `x ≥ 1`을 넣으면 앞뒤 정리를 거친 뒤 직선이 3개 미만(2개) 남는다 → `[]`.
- **넓이 0**: `y ≤ 0`과 `y ≥ 0`은 선분 하나로 겹친다. 방향이 정반대(`180°` 차이)인 두 직선이 덱에서 이웃하게 되고, 이는 사이가 비었거나 띠 모양이 상자에 갇히지 않았다는 뜻이라 `[]`. `x ≤ 0, x ≥ 0, y ≤ 0, y ≥ 0`(한 점)도 같은 경로.
- **한 점에서 만나는 세 직선**: 바닥 변과 두 대각선(`45°`, `315°`)이 한 점에서 만나면 바닥 변은 그 점에만 닿는 군더더기라 pop되고 꼭짓점이 중복되지 않는다 ([테스트](test_solution.py)에서 확인).

**핵(kernel)**: 화살촉 모양 `[(0,0), (4,2), (0,4), (1,2)]`(반시계)의 핵은 꼭짓점 `(4,2), (8/5,16/5), (1,2), (8/5,4/5)`인 사각형, 넓이 `18/5`. 오목한 꼭짓점 `(1,2)`가 핵의 꼭짓점이고 거기서 모든 변이 보인다.

**선형 계획**: `x ≥ 0, y ≥ 0, x + 2y ≤ 8, 3x + y ≤ 9`에서 `x + y` 최대화 — 교집합의 꼭짓점 중 목적 함수가 가장 큰 `(2, 3)`에서 5.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def half_plane_intersection(planes, bound=10**9):
    ordered = sorted(list(planes) + box, key=cmp_to_key(_angle_compare))      # 방향 각도 순 (외적으로 정확히)
    unique = []                                                               # 같은 방향은 더 안쪽 하나만
    for plane in ordered:
        if unique and _angle_compare(unique[-1], plane) == 0:
            if unique[-1].side(plane_point) > 0: unique[-1] = plane
        else: unique.append(plane)
    lines, head = [], 0                                                       # 덱: lines[head:]
    for plane in unique:
        while len(lines) - head >= 2 and plane.side(_intersection(lines[-2], lines[-1])) <= 0: lines.pop()
        while len(lines) - head >= 2 and plane.side(_intersection(lines[head], lines[head+1])) <= 0: head += 1
        if len(lines) - head >= 1 and cross(lines[-1].d, plane.d) == 0: return []     # 정반대 방향이 이웃: 비었다
        lines.append(plane)
    ...                                                                       # 앞뒤 마지막 정리
    return [_intersection(window[i], window[(i + 1) % len(window)]) for i in range(len(window))]
```

- `HalfPlane(px, py, dx, dy)`, `HalfPlane.from_points(a, b)`(`a → b` 왼쪽), `HalfPlane.from_inequality(a, b, c)`(`a·x + b·y ≤ c`), `side(point)`(양수 안쪽, 0 경계, 음수 바깥), `contains`.
- `half_plane_intersection(planes, bound)` → 꼭짓점 목록 (`Fraction` 좌표, 반시계). 비었거나 넓이 0이면 `[]`.
- `polygon_area`, `point_in_all`, `polygon_kernel(vertices)`, `convex_polygon_intersection(first, second)`, `linear_program_2d(planes, objective)`(최적 꼭짓점이 모두 상자 위이면 `ValueError`).
- 직접 실행하면 `N`과 `N`개의 선분(`x1 y1 x2 y2`)을 받아, 각 선분의 **왼쪽**을 허용하는 반평면 `N`개의 교집합 넓이를 출력합니다 (정수가 아니면 `분자/분모`).

## 5. 복잡도와 입력 크기 가이드

- 각도 정렬이 `O(n log n)`, 덱 처리는 각 직선이 한 번 들어가고 한 번 빠지므로 `O(n)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다 (원점을 안쪽에 두는 무작위 반평면, 정확한 분수 계산).

| 반평면 수 `n` | 시간 |
|---|---|
| 1,000 | 0.05초 |
| 5,000 | 0.26초 |
| 20,000 | 1.24초 |

- 교점을 `Fraction`으로 계산해서 느리지만 **정확**합니다. 좌표가 정수이고 교점을 비교만 한다면 정수 곱셈으로 바꿔(교점의 분모를 곱해서 비교) 더 빠르게 할 수 있습니다. 실수(`float`)로 하면 경계 위의 판정이 오차에 흔들립니다.
- 위 측정은 교집합이 19각형인 경우입니다. 변이 많은 교집합(예: 원에 접하는 `n`개)도 같은 `O(n log n)`.

## 6. 자주 하는 실수

- **왼쪽/오른쪽 규약**: 이 구현은 "방향의 **왼쪽**이 안쪽"입니다. 다각형의 변을 반시계 방향으로 주면 안쪽이 왼쪽이라 그대로 반평면입니다. 시계 방향으로 주면 바깥쪽이 되어 틀립니다.
- **각도 정렬을 `atan2`로**: 부동소수 오차로 거의 평행한 직선의 순서가 뒤바뀝니다. 정수 좌표는 외적으로 정확히 비교하세요.
- **같은 방향 중복 제거 누락**: 같은 방향의 반평면이 둘이면 덱에서 평행선의 교점을 구하다 0으로 나눕니다. 정렬 뒤 같은 방향은 더 안쪽 것만 남깁니다.
- **엄격/비엄격 pop**: 경계 위의 교점(`side == 0`)에서 pop하지 않으면 한 점에서 만나는 세 직선이 꼭짓점을 중복시킵니다. 반대로 비엄격이면 넓이 0인 결과가 점·선분으로 남지 않고 `[]`가 됩니다 (문제가 넓이 0도 비지 않았다고 본다면 규약을 맞추세요).
- **정반대 방향 평행선이 이웃**: 덱에서 방향이 `180°` 다른 직선이 이웃하면 사이가 비었거나(교집합 없음) 띠 모양입니다. 상자가 있으면 띠는 상자 직선이 사이에 끼므로 비었다고 판단합니다.
- **상자 크기**: `bound`가 실제 꼭짓점의 좌표보다 충분히 커야 합니다. 작으면 진짜 영역이 잘립니다. 유계가 아닌지 판단하려면 결과 꼭짓점에 `±bound`가 있는지 봅니다.
- **교집합 공식의 부호**: 두 직선의 교점 `p + t·d₁`에서 `t = cross(d₂, p₂ − p₁) / cross(d₂, d₁)`. 분자의 순서를 바꾸면 부호가 반대가 됩니다.
- **빈 교집합과 넓이 0 구분**: 이 구현은 둘 다 `[]`입니다. 선분·점도 "있다" 고 봐야 하는 문제(핵이 한 점이라도 있으면 가능)라면 비엄격 pop과 다른 후처리가 필요합니다.
- **점들의 순서/방향**: 다각형의 핵을 구할 때 꼭짓점이 반시계가 아니라 시계 방향이면 모든 반평면이 반대가 됩니다.

## 7. 변형과 응용

- **2차원 선형 계획**: 교집합 다각형의 꼭짓점 중 목적 함수 최댓값 (`linear_program_2d`). 대회에서는 (기대 `O(n)`의) 시델의 증분 알고리즘도 쓰입니다.
- **다각형의 핵**: 변마다 반평면을 만들어 교집합이 비어 있는지 / 넓이를 구한다 (`polygon_kernel`).
- **두 볼록 다각형의 교집합**: 변들을 모두 반평면으로 (`convex_polygon_intersection`). 선분 교차를 직접 처리하는 것보다 단순합니다.
- **이분 탐색**: 반지름 `r`의 원이 볼록 다각형 안에 들어가는가 = 각 변을 안쪽으로 `r`만큼 민 반평면의 교집합이 비어 있지 않은가. `r`에 대한 이분 탐색 + 이 알고리즘.
- **보로노이 칸**: 점 하나의 칸은 다른 모든 점과의 수직이등분선의 한쪽의 교집합 (`O(n log n)` 한 칸, 전체 `O(n² log n)`).
- **쌍대성**: 점-직선 쌍대성으로 반평면 교집합은 볼록 껍질과 서로 변환됩니다. [볼록 껍질](../../../lv3-advanced/04-geometry/convex-hull/)과 같은 정렬 + 스택/덱 구조인 이유입니다.
- **3차원 이상**: 반공간 교집합은 이 알고리즘이 아니라 쌍대 볼록 껍질(`O(n log n)`)이나 시델의 선형 계획으로 갑니다.
