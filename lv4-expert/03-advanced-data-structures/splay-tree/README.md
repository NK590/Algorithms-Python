# 스플레이 트리 (Splay Tree)

> **한 줄 요약**: 별도의 균형 정보(높이·색·우선순위)가 **없는** 이진 탐색 트리. 대신 어떤 노드든 접근할 때마다 그 노드를 **회전으로 루트까지 끌어올린다(splay).** 한 번은 느릴 수 있지만 `m`번의 연산이 `O((m + n) log n)`에 끝나고(분할 상환), 최근에 쓴 것이 위에 있어서 접근에 지역성이 있으면 훨씬 빠르다. 구간 뒤집기·삽입·삭제 같은 시퀀스 연산을 "구간을 한 서브트리로 만들기" 로 처리한다.

## 1. 언제 쓰나 (문제 신호)

- [트립](../treap/)과 같은 문제들: 수열의 중간 삽입·삭제, **구간 뒤집기·잘라 붙이기·구간 합**, 정렬된 다중집합의 `k`번째·순위·`floor`/`ceil`
- 접근 패턴에 **지역성**이 있다 (같은 원소를 반복해서 찾거나 순서대로 훑는다) — 그럴수록 이득이 큰 구조
- **링크-컷 트리**(Lv5)의 부품 — 경로를 스플레이 트리로 표현하므로 스플레이를 정확히 구현하는 것이 그 첫 단계
- 무작위성에 기대고 싶지 않고 포인터(부모 링크)를 다루는 구현이 괜찮을 때
- 최악의 한 연산 시간이 중요하면 (실시간) 부적합: 한 번의 `splay`가 `O(n)`일 수 있다
- 파이썬에서는 트립과 속도가 비슷하다 (아래 표). 짧은 코드가 필요하면 트립이 약간 더 쉽다

## 2. 핵심 아이디어

**스플레이(splay)**: 노드 `x`를 루트로 올린다. 부모 `p`, 조부모 `g`와의 위치에 따라 세 경우:

| 경우 | 모양 | 하는 일 |
|---|---|---|
| **zig** | `p`가 루트 | `x`를 한 번 회전 |
| **zig-zig** | `x`와 `p`가 둘 다 왼쪽(또는 둘 다 오른쪽) 자식 | **`p`를 먼저** 회전한 뒤 `x`를 회전 |
| **zig-zag** | 방향이 다름 (`x`는 왼쪽, `p`는 오른쪽 등) | `x`를 두 번 회전 |

**zig-zig에서 `p`를 먼저 돌리는 것이 핵심**이다. `x`만 두 번 돌리면 `x`는 올라가지만 긴 사슬의 나머지 노드들이 거의 그대로 깊이에 남아서, 사슬을 접근해도 모양이 좋아지지 않고 분할 상환 `O(log n)`이 깨진다. `p`를 먼저 돌리면 사슬이 *절반으로 접힌다.*

**분할 상환 분석(접근 보조정리)**: 서브트리 크기의 로그 합 `Φ = Σ log₂ size(v)`를 퍼텐셜로 두면, `x`를 루트까지 올리는 splay의 분할 상환 비용은 `3(log n − log size(x)) + 1 = O(log n)`이다. 깊은 노드를 접근하는 느린 연산은 퍼텐셜을 크게 줄여 이후를 빠르게 만든다. 이로부터 따라 나오는 성질:

- **균형**: `m`번의 접근이 `O((m + n) log n)`.
- **순차 접근**: 키를 오름차순으로 모두 접근하는 전체 비용이 `O(n)`.
- **작업 집합**: 최근에 접근한 `t`개의 서로 다른 원소 중 하나를 접근하는 비용은 `O(log t)`.
- (동적 최적성 추측: 어떤 접근 열이든 최적의 이진 탐색 트리와 상수배 이내 — 아직 증명되지 않았다.)

**연산을 `splay`로**:
- 찾기: 찾아 내려가다 *마지막으로 방문한 노드* 를 splay (찾지 못해도 해야 분할 상환 보장이 유지된다).
- 삽입: 찾아서 splay한 뒤, 루트가 새 키보다 크면 왼쪽 서브트리 전체를 새 노드의 왼쪽으로 옮겨 새 노드를 루트로 만든다 (회전 없이 `O(1)`).
- 삭제: 지울 노드를 splay → 왼쪽 서브트리의 최댓값을 splay → 그 오른쪽 자식 자리에 지울 노드의 오른쪽 서브트리를 붙인다.

**시퀀스 연산(암시적 키)**: 양 끝에 **보초 노드**를 두면 구간 `[l, r)`은 "위치 `l − 1`의 노드를 루트로 올리고, 위치 `r`의 노드를 그 오른쪽 자식으로 올렸을 때, 그 노드의 **왼쪽 서브트리**" 가 정확히 구간이 된다. 이 서브트리에 `reversed` 태그를 달면 뒤집기, 합을 읽으면 구간 합. 삽입은 그 빈 자리(왼쪽 서브트리가 비어 있다)에 새 노드를 달고, 삭제는 그 서브트리를 떼면 된다. 지연 태그는 노드를 찾아 내려가는 `_locate`가 경로를 위에서부터 `push`해 두므로, 그 뒤의 `splay`는 정리된 경로에서 회전만 하면 된다.

## 3. 손으로 따라가기

### 사슬에서 가장 깊은 노드를 splay (zig-zig 두 번)

`1, 2, 3, 4, 5`를 오름차순으로 넣으면 매번 새 키가 루트(이전 루트는 그 왼쪽 자식)가 되어, 루트 `5`에서 왼쪽으로만 내려가는 **깊이 5의 사슬**이 된다 (여기까지 회전은 0번).

```
5          루트 5, 왼쪽 자식 4, 그 왼쪽 3, 그 왼쪽 2, 그 왼쪽 1
└ 4
  └ 3
    └ 2
      └ 1
```

`1`을 접근한다 (가장 깊은 노드). 경로 `1 → 2 → 3 → 4 → 5`:

| 단계 | 상황 | 회전 | 결과 (간선 `부모.방향 = 자식`) |
|---|---|---|---|
| 1 | `x = 1`, `p = 2`, `g = 3`: zig-zig | `p = 2`를 먼저 (`2`가 `3` 자리로) | `2.L=1, 2.R=3, 4.L=2, 5.L=4` |
| 2 | (이어서) | `x = 1`을 (`1`이 `2` 자리로) | `1.R=2, 2.R=3, 4.L=1, 5.L=4` |
| 3 | `x = 1`, `p = 4`, `g = 5`: zig-zig | `p = 4`를 먼저 | `4.L=1, 4.R=5` (루트 4) |
| 4 | (이어서) | `x = 1`을 | **루트 1**, `1.R=4`, `4.L=2, 4.R=5`, `2.R=3` |

회전 4번. 깊이가 5에서 **4**로 줄었다 (이 크기에서는 작은 차이지만 사슬이 길수록 절반에 가깝다: 깊이 2000의 사슬에서 가장 깊은 노드를 접근하면 깊이가 약 1000으로 줄고, 이 구현의 [테스트](test_solution.py)가 이를 확인한다. `x`만 두 번 돌리면 줄지 않는다).

### 순서 집합

위 트리에서 `rank(5)`(5보다 작은 키의 수)는 `4`. `5`를 찾아 splay하면 `5`가 루트가 된다. 이어서 `floor(10) = 5`, `ceil(0) = 1`, `kth_smallest(3) = 3`. 1부터 7까지를 오름차순으로 넣은 뒤 `1`을 접근하면 회전 6번(`7`이 루트인 깊이 7짜리 사슬), 이어서 `7`을 접근하면 2번, `4`를 접근하면 3번이 든다.

### 시퀀스 (보초 노드)

`[1, 2, 3, 4, 5]`는 내부적으로 `[S, 1, 2, 3, 4, 5, S]` (`S` = 보초). 구간 `[1, 4)` = 원소 `2, 3, 4`를 잡으려면 바로 앞 노드 `1`을 루트로, 바로 뒤 노드 `5`를 그 자식으로 올린다. `5`의 왼쪽 서브트리가 `2, 3, 4`. 여기에 `reversed` 태그를 달면 `[1, 4, 3, 2, 5]`가 된다. 합 질의는 같은 서브트리의 `total`을 읽는다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _rotate(self, x):                      # x 를 부모 p 의 자리로 올린다
    p, g = self.parent[x], self.parent[self.parent[x]]
    if self.left[p] == x:
        inner = self.right[x]; self.left[p] = inner; self.right[x] = p
    else:
        inner = self.left[x];  self.right[p] = inner; self.left[x] = p
    if inner: self.parent[inner] = p
    self.parent[p] = x; self.parent[x] = g
    if g: (self.left if self.left[g] == p else self.right)[g] = x
    self._pull(p); self._pull(x)

def _splay(self, x, goal=0):               # x 를 goal 의 자식(0 이면 루트)으로
    # (경로의 지연 태그를 위에서부터 push)
    while self.parent[x] != goal:
        p = self.parent[x]; g = self.parent[p]
        if g != goal:
            same_side = (self.left[g] == p) == (self.left[p] == x)
            self._rotate(p if same_side else x)     # zig-zig 는 부모를 먼저, zig-zag 는 x 를 먼저
        self._rotate(x)
    if goal == 0: self.root = x
```

- 모든 코드가 반복문(부모 포인터)이라 사슬 모양으로 깊어진 트리(`10⁵`개를 오름차순으로 넣은 직후)에서도 재귀 한도 문제가 없습니다. 초기 배열의 균형 트리 구성만 깊이 `log n`의 재귀입니다.
- `SplaySet`: 서로 다른 키의 순서 집합. `add`(이미 있으면 `False`), `remove`, `in`, `rank`, `kth_smallest`(1부터), `floor`/`ceil`/`predecessor`/`successor`, `min`/`max`/`pop_min`. `rotations`로 회전 횟수를 셉니다.
- `SplaySequence`: 암시적 키. `insert`, `append`, `erase`, `get`/`[]`, `set`, `reverse(l, r)`, `range_sum(l, r)`, `to_list`(양 끝 보초 포함). 지운 노드는 `free` 목록에서 재사용합니다.
- 직접 실행하면 Luogu P3391 "文艺平衡树" 형식 — `n m`, 이어서 `m`줄의 `l r`(1부터, 양끝 포함 뒤집기) — 을 처리해 `1..n`의 최종 배열을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 분할 상환 `O(log n)`, 한 번의 연산은 `O(n)`까지 가능 (사슬의 가장 깊은 노드를 처음 접근할 때). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 회전 횟수입니다 (`SplaySet`, 키 `0..n−1`).

| 접근 패턴 | `n = 1000` | `n = 5000` | `n = 20000` |
|---|---|---|---|
| 오름차순으로 만든 사슬에서 시작해 키를 **순서대로** 전부 접근 (키당 회전) | 4.37 | 4.41 | 4.41 |
| 무작위 순서로 만든 트리에서 키를 **순서대로** 접근 (키당) | 2.58 | 2.53 | 2.54 |
| 무작위 키를 `n`번 접근 (접근당) | 11.7 | 14.9 | 17.8 |

- 순서대로 접근하면 `n`이 20배가 되어도 키당 회전이 상수 (**순차 접근 정리**: 전체 `O(n)`). 첫 접근 하나가 `n`번 회전하는 큰 비용을 이후가 나눠 갚는다.
- 무작위 접근은 `log n`에 비례해 늘어납니다 (11.7 → 17.8, `log₂ n`이 10 → 14.3).
- 이 환경에서 측정한 시간입니다.

| 작업 | 시간 |
|---|---|
| 오름차순 삽입 `10⁵`번 (매번 루트에 붙으므로 회전 0번) | 0.15초 |
| 무작위 키 삽입 `10⁵`번 | 4.26초 |
| 무작위 조회 `10⁵`번 (위 삽입과 조회를 합쳐 접근당 평균 약 23.5번 회전) | 3.56초 |
| `SplaySequence` 준비, `n = 5·10⁴` | 0.04초 |
| `reverse` `10⁴`번, `n = 5·10⁴` | 0.57초 (같은 입력에서 트립 0.62초) |
| `range_sum` `10⁴`번 | 0.56초 (트립 0.58초) |

- 조회마다 구조를 바꾸므로 읽기 전용 질의가 많은 문제에서는 트립의 `rank`(분할 없이 내려가기만)가 더 빠릅니다 (트립 `rank` `10⁵`번 0.55초 대 스플레이 조회 3.56초). 스플레이는 지역성이 있는 접근에서 빛납니다.

## 6. 자주 하는 실수

- **zig-zig에서 `x`만 두 번 회전**: 가장 흔한 실수이자 가장 조용한 버그입니다. 결과 트리는 올바른 BST지만 분할 상환 `O(log n)`이 깨져서 큰 입력에서만 느려집니다. 그래서 [테스트](test_solution.py)에서 사슬의 깊이가 줄어드는지 확인합니다. 부모를 먼저 돌리세요.
- **지연 태그를 `push`하지 않고 회전**: 뒤집기 태그가 남은 노드에서 회전하면 좌우가 뒤섞입니다. 루트에서 `x`까지의 경로를 *위에서 아래로* `push`한 뒤에 `splay`하세요 (이 구현은 `_locate`가 내려가며 `push`하므로 `_splay`를 직접 부르지 않는 한 안전합니다. 목표 `goal`의 자식으로 올릴 때도 루트부터 전부).
- **회전 뒤 `pull` 누락**: 회전은 `p`와 `x`의 서브트리를 바꾸므로 `p`를 먼저, `x`를 나중에 `pull`합니다 (아래부터).
- **부모 포인터 갱신 누락**: 회전에서 `inner`(옮겨진 자식)의 `parent`, `p`의 `parent`, `x`의 `parent`, 조부모의 자식 포인터 — 네 곳을 모두 고쳐야 합니다. 불변식 검사(모든 노드의 자식의 `parent`가 자신)를 [테스트](test_solution.py)에 넣었습니다.
- **찾지 못했을 때 splay 안 함**: 못 찾은 경우에도 마지막 방문 노드를 splay해야 분할 상환 보장이 유지됩니다 (그래야 `rank`, `floor` 등도 안전하게 읽습니다).
- **삭제 후 루트**: 삭제 뒤에는 `root`를 새 루트로 갱신해야 합니다. 왼쪽이 비었으면 오른쪽 서브트리가 루트.
- **보초 노드 위치 계산**: 시퀀스에서 보초가 맨 앞에 있으면 위치 `i`(0부터)의 원소는 순위 `i + 2`(1부터)입니다. 구간 `[l, r)`의 앞 노드는 순위 `l + 1`, 뒤 노드는 `r + 2`.
- **0번 노드의 값을 오염**: `0`번은 "없음" 센티널이라 부모·자식 배열에 쓰면 안 됩니다. 이 구현은 `if inner:`/`if g:` 같은 조건으로 막습니다.
- **재귀 구현**: 사슬 모양에서 깊이가 `n`이 되므로 재귀 `splay`/탐색은 한도에 걸립니다.
- **분할 상환을 최악으로 오해**: 한 번의 연산이 `O(n)`일 수 있습니다 (실시간 제약이 있으면 부적합).

## 7. 변형과 응용

- **링크-컷 트리**: 루트에서의 경로를 스플레이 트리 하나로 두고 `access`가 경로를 갈아 끼웁니다 (Lv5).
- **톱다운 스플레이**: 내려가면서 구조를 쪼개는 방식으로 부모 포인터 없이 쓴다 (상수가 작음).
- **스플레이로 `split`/`join`**: 키 `x`를 splay하면 루트의 왼쪽/오른쪽 서브트리가 곧 `< x`, `> x`로 갈라진 두 트리이므로, `O(1)`로 `split`이 됩니다. 두 트리의 `join`은 왼쪽 트리의 최댓값을 splay한 뒤 오른쪽 트리를 붙입니다.
- **구간 더하기 / 아핀 태그**: 트립과 같은 방식으로 지연 태그를 확장.
- **작업 집합 / 캐시 구조**: 최근 접근한 항목이 위에 오는 성질을 이용한 자료구조.
- **균형 트리 비교**: AVL·레드블랙은 최악 `O(log n)`을 보장하지만 구현이 복잡. [트립](../treap/)은 기대 `O(log n)`, 스플레이는 분할 상환. 구간 연산에는 `split`/`merge` 기반 트립의 구현이 더 짧다고 느끼는 경우가 많습니다.
