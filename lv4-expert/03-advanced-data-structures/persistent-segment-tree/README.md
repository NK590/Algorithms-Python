# 퍼시스턴트 세그먼트 트리 (Persistent Segment Tree)

> **한 줄 요약**: 구간 트리를 갱신할 때 **바뀐 경로(루트에서 잎까지 `O(log n)`개 노드)만 새로 만들고 나머지는 옛 노드를 그대로 가리킨다.** 그러면 갱신마다 "새 버전의 루트" 가 하나씩 생기고, 과거의 어떤 버전도 그대로 질의할 수 있다. 두 버전의 **차이**를 이용하면 "구간에서 `k`번째로 작은 수" 같은 질문도 온라인으로 `O(log n)`에 답한다.

## 1. 언제 쓰나 (문제 신호)

- "과거의 `k`번째 갱신 직후의 상태에서 구간 합을 구하라" — 갱신 이력에 접근한다
- "구간 `[l, r]`에서 `k`번째로 작은 수", "구간에서 `x`보다 큰 수의 개수" — **정적 배열, 구간이 값에 따라 달라지는 질의**, 그리고 **온라인**(앞의 답이 다음 질의를 결정)이라 오프라인 정렬이 안 될 때
- "트리의 경로 `u–v` 위에서 `k`번째 수" (루트에서 각 정점까지의 버전을 쌓는다)
- 어느 버전에서든 갈라져 나가는(분기하는) 이력: 각 질의가 "`j`번째 버전에서 시작해 한 가지 변경" (CF 707D)
- 점 갱신과 구간 합뿐이고 과거 상태가 필요 없으면 [구간 트리](../../../lv3-advanced/01-range-query-structures/segment-tree/)나 [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/)가 더 간단하고 가볍다
- 질의를 모아 한꺼번에 정렬해 처리해도 되면 오프라인 기법([모스 알고리즘](../../../lv3-advanced/06-query-techniques/mos-algorithm/), 병렬 이분 탐색)이 메모리를 덜 쓴다

## 2. 핵심 아이디어

**경로 복사(path copying)**: 구간 트리에서 `a[i] += d`를 하면 값이 바뀌는 노드는 루트에서 잎 `i`까지의 경로 위 `⌈log₂ n⌉ + 1`개뿐이다. 그 노드들의 *복사본* 을 새로 만들고 (값에 `d`를 더함), 경로에서 벗어나는 자식은 **옛 노드를 그대로 가리키게** 한다. 옛 루트에서 시작하면 옛 버전이 변함없이 보이고, 새 루트에서 시작하면 새 버전이 보인다. 갱신 한 번에 노드가 `O(log n)`개만 늘고, 시간도 `O(log n)`이다.

노드는 `(left, right, value)`를 배열에 넣고 `0`번 노드를 "값 `0`인 빈 트리"(자식이 모두 `0`)로 둔다. 그러면 처음 버전(전부 `0`)을 따로 만들 필요 없이 `roots[0] = 0`이다.

**구간 `k`번째 수 (차이 이용)**: 배열 `a`의 값을 크기 순위로 압축하고, `i`번째 버전 = *앞의 `i`개 원소를 넣은* 트리로 만든다 (트리의 칸은 값의 순위, 칸의 값은 그 순위가 몇 번 나왔는가). 구간 `[l, r)`의 값 분포는 `버전 r − 버전 l`, 즉 **같은 위치의 노드끼리 뺀 값** 이다. 이 "차이 트리" 에서 `k`번째를 찾으려면 왼쪽 자식의 개수(두 버전의 왼쪽 자식 값의 차)와 `k`를 비교해 왼쪽 또는 오른쪽으로 내려가면 된다. 차이 트리를 실제로 만들지 않고 두 포인터(`a`, `b`)를 나란히 내려가기만 한다 → `O(log n)`.

```python
def kth_in_difference(version_hi, version_lo, k):
    a, b = roots[version_hi], roots[version_lo]
    lo, hi = 0, n                                   # 압축된 값의 구간 [lo, hi)
    while hi - lo > 1:
        mid = (lo + hi) // 2
        in_left = value[left[a]] - value[left[b]]   # 구간에서 왼쪽 절반 값의 개수
        if k <= in_left: a, b, hi = left[a], left[b], mid
        else:            k -= in_left; a, b, lo = right[a], right[b], mid
    return lo                                       # 압축된 값의 순위
```

**차이가 되려면**: 합·개수처럼 *뺄 수 있는* 값이어야 한다. 최댓값은 빼기가 없어서 이 방법을 못 쓴다.

### 무엇을 저장하고 어떻게 움직이나

갱신 전 트리 버전을 보존하고 바뀌는 루트→리프 경로의 노드만 새로 만듭니다. 나머지 서브트리는 이전 버전과 공유합니다. 각 버전의 루트가 서로 다른 시점의 전체 배열을 나타내며 이전 노드는 수정하지 않습니다.

### 왜 이 방법이 맞는가

점 갱신이 영향을 주는 노드는 한 경로의 O(log n)개뿐입니다. 공유 노드를 불변으로 유지하면 새 버전의 갱신이 이전 버전의 질의에 영향을 주지 않습니다. 접두 빈도 버전 두 개를 빼면 중간 구간의 값 분포가 됩니다.

### 작은 예제로 검산하기

배열 `[3,1,2]`의 앞 3개 버전에서 앞 1개 버전을 빼면 구간 `[1,3)`의 값 1,2만 남습니다. k번째 값을 찾을 때 왼쪽 자식의 개수 차이를 보고 내려갑니다. 버전 번호와 배열 인덱스를 혼동하지 마세요.

## 3. 손으로 따라가기

### 버전이 어떻게 만들어지나

길이 4인 배열(`a₀..a₃`, 처음엔 전부 0)에서:
`버전 1 = update(버전 0, 위치 2, +5)`, `버전 2 = update(버전 1, 위치 0, +3)`, `버전 3 = update(버전 2, 위치 2, +1)`, `버전 4 = update(버전 0, 위치 1, +7)` (버전 0에서 분기).

만들어지는 노드 (노드 `0`은 모든 버전이 공유하는 빈 트리):

| 노드 | 구간 | 왼쪽 | 오른쪽 | 값 | 만들어진 버전 |
|---|---|---|---|---|---|
| 1 | [0,4) | 0 | 2 | 5 | 버전 1의 루트 |
| 2 | [2,4) | 3 | 0 | 5 | |
| 3 | [2,3) 잎 | 0 | 0 | 5 | |
| 4 | [0,4) | 5 | **2** | 8 | 버전 2의 루트 — 오른쪽은 노드 2를 **그대로 공유** |
| 5 | [0,2) | 6 | 0 | 3 | |
| 6 | [0,1) 잎 | 0 | 0 | 3 | |
| 7 | [0,4) | **5** | 8 | 9 | 버전 3의 루트 — 왼쪽은 노드 5를 공유 |
| 8 | [2,4) | 9 | 0 | 6 | |
| 9 | [2,3) 잎 | 0 | 0 | 6 | |
| 10 | [0,4) | 11 | 0 | 7 | 버전 4의 루트 (버전 0에서 갈라짐) |
| 11 | [0,2) | 0 | 12 | 7 | |
| 12 | [1,2) 잎 | 0 | 0 | 7 | |

- 루트: 버전 0~4 = `[0, 1, 4, 7, 10]`. 노드는 13개 = 빈 노드 1 + 갱신 4번 × 3(= `log₂ 4 + 1`).
- 각 버전의 배열 값: 버전 1 `[0,0,5,0]`, 버전 2 `[3,0,5,0]`, 버전 3 `[3,0,6,0]`, 버전 4 `[0,7,0,0]`. 버전 2를 만든 뒤에도 버전 1은 그대로다 (버전 1의 노드 1, 2, 3은 한 번도 바뀌지 않는다).
- 버전 3의 위치 2 값 6 = 노드 7 → 오른쪽 8 → 왼쪽 9. 버전 2의 위치 2 값 5 = 노드 4 → 오른쪽 2 → 왼쪽 3.

### 구간 `k`번째 수

`a = [5, 1, 4, 2, 3]`, 구간 `[1, 4) = [1, 4, 2]`에서 2번째로 작은 수. 값을 순위로 압축하면 `1→0, 2→1, 3→2, 4→3, 5→4`, 구간의 순위들은 `{0, 3, 1}`.

| 단계 | 값의 구간 | 가운데 | 왼쪽 절반의 개수 | `k` | 선택 |
|---|---|---|---|---|---|
| 1 | [0, 5) | 2 | 2 (순위 0, 1) | 2 | `2 ≤ 2` → 왼쪽 |
| 2 | [0, 2) | 1 | 1 (순위 0) | 2 | `2 > 1` → `k = 1`, 오른쪽 |
| 3 | [1, 2) | 잎 | | 1 | 순위 1 → 값 **2** ✓ |

실제로 구간을 정렬하면 `[1, 2, 4]`의 2번째가 `2`. 같은 방식으로 `[0, 5)`에서 `k = 1..5`를 구하면 `1, 2, 3, 4, 5`.

### 구간 k번째 값 예제 예제

`1 5 2 6 3 7 4`에서 `(2 5 3)`: 구간 `[2..5] = [5, 2, 6, 3]`의 3번째 = `5`, `(4 4 1)`: `[6]`의 1번째 = `6`, `(1 7 3)`: 전체의 3번째 = `3`. 출력 `5 6 3`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
class PersistentSegmentTree:
    def __init__(self, n):
        self.left, self.right, self.value = [0], [0], [0]   # 0 번 노드 = 값 0 인 빈 트리
        self.roots = [0]                                    # 버전 0 = 전부 0

    def _clone(self, node, delta):                          # 노드를 복사하면서 값을 갱신
        self.left.append(self.left[node]); self.right.append(self.right[node])
        self.value.append(self.value[node] + delta)
        return len(self.value) - 1

    def update(self, version, index, delta):                # 새 버전 번호를 돌려준다
        old = self.roots[version]
        new_root = self._clone(old, delta)
        node, lo, hi = new_root, 0, self.n
        while hi - lo > 1:                                  # 경로를 따라 내려가며 한 칸씩 복사
            mid = (lo + hi) // 2
            if index < mid:
                child = self._clone(self.left[old], delta);  self.left[node] = child
                old, hi = self.left[old], mid
            else:
                child = self._clone(self.right[old], delta); self.right[node] = child
                old, lo = self.right[old], mid
            node = child
        self.roots.append(new_root)
        return len(self.roots) - 1
```

- `PersistentSegmentTree(n)`: `update(version, index, delta)`(새 버전), `query(version, l, r)`(반열린 구간 합), `kth_in_difference(hi, lo, k)`, `node_count()`. 모두 반복문이라 깊이 문제가 없습니다.
- `PersistentArray(values)`: 버전이 있는 배열. `get(version, i)`, `set(version, i, value)`(새 버전), 과거 버전에서 갈라져 나가기도 됩니다.
- `KthSmallest(values)`: 정적 배열에서 `kth(l, r, k)`(반열린 `[l, r)`, `k`는 1부터), `count_less`, `count_at_most`.
- 직접 실행하면 구간 k번째 값 예제 형식 — `N M`, 수열, `M`개의 `i j k`(1부터) — 을 받아 `a[i..j]`의 `k`번째로 작은 값을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 갱신·질의 모두 `O(log n)`. 노드는 갱신 한 번에 `⌈log₂ n⌉ + 1`개씩 늘어 `n`번 갱신하면 `O(n log n)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 시간 / 크기 |
|---|---|
| `KthSmallest` 준비, `n = 10⁴` | 0.09초, 노드 143,617개 (원소당 14.4개) |
| `KthSmallest` 준비, `n = 10⁵` | 1.0초, 노드 1,768,921개 (원소당 17.7개) |
| `kth` 질의 `10⁵`개, `n = 10⁵` | 1.66초 |

- 노드 수가 *원소 수 × 17* 로 늘어납니다. 파이썬 리스트에 정수를 넣는 방식이라 `n = 10⁶`이면 노드 약 2·10⁷개로 메모리와 시간이 부담스럽습니다. 질의가 온라인이 아니면 오프라인 방법을 고려하세요.
- 같은 문제를 [웨이블릿 트리](../wavelet-tree/)는 메모리 `O(n log σ)`의 정수 배열 두 개 정도로 풀어 훨씬 가볍고, [머지 소트 트리](../merge-sort-tree/)는 구현이 가장 쉽지만 질의가 `O(log² n)`입니다.

## 6. 자주 하는 실수

- **옛 노드를 제자리에서 고침**: 경로 복사의 핵심은 *절대 옛 노드를 바꾸지 않는* 것입니다. 하나라도 제자리에서 고치면 과거 버전이 조용히 틀려집니다.
- **빈 트리 `0`번 노드**: `0`번의 자식이 모두 `0`이어야 "아직 한 번도 안 만든 부분" 을 따라 내려가도 항상 `0`입니다. 그리고 `0`번 노드 자체의 값을 바꾸면 안 됩니다 (`_clone`으로 복사한 뒤 바꿉니다).
- **버전 번호와 원소 수**: `KthSmallest`에서 `versions[i]`는 *앞의 `i`개* 를 넣은 버전입니다. 반열린 `[l, r)`은 `versions[r]`에서 `versions[l]`을 뺍니다 (`versions[r + 1]`, `versions[l]`이라고 쓰는 건 1부터 센 닫힌 구간일 때).
- **값을 압축하지 않음**: 값이 `10⁹`이면 트리 크기가 폭발합니다. 정렬된 서로 다른 값의 순위로 압축하세요 (같은 값은 같은 순위 → 칸의 값이 개수).
- **뺄 수 없는 값으로 차이 이용**: `r` 버전에서 `l` 버전을 빼는 방법은 합·개수에만 됩니다. 구간 최댓값을 묻는 문제는 다른 방법이 필요합니다.
- **`k`의 기준**: 1부터인지 0부터인지(이 구현은 1부터), 구간이 닫힌지 반열린지를 문제마다 확인하세요.
- **재귀로 구현**: 재귀 깊이는 `log n`이라 문제는 없지만 파이썬에서는 반복문이 몇 배 빠릅니다.
- **지연 전파를 그대로 가져옴**: 구간 갱신까지 하려면 `push` 시점에 자식을 *복사* 해야 합니다 (아니면 "영구 태그" 방식으로 내려보내지 않고 질의 때 경로의 태그를 모읍니다).

## 7. 변형과 응용

- **퍼시스턴트 배열 / 스택 / 큐 / 유니온 파인드**: 배열을 구간 트리로 표현하면 `set(version, i, v)`가 `O(log n)`에 새 버전을 만듭니다. 분기도 됩니다 (`PersistentArray`).
- **트리 경로의 `k`번째 수**: 정점 `v`의 버전 = 부모의 버전에 `a[v]`를 한 번 갱신. 경로 `u–v`의 분포 = `버전[u] + 버전[v] − 버전[lca] − 버전[parent(lca)]`. 구간 대신 네 버전의 가감을 합니다.
- **2차원 점 세기**: 점을 `x` 순으로 정렬해 `x`가 늘 때마다 `y` 위치를 갱신한 버전을 만들면, `x ∈ [x₁, x₂]`, `y ∈ [y₁, y₂]` 안의 점 수 = 두 버전의 `[y₁, y₂]` 합의 차이.
- **구간 갱신(영구 태그)**: 구간에 더하는 갱신도 버전으로 쌓을 수 있습니다. 노드마다 "이 구간 전체에 더한 값" 을 갖고 내려보내지 않는 방식.
- **이분 탐색과 결합**: "최솟값이 `x` 이상인 가장 긴 구간" 같은 문제를 버전(= 임계값)에 대한 이분 탐색 + 구간 정보 합치기로 푼다 (CF 484E).
- **지속적 해시 / 큰 수**: 버전마다 노드 해시를 달아 두 버전이 같은지 `O(1)`에 비교하거나, 이진수를 노드에 담아 큰 수끼리 비교 (CF 464E).
- **오프라인 대안**: 질의를 먼저 모두 읽을 수 있으면 [웨이블릿 트리](../wavelet-tree/), [머지 소트 트리](../merge-sort-tree/), 오프라인 펜윅 트리 + 병렬 이분 탐색, [모스 알고리즘](../../../lv3-advanced/06-query-techniques/mos-algorithm/)이 더 가볍습니다.
