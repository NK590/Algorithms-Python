# 리 차오 트리 심화 (Li Chao Tree: 선분·되돌리기·오프라인)

> **한 줄 요약**: [볼록 껍질 트릭](../../../lv3-advanced/07-dp-advanced/convex-hull-trick/)의 기본 리 차오 트리는 *정의역 전체에서 유효한* 직선을 `O(log C)`에 넣고 최솟값을 묻는다. 여기서는 그것을 세 방향으로 넓힌다 — **정의역의 일부 구간에서만 유효한 선분**(`O(log² C)`), **삽입 되돌리기**(롤백), 그리고 **직선마다 살아 있는 시간 구간이 있는 오프라인 문제**(시간에 대한 구간 트리 + 롤백).

## 1. 언제 쓰나 (문제 신호)

- "직선 `y = ax + b`를 계속 추가하며, 임의의 `x`에서 **최솟값(최댓값)**" — 기울기가 정렬되어 있지 않고 질의 `x`도 임의 순서
- "직선이 `x ∈ [l, r]`에서만 존재한다" (**선분** 추가) — 볼록 껍질 하나로는 안 된다 (각 `x`마다 활성 직선 집합이 다르다)
- "직선이 **시각 `[s, e)`에만 살아 있고**, 시각 `t`에 `x`에서의 최솟값을 묻는다" — 삽입과 삭제가 섞여도 오프라인이면 풀린다
- DP 점화식 `dp[i] = min_j (dp[j] + b_j·a_i + …)`에서 기울기·질의 순서의 단조성이 **없다** ([CHT](../../../lv3-advanced/07-dp-advanced/convex-hull-trick/)는 단조성이 있을 때)
- 트리 위 DP에서 직선 집합을 **합쳐야** 한다 (리 차오 트리 병합)
- `x`가 정수이고 범위가 `±10⁹` 정도로 크다 — 좌표 압축 없이 동적 노드로 처리 가능

## 2. 핵심 아이디어

### 기본 (복습)

정의역 `[lo, hi]`를 구간 트리로 쪼갠다. 노드는 *직선 하나* 만 저장한다. 새 직선 `ℓ`을 노드에 넣을 때:

1. 노드 구간의 **가운데 `mid`** 에서 `ℓ`과 저장된 직선 `c`를 비교해 더 낮은 쪽을 노드에 *남긴다*.
2. 진 직선은 두 직선이 한 번만 만난다는 성질 때문에 *한쪽 끝에서만* 이길 수 있다: 왼쪽 끝(`lo`)에서 이기면 왼쪽 자식으로, 오른쪽 끝(`hi`)에서 이기면 오른쪽 자식으로 내려보낸다. 어느 쪽에서도 못 이기면 버린다.

질의 `x`는 루트에서 `x`의 잎까지 내려가며 만난 직선들의 최솟값이다. 깊이가 `log C`라 둘 다 `O(log C)` (`C` = 정의역의 크기).

### 확장 1 — 선분 (구간에서만 유효한 직선)

선분 `(m, b, [l, r])`을 `[l, r]`을 덮는 `O(log C)`개의 노드로 쪼갠다. 각 노드는 구간 *전체* 가 선분 안에 있다. 그 노드에서 위의 삽입 과정을 하되 **그 노드 구간 안에서만** 내려보낸다. 노드에 저장된 직선은 *그 노드 구간 전체에서 유효* 해야 질의가 맞는데, 쪼갠 노드는 선분이 구간을 완전히 덮으므로 그 조건이 만족된다. 삽입 하나가 `O(log C)`이고 노드가 `O(log C)`개라 선분 추가는 `O(log² C)`.

> **질의가 달라지는 곳**: 기본형은 노드가 비어 있으면 그 아래도 비어 있어서 거기서 질의를 멈출 수 있다. 선분 삽입에서는 윗 노드가 비어 있어도 *아래 노드에 선분이 있을 수 있다.* 질의는 항상 잎까지 내려가야 한다.

### 확장 2 — 되돌리기 (롤백)

삽입이 바꾸는 것은 `(노드 번호 → 저장된 직선)`뿐이다 — 삽입 하나가 최대 `O(log C)`개의 노드를 바꾼다. 바꾸기 전 값을 스택에 `(노드, 이전 직선)`으로 쌓아 두고, `snapshot()`이 스택의 길이를 기억하고 `rollback(표지)`가 그 길이까지 되감는다.

### 확장 3 — 직선마다 살아 있는 시간이 있는 오프라인 문제

직선 `i`가 시각 `[sᵢ, eᵢ)`에만 존재하고 질의가 `(시각 t, 위치 x)`. 삭제를 직접 구현하는 대신 **시간에 대한 구간 트리**(시각 순으로 정렬한 질의가 잎)를 만든다:

1. 각 직선의 생존 구간을 질의 번호 구간으로 바꿔 구간 트리의 `O(log Q)`개 노드에 걸어 둔다.
2. 루트에서 DFS로 내려가며 노드에 걸린 직선을 리 차오 트리에 삽입한다. 잎에서 질의에 답한다.
3. 노드를 떠날 때 롤백으로 그 노드의 삽입을 취소한다.

한 시점에 살아 있는 직선은 그 시점의 잎까지의 경로에 걸린 직선들이고, 정확히 그 직선들만 트리에 들어 있다. 삽입 총 `O(L log Q)`번 × 각 `O(log C)`.

## 3. 손으로 따라가기

### 직선 3개 (정의역 `[0, 7]`, 최솟값)

노드 1 = `[0,7]` (`mid = 3`), 노드 2 = `[0,3]`, 노드 3 = `[4,7]`.

| 추가 | 일어나는 일 | 저장된 직선 |
|---|---|---|
| `y = x + 6` | 루트가 비어 있어 그대로 저장 | 노드 1: `x+6` |
| `y = −x + 9` | `mid = 3`에서 `−x+9 = 6 < x+6 = 9` → 새 직선이 노드 1을 차지. 진 `x+6`은 왼쪽 끝 `x=0`에서 `6 < 9`로 이긴다 → 왼쪽 자식 노드 2로 | 노드 1: `−x+9`, 노드 2: `x+6` |
| `y = 2x − 2` | `mid = 3`에서 `4 < 6` → 새 직선이 노드 1을 차지. 진 `−x+9`는 오른쪽 끝 `x=7`에서 `2 < 12`로 이긴다 → 오른쪽 자식 노드 3으로 | 노드 1: `2x−2`, 노드 2: `x+6`, 노드 3: `−x+9` |

질의 `x = 5`: 노드 1 `2·5−2 = 8`, 노드 3 `−5+9 = 4` → 최솟값 **4**. `x = 0..7`의 답은 `−2, 0, 2, 4, 5, 4, 3, 2` — 세 직선을 직접 평가해 최솟값을 구한 것과 같다.

### 선분 `y = x`, `x ∈ [2, 5]` (정의역 `[0, 7]`)

`[2, 5]`를 덮는 노드: 노드 2의 오른쪽 자식 `[2,3]`(노드 5)와 노드 3의 왼쪽 자식 `[4,5]`(노드 6). 두 노드에 `y = x`가 저장된다.

- 질의 `x = 2..5`는 `2, 3, 4, 5`, 그 밖은 직선 없음(`None`).
- 이제 정의역 전체에 `y = −x + 8`을 추가하면 루트(노드 1)에 저장된다(루트가 비어 있었다). 질의 `x = 3`: 노드 1에서 `5`, 노드 5에서 `3` → **3**. `x = 5`: 노드 1에서 `3`, 노드 6에서 `5` → **3**. `x = 0, 1`: 노드 1만 있어 `8, 7`.
- 만약 `[2,5]`를 루트 하나에 `y = x`로 저장했다면 `x = 0, 1, 6, 7`에서도 값이 나와 틀린다 — 노드 구간으로 쪼개는 이유.

### 되돌리기

`y = x + 6`을 넣고 `snapshot()` (스택 길이 1), 이어서 `y = −x + 9`, `y = 2x − 2`를 넣으면 스택에 5개의 변경 기록이 쌓인다. `rollback(1)`은 4개를 되돌려 저장된 직선이 노드 1의 `x+6` 하나로 돌아가고, 질의가 다시 `6, 7, …, 13`이 된다.

### 오프라인 (시간 구간)

직선 A: `y = x`, 시각 `[0, 4)`. 직선 B: `y = −x + 10`, 시각 `[2, 6)`. 질의 `(t, x)`:

| 질의 | 살아 있는 직선 | 답 |
|---|---|---|
| (0, 3) | A | 3 |
| (2, 3) | A, B | `min(3, 7) = 3` |
| (3, 5) | A, B | `min(5, 5) = 5` |
| (5, 5) | B (A는 시각 4에 사라짐) | 5 |
| (6, 5) | 없음 (B는 시각 6에 사라짐) | `None` |

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
class LiChaoTree:
    def _insert(self, node, lo, hi, line):             # 노드 구간 [lo, hi] 안에서만 삽입
        while True:
            current = self.lines.get(node)
            if current is None: self._set(node, line); return
            mid = (lo + hi) // 2
            if at(line, mid) < at(current, mid):       # 가운데에서 더 낮은 쪽을 노드에 남긴다
                self._set(node, line); line, current = current, line
            if lo == hi: return
            if at(line, lo) < at(current, lo):   node, hi = 2 * node, mid         # 왼쪽 끝에서 이기면 왼쪽
            elif at(line, hi) < at(current, hi): node, lo = 2 * node + 1, mid + 1 # 오른쪽 끝에서 이기면 오른쪽
            else: return

    def add_segment(self, slope, intercept, left, right):
        stack = [(1, self.lo, self.hi)]                # [left, right] 를 덮는 노드로 분해
        while stack:
            node, lo, hi = stack.pop()
            if right < lo or hi < left: continue
            if left <= lo and hi <= right: self._insert(node, lo, hi, line); continue
            mid = (lo + hi) // 2
            stack += [(2 * node + 1, mid + 1, hi), (2 * node, lo, mid)]
```

- `LiChaoTree(lo, hi, maximize=False)`: `add_line`, `add_segment(m, b, l, r)`(양끝 포함, 정의역 밖은 잘라냄), `query(x)`(덮는 직선이 없으면 `None`), `snapshot()`, `rollback(snapshot)`. 최댓값은 부호를 뒤집어 같은 최솟값 구조로 처리합니다.
- `min_over_time(lo, hi, lines, queries, maximize=False)`: `lines = [(m, b, start, end)]`(시각 `start ≤ t < end`), `queries = [(t, x)]`. 시간 구간 트리 + 롤백.
- 직접 실행하면 Library Checker "Segment Add Get Min" 형식 — `N Q`, 선분 `N`개 `l r a b`(직선 `y = a·x + b`, 반열린 `[l, r)`), 질의 `0 l r a b`(선분 추가) 또는 `1 p`(`x = p`에서 최솟값, 없으면 `INFINITY`) — 를 처리합니다. 정의역은 `[−10⁹, 10⁹]`.
- 노드는 딕셔너리(힙 번호 → 직선)에 필요한 것만 만듭니다. 정의역이 `±10⁹`이어도 좌표 압축이 필요 없습니다.

## 5. 복잡도와 입력 크기 가이드

- 직선 추가·질의 `O(log C)`, 선분 추가 `O(log² C)`, 롤백은 기록한 만큼. `C = 2·10⁹`이면 `log C ≈ 31`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 시간 |
|---|---|
| 포물선 접선 `10⁵`개 `add_line` (정의역 `[0, 10⁶]`, 포락선에 모두 속하는 최악 입력), 노드 95,104개 | 1.29초 |
| 같은 트리에서 질의 `10⁵`개 | 0.92초 |
| 무작위 선분 `10⁵`개 `add_segment` (정의역 `±10⁹`), 노드 1,512,819개 | 5.53초 |
| 같은 트리에서 질의 `10⁵`개 | 1.74초 |
| `min_over_time`, 직선 5·10⁴개와 질의 5·10⁴개 | 1.54초 |

- 선분 추가가 직선 추가보다 훨씬 비쌉니다 (`log² C`, 그리고 노드가 최대 `2 log C`개). 선분 `10⁵`개에 5초대라 파이썬에서는 `10⁵` 근처가 한계입니다.
- 정의역 `±10⁹`에 기울기 `±10⁶`, 절편 `±10¹²`인 *무작위 직선* `10⁵`개를 넣어 보면 포락선에 드는 직선이 몇 개 안 돼 노드가 41개로 끝나고 0.17초에 끝났습니다. 속도 비교는 위 표의 첫 줄처럼 직선이 모두 포락선에 남는 입력으로 해야 합니다.

## 6. 자주 하는 실수

- **선분 전체를 한 노드에 저장**: 노드에 저장하는 직선은 *그 노드 구간 전체에서 유효* 해야 합니다. 선분을 루트에 그냥 넣으면 구간 밖 `x`에서도 값이 나옵니다. 반드시 `[l, r]`을 덮는 노드로 쪼개세요.
- **빈 노드에서 질의를 멈춤**: 기본형의 습관(`if line is None: break`)을 선분에서도 쓰면 윗 노드가 비어 있고 아래 노드에만 선분이 있을 때 `None`/틀린 값이 나옵니다.
- **끝점 포함 여부**: 이 구현은 닫힌 `[l, r]`입니다. Library Checker는 반열린 `[l, r)`이라 `main()`에서 `r − 1`로 바꿉니다.
- **비교 위치**: 삽입은 *노드 구간의 `mid`, `lo`, `hi`* 에서 비교합니다. 정의역 전체의 `lo`, `hi`로 비교하면 아래 노드에서 틀립니다. 노드를 따라 `lo`/`hi`를 갱신하세요.
- **음수 정의역의 `mid`**: `mid = (lo + hi) // 2`는 음수에서도 내림이라 `lo ≤ mid < hi`가 유지됩니다. 구간을 `[lo, mid]`, `[mid + 1, hi]`로 나누면 되고, `int(x / 2)`처럼 0 쪽으로 자르는 방식을 쓰면 `lo = −1, hi = 0` 같은 경우에 무한히 내려갑니다.
- **최댓값 모드의 부호**: 기울기·절편을 모두 부정하고, 답도 부정해서 돌려줍니다. 하나만 빼먹으면 틀립니다.
- **롤백 순서**: `rollback`은 *가장 최근* 삽입부터 되돌립니다. 두 `snapshot`을 쓸 때 안쪽(최근)부터 되돌리세요. 오프라인 DFS에서는 노드를 떠날 때 그 노드에서 얻은 표지로 되돌립니다.
- **시간 구간의 열림**: `[start, end)`에서 `end` 시각의 질의에는 직선이 이미 없습니다. 질의 번호 구간으로 바꿀 때 `bisect_left(times, end)`를 씁니다 (`bisect_right`면 한 칸 더 포함).
- **같은 시각의 질의**: 정렬한 질의 번호가 같은 시각을 구분하지 않으므로 직선의 생존 구간이 질의 *번호* 로 정확히 환산되어야 합니다.
- **질의 `x`가 정의역 밖**: 오류. `min_over_time`의 정의역을 질의 `x` 범위에 맞춰 주세요.

## 7. 변형과 응용

- **리 차오 트리 병합**: 두 트리를 노드 단위로 겹쳐 가며 한쪽 노드의 직선을 다른 쪽에 삽입하는 방식으로 합칠 수 있습니다. 삽입된 직선의 깊이는 줄어들지 않으므로 전체 `O(n log C)`로 알려져 있고, 트리 DP에서 자식의 직선 집합을 부모로 모을 때 쓰입니다 (CF 932F). 이 구현에는 병합이 들어 있지 않습니다.
- **퍼시스턴트 리 차오 트리**: 삽입 경로의 노드를 복사해 버전을 만들면 과거 버전에 질의할 수 있습니다 ([퍼시스턴트 세그먼트 트리](../persistent-segment-tree/)와 같은 발상).
- **다항식·곡선**: 직선 대신 "두 함수가 한 번만 만난다" 는 성질을 가진 함수(예: `a·f(x) + b`)에도 같은 구조가 통합니다. 두 곡선이 여러 번 만나면 안 됩니다.
- **센트로이드 분해와 결합**: 센트로이드마다 경로의 `(길이, 값)`을 직선으로 보고 질의 — 경로 합의 최대화 (CF 1303G).
- **실수 `x`**: 질의 점이 정해져 있으면 점을 정렬해 인덱스 위에서 구간 트리를 만들고 `mid` 비교를 점에서 합니다. 연속적인 정의역에서는 고정 횟수로 반복하는 방식(오차 주의).
- **CHT와의 선택**: 기울기와 질의가 단조면 [CHT 덱](../../../lv3-advanced/07-dp-advanced/convex-hull-trick/)이 `O(1)` 분할 상환으로 더 빠르고 짧습니다. 리 차오 트리는 그렇지 않을 때와 선분·롤백이 필요할 때.
