# 고급 자료구조 (Advanced Data Structures)

Lv3의 구간 트리·펜윅 트리는 "구간의 합이나 최솟값" 처럼 *합쳐지는 값* 을 묻는 구조였습니다. 이 단원의 구조들은 그것으로 안 되는 질문 — **구간의 `k`번째 수, 과거 버전, 직선 집합의 최솟값, 중간 삽입·삭제와 구간 뒤집기** — 을 다룹니다. 크게 두 갈래입니다.

- **정적 배열의 구간 순서 통계**: [퍼시스턴트 세그먼트 트리](persistent-segment-tree/), [머지 소트 트리](merge-sort-tree/), [웨이블릿 트리](wavelet-tree/)
- **동적으로 변하는 시퀀스/집합**: [트립](treap/), [스플레이 트리](splay-tree/)
- 그리고 직선·선분을 다루는 [리 차오 트리](li-chao-tree/) (볼록 껍질 트릭의 일반형)

## 한눈에 비교

| 개념 | 대상 | 핵심 | 질의 시간 | 갱신 |
|---|---|---|---|---|
| [퍼시스턴트 세그먼트 트리](persistent-segment-tree/) | 정적 배열 + 과거 버전 | 경로 복사, 두 버전의 차 | O(log n) | 새 버전 만들기 O(log n) |
| [머지 소트 트리](merge-sort-tree/) | 배열 (점 갱신 가능) | 노드마다 정렬된 리스트 | O(log² n) (`k`번째 O(log³ n)) | 점 갱신 O(n) (C 속도) |
| [웨이블릿 트리](wavelet-tree/) | 정적 배열 | 비트별 안정 분할 | O(log σ) | 불가 |
| [리 차오 트리](li-chao-tree/) | 직선·선분 집합 | 노드마다 직선 하나, 가운데 비교 | 추가·질의 O(log C), 선분 O(log² C) | 추가, 롤백 |
| [트립](treap/) | 동적 시퀀스·집합 | 무작위 우선순위 + split/merge | 기대 O(log n) | 모든 연산 |
| [스플레이 트리](splay-tree/) | 동적 시퀀스·집합 | 접근한 노드를 루트로 | 분할 상환 O(log n) | 모든 연산 |

같은 입력(`n = 10⁵`, 무작위 값)에서 구간 `k`번째 질의 20000개를 세 구조로 풀어 이 환경에서 측정했습니다 (세 결과가 모두 일치).

| 구조 | 준비 | 질의 20000개 | 메모리 규모 |
|---|---|---|---|
| 퍼시스턴트 세그먼트 트리 | 0.95초 | 0.29초 | 노드 1,768,929개 |
| 머지 소트 트리 | 0.35초 | 1.78초 | 리스트 원소 1,800,000개 |
| 웨이블릿 트리 | 0.63초 | 0.19초 | 정수 배열 17개 × `n` (+ 접두사 합) |

웨이블릿 트리가 가장 빠르고 가볍지만 갱신이 안 됩니다. 머지 소트 트리는 질의가 가장 느리지만 구현이 짧고 **점 갱신이 됩니다.** 퍼시스턴트 트리는 중간 정도이고 **과거 버전에 질의**할 수 있는 유일한 구조입니다.

## 문제 신호로 고르기

| 문제의 신호 | 선택 |
|---|---|
| 정적 배열, 구간 `k`번째·`x`보다 작은 수의 개수, 큰 입력 | [웨이블릿 트리](wavelet-tree/) |
| 위와 같은데 **값이 바뀐다** | [머지 소트 트리](merge-sort-tree/) |
| "`k`번째 갱신 직후의 상태", 버전이 분기, 트리 경로의 `k`번째 | [퍼시스턴트 세그먼트 트리](persistent-segment-tree/) |
| 직선을 넣고 임의의 `x`에서 최솟값/최댓값 | [리 차오 트리](li-chao-tree/) |
| 직선이 일부 구간에서만 유효, 또는 시간 구간이 있다 | [리 차오 트리](li-chao-tree/) (선분 / 롤백 / 오프라인) |
| 수열 중간 삽입·삭제 + 구간 뒤집기/잘라 붙이기/구간 합 | [트립](treap/) 또는 [스플레이 트리](splay-tree/) |
| 정렬된 다중집합, `k`번째·순위·`floor`/`ceil` | [트립](treap/) (또는 값 범위가 작으면 [펜윅 트리](../../lv3-advanced/01-range-query-structures/fenwick-tree/)) |
| 접근에 지역성이 있다 (같은 곳을 반복, 순서대로) | [스플레이 트리](splay-tree/) |

## 개념 사이의 관계

- 정적 구간 순서 통계 세 구조는 **같은 질문 / 다른 트레이드오프** 입니다. 모두 "값을 기준으로 구간을 나눈다" 는 발상이지만 구조가 다릅니다: 머지 소트 트리는 *위치로* 쪼개고 노드에 *값 정렬 리스트* 를, 웨이블릿은 *값의 비트로* 쪼개고 *위치 정보* 를 저장하며, 퍼시스턴트는 *값 구간 트리* 를 위치 순으로 쌓은 *버전* 으로 둡니다.
- [리 차오 트리](li-chao-tree/)는 Lv3의 [볼록 껍질 트릭](../../lv3-advanced/07-dp-advanced/convex-hull-trick/) 기본형을 선분·롤백·오프라인으로 넓힙니다. "오프라인 + 롤백" 구조는 Lv5의 [오프라인 동적 연결성](../../lv5-master/04-offline-dynamic/offline-dynamic-connectivity/)과 같은 틀입니다.
- [트립](treap/)과 [스플레이 트리](splay-tree/)는 **같은 연산 집합**(삽입·삭제·순위·구간 뒤집기·구간 합)을 서로 다른 균형 전략으로 제공합니다. 트립은 무작위성 + `split`/`merge`, 스플레이는 회전 + 분할 상환입니다. 스플레이 트리는 Lv5의 [링크-컷 트리](../../lv5-master/01-dynamic-trees/link-cut-tree/)의 부품입니다.
- 트리 위의 문제에서는 [헤비-라이트 분할](../02-tree-decomposition/heavy-light-decomposition/)이 경로를 구간으로 바꾸어 이 단원의 구조에 연결해 줍니다.

## 공통 원칙

- **압축과 순위**: 값이 `10⁹`이어도 구조는 *순위* 위에서 만듭니다. 질의 값은 `bisect`로 순위 한도로 바꿉니다.
- **반열린 구간 `[l, r)`**: 이 단원의 모든 구현이 반열린 구간입니다. 1부터 닫힌 구간 입력이면 `[i − 1, j)`로 바꿉니다.
- **느린 기준과 비교**: 모든 구현은 리스트를 직접 자르고 정렬하는 방법, 모든 직선·선분을 평가하는 방법과 무작위 질의로 맞춰 검증했습니다.
- **불변식 확인**: 트립의 힙 순서, 스플레이의 부모 포인터, 정렬된 리스트 같은 구조적 불변식을 테스트에서 직접 확인합니다. 결과만 맞는 틀린 구조(예: 깊이가 줄지 않는 스플레이)가 있기 때문입니다.
- **지연 태그는 읽기 전에 `push`**: 트립과 스플레이 모두 자식에 접근하기 전에 태그를 내려보냅니다.

4. [리 차오 트리](li-chao-tree/): 직선 집합의 최솟값, 선분·롤백
