# 트립 (Treap)

> **한 줄 요약**: 이진 탐색 트리(키 순서)이면서 각 노드의 **무작위 우선순위**에 대해 최대 힙인 트리. 우선순위가 무작위이므로 모양이 키를 무작위로 넣은 BST와 같아 **기대 깊이가 `O(log n)`**. 핵심 연산은 `split`(앞 `k`개와 나머지로 자르기)와 `merge`(두 트리 이어 붙이기) 둘뿐이고, 삽입·삭제·**구간 뒤집기·잘라 붙이기**가 모두 이 둘의 조합이다.

## 1. 언제 쓰나 (문제 신호)

- **수열의 중간에 삽입·삭제**하면서 위치로 접근한다 (`list.insert`는 `O(n)`)
- "구간 `[l, r]`을 **뒤집어라** / **잘라서 다른 곳에 붙여라** / 순환 이동하라" — 배열이 구조적으로 바뀌는 연산
- 위의 연산들과 함께 **구간 합·최솟값·구간 더하기** (지연 전파)
- 값이 들어오고 나가는 **정렬된 다중집합**: `k`번째로 작은 값, 어떤 값의 **순위**(작은 값의 개수), `floor`/`ceil`, 최솟값·최댓값 꺼내기. 파이썬에는 표준 라이브러리에 이런 정렬된 컨테이너가 없다.
- 슬라이딩 윈도우의 **중앙값**, 이중 우선순위 큐 (최솟값과 최댓값을 모두 꺼냄)
- 배열이 고정이면 [웨이블릿 트리](../wavelet-tree/)·[구간 트리](../../../lv3-advanced/01-range-query-structures/segment-tree/)가 더 가볍다. 값이 정수이고 범위가 작으면 [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/) 위 이분 탐색으로 순서 통계도 된다.

## 2. 핵심 아이디어

**트립 = BST + 힙**: 각 노드는 (키, 우선순위). 키로는 이진 탐색 트리 규칙, 우선순위로는 루트가 가장 큰 힙 규칙. 키와 우선순위가 정해지면 이 조건을 만족하는 트리는 **하나뿐** (우선순위가 가장 큰 노드가 루트, 키가 작은 쪽이 왼쪽 서브트리, …): 데카르트 트리다. 우선순위를 무작위로 주면 "키를 무작위 순서로 넣은 BST" 와 같은 분포가 되어 기대 깊이 `≈ 2 ln n`. 깊이를 균형 조건으로 직접 관리하지 않는다 — 회전도, 색도, 높이도 없다.

**두 연산**:

- `split(t, k)` → `(A, B)`: 중위 순회의 앞 `k`개가 `A`, 나머지가 `B`. 루트의 왼쪽 서브트리 크기 `s`와 `k`를 비교한다. `s ≥ k`면 루트와 오른쪽은 모두 `B`쪽이니 왼쪽 서브트리를 재귀로 쪼개 오른쪽 조각을 루트의 왼쪽 자식으로 달고, 아니면 대칭.
- `merge(A, B)`: `A`의 모든 원소가 `B`의 모든 원소 앞에 있을 때 하나로 합친다. 두 루트의 우선순위가 높은 쪽이 새 루트가 되고, 그 노드의 안쪽 서브트리를 다른 트리와 재귀로 합친다.

둘 다 루트에서 아래로 한 경로만 따라가므로 기대 `O(log n)`.

**모든 것이 이 둘의 조합**:
- 삽입(위치 `i`에 `x`): `split(root, i)` → `merge(merge(A, 새노드), B)`.
- 삭제(위치 `i`): `split`을 두 번 해서 가운데 한 노드를 떼고 `merge(A, C)`.
- 구간 `[l, r)` 처리: `A | B | C`로 세 조각을 내어 `B`에만 태그/질의를 하고 `merge(merge(A, B), C)`.
- 잘라 붙이기 `move`: `B`를 뗀 나머지 `A + C`를 다시 `to`에서 쪼개 `B`를 끼워 넣는다.

**암시적 키(implicit key)**: 키를 저장하지 않는다. 노드의 위치 = 중위 순회 순서이고, 위치는 서브트리 크기로 계산한다. 그래서 `split`이 "값 기준" 이 아니라 "개수 기준". 배열 인덱스가 곧 키인 BST.

**지연 전파**: 구간 뒤집기를 "서브트리 전체의 좌우 반전" 으로 보고, 노드에 `reversed` 표시만 해 둔다. 구간 더하기는 `lazy_add`. 어떤 노드의 자식에 접근하기 *전에* `push`로 표시를 자식에게 내려준다. 합·최솟값 같은 서브트리 요약은 `pull`에서 다시 계산한다 (뒤집기는 합·최솟값에 영향이 없다).

**값이 키인 다중집합**: 같은 구조에서 `split`의 기준을 "개수" 대신 "값 `< x`" 로 바꾸면 `OrderedMultiset`. 순위는 서브트리 크기를 더하며 내려가면서, `k`번째는 크기 비교로 내려가면서 구한다.

### 무엇을 저장하고 어떻게 움직이나

키 또는 수열 위치의 이진 탐색 트리와 무작위 우선순위 힙을 동시에 유지합니다. split은 기준으로 두 트리를 나누고 merge는 모든 왼쪽 원소가 오른쪽보다 앞설 때 둘을 합칩니다. 수열용 트립은 키 대신 왼쪽 서브트리 크기를 사용합니다.

### 왜 이 방법이 맞는가

서로 독립적인 무작위 우선순위가 평균적으로 균형 잡힌 트리 모양을 만듭니다. 분할·병합은 BST의 순서와 힙 우선순위를 모두 유지해야 합니다. 크기·합은 자식 변경 후 다시 계산하고 지연 표시는 구조를 읽기 전에 내려야 합니다.

### 작은 예제로 검산하기

수열 `[1,2,3,4]`를 위치 2에서 split하면 `[1,2]`와 `[3,4]`입니다. 구간 `[1,3)`을 뒤집으려면 두 번 분할해 가운데 `[2,3]`만 뒤집고 순서대로 합칩니다. 평균 O(log n)과 최악 O(n)을 구분합니다.

## 3. 손으로 따라가기

수열 `[10, 20, 30, 40, 50, 60, 70]`에 우선순위 `[0.5, 0.9, 0.3, 0.7, 0.2, 0.8, 0.4]`를 이 순서로 준다 (실제 구현은 난수). 가장 큰 우선순위 0.9가 `20`이라 루트.

```
                70(0.4)
            60(0.8)
                    50(0.2)
                40(0.7)
                    30(0.3)
        20(0.9)                 ← 루트 (왼쪽 서브트리 = 10)
            10(0.5)
```

(오른쪽 서브트리가 위, 왼쪽이 아래로 눕혀 그린 그림입니다.) 즉 `20`의 왼쪽 자식 `10`, 오른쪽 자식 `60`. `60`의 왼쪽 `40`(그 왼쪽 `30`, 오른쪽 `50`), 오른쪽 `70`.

### `split(root, 4)` — 앞 4개 / 나머지

1. 루트 `20`: 왼쪽 서브트리 크기 1 < 4 → `20`은 왼쪽 조각 `A`에 속한다. 오른쪽 서브트리 `60`을 `k = 4 − 1 − 1 = 2`개로 쪼갠다.
2. `60`: 왼쪽 서브트리(`40` 아래)의 크기 3 ≥ 2 → `60`은 `B`쪽. 왼쪽 서브트리 `40`을 `k = 2`로 쪼갠다.
3. `40`: 왼쪽 서브트리 `30`의 크기 1 < 2 → `40`은 `A`쪽, 오른쪽 `50`을 `k = 2 − 1 − 1 = 0`개로 쪼개면 `(비어 있음, 50)`.
4. 돌아오며 연결: `40`의 오른쪽 = 비어 있음 → `A' = 40(30)`; `60`의 왼쪽 = `50`; `20`의 오른쪽 = `A'`.

결과: `A` = 루트 `20`(왼쪽 `10`, 오른쪽 `40`(왼쪽 `30`)) → 중위 `10 20 30 40`, `B` = 루트 `60`(왼쪽 `50`, 오른쪽 `70`) → 중위 `50 60 70`. 우선순위가 큰 `20`, `60`이 각 조각의 루트로 남는다.

### `merge(A, B)`

두 루트 `20`(0.9)과 `60`(0.8) 중 높은 `20`이 루트. `20`의 오른쪽 서브트리 `40`과 `B`를 재귀로 합친다 (`40`(0.7) < `60`(0.8)이므로 `60`이 위로, `60`의 왼쪽에 `merge(40, 50)` …). 합친 결과의 중위 순회는 `10 … 70`이고 힙 규칙이 유지된다.

### 구간 연산

(위 수열에서) `reverse(1, 5)` → `[10, 50, 40, 30, 20, 60, 70]`. `add(0, 3, 100)` → `[110, 150, 140, 30, 20, 60, 70]`. `range_sum(2, 6) = 140 + 30 + 20 + 60 = 250`, 전체 `range_min = 20`. `move(1, 3, 4)`: `[150, 140]`를 떼어 남은 `[110, 30, 20, 60, 70]`의 4번째 자리 앞에 끼운다 → `[110, 30, 20, 60, 150, 140, 70]`.

### 정렬된 다중집합

`[5, 1, 5, 3, 9, 7, 5]` → 중위 `[1, 3, 5, 5, 5, 7, 9]`. `count(5) = 3`, `rank(5)` (5보다 작은 개수) `= 2`, `kth_smallest(3) = 5`, `floor(4) = 3`, `ceil(4) = 5`, `successor(5) = 7`, `predecessor(5) = 3`. `remove(5)` 한 번 → `[1, 3, 5, 5, 7, 9]`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _split(self, t, k):                         # 중위 순회의 앞 k 개 / 나머지
    if not t: return 0, 0
    self._push(t)                               # 자식을 읽기 전에 지연 표시를 내려보낸다
    if self.size[self.left[t]] >= k:
        a, b = self._split(self.left[t], k)
        self.left[t] = b; self._pull(t)
        return a, t
    a, b = self._split(self.right[t], k - self.size[self.left[t]] - 1)
    self.right[t] = a; self._pull(t)
    return t, b

def _merge(self, a, b):                         # a 의 모든 원소가 b 의 앞
    if not a: return b
    if not b: return a
    if self.priority[a] > self.priority[b]:
        self._push(a); self.right[a] = self._merge(self.right[a], b); self._pull(a); return a
    self._push(b); self.left[b] = self._merge(a, self.left[b]); self._pull(b); return b
```

- 노드는 배열 여러 개(`value`, `priority`, `left`, `right`, `size`, `total`, `low`, `lazy_add`, `reversed`)에 저장하고 `0`번이 "없음"입니다. 지운 노드는 `free` 목록에서 재사용합니다.
- `ImplicitTreap(values, seed)`: `insert`, `append`, `erase`(값 반환), `get`/`[]`, `reverse(l, r)`, `add(l, r, d)`, `range_sum`, `range_min`, `move(l, r, to)`, `to_list`. 초기 배열은 데카르트 트리 방식으로 `O(n)`에 만듭니다 (스택으로 오른쪽 척추 유지).
- `OrderedMultiset(values, seed)`: `add`, `remove`(하나, 성공 여부), `count`, `rank`, `count_at_most`, `kth_smallest`(1부터), `[i]`(0부터), `floor`/`ceil`/`predecessor`/`successor`, `pop_min`/`pop_max`, `in`.
- 우선순위는 시드가 있는 난수라 같은 입력이면 같은 모양입니다. 분할·병합이 재귀지만 기대 깊이가 `O(log n)`이라 재귀 한도 문제가 없습니다 (아래 표 참고).
- 직접 실행하면 Library Checker "Range Reverse Range Sum" 형식 — `N Q`, 수열, 질의 `0 l r`(반열린 `[l, r)` 뒤집기) 또는 `1 l r`(합 출력) — 을 처리합니다.

## 5. 복잡도와 입력 크기 가이드

- `split`, `merge`, 삽입, 삭제, 구간 연산 모두 기대 `O(log n)` (우선순위가 무작위일 때, 입력과 무관하게). 최악은 `O(n)`이지만 확률이 극히 낮습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 트리 깊이 (같은 시드로 `0..n−1`을 넣은 결과, `2 ln n`은 평균 깊이의 기대치):

| `n` | 최대 깊이 | 평균 깊이 | `2 ln n` | `log₂ n` |
|---|---|---|---|---|
| 1,000 | 21 | 12.3 | 13.8 | 10.0 |
| 10,000 | 32 | 17.1 | 18.4 | 13.3 |
| 100,000 | 45 | 23.2 | 23.0 | 16.6 |

- 정렬된 순서로 `20000`개를 `append`해도 깊이는 균형을 유지합니다 (우선순위가 입력 순서와 무관하므로). 깊이 최댓값이 `log₂ n`의 2~3배라 재귀 한도(기본 1000)는 안전합니다.
- 이 환경에서 측정한 값입니다.

| 작업 | 시간 |
|---|---|
| `ImplicitTreap` 준비, `n = 10⁵` (`O(n)` 데카르트 트리 방식) | 0.14초 |
| `reverse` `2·10⁴`번, `n = 10⁵` | 1.47초 |
| `range_sum` `2·10⁴`번 | 1.41초 |
| `insert` `2·10⁴`번 (무작위 위치) | 0.92초 |
| `OrderedMultiset` `add` `10⁵`번 | 3.43초 |
| `OrderedMultiset` `rank` `10⁵`번 (분할 없이 내려가기만) | 0.55초 |

- 구간 연산 하나가 분할 2번 + 병합 2번이라 상수가 큽니다. `10⁵`개 연산이 몇 초 단위입니다. `rank`·`kth_smallest`처럼 *구조를 바꾸지 않는* 질의는 훨씬 빠릅니다 (분할을 하지 않고 내려가기만).

## 6. 자주 하는 실수

- **`push` 없이 자식에 접근**: 지연 표시가 있는 노드의 `left`/`right`는 *아직 좌우가 바뀌지 않은* 값입니다. `split`, `merge`, `get`, 순회에서 자식을 읽거나 따라가기 전에 항상 `push`하세요.
- **`pull`을 빼먹음**: 자식 연결을 바꾼 노드는 `pull`로 `size`·`total`·`low`를 다시 계산해야 합니다. `split`/`merge`의 반환 직전에 한 번씩.
- **지연 태그의 합성 순서**: 뒤집기와 더하기는 서로 독립이라 어떤 순서든 되지만, "더하기 후 곱하기" 같은 아핀 태그는 합성 순서가 있어서 `push`에서 자식의 태그에 자신의 태그를 올바른 순서로 합성해야 합니다.
- **우선순위가 무작위가 아님**: 인덱스나 값에서 만든 결정적 우선순위는 입력에 따라 사슬이 됩니다. 반드시 난수 (예: `random.random()`).
- **`split`의 의미**: `split(t, k)`의 `k`는 *개수* (앞의 `k`개). 위치 `l`부터 `r` 전까지(`[l, r)`)면 `split(root, l)` 뒤에 `split(rest, r − l)`. 두 번째 인자를 `r`로 쓰는 실수가 흔합니다.
- **`merge`의 전제**: 왼쪽 트리의 모든 원소가 오른쪽 앞에 있어야 합니다. 순서가 뒤바뀐 두 트리를 합치면 BST 순서가 깨집니다.
- **다중집합에서 하나만 지우기**: 값이 `x`인 노드 *전부* 를 지우면 안 됩니다. `x`인 노드들의 조각에서 뿌리 하나만 떼어 내고 자식들을 `merge`로 이어 붙입니다.
- **범위 확인**: 구간 `[l, r)`이 `0 ≤ l ≤ r ≤ n`인지, 위치가 `0 ≤ i < n`인지 먼저 확인하세요. 구조를 건드린 *뒤* 에 오류를 내면 트리가 쪼개진 채로 남습니다 (이 구현은 확인을 먼저 합니다).
- **지운 노드를 계속 참조**: 노드를 `free` 목록에 넣은 뒤에 그 번호를 쓰면 재사용된 노드를 건드립니다. 값을 읽은 뒤에 반환하세요.
- **빈 구간의 최솟값**: 요약값이 `∞`로 나옵니다. 오류로 처리하세요.
- **재귀로 `10⁶` 규모를 기대**: 기대 깊이가 작아서 재귀는 안전하지만, 파이썬에서 호출 비용이 커서 `10⁵`~`2·10⁵` 규모가 현실적인 한계입니다.

## 7. 변형과 응용

- **퍼시스턴트 트립**: `split`/`merge`가 지나는 노드를 복사하면 과거 버전을 보존합니다 (경로 복사). 구간 복제 같은 연산도 `O(log n)`에 됩니다.
- **로프(rope)**: 문자열 편집(삽입·삭제·잘라 붙이기)의 표준 구조.
- **구간 정렬·셔플**: 구간을 떼어 내 다른 방식으로 재구성하고 다시 붙입니다.
- **트립 합집합**: 키가 있는 두 트립을 우선순위로 합치는 `union`은 `O(m log(n/m))` — 집합 연산을 이진 탐색 트리로.
- **데카르트 트리**: 우선순위를 배열 값으로 주면 구간 최솟값(RMQ) 구조가 됩니다. 이 단원의 구조들이 모두 "트리 모양을 우선순위로 결정" 한다는 점에서 연결됩니다.
- **동적 순서 통계**: 값이 계속 들어오고 나가는 문제의 `k`번째/순위 질의. 값 범위가 작으면 [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/)로 충분.
- **스플레이 트리와의 비교**: 같은 연산을 [스플레이 트리](../splay-tree/)가 분할 상환 `O(log n)`으로 하고, 무작위성이 필요 없는 대신 한 연산이 `O(n)`일 수 있습니다.
- **더 큰 구조의 부품**: [링크-컷 트리](../../../lv5-master/01-dynamic-trees/link-cut-tree/)(Lv5)가 경로를 균형 트리(스플레이 또는 트립)로 표현합니다.
