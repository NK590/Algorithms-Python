# 흐름과 매칭 심화 (Flow & Matching)

Lv3에서 [디닉](../../lv3-advanced/03-graph-advanced/dinic/)(최대 유량)과 [이분 매칭](../../lv3-advanced/03-graph-advanced/bipartite-matching/)(최대 매칭)을 배웠습니다. 이 단원은 거기에 **비용**을 붙입니다 — "가장 많이" 가 아니라 "가장 싸게". 같은 문제(비용 있는 이분 배정)를 흐름과 쌍대 변수라는 두 가지 방법으로 푸는 두 개념이 짝을 이룹니다.

## 한눈에 비교

| 개념 | 푸는 문제 | 핵심 | 시간 |
|---|---|---|---|
| [최소 비용 최대 유량](min-cost-max-flow/) | 비용이 있는 네트워크의 (최대) 유량 중 최소 비용 | 가장 싼 증가 경로를 반복 (역간선 비용 −w), 퍼텐셜 + 다익스트라 | O(F · E log V) |
| [헝가리안 알고리즘](hungarian-algorithm/) | 꽉 찬 비용 행렬의 완전 배정(할당 문제) | 퍼텐셜 u, v를 키우며 등호 간선으로 교대 경로 탐색 (쌍대성) | O(n²m) |

같은 완전 이분 `n × n` 배정을 두 방법으로 풀어 이 환경에서 측정했습니다 (비용 무작위, 두 결과가 일치).

| `n` | 흐름 (MCMF) | 헝가리안 |
|---|---|---|
| 100 | 0.25초 | 0.01초 |
| 200 | 1.95초 | 0.08초 |
| 300 | 6.77초 | 0.28초 |

꽉 찬 행렬에서는 헝가리안이 20배 넘게 빠릅니다. 간선이 희소하거나, 용량이 1이 아니거나, 일반 네트워크(경로, 운송, 정점 용량)이면 흐름이 맞습니다.

## 문제 신호로 고르기

| 문제의 신호 | 선택 |
|---|---|
| "`n`명에게 `n`개 일을 하나씩, 비용 행렬이 주어진다, 총합 최소/최대" | [헝가리안](hungarian-algorithm/) |
| 위와 같은데 일부 칸이 불가능하고 "가능한 만큼 최대로 배정" | [최소 비용 최대 유량](min-cost-max-flow/) (또는 가상 열을 넣은 헝가리안) |
| 용량이 있는 간선, 운송 문제, 정확히 `k`만큼 보내는 최소 비용 | [최소 비용 최대 유량](min-cost-max-flow/) |
| 서로 겹치지 않는 경로 `k`개의 최단 총 길이 | [최소 비용 최대 유량](min-cost-max-flow/) |
| 이득이 나는 동안만 보내기 | [최소 비용 최대 유량](min-cost-max-flow/) (`flow_curve`의 볼록성) |
| 가장 큰 한 칸을 최소로 (병목 배정) | [헝가리안](hungarian-algorithm/)의 `bottleneck_assignment` |
| 비용 없이 최대 유량/최대 매칭 | [디닉](../../lv3-advanced/03-graph-advanced/dinic/) / [이분 매칭](../../lv3-advanced/03-graph-advanced/bipartite-matching/) |
| 이분이 아닌 일반 그래프의 매칭 | [블로섬](../../lv5-master/02-matching-matroid/blossom/) (Lv5) |

## 개념 사이의 관계

- 헝가리안의 퍼텐셜 `u[i] + v[j] ≤ cost[i][j]`는 MCMF의 **퍼텐셜(줄인 비용)** 과 같은 쌍대 변수입니다. 헝가리안은 행을 하나씩 더하는 SSP를 이분 구조에 맞춰 `O(nm)`으로 구현한 것으로 볼 수 있습니다.
- 둘 다 **교대(증가) 경로** 로 배정을 키웁니다: [이분 매칭](../../lv3-advanced/03-graph-advanced/bipartite-matching/)의 증가 경로에 "가장 싼" 이라는 조건이 붙은 것이 최소 비용 흐름이고, 등호 간선만 쓰는 것이 헝가리안입니다.
- MCMF의 **볼록성**(유량에 대한 최소 비용이 볼록)은 헝가리안에서 "행을 하나씩 더해 갈 때 최소 비용의 증가분" 이 늘어나는 성질과 대응합니다.
- 최대화 문제는 둘 다 비용 부호를 뒤집어 같은 알고리즘을 씁니다.

## 공통 원칙

- **전수 탐색과 비교**: 작은 크기에서 모든 정수 유량/모든 순열을 나열한 값과 맞춰 검증했습니다.
- **쌍대 증명서**: 헝가리안은 `u, v`로 최적성을 직접 확인합니다 (`Σu + Σv = 배정 비용`). 흐름은 "음의 사이클 없음" 으로 확인합니다.
- **정수 비용은 정확**: 파이썬 정수라 오버플로가 없고, 퍼텐셜이 정수로 유지되어 등호 비교가 정확합니다. 실수 비용이면 오차를 고려합니다.
- **네트워크는 한 번 쓰고 새로**: `flow()`를 부른 뒤 네트워크는 유량이 흐른 상태입니다.
