# 헝가리안 알고리즘 (Hungarian Algorithm)

> **한 줄 요약**: `n × m` 비용 행렬에서 **행마다 서로 다른 열을 하나씩** 골라 합을 최소로 하는 할당 문제를 `O(n²m)`에 푼다. 행과 열에 **퍼텐셜** `u[i]`, `v[j]`를 붙여 `u[i] + v[j] ≤ cost[i][j]`를 지키면서, 배정된 칸에서는 등호가 되도록 키워 간다. 이 조건이 만족되면 선형 계획법의 **쌍대성**에 의해 그 배정이 최적이라는 증명서가 된다.

## 1. 언제 쓰나 (문제 신호)

- "`n`명에게 `n`개의 일을 하나씩, 사람-일 비용이 주어진다, 총합을 최소(최대)로" — 전형적인 할당 문제
- 완전 이분 그래프(모든 사람이 모든 일을 할 수 있음)에서 **완전 매칭의 최소(최대) 가중치**
- `n < m`: 행이 더 적은 직사각형 (사람이 일보다 적다). 이 구현은 반대(`n > m`)도 행렬을 바꿔서 처리
- 일부 칸이 **배정 불가**(`None`): 가능한 완전 배정이 있으면 그중 최솟값, 없으면 오류
- 합이 아니라 **가장 큰 한 칸을 최소로**(병목 할당): 값에 대한 이분 탐색 + 매칭 (`bottleneck_assignment`)
- 간선이 **희소**하거나 용량이 1이 아니거나 일반 네트워크이면 [최소 비용 최대 유량](../min-cost-max-flow/)이 맞다. 꽉 찬 행렬에는 이 알고리즘이 훨씬 빠르다 (아래 표)
- 비용이 필요 없는 매칭이면 [이분 매칭](../../../lv3-advanced/03-graph-advanced/bipartite-matching/)

## 2. 핵심 아이디어

**쌍대 조건**: 배정을 `x[i][j] ∈ {0, 1}`로 쓰면 최소화 문제의 쌍대(선형 계획법)는 "`u[i] + v[j] ≤ cost[i][j]`를 만족하며 `Σu + Σv`를 최대화" 하는 문제다. 어떤 배정과 퍼텐셜이 있어서
1. 모든 `(i, j)`에서 `u[i] + v[j] ≤ cost[i][j]` (쌍대 가능),
2. 배정된 칸 `(i, j)`에서 `u[i] + v[j] = cost[i][j]` (**상보적 여유**: 여유 0),

이면 `배정의 비용 = Σ_(i,j 배정) (u[i] + v[j]) = Σu + Σv ≤ 어떤 배정의 비용`, 그래서 그 배정은 최적이다. 알고리즘은 이 두 조건을 유지하며 배정을 키운다.

**등호 간선 그래프**: `u[i] + v[j] = cost[i][j]`인 칸(여유 0)만 이은 이분 그래프. 이 안에서 배정(매칭)을 찾는다.

**행을 하나씩 추가**: 새 행 `i`에서 시작해 [이분 매칭](../../../lv3-advanced/03-graph-advanced/bipartite-matching/)의 교대 경로를 찾는다 — 등호 간선으로 못 가는 열이 있으면 **여유가 가장 작은 칸의 여유 `delta`** 만큼 퍼텐셜을 조정한다:
- 지금까지 방문한 행의 `u`를 `+delta`, 방문한 열의 `v`를 `−delta` (방문한 행과 방문한 열 사이 칸의 합은 그대로이므로 기존 등호 간선은 유지),
- 방문하지 않은 열의 여유 `slack[j]`는 `−delta` (이제 하나 이상이 0이 되어 새 등호 간선이 생긴다).

새로 닿은 열에 이미 배정된 행이 있으면 그 행도 방문하고 반복, **배정이 없는 열**에 닿으면 교대 경로를 따라 배정을 뒤집어 배정이 하나 늘어난다. 다익스트라처럼 `slack`이 최단 거리 역할이다. 행 하나에 `O(nm)`, 전체 `O(n²m)`.

**왜 `delta ≥ 0`인가**: `slack[j]`는 항상 `cost − u − v ≥ 0` (쌍대 가능)이므로 최솟값도 0 이상.

**최대화·직사각형·불가능 칸**: 최대화는 비용에 `−1`을 곱한다. `n > m`이면 행렬을 바꿔(열이 행 역할) 푼다. `None` 칸은 큰 값 `big = (유한한 비용의 절댓값 합) + 1`로 바꿔서, 다른 완전 배정이 있는 한 절대 선택되지 않게 하고, 선택되면 오류. 이만큼이면 충분한 이유: `None`을 쓰는 배정과 쓰지 않는 배정의 비용 차이에서 두 배정이 *서로 다르게* 고른 칸들만 남는데, 그 칸들의 절댓값 합은 `big − 1` 이하이므로 `None` 칸 하나(`big`)가 항상 더 비싸다.

## 3. 손으로 따라가기

비용 행렬 (행 = 사람, 열 = 일, 이후 열 번호는 0부터)

```
        일0  일1  일2
사람0     4    2    8
사람1     2    3    7
사람2     3    1    6
```

처음 `u = [0, 0, 0]`, `v = [0, 0, 0]`.

| 단계 | 하는 일 | 퍼텐셜 / 배정 |
|---|---|---|
| 행 0 추가 | 사람 0의 여유 `[4, 2, 8]`, 가장 작은 `delta = 2`(일 1). `u₀ += 2`. 일 1에 배정된 행이 없으니 끝 | `u = [2, 0, 0]`, 배정: 사람0 → 일1 |
| 행 1 추가 | 사람 1의 여유 `[2, 3, 7]`, `delta = 2`(일 0). `u₁ += 2`. 일 0은 비어 있어 끝 | `u = [2, 2, 0]`, 사람1 → 일0 |
| 행 2 추가 (1) | 사람 2의 여유 `[3, 1, 6]`, `delta = 1`(일 1). `u₂ += 1`. 일 1에는 사람 0이 있으니 사람 0도 방문 | `u = [2, 2, 1]` |
| 행 2 추가 (2) | 방문한 행 `{사람2, 사람0}`, 남은 일 0·2의 여유: 일 0은 `min(3 − 1 − 0, 4 − 2 − 0) = 2`, 일 2는 `min(6 − 1, 8 − 2) = 5`, `delta = 2`(일 0). 방문한 행의 `u`를 +2, 방문한 열(일 1)의 `v`를 −2. 일 0에는 사람 1이 있으니 사람 1도 방문 | `u = [4, 2, 3]`, `v = [0, −2, 0]` |
| 행 2 추가 (3) | 방문한 행 `{사람2, 사람0, 사람1}`, 일 2의 여유 `min(6 − 3 − 0, 8 − 4 − 0, 7 − 2 − 0) = 3`, `delta = 3`(일 2). 방문한 행 `+3`, 방문한 열(일 0·일 1) `−3`. 일 2는 비어 있어 끝 → 교대 경로로 배정 뒤집기 | `u = [7, 5, 6]`, `v = [−3, −5, 0]` |

최종 배정: 사람 0 → 일 1(2), 사람 1 → 일 0(2), 사람 2 → 일 2(6) = **10**.

**증명서(쌍대 해)**: `Σu + Σv = (7 + 5 + 6) + (−3 − 5 + 0) = 18 − 8 = 10` — 배정의 비용과 같다. 모든 칸에서 `u[i] + v[j] ≤ cost[i][j]`: 사람0 `[4, 2, 8]` 대 `u₀ + v = [4, 2, 7]`, 사람1 `[2, 3, 7]` 대 `[2, 0, 5]`, 사람2 `[3, 1, 6]` 대 `[3, 1, 6]` — 모두 이하이고, 배정된 칸(사람0-일1, 사람1-일0, 사람2-일2)에서는 등호. 따라서 10이 최솟값이다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _solve(cost):                                         # n ≤ m
    u, v = [0] * (n + 1), [0] * (m + 1)
    row_of, way = [0] * (m + 1), [0] * (m + 1)            # row_of[j]: 열 j 의 배정 행 (1부터), way: 교대 경로 복원
    for i in range(1, n + 1):
        row_of[0] = i; j0 = 0
        slack, used = [INF] * (m + 1), [False] * (m + 1)
        while True:
            used[j0] = True; i0 = row_of[j0]; delta, j1 = INF, 0
            for j in range(1, m + 1):
                if not used[j]:
                    current = cost[i0 - 1][j - 1] - u[i0] - v[j]
                    if current < slack[j]: slack[j], way[j] = current, j0
                    if slack[j] < delta:   delta, j1 = slack[j], j
            for j in range(m + 1):                        # 퍼텐셜 조정
                if used[j]: u[row_of[j]] += delta; v[j] -= delta
                else:       slack[j] -= delta
            j0 = j1
            if row_of[j0] == 0: break                     # 짝 없는 열에 닿았다
        while j0:                                         # 교대 경로를 따라 배정 뒤집기
            j1 = way[j0]; row_of[j0] = row_of[j1]; j0 = j1
```

- `hungarian(cost, maximize=False)` → `(합, 행마다 배정된 열)` (`n > m`이면 배정 못 받은 행은 `-1`). `cost` 원소는 정수, 분수, 실수 모두 되고 `None`은 배정 불가.
- `hungarian_duals(cost, maximize)` → `(합, 배정, u, v)`: 쌍대 해를 증명서로 돌려줍니다 (최대화는 부호가 바뀐 쌍대 해).
- `bottleneck_assignment(cost)` → `(배정된 칸의 최댓값의 최솟값, 배정)`: 값의 이분 탐색 + 쿤 매칭.
- 직접 실행하면 Library Checker "Assignment Problem" 형식 — `N`, 이어서 `N`줄의 `N`개 정수 — 를 받아 최소 비용과 행마다 배정된 열(0부터)을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 행 하나가 `O(nm)`이므로 전체 `O(n²m)` (정사각이면 `O(n³)`). 메모리는 입력 행렬 `O(nm)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다 (비용 무작위).

| 작업 | 시간 |
|---|---|
| `n = 100` 정사각 | 0.01초 |
| `n = 200` | 0.08초 |
| `n = 300` | 0.28초 |
| `n = 500` (비용 −10⁶..10⁶) | 0.71초 |
| `n = 200` 병목 할당 | 0.34초 |
| 같은 `n = 100 / 200 / 300` 배정을 [최소 비용 흐름](../min-cost-max-flow/)으로 | 0.25초 / 1.95초 / 6.77초 |

- `n = 500`은 파이썬에서 1초 안에 들어옵니다. 시간은 `n³`에 비례하므로 `n = 1000`은 `n = 500`의 8배, 약 6초(추정)입니다. 더 크면 행렬이 희소한지, 다른 구조(그리디, 흐름)가 가능한지 먼저 보세요.
- 조밀한 완전 이분 배정에서 흐름 대비 20배 이상 빠릅니다 (`n = 300`에서 24배).

## 6. 자주 하는 실수

- **`n > m`일 때 행을 다 배정하려 함**: 행이 열보다 많으면 모든 행을 배정할 수 없습니다. 이 구현은 행렬을 바꿔서 풀고 배정 못 받은 행에 `-1`을 돌려줍니다. 문제가 "열이 모두 배정되어야 한다" 인지 "행이 모두" 인지 확인하세요.
- **불가능 칸에 `INF`를 넣고 합이 오버플로/부동소수 오차**: 파이썬 `float('inf')`는 `u`, `v` 계산에서 `inf − inf = nan`을 낼 수 있습니다. 충분히 큰 *유한한* 값(이 구현의 `None` 처리)을 쓰세요.
- **음수 비용을 양수로 이동**: 이 구현은 음수 비용을 그대로 처리합니다. 모든 칸에 상수를 더해도 최적 배정은 같지만(모든 완전 배정에 같은 값이 더해지므로) 직사각형에서는 배정되는 행의 수가 같을 때만 성립합니다.
- **최대화에서 부호 반전 누락**: 최대 합은 `−cost`의 최소 합. 쌍대 해도 부호가 바뀌므로 증명서를 쓰려면 주의.
- **`slack` 초기화 누락**: 행을 추가할 때마다 `slack`을 `INF`로, `used`를 `False`로 되돌려야 합니다.
- **`way` 갱신 조건**: 더 작은 여유를 찾았을 때만 (`current < slack[j]`) 직전 열을 기록합니다. 그렇지 않으면 교대 경로 복원이 틀립니다.
- **1부터 인덱스와 0부터 인덱스 혼동**: 구현은 `row_of[0]`을 가상 열로 쓰는 1부터 인덱스입니다. 결과를 돌려줄 때 `-1`로 되돌립니다.
- **같은 값이 많아 동점**: 동점이면 최적 배정이 여러 개입니다. 총합만 같으면 정답이므로 특정 배정을 기대하지 마세요 (문제가 사전순 등을 요구하면 별도 처리).
- **`O(n⁴)` 순진한 구현**: 행마다 전체 열에 대해 다시 최소를 구하면 느려집니다. `slack` 배열을 유지하는 것이 `O(n³)`의 핵심.

## 7. 변형과 응용

- **병목 할당(최대 칸 최소화)**: 값의 이분 탐색 + 쿤 매칭 (`bottleneck_assignment`).
- **일부만 배정**: 배정하지 않아도 되고 배정하지 않는 비용이 있다면 비용 `0`(또는 그 비용)의 가상 열을 추가해 직사각형으로 만듭니다.
- **최대 가중치 (완전하지 않은) 매칭**: 음수 이득을 피하려면 `0`비용 가상 행·열을 추가해 "배정 안 함" 을 허용합니다.
- **한 행 추가의 증분**: 새 행 하나를 추가하는 것은 이 알고리즘의 한 단계(`O(nm)`)와 같으니 온라인으로 행을 받는 문제에서 재사용할 수 있습니다.
- **쌍대 해의 활용**: 퍼텐셜이 곧 그림자 가격(shadow price): 한 열의 비용을 바꿨을 때 최적값이 어떻게 변하는지 분석에 쓰입니다.
- **일반 그래프의 가중치 매칭**: 이분 그래프가 아니면 블로섬 알고리즘 계열이 필요합니다 (Lv5의 블로섬은 가중치 없는 매칭을 다룹니다).
- **흐름과의 선택**: 행렬이 꽉 찼으면 헝가리안, 희소하거나 용량·부가 제약이 있으면 [최소 비용 흐름](../min-cost-max-flow/).
