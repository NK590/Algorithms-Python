# FFT / NTT (고속 푸리에 변환, 수론 변환)

> **한 줄 요약**: 두 수열(다항식)의 **합성곱** `c[k] = Σ a[i]·b[k−i]`를 `O(nm)` 대신 `O((n+m) log(n+m))`에 구한다. 다항식을 계수가 아니라 **`n`개 점에서의 값**으로 표현하면 곱이 점별 곱 `O(n)`이 되고, 계수 ↔ 점 값 변환은 1의 거듭제곱근의 대칭성을 이용한 분할 정복으로 `O(n log n)`이다. 복소수로 하면 **FFT**(오차 있음), 소수 `p`의 나머지 위에서 하면 **NTT**(정확).

## 1. 언제 쓰나 (문제 신호)

- "두 수열의 합성곱", "다항식의 곱", 길이가 `10⁵`~`10⁶`
- "`A`에서 하나, `B`에서 하나를 골라 합이 `s`가 되는 방법의 수" — 지시 배열 두 개의 합성곱
- **매우 긴 수의 곱셈** (자릿수 `10⁵` 이상을 직접 구현해야 할 때)
- "원형으로 `k`칸 밀었을 때 내적의 최댓값" (순환 내적 예제) — 한 번의 합성곱
- 와일드카드가 있는 문자열 매칭, 부분 배열 개수 세기 등 *위치의 합이 고정*인 조합 문제
- 생성 함수: 주사위 합의 분포 `(x + … + x⁶)ⁿ`, 동전 조합 수
- `n ≤ 5000` 정도면 `O(n²)` 이중 반복이 더 간단하고, 합성곱이 아니라 *곱 한 번* 정도면 파이썬의 큰 정수 곱셈이 훨씬 빠르다

## 2. 핵심 아이디어

**합성곱**: `a`가 길이 `n`, `b`가 길이 `m`이면 결과 `c`는 길이 `n + m − 1`, `c[k] = Σ_{i+j=k} a[i]·b[j]`. 정의대로면 `O(nm)`. 다항식 `A(x) = Σ a[i]xⁱ`, `B(x)`의 곱 `A(x)B(x)`의 계수가 곧 `c`다.

**점 값 표현**: 차수 `< N`인 다항식은 서로 다른 `N`개의 점에서의 값으로 유일하게 정해진다. 두 다항식을 *같은 점들*에서 평가하면 곱 `C(x_k) = A(x_k)·B(x_k)`는 `O(N)`이다. 문제는 *계수 → 값*(평가)과 *값 → 계수*(보간)의 변환 비용. 점을 아무렇게나 고르면 `O(N²)`.

**점을 1의 `N`제곱근으로**: `ω = e^{2πi/N}` (또는 mod `p`의 위수 `N`인 원소)로 `x_k = ωᵏ`를 잡으면 분할 정복이 된다 (`N`은 2의 거듭제곱).

```
A(x) = A_짝(x²) + x·A_홀(x²)          (짝수 번째 / 홀수 번째 계수로 분리)
A(ωᵏ)      = A_짝(ω²ᵏ) + ωᵏ · A_홀(ω²ᵏ)
A(ω^{k+N/2}) = A_짝(ω²ᵏ) − ωᵏ · A_홀(ω²ᵏ)      (ω^{N/2} = −1)
```

크기 `N/2`의 변환 두 개(`ω²`가 `N/2`제곱근)로 크기 `N`의 값 `N`개를 *모두* 얻는다 → `T(N) = 2T(N/2) + O(N) = O(N log N)`. 이 결합을 **나비(butterfly) 연산** `(u, v) → (u + ω·v, u − ω·v)`라 한다.

**역변환**: 값 → 계수는 같은 변환에서 `ω`를 `ω⁻¹`로 바꾸고 `N`으로 나눈다.

**FFT vs NTT**:
- **FFT**: 복소수 단위근. 구현이 단순하지만 부동소수점이라 *결과 계수가 약 10¹⁴를 넘으면 오차*로 틀린다 (반올림 필요).
- **NTT**: 정수 mod `p` 위에서. `N | (p − 1)`인 소수에서 `ω = g^{(p−1)/N}` (`g`는 원시근). `998244353 = 119·2²³ + 1`은 `N ≤ 2²³`까지 지원하고 `g = 3`. 정확하지만 결과도 mod `p`.

**임의의 modulus·정확한 정수**: 서로 다른 NTT 소수 세 개(`998244353`, `167772161`, `469762049`)로 각각 구한 뒤 **중국인의 나머지 정리**(가르너 방법)로 합치면 결과 계수가 `±3.9·10²⁵` 안에서 정확하다. 임의 mod는 계수를 `[0, mod)`로 줄여 같은 방식으로 정확한 값을 얻은 뒤 `mod`로 나눈다.

**길이**: 변환 길이 `N`은 *결과 길이 `n + m − 1` 이상*의 2의 거듭제곱이어야 한다 (짧으면 뒤쪽 계수가 앞으로 접혀 겹친다: 순환 합성곱). 모자란 자리는 0으로 채운다.

### 무엇을 저장하고 어떻게 움직이나

다항식의 계수 표현을 여러 점에서의 값 표현으로 바꾸면 곱셈이 점별 곱이 됩니다. 역변환으로 다시 계수를 얻습니다. FFT는 복소수 오차를, NTT는 모듈러에서 필요한 길이의 단위근 존재 조건을 관리해야 합니다.

### 왜 이 방법이 맞는가

서로 다른 충분한 점에서 값이 정해지면 해당 차수의 다항식이 유일하게 정해집니다. 곱 결과 길이 이상으로 0을 채우면 순환 합성곱이 아니라 원하는 선형 합성곱을 얻습니다. 변환 길이와 역변환의 정규화가 맞아야 합니다.

### 작은 예제로 검산하기

`(1+2x)*(3+4x)`의 계수는 `[3,10,8]`입니다. 필요한 길이는 2+2-1=3이고 보통 길이 4로 변환합니다. 큰 정수나 여러 모듈러 합성에서는 오차·계수 상한·CRT의 복원 범위를 함께 따집니다.

## 3. 손으로 따라가기

### `(1 + 2x + 3x²)(4 + 5x)`를 mod 17의 NTT로 (`N = 4`, `ω = 4`)

`4² = 16 = −1`, `4⁴ = 256 ≡ 1 (mod 17)`이므로 `4`는 위수 4의 원소. 정답은 `4 + 13x + 22x² + 15x³`이고 mod 17로는 `[4, 13, 5, 15]`.

계수를 길이 4로 0을 채운다: `a = [1, 2, 3, 0]`, `b = [4, 5, 0, 0]`.

| `k` | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| `ωᵏ` | 1 | 4 | 16 | 13 |
| `A(ωᵏ)` | 1+2+3 = 6 | 1 + 8 + 48 = 57 ≡ 6 | 1 + 32 + 3 = 36 ≡ 2 | 1 + 26 + 48 = 75 ≡ 7 |
| `B(ωᵏ)` | 9 | 4 + 20 = 24 ≡ 7 | 4 + 80 = 84 ≡ 16 | 4 + 65 = 69 ≡ 1 |
| `C(ωᵏ) = A·B` | 54 ≡ 3 | 42 ≡ 8 | 32 ≡ 15 | 7 |

역변환(`ω⁻¹ = 13`, 그리고 `4⁻¹ ≡ 13`로 나누기)을 하면 `[4, 13, 5, 15]` — 기대한 값 `[4, 13, 22, 15] mod 17`과 같다 (`22 mod 17 = 5`). 실제 문제에서는 계수가 `p`보다 작도록 소수를 고릅니다.

### 큰 수 곱셈 `123 × 45`

자릿수를 낮은 자리부터 계수로: `[3, 2, 1]`, `[5, 4]`. 합성곱 `[3·5, 3·4 + 2·5, 2·4 + 1·5, 1·4] = [15, 22, 13, 4]`. 올림을 처리한다.

| 자리 | 계수 | 올림 포함 값 | 쓰는 자리 | 다음 올림 |
|---|---|---|---|---|
| 0 | 15 | 15 | 5 | 1 |
| 1 | 22 | 23 | 3 | 2 |
| 2 | 13 | 15 | 5 | 1 |
| 3 | 4 | 5 | 5 | 0 |

뒤집으면 `5535 = 123 × 45`. 계수의 크기는 `자릿수 × 81` 이하이므로 NTT mod `998244353` 하나로 자릿수 `1.2·10⁷`까지 정확합니다.

### 순환 이동 내적: `a = [1, 2, 3, 4, 5]`, `b = [5, 4, 3, 2, 1]`

`b`를 `s`칸 밀었을 때 `Σ a[i]·b[(i+s) mod 5]`는 `s = 0..4`에서 `35, 45, 50, 50, 45`이고 최댓값은 50. `a`를 뒤집고 `b`를 두 번 이은 수열 `[b, b]`와 합성곱을 하면 인덱스 `n − 1 + s`에서 모든 `s`의 값이 한꺼번에 나옵니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def ntt(a, invert=False, mod=998244353, root=3):
    n = len(a)
    _bit_reverse(a)                                      # 입력을 비트 반전 순서로 (재귀 없는 구현)
    length = 2
    while length <= n:
        w = pow(root, (mod - 1) // length, mod)          # length 제곱근
        if invert:
            w = pow(w, -1, mod)
        half = length >> 1
        twiddles = [pow(w, k, mod) for k in range(half)]
        for start in range(0, n, length):                # 나비 연산 (u, v) -> (u + w·v, u - w·v)
            middle = start + half
            low = a[start:middle]
            high = [x * t % mod for x, t in zip(a[middle:start + length], twiddles)]
            a[start:middle] = [(x + y) % mod for x, y in zip(low, high)]
            a[middle:start + length] = [(x - y) % mod for x, y in zip(low, high)]
        length <<= 1
    if invert:
        n_inverse = pow(n, -1, mod)
        for i in range(n): a[i] = a[i] * n_inverse % mod
```

- `convolution(a, b, mod)`: `mod`로 나눈 나머지. `998244353`이 아니면 세 소수 + 가르너. 짧은 입력은 직접 곱.
- `convolution_exact(a, b)`: 음수 포함 정수 계수의 정확한 결과 (절댓값 `< 3.9·10²⁵`).
- `fft(a, invert)`, `fft_convolution(a, b)`: 복소수 FFT. 결과를 반올림 (계수가 작을 때만).
- `multiply_decimal_strings(x, y)`: 아주 긴 십진수 곱 (큰 정수 곱 예제).
- `max_cyclic_dot_product(a, b)`, `count_pair_sums(a, b)`: 합성곱 응용.
- 직접 실행하면 한 줄의 두 자연수를 받아 곱을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 `O(N log N)`** (`N`은 결과 길이를 덮는 2의 거듭제곱, 변환 3번), **공간 `O(N)`**. 정확한 정수나 임의 mod는 NTT 소수 3개로 3배. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 시간 |
|---|---|
| `ntt` 길이 2¹⁰ | 0.002초 |
| `ntt` 길이 2¹⁴ | 0.052초 |
| `ntt` 길이 2¹⁶ | 0.24초 |
| `ntt` 길이 2¹⁷ | 0.55초 |
| `convolution` 길이 5·10⁴ × 5·10⁴ (mod 998244353) | 1.3초 |
| `convolution_exact` 같은 입력 (소수 3개) | 3.9초 |
| `convolution` 2000 × 2000 vs 이중 반복 | 0.029초 vs 0.273초 |
| `fft_convolution` 2000 × 2000 | 0.025초 |
| `multiply_decimal_strings` 3만 자리 × 3만 자리 | 0.63초 |
| 같은 곱을 파이썬 `int`로 | 0.02초 |
| `multiply_decimal_strings` 10만 자리 × 10만 자리 | 2.8초 |

- **파이썬의 큰 정수 곱셈은 C로 구현된 카라츠바**라서 숫자 하나의 곱은 이 NTT보다 훨씬 빠릅니다. NTT가 필요한 곳은 *계수 단위의 합성곱*(위치별 합, 다항식)입니다.
- 부동소수점 FFT의 한계 (측정): 계수 `10⁷`이 512개인 합성곱(결과 계수 `5·10¹⁶`)에서 최대 오차 16, 계수 `10⁹ + 7`이 1024개인 경우 오차가 약 38만이었습니다. 결과 계수가 `10¹⁴`를 넘으면 NTT(+CRT)를 쓰세요.
- 파이썬(순수)으로 길이 `10⁵`~`2·10⁵` 합성곱은 몇 초입니다. `10⁶`이면 PyPy/C++이 필요합니다.

## 6. 자주 하는 실수

- **변환 길이가 모자람**: `N ≥ n + m − 1`. 짧으면 결과 뒤쪽이 앞쪽에 더해집니다 (순환 합성곱).
- **길이를 2의 거듭제곱으로 맞추지 않음**: 이 구현은 `ValueError`.
- **NTT에 맞지 않는 소수**: `p − 1`이 `N`으로 나누어떨어져야 합니다. `10⁹ + 7`은 `p − 1 = 2·500000003`이라 안 됩니다 (그래서 임의 mod는 세 소수를 씁니다).
- **계수가 `mod`보다 크거나 음수**: 먼저 `% mod`로 줄입니다 (이 구현이 처리).
- **역변환에서 `N`으로 나누기를 빼먹음**: 결과가 `N`배가 됩니다.
- **FFT 결과를 `int()`로 자름**: `4.9999999`가 `4`가 됩니다. `round`.
- **FFT 정밀도 한계를 모름**: 결과 계수가 `10¹⁴` 정도를 넘으면 오차가 정수 단위를 넘습니다.
- **자릿수 곱셈의 올림**: 합성곱의 계수는 한 자리를 넘으므로 *낮은 자리부터 올림*을 처리하고 끝에서도 남은 올림을 풉니다. 앞쪽 0은 제거합니다.
- **자릿수 순서**: 계수를 낮은 자리부터 두어야 합니다 (`reversed`).
- **재귀 구현**: 파이썬에서 느리고 깊이 이슈가 있으니 반복 구현.
- **세 소수 방식의 범위**: 정확한 결과가 `±3.9·10²⁵`을 넘으면 복원되지 않습니다. 이 구현은 임의 mod에서 범위를 넘으면 `ValueError`.

## 7. 변형과 응용

- **[다항식 연산](../../../lv5-master/03-algebra/polynomial-operations/)**: 역원, 로그, 지수, 나눗셈, 다점 평가 — 모두 합성곱 위에 쌓입니다.
- **문자열 매칭**: 와일드카드가 있는 매칭을 `Σ (aᵢ − bⱼ)²·aᵢ·bⱼ`의 합성곱 세 번으로, 또는 문자별 지시 배열의 합성곱 (Codeforces 528D).
- **부분집합 합성곱(왈시-아다마르 / 제타 변환)**: `i | j = k`나 `i ⊕ j = k` 꼴의 합성곱은 비트마스크 위의 비슷한 변환으로 `O(n log n)`에 풉니다.
- **온라인 합성곱**: `dp[i] = Σ dp[j]·w[i − j]` 같은 점화식은 CDQ 분할 정복 + FFT로 `O(n log² n)`.
- **블루스타인(Bluestein) / 쳐프-z**: 길이가 2의 거듭제곱이 아니어도 변환을 `O(n log n)`에.
- **카라츠바**: 작은 크기에서 `O(n^1.58)`로 단순하고 상수가 작은 대안 (파이썬 `int`가 이것을 씁니다).
- **슈나어-슈트라센**: 수천만 자리 정수 곱셈은 NTT 기반.
- **생성 함수**: 합성곱의 거듭제곱으로 확률/개수 분포를 구합니다 ([기댓값 DP](../../../lv3-advanced/07-dp-advanced/expected-value-dp/)의 `sum_distribution`을 FFT로 가속).
