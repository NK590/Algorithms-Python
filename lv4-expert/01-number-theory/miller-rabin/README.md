# 밀러-라빈 소수 판정법 (Miller–Rabin Primality Test)

> **한 줄 요약**: 큰 수 `n`이 소수인지를 시행 나눗셈(`√n`번)이 아니라 **거듭제곱 몇 번**으로 판정한다. 소수에서는 `n − 1 = 2ˢ·d`일 때 `a^d, a^{2d}, …`의 제곱 사슬이 *1에서 시작하거나 −1을 거쳐 1에 도달*해야 한다는 성질로 합성수를 걸러 내고, 이 조건을 통과하는 합성수는 밑 `a`의 1/4 이하라서 몇 개의 밑으로 확률적(또는 `n < 3.3·10²⁴`에서는 결정적)으로 판정한다.

## 1. 언제 쓰나 (문제 신호)

- "`10¹²`~`10¹⁸`의 수가 소수인가" — 시행 나눗셈은 `√n`이 `10⁶~10⁹`번이라 질의가 많으면 불가능
- 소수 판정 질의가 `10⁵`개 이상이고 값이 `2⁶⁴` 이하 (Library Checker, 아파트 임대 류)
- 아주 큰 소수를 찾아야 할 때 (`next_prime`, 무작위 소수 생성)
- [폴라드 로](../pollard-rho/) 소인수분해의 필수 부품 (분해 도중 "이 수는 소수인가" 확인)
- `n ≤ 10⁷`이면 [에라토스테네스의 체](../../../lv1-elementary/06-number-theory/sieve-of-eratosthenes/)가 더 간단하고, 구간 전체의 소수를 모두 구할 때도 체가 낫다

## 2. 핵심 아이디어

**페르마 판정**: [페르마의 소정리](../../../lv2-intermediate/06-number-theory/fermat-little-theorem/)에 따라 `n`이 소수이면 `n`과 서로소인 `a`에 대해 `a^{n−1} ≡ 1 (mod n)`. 이를 만족하지 않으면 합성수가 확실하다. 하지만 **카마이클 수**(561, 1105, 1729 …)는 합성수인데 `n`과 서로소인 *모든* `a`에서 이 식을 만족해서 속는다.

**더 강한 조건**: 소수 `p`에서는 `x² ≡ 1 (mod p)`의 해가 `x ≡ ±1` 두 개뿐이다 (`(x−1)(x+1) ≡ 0`이고 `p`는 소수라 한쪽이 `p`의 배수). 합성수에서는 `±1`이 아닌 1의 제곱근(자명하지 않은 제곱근)이 생길 수 있다.

`n − 1 = 2ˢ·d` (`d`는 홀수)라 하고 사슬

```
a^d,  a^{2d},  a^{4d},  …,  a^{2^{s}·d} = a^{n−1}
```

을 보자. 각 항은 앞 항의 제곱이다. `n`이 소수라면 마지막 항은 1이고(페르마), 사슬에서 1이 처음 나오는 곳의 *바로 앞* 항은 `1`의 제곱근이므로 `−1 ≡ n−1`이어야 한다. 즉 소수라면

```
a^d ≡ 1      또는      a^{2^r·d} ≡ −1  인 r (0 ≤ r < s) 가 있다
```

이 조건을 만족하지 못하는 `a`가 있으면 `n`은 합성수 — 그 `a`를 **증인(witness)**이라 한다. 조건을 만족하는 합성수 `n`을 *`a`에 대한 강한 의사소수*, 그런 `a`를 **거짓 증인(strong liar)**이라 한다.

**거짓 증인은 드물다**: 홀수 합성수 `n`의 거짓 증인은 `1..n−1` 중 *최대 1/4*이다 (라빈의 정리). 서로 다른 무작위 밑 `k`개가 모두 속을 확률은 `4^{−k}` 이하다. 실제로는 훨씬 드물어서 밑 몇 개로 충분하다.

**결정적으로**: 밑을 처음 몇 개의 소수로 고정하면 *범위 안의 모든 `n`*에서 오답이 없다는 것이 계산으로 알려져 있다.

| 밑 | 결정적인 범위 (`n <`) |
|---|---|
| 2 | 2047 |
| 2, 3 | 1 373 653 |
| 2, 3, 5 | 25 326 001 |
| 2, 3, 5, 7 | 3 215 031 751 |
| 2 ~ 11 | 2 152 302 898 747 |
| 2 ~ 13 | 3 474 749 660 383 |
| 2 ~ 17 | 341 550 071 728 321 |
| 2 ~ 23 | 3 825 123 056 546 413 051 |
| 2 ~ 37 (12개) | 318 665 857 834 031 151 167 461 |
| 2 ~ 41 (13개) | 3 317 044 064 679 887 385 961 981 |

각 한계 값은 그 밑들에 대한 가장 작은 강한 의사소수입니다. 이 구현은 13개 밑을 쓰며 `n < 3.3·10²⁴`에서 결정적이고, 그보다 크면 무작위 밑 40개로 오답 확률이 `4⁻⁴⁰`입니다.

**비용**: 밑 하나에 모듈러 거듭제곱 한 번(`O(log n)`번의 곱셈)과 최대 `s − 1`번의 제곱. 소수라고 답했을 때만 틀릴 *가능성*이 있고 "합성수"라는 답은 항상 확실합니다.

## 3. 손으로 따라가기

### 소수인 경우: `n = 97`, 밑 2

`n − 1 = 96 = 2⁵·3`이므로 `s = 5`, `d = 3`.

| `r` | `a^{2^r·d} mod 97` |
|---|---|
| 0 | `2³ = 8` |
| 1 | `8² = 64` |
| 2 | `64² = 4096 mod 97 = 22` |
| 3 | `22² = 484 mod 97 = 96 = −1` ✓ |
| 4 | `96² mod 97 = 1` |

`r = 3`에서 `−1`이 나왔으므로 통과. 소수는 어떤 밑에서도 통과합니다.

### 카마이클 수: `n = 561 = 3·11·17`, 밑 2

페르마 판정은 `2⁵⁶⁰ ≡ 1 (mod 561)`이라 통과하지만 (이 수는 서로소인 320개의 밑 모두에서 통과), 밀러-라빈은:

`n − 1 = 560 = 2⁴·35`, `s = 4`, `d = 35`.

| `r` | `2^{2^r·35} mod 561` |
|---|---|
| 0 | 263 |
| 1 | `263² mod 561 = 166` |
| 2 | `166² mod 561 = 67` |
| 3 | `67² mod 561 = 1` |

사슬이 `1`이나 `−1 = 560`을 거치지 않고 `67`에서 `1`로 떨어졌다. `67² ≡ 1`인데 `67 ≠ ±1`이므로 **자명하지 않은 제곱근**이 발견되었고, 561은 합성수. (덤으로 `gcd(67 − 1, 561) = gcd(66, 561) = 33`이 약수입니다 — 561 = 33·17.) 밑 5로도 `23, 529, 463, 67`로 같은 결론입니다.

### 거짓 증인: `n = 2047 = 23·89`

`n − 1 = 2046 = 2·1023`, `s = 1`, `d = 1023`. 밑 2는 `2¹⁰²³ mod 2047 = 1`로 **통과**해서 소수처럼 보인다. 밑 3은 `3¹⁰²³ mod 2047 = 1565`로 1도 −1도 아니라 합성수라고 판정합니다. `n = 221 = 13·17`은 밑 174가 `174⁵⁵ ≡ 47`, `47² ≡ 220 = −1`로 통과하는 거짓 증인이고 밑 2는 `128, 30`으로 걸러집니다.

### 거짓 증인의 비율 (`1..n−1` 중)

| 합성수 `n` | 강한 거짓 증인 수 | 페르마 거짓 증인 수 (서로소 `a`) | `φ(n)` |
|---|---|---|---|
| 9 | 2 (1, 8) | 2 | 6 |
| 15 | 2 | 4 | 8 |
| 91 | 18 | 36 | 72 |
| 561 | 10 | 320 | 320 |
| 1105 | 30 | 768 | 768 |

카마이클 수(561, 1105)는 페르마 거짓 증인이 서로소인 *전부*(`φ(n)`)이지만 강한 거짓 증인은 1/4보다 훨씬 적습니다. 어느 합성수도 `(n−1)/4`를 넘지 않습니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def is_strong_probable_prime(n, a):
    s, d = _decompose(n)                     # n - 1 = 2^s · d
    x = pow(a, d, n)                         # 3 인자 pow: 모듈러 거듭제곱
    if x == 1 or x == n - 1:
        return True
    for _ in range(s - 1):
        x = x * x % n
        if x == n - 1:
            return True
    return False


def is_prime(n, rounds=40, rng=None):
    if n < 2:
        return False
    for p in SMALL_PRIMES:                   # 작은 소수는 직접 확인 (밑과 n 이 같거나 n 의 배수인 경우도 막는다)
        if n % p == 0:
            return n == p
    bases = SMALL_PRIMES if n < DETERMINISTIC_LIMIT else [rng.randrange(2, n - 1) for _ in range(rounds)]
    return all(is_strong_probable_prime(n, a) for a in bases)
```

- `is_fermat_probable_prime(n, a)`: 비교용 페르마 판정. 카마이클 수에 속는 것을 실험해 볼 수 있다.
- `next_prime(n)`: `n`보다 큰 가장 작은 소수. 소수 밀도가 `1/ln n`이라 평균 `ln n / 2`개의 홀수만 검사하면 된다.
- 직접 실행하면 BOJ 5615 형식 — `N`과 `N`개의 넓이 `S` — 을 받아, `2S + 1`이 소수인 `S`의 개수를 출력합니다 (`S = 2xy + x + y`로 쓸 수 없는 넓이는 `2S + 1 = (2x + 1)(2y + 1)`이 합성수가 아닌 경우).

## 5. 복잡도와 입력 크기 가이드

- **시간 `O(k log³ n)`** (밑 `k`개, 모듈러 거듭제곱 `O(log n)`번의 곱셈, 큰 정수의 곱셈 `O(log² n)`), **공간 `O(1)`**. 64비트 범위에서는 `k = 12~13`이면 충분합니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 시간 |
|---|---|
| 무작위 62비트 홀수 `10⁴`개의 소수 판정 | 0.127초 (개당 약 13마이크로초, 대부분 작은 소수로 걸러짐) |
| `is_prime(2⁶¹ − 1)` (소수, 밑 13개 모두 통과) | 235마이크로초 |
| `is_prime(2¹²⁷ − 1)` (결정적 한계 밖, 무작위 밑 40개) | 1.3밀리초 |
| `is_prime(2⁵²¹ − 1)` | 27.7밀리초 |
| 시행 나눗셈으로 `10¹² + 39` 소수 판정 | 0.059초 |

- 시행 나눗셈은 `10¹²`에서 59밀리초지만 `10¹⁸`에서는 `√n`이 1000배라 한 번에 약 1분(**추정**), 질의 10⁵개면 두 달이 넘습니다. 밀러-라빈은 둘 다 마이크로초 단위입니다.
- 질의가 10⁵개이고 값이 `10¹⁸` 이하일 때: 합성수 위주면 개당 약 13마이크로초라 1~2초, **모두 소수**인 최악 입력이면 개당 235마이크로초라 약 24초(측정값에서 환산한 **추정**)입니다.

## 6. 자주 하는 실수

- **작은 수와 짝수를 먼저 처리하지 않음**: `n = 2, 3`, `n`이 밑의 배수인 경우(`n = 41`, 밑 41) 등에서 `a mod n = 0`이 되어 틀립니다. 작은 소수로 나누는 단계가 이것을 막습니다.
- **카마이클 수에 페르마 판정만 사용**: 561, 1105, 1729 …는 서로소인 모든 밑을 통과합니다.
- **`a^d`를 거듭제곱 먼저, 나머지는 나중에 계산**: `pow(a, d)`로 정수를 만들면 수가 폭발합니다. 반드시 3인자 `pow(a, d, n)`.
- **제곱 횟수**: 사슬은 `a^d`에서 시작해 `s − 1`번 제곱합니다 (마지막 `a^{n−1}`은 `−1`을 확인한 뒤의 항이라 보지 않아도 됨).
- **곱셈 오버플로** (C++/Java): `n`이 `2³²`을 넘으면 `x·x`가 64비트를 넘습니다. `__int128`이나 `mulmod`가 필요합니다. 파이썬은 해당 없음.
- **결정적 한계를 모르고 확장**: 밑 12개는 `3.18·10²³`까지, 13개는 `3.3·10²⁴`까지입니다. 더 큰 수는 확률적입니다.
- **밑을 `1`이나 `n − 1`로 선택**: 항상 통과해서 의미가 없습니다. 밑은 `2 ≤ a ≤ n − 2`.
- **"합성수" 답이 확률적이라고 착각**: "합성수"는 항상 확실하고, "소수"일 때만 확률적입니다.
- **무작위 밑을 같은 시드로 계속 사용**: 대회에서는 문제가 없지만 보안 용도에서는 예측할 수 없는 난수를 써야 합니다.
- **`n < 2`와 음수**: 소수가 아닙니다.

## 7. 변형과 응용

- **더 적은 밑으로 결정적**: `n < 2⁶⁴`에서는 서로 다른 7개 밑 `{2, 325, 9375, 28178, 450775, 9780504, 1795265022}`로 충분하다는 결과가 알려져 있습니다 (이 구현은 검증하지 않았으므로 13개 소수 밑을 씁니다).
- **소인수분해**: 합성수로 판정된 뒤 약수를 찾는 것이 [폴라드 로](../pollard-rho/)입니다. 둘을 합쳐 `10¹⁸`까지 분해합니다.
- **소수 생성**: `next_prime`, 또는 무작위 `b`비트 홀수를 뽑아 소수가 나올 때까지 반복 (평균 `0.35·b`번).
- **다른 판정법**: *솔로바이-스트라센*(더 약함), *바일리-PSW*(밀러-라빈 + 루카스, 알려진 반례 없음), *AKS*(결정적 다항 시간이지만 실용적이지 않음), *루카스-레머*(메르센 수 `2ᵖ − 1` 전용).
- **구간 안의 모든 소수**: `[L, R]`이 `10¹²` 근처이고 길이가 `10⁶` 정도면 *구간 체*(작은 소수들로 지우기)가 낫습니다.
- **암호**: RSA의 큰 소수 생성이 이 알고리즘입니다.
- **이산 로그·제곱근**: 자명하지 않은 제곱근 개념은 톤넬리-섕크스(모듈러 제곱근)와 연결됩니다.
