# 폴라드 로 (Pollard's rho)

> **한 줄 요약**: 합성수 `n`의 약수를 **`n^(1/4)`번 안팎의 연산**으로 찾는다. 의사 난수 수열 `x → x² + c (mod n)`을 만들면 `n`의 소인수 `p`로 나눈 나머지(mod `p`)가 `√p`번 만에 순환에 들어가고, 그 순간 두 항의 차와 `n`의 `gcd`가 `p`의 배수가 되어 약수가 튀어나온다. [밀러-라빈](../miller-rabin/)으로 소수 여부를 확인하면서 재귀적으로 쪼개면 `10¹⁸` 근처의 수를 순식간에 소인수분해한다.

## 1. 언제 쓰나 (문제 신호)

- "`10¹²`~`10¹⁸`(또는 그 이상)의 수를 **소인수분해**" — 시행 나눗셈은 `√n`번이라 `10⁹`번
- "큰 `n`의 약수의 개수·합·오일러 피 `φ(n)`" (소인수분해가 선행 단계)
- `n ≤ 10¹⁸`에서 `gcd(n, k) = 1`인 `k`의 개수 같은 `φ(n)` 문제
- RSA 류 모듈러 `n = p·q`에서 `p`, `q`를 찾는 문제 (작은 크기의 연습)
- `n ≤ 10⁷`이면 [소인수분해](../../../lv1-elementary/06-number-theory/prime-factorization/)와 체로 충분하다

## 2. 핵심 아이디어

**순진한 방법**: `2`부터 `√n`까지 나눠 본다. `n = 10¹⁸`이면 `10⁹`번.

**생일 역설**: `p`개의 칸에 무작위로 공을 던지면 *약 `√p`개*만 던져도 두 공이 같은 칸에 들어간다. `n`의 가장 작은 소인수 `p`가 `n^(1/2)` 이하이므로, 무작위 수열을 `p`로 나눈 나머지는 `√p ≤ n^(1/4)`번 만에 충돌한다.

**수열 만들기**: `x₀`을 하나 고르고 `xᵢ₊₁ = f(xᵢ) = xᵢ² + c (mod n)`. 이 수열은 무작위처럼 행동하면서 `n`이 *유한*하므로 결국 순환한다 (그림이 그리스 문자 ρ처럼 생겨 rho). 같은 식을 `p`로 나눈 나머지에 적용한 수열도 (더 작은 모듈러라) 더 *일찍* 순환한다.

**gcd로 꺼내기**: `xᵢ ≡ xⱼ (mod p)`인데 `xᵢ ≢ xⱼ (mod n)`이면 `p | (xᵢ − xⱼ)`이고 `n`은 `p`의 배수이므로 `gcd(|xᵢ − xⱼ|, n)`은 `p`의 배수이면서 `n`보다 작다 — `n`의 자명하지 않은 약수다. `p`를 *모르는 채로* mod `p`의 충돌을 gcd가 찾아 준다는 것이 핵심.

**순환을 찾는 법**:
- **플로이드(토끼와 거북이)**: `x ← f(x)` 한 칸, `y ← f(f(y))` 두 칸씩 가며 매번 `gcd(|x − y|, n)`을 본다.
- **브렌트(Brent)**: 2의 거듭제곱 번째 항을 기준점으로 삼아 그 뒤의 항들과 비교한다. 같은 항을 덜 계산한다. 또한 `|x − y|`를 128개씩 *곱한 뒤 한 번만 gcd*를 구해 비싼 `gcd` 횟수를 줄인다. 이 구현은 브렌트 방식이다.

**실패하는 경우**: `g = n` (두 소인수에서 *동시에* 충돌) 또는 곱이 `0`이 되는 경우 → 직전 구간을 한 걸음씩 다시 보며 `gcd`를 구하고, 그래도 안 되면 `c`를 바꿔 다시 시작한다.

**소인수분해로**:
1. 작은 소수(`≤ 1000`)로 시행 나눗셈 — 이것이 대부분의 작은 인수를 없앤다.
2. 남은 수 `m`이 소수(밀러-라빈)면 기록하고, 아니면 `d = pollard_rho(m)`로 쪼개 `d`와 `m / d`를 각각 반복.

`n`이 소수면 이 방법은 영원히 약수를 못 찾으므로 **반드시 먼저 소수 판정**을 합니다.

**복잡도**: 약수 하나를 찾는 데 기대 `O(n^(1/4))`번의 곱셈(휴리스틱이며 엄밀한 증명은 없음). 가장 작은 소인수가 `p`이면 `O(√p)`.

## 3. 손으로 따라가기

### `n = 8051 = 83 · 97`, `f(x) = x² + 1`, `x₀ = 2` (플로이드)

수열: `2, 5, 26, 677, 7474, …` (`26² + 1 = 677`, `677² + 1 = 458330 ≡ 7474 (mod 8051)`).

| `i` | `x = xᵢ` | `y = x₂ᵢ` | `gcd(\|x − y\|, 8051)` |
|---|---|---|---|
| 1 | 5 | 26 | `gcd(21, 8051) = 1` |
| 2 | 26 | 7474 | `gcd(7448, 8051) = 1` |
| 3 | 677 | 871 | `gcd(194, 8051) = 97` ✓ |

왜 `i = 3`에서 걸렸는지 소인수로 나눈 나머지를 봅니다.

| 수열 | `mod 97` | `mod 83` |
|---|---|---|
| `x₀…x₁₂` | `2, 5, 26, 95, 5, 26, 95, 5, 26, 95, …` | `2, 5, 26, 13, 4, 17, 41, 22, 70, 4, 17, …` |
| 순환 | 꼬리 1 + 주기 3 | 꼬리 4 + 주기 5 |

`x₃ = 677 ≡ 95`, `x₆ = 871 ≡ 95 (mod 97)`로 **mod 97에서는 이미 같은 값**(`677 mod 83 = 13`, `871 mod 83 = 41`로 mod 83에서는 다름). `|677 − 871| = 194 = 2 · 97`이 97의 배수라 `gcd = 97`. `8051 / 97 = 83`.

### 전체 흐름: `n = 600851475143`

1. 작은 소수 시행 나눗셈이 `71`과 `839`를 뽑는다. 남은 수는 `10086647`.
2. `10086647`은 `√ ≈ 3176 > 1000`이라 시행 나눗셈이 끝났다. 밀러-라빈: 합성수.

def _brent(n, c, rng, batch=128):
    y = rng.randrange(1, n)
    g = r = q = 1
    while g == 1:
        x = y
        for _ in range(r):                       # r 칸 앞으로 (기준점 x 는 고정)
            y = (y * y + c) % n
        k = 0
        while k < r and g == 1:
            ys = y
            for _ in range(min(batch, r - k)):
                y = (y * y + c) % n
                q = q * abs(x - y) % n           # |x - y| 를 곱해 모은다
            g = math.gcd(q, n)                   # 128 개마다 한 번만 gcd
            k += batch
        r *= 2
    if g == n:                                   # 곱이 n 의 배수로 뭉쳤다: 직전 구간을 한 걸음씩

    return g

## 5. 복잡도와 입력 크기 가이드

- **기대 `O(n^(1/4))`** (정확히는 `O(√p)`, `p`는 가장 작은 소인수), 공간 `O(1)`. 소인수분해 전체는 소인수 개수 × 위 비용 + 소수 판정. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 입력 | 시간 |
|---|---|
| 31비트 소수 두 개의 곱 (62비트), 5개 | 0.006~0.018초 |
| 25비트 소수 세 개의 곱 | 0.003초 |
| 50비트 소수 두 개의 곱 (100비트) | 15.1초 |
| `2⁶² − 57` (소수) | 0.0초 (밀러-라빈이 즉시 확인) |

- 62비트 반소수(`p ≈ q ≈ 2³¹`)는 `√p ≈ 46000`번 정도의 반복이면 끝나서 파이썬으로도 개당 수 밀리초입니다. 100비트(`p ≈ 2⁵⁰`)는 `√p ≈ 3300만`번이라 15초로 늘어납니다. `n^(1/4)`의 증가가 그대로 보입니다.
- 시행 나눗셈은 `p = 2³¹`이면 `2·10⁹`번이라 불가능합니다.
- 파이썬으로 `n ≤ 10¹⁸` 소인수분해 질의 100개 정도는 1초 안에 됩니다. 질의가 `10⁵`개이면 C++/PyPy가 필요합니다.

## 6. 자주 하는 실수

- **소수에 `pollard_rho`를 호출**: 약수가 없으니 무한 루프입니다. 항상 먼저 소수 판정 ([밀러-라빈](../miller-rabin/)). 이 구현은 `ValueError`를 냅니다.
- **`g = n`이면 포기하거나 같은 `c`로 반복**: 상수 `c`를 바꿔야 다른 수열이 나옵니다. `c = 0`(수열 `x²`)과 `c = −2`는 피합니다.
- **짝수**: `x² + c` 수열이 mod 2에서 곧바로 순환해 약수를 못 찾을 수 있으니 `2`를 먼저 돌려줍니다. `p²` 꼴은 특별 처리 없이도 브렌트가 `p`를 찾습니다 (테스트가 `(10⁹ + 7)²`까지 확인).
- **작은 소수 시행 나눗셈을 생략**: 작은 인수가 많은 수에서 `gcd`가 자주 `n`이 되어 느려지거나 실패합니다.
- **`|x − y|`를 `0`으로 곱함**: `x = y`이면 곱 전체가 `0`이 되어 `gcd(0, n) = n`. 이때는 실패이므로 구간을 되짚습니다.
- **`gcd`를 매번 호출**: 비싸서 전체 시간이 `log n`배로 늘어납니다. 128개씩 곱해서 묶으세요.
- **소인수 중복 처리**: `p^k`의 지수를 `dict`로 세야 합니다 (`factorize`가 이렇게 반환).
- **곱 오버플로** (C++): `x · x`가 64비트를 넘으니 `__int128` 또는 몽고메리 곱셈.
- **재귀 깊이**: 소인수가 많은 수에서 재귀로 쪼개면 깊어질 수 있어 스택으로 반복합니다.
- **난수 시드**: 같은 입력이면 같은 시드를 쓰는 것이 재현에 좋습니다 (이 구현은 `n`을 시드로).

## 7. 변형과 응용

- **폴라드 p − 1**: `p − 1`이 작은 소수들의 곱인(매끄러운) 소인수 `p`를 가진 수에 매우 빠릅니다. 폴라드 로와 보완 관계.
- **ECM(타원곡선 분해)**: 중간 크기(수십 자리)의 소인수를 찾는 데 쓰이고, 가장 큰 수는 이차 체·수체 체(GNFS)로 합니다.
- **약수 관련 함수**: `d(n)`, `σ(n)`, `φ(n)`을 소인수분해로 바로 계산 (`divisors`, `count_divisors`, `sum_divisors`, `euler_phi`).
- **원시근·위수**: `φ(n)`의 소인수분해를 알면 원시근 판정과 위수 계산이 됩니다.
- **이산 로그와 결합**: 폴리그-헬먼 알고리즘은 군의 위수의 소인수분해에 의존합니다.
- **GCD 응용**: 여러 수의 `gcd`를 이용한 충돌 탐색은 RSA 키 쌍에서 공통 소인수를 찾는 공격에도 쓰입니다.
