# 알고리즘 설명을 코드로 연결하는 법

알고리즘을 익힐 때는 이름이나 코드를 외우기 전에 **무엇을 저장하고, 어떤 조건에서 상태를 바꾸며, 왜 답을 잃지 않는지**를 이해해야 합니다. 각 개념 문서의 2절은 이 세 질문을 설명하고, 3절은 계산 과정을 따라갑니다. 이해가 막히면 아래 순서로 다시 읽어 보세요.

## 1. 입력과 답을 먼저 한 문장으로 쓰기

다익스트라라면 “비음수 비용의 방향 그래프에서 시작점으로부터 각 정점까지의 최소 비용을 구한다”입니다. 여기에는 적용 조건과 반환할 정보가 모두 들어 있습니다.

다음 조건은 서로 다른 문제를 만듭니다.

| 확인할 것 | 왜 중요한가 |
|---|---|
| 순서가 중요한가 | 순열과 조합, 부분 수열과 부분집합이 달라집니다 |
| 반복 사용이 가능한가 | 0/1 배낭과 무한 배낭의 전이가 달라집니다 |
| 값이 음수일 수 있는가 | 다익스트라·일부 투 포인터의 근거가 깨집니다 |
| 간선이 방향을 갖는가 | 연결성과 왕복 도달 가능성이 달라집니다 |
| 구간 끝을 포함하는가 | `[l,r)`와 `[l,r]`의 길이·인덱스 변환이 달라집니다 |
| 최적값만 필요한가 | 실제 경로·선택 복원에는 부모 정보가 추가됩니다 |
| 입력이 바뀌는가 | 누적 합·희소 테이블과 갱신 자료구조를 구분합니다 |

“가장 짧은 경로”라는 말만으로 알고리즘을 결정하지 말고 가중치, 정점 수, 시작점 수를 확인합니다. [문제 신호 가이드](problem-to-algorithm.md)는 이 조건을 찾는 출발점입니다.

## 2. 상태의 뜻을 정확히 정의하기

상태는 계산이 끝난 정보를 다음 계산에 쓰기 위한 요약입니다. 변수 이름만으로는 부족합니다.

| 상태 | 정확한 의미 |
|---|---|
| `dist[v]` | 지금까지 발견한 시작점→v 경로 중 최소 비용 |
| `P[i]` | 배열의 앞 i개 원소의 합. `P[0]=0` |
| `dp[i]` | i칸에 도달하는 경우의 수 등, 문제마다 정한 하나의 의미 |
| `parent[v]` | 답 경로에서 v 직전의 정점. 실제 트리 부모와 다를 수 있음 |
| 스택 | 아직 답을 확정하지 못한 후보들을 정해진 순서로 저장 |

“`dp[i]`는 i까지의 최댓값”처럼 모호하게 쓰면 i를 반드시 선택하는지 알 수 없습니다. 최대 구간 합에서는 **i에서 끝나는 최대 합**과 **i까지 어디에서든 끝나는 최대 합**이 다릅니다.

상태를 합쳐도 되는지는 미래를 보면 알 수 있습니다. 같은 상태의 두 과거에서 앞으로 가능한 행동과 그 비용이 같다면 과거 전체를 저장하지 않아도 됩니다. 마지막 위치에 따라 이동 비용이 달라지면 방문 집합만 저장해서는 안 됩니다.

## 3. 전이를 작은 행동으로 나누기

전이는 현재 상태에서 다음 상태를 만드는 규칙입니다. 아래 네 가지를 표시하면 코드를 읽기 쉬워집니다.

1. **조회**: 어떤 이전 상태를 읽는가?
2. **후보 생성**: 현재 행동의 비용·기여를 어떻게 더하는가?
3. **선택·집계**: 최소, 최대, 합 중 무엇을 취하는가?
4. **기록**: 상태가 바뀔 때 부모·개수·방문 정보도 바뀌는가?

다익스트라의 한 간선 u→v에서는 `dist[u]+weight`를 후보로 만들고 기존 `dist[v]`보다 작으면 갱신합니다. “v를 방문했다”는 이유만으로 모든 갱신을 막는 코드와는 다릅니다. 힙의 낡은 후보는 현재 거리와 비교해 건너뜁니다.

### 다익스트라를 직접 따라가기

간선은 A→B=5, A→C=1, C→B=2이고 시작점은 A입니다.

| 단계 | 처리 | A 거리 | B 거리 | C 거리 | 남은 유효 후보 |
|---|---|---:|---:|---:|---|
| 초기 | 시작점 등록 | 0 | ∞ | ∞ | A:0 |
| 1 | A의 두 간선 | 0 | 5 | 1 | C:1, B:5 |
| 2 | C→B 완화 | 0 | 3 | 1 | B:3, 낡은 B:5 |
| 3 | B:3 처리 | 0 | 3 | 1 | 낡은 B:5 |
| 4 | B:5 건너뜀 | 0 | 3 | 1 | 없음 |

처음 발견한 B의 5는 답이 아닙니다. 작은 비용부터 처리하는 순서와 거리 개선 조건을 함께 이해해야 합니다. 아래 실행 예제는 저장소 루트에서 실행할 수 있으며 테스트에서도 확인합니다.

<!-- RUNNABLE -->
```python
import runpy

module = runpy.run_path('lv2-intermediate/01-shortest-path/dijkstra/solution.py')
graph = [[(1, 5), (2, 1)], [], [(1, 2)]]
assert module['dijkstra'](graph, 0) == [0, 3, 1]
dist, prev = module['dijkstra_with_prev'](graph, 0)
assert module['restore_path'](prev, 0, 1) == [0, 2, 1]
```

## 4. 왜 맞는지를 설명하는 세 가지 방법

### 불변식: 반복 중에도 항상 맞는 약속

이진 탐색에서는 답이 남아 있는 후보 구간 안에 있다는 약속을 유지합니다. 구간을 버릴 때 그곳에 답이 없다는 근거가 있어야 합니다. 반복 종료 시 후보가 더 이상 없거나 경계 하나만 남으면 그 약속에서 최종 답을 읽습니다.

불변식 설명은 **초기 상태에서 맞음 → 한 단계가 보존함 → 종료 시 답이 됨** 순서로 씁니다. “계속 반복하면 된다”는 설명은 보존 근거가 빠져 있습니다.

### 귀납법: 작은 문제의 답에서 큰 문제로

계단을 1칸 또는 2칸 올라가는 경우의 수에서 마지막 걸음은 둘 중 하나입니다. 따라서 `ways[n]=ways[n-1]+ways[n-2]`입니다. 두 경우는 겹치지 않고 모든 도착 방법을 덮습니다.

`ways[0]=1`은 빈 이동 한 가지를 뜻합니다. 0으로 두면 2칸을 한 번에 오르는 경로 같은 정상적인 전이가 사라집니다. 기저값은 편의를 위한 숫자가 아니라 실제 작은 문제의 답입니다.

<!-- RUNNABLE -->
```python
import runpy

module = runpy.run_path('lv1-elementary/07-algorithm-paradigms/dynamic-programming/solution.py')
assert module['climb_stairs'](0) == 1
assert module['climb_stairs'](4) == 5
```

### 교환 논증: 최적해를 내 선택으로 바꾸기

끝나는 시간이 가장 빠른 회의를 고른다고 합시다. 어떤 최적해의 첫 회의가 그보다 늦게 끝나면 그 첫 회의를 우리의 선택으로 교체할 수 있습니다. 남은 회의가 시작할 수 있는 시간은 줄지 않아 선택 수가 나빠지지 않습니다.

이 논증은 “짧은 회의부터 고르기”나 “일찍 시작하는 회의부터 고르기”에는 자동으로 적용되지 않습니다. 그리디 기준마다 교환 뒤 무엇이 보존되는지 다시 설명해야 합니다.

## 5. 계산 순서도 알고리즘의 일부

같은 식도 언제 값을 읽고 쓰는지에 따라 다른 답을 만듭니다.

- 0/1 배낭의 용량 역순 순회는 현재 물건의 중복 사용을 막습니다.
- 트리 DP의 후위 순회는 자식 답이 먼저 준비되게 합니다.
- 플로이드–워셜의 바깥 k 반복은 허용한 중간 정점을 단계별로 제한합니다.
- 누적 합 빈도 조회 후 등록은 길이 0인 구간을 잘못 세지 않게 합니다.
- Lazy Propagation의 갱신 합성은 시간 순서를 보존합니다.

한 물건의 무게 2·가치 3, 용량 4에서 0/1 배낭은 3이지만 무한 배낭은 6입니다. 결과를 외우는 대신 어느 단계의 `dp[2]`를 읽었는지 확인하세요.

## 6. 복잡도는 작업별로 합산하기

전처리 P, 질의 한 번 Q, 질의 수 q라면 전체는 `P+q*Q`입니다. 자료구조를 구축하는 시간을 생략하면 작은 입력에서 더 느린 이유를 설명하지 못합니다.

| 구조 | 비용을 세는 관점 |
|---|---|
| 누적 합 | O(n) 전처리 + q번의 O(1) 질의 |
| 투 포인터 | 두 포인터가 전체 실행 동안 각각 n번 이동 |
| 단조 스택 | 원소마다 최대 한 번 삽입·한 번 제거 |
| 병합 정렬 | O(log n)개 깊이 × 깊이당 O(n) 결합 |
| 비트마스크 DP | 2^n개 상태 × 상태당 전이 후보 수 |
| 다항식 연산 | 실제 곱셈 비용 M(n)을 기준으로 계산 |

파이썬에서는 슬라이스·문자열 결합·정수의 비트 길이·리스트 원소 메모리도 비용에 들어갑니다. 복잡도와 특정 컴퓨터의 측정 시간을 구분하고, 수치만 보고 통과를 보장하지 마세요. [복잡도 치트시트](complexity-cheatsheet.md)에 기준을 정리했습니다.

## 7. 직접 검산하는 순서

1. 원소 하나·간선 없음·빈 구간 같은 가장 작은 입력을 계산합니다.
2. 중복값·0·음수·같은 좌표처럼 적용 조건의 경계를 확인합니다.
3. 단계마다 상태를 기록하고 상태 정의와 일치하는지 비교합니다.
4. 작은 입력에서 브루트 포스나 다른 알고리즘을 정답 기준으로 만듭니다.
5. 무작위 비교에서 실패하면 입력·시드·중간 상태를 함께 남깁니다.
6. 큰 사슬·역순 배열처럼 깊이와 최악 동작을 유발하는 입력도 검사합니다.

테스트 통과는 검사한 범위의 증거입니다. 모든 입력에 대한 정당성 설명, 특정 채점기의 시간·메모리 제한, 문서 코드 블록의 실행 가능성은 각각 따로 확인해야 합니다.

## 8. 용어를 짧게 풀어 보기

| 용어 | 이 저장소에서의 뜻 |
|---|---|
| 상태 | 다음 판단에 필요한 지금까지의 정보 |
| 전이 | 한 행동으로 상태를 바꾸는 규칙 |
| 완화 | 더 좋은 경로 후보를 발견해 값을 낮춤 |
| 불변식 | 반복 전후에 유지되는 정확성 약속 |
| 항등원 | 결합해도 값을 바꾸지 않는 원소. 합의 0, 곱의 1 |
| 결합법칙 | 괄호 위치를 바꿔도 결과가 같음 |
| 교환법칙 | 좌우 순서를 바꿔도 결과가 같음 |
| 멱등성 | 같은 정보를 두 번 결합해도 결과가 같음 |
| 분할 상환 | 한 번의 최악이 아니라 연산열 전체에서 평균 비용을 계산 |
| 오프라인 | 모든 질의를 먼저 보고 순서·구조를 재편할 수 있음 |
| 퍼텐셜 | 최단 경로의 비교 순서를 보존하며 간선 비용을 재표현하는 정점 값 |

이 용어들을 읽은 뒤 각 개념의 **무엇을 저장하고 어떻게 움직이나 → 왜 이 방법이 맞는가 → 작은 예제로 검산하기**를 순서대로 확인하면 구현의 각 줄이 맡은 역할을 찾기 쉬워집니다.
