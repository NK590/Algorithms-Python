# 블로섬 알고리즘 (Blossom Algorithm, Edmonds)

> **한 줄 요약**: 이분 그래프가 *아니어도* 되는 일반 그래프에서 최대 매칭을 구한다. 매칭을 키우는 "증가 경로" 를 BFS로 찾는다는 뼈대는 이분 매칭과 같고, 다른 점은 **홀수 길이 사이클(꽃, blossom)** 을 만나면 그 사이클을 한 정점으로 **수축**해서 탐색을 이어 간다는 것이다. 마지막 탐색이 남기는 정보로 최적성의 증명서(투테–버지 공식, 갈라이–에드먼즈 분해)도 얻는다.

## 1. 언제 쓰나 (문제 신호)

- "서로 짝이 될 수 있는 쌍이 간선으로 주어진다, 한 사람은 한 쌍에만, **최대 몇 쌍**" 이고 그래프가 이분 그래프라는 보장이 없다 (같은 집합 안에서 짝을 짓는다)
- **완전 매칭(모두 짝지을 수 있는가)** 의 존재 여부: 정점 수가 홀수이면 불가능하고, 짝수일 때는 최대 매칭 크기가 `V/2`인지 확인
- **최소 간선 덮개** (모든 정점을 덮는 간선의 최소 개수) `= V − ν` (`ν`: 최대 매칭 크기, 고립 정점이 없을 때)
- 어떤 정점이 **모든 최대 매칭에 들어가는가 / 어떤 최대 매칭에서 빠질 수 있는가**: 갈라이–에드먼즈 분해(`gallai_edmonds`)
- 그래프가 이분 그래프임을 알면 [이분 매칭](../../../lv3-advanced/03-graph-advanced/bipartite-matching/)의 호프크로프트–카프가 더 빠르고 단순하다
- 간선에 **가중치**가 있는 일반 그래프 매칭은 이 구현이 다루지 않는다 (가중치 있는 블로섬 알고리즘 또는 [매트로이드 교집합](../matroid-intersection/)의 가중치 판 같은 별도 도구가 필요하다. 이분 그래프의 가중치 매칭은 [헝가리안](../../../lv4-expert/04-flow-matching/hungarian-algorithm/))

## 2. 핵심 아이디어

**증가 경로**: 매칭 `M`에 대해 짝이 없는 정점에서 시작해 짝이 없는 정점에서 끝나고, 간선이 *매칭에 없는 것, 있는 것, 없는 것, …* 로 번갈아 나오는 경로. 이 경로의 간선을 뒤집으면 매칭이 하나 커진다. **베르주의 정리**: `M`이 최대 매칭 ⇔ `M`에 대한 증가 경로가 없다. 그래서 짝 없는 정점마다 증가 경로를 찾고, 못 찾으면 그 정점은 영원히 짝을 못 얻는다 (이후 매칭이 바뀌어도 마찬가지).

**이분 그래프라면** 짝 없는 정점 `r`에서 BFS를 하며 거리의 홀짝으로 정점에 *홀수/짝수* 표를 붙이면 된다. 짝수 정점에서 나가는 비매칭 간선 끝은 홀수 정점이고, 홀수 정점은 자기 짝으로만 이어져 그 짝이 짝수 정점이 된다. 사이클이 모두 짝수라서 한 정점이 홀수이면서 동시에 짝수가 되는 일이 없기 때문에 성립한다.

**일반 그래프에서 깨지는 곳**: 홀수 사이클이 있으면 한 정점에 *두 가지 표* 가 붙을 수 있다. 아래 6개 정점의 예 (`M = {1–2, 3–4}`, 짝 없는 정점 `0`, `5`) 에서 단순 홀짝 BFS는 증가 경로 `0–1–2–4–3–5`를 놓친다 (3절).

**꽃(blossom)**: 교대 트리에서 짝수 정점 `u`, `v`를 잇는 간선이 있으면 `u`, `v`와 그 공통 조상까지의 경로가 **홀수 길이 사이클**을 이룬다. 이 사이클의 정점 중 *뿌리에 가장 가까운 것* 을 **base** 라 하고, 사이클 전체를 하나의 정점(`base`)으로 **수축**한다.

**핵심 보조정리**: 꽃 `B`를 수축해서 얻은 그래프 `G/B`(매칭 `M/B`)에 증가 경로가 있으면 `G`에도 있다 — 수축 정점을 지나는 경로는 꽃 안에서 *어느 쪽으로 돌아도* 교대가 맞는 쪽을 골라 펼칠 수 있기 때문이다 (사이클이 홀수라서 한쪽 방향은 항상 교대 조건을 만족). 역도 성립해서 `G`에 증가 경로가 있으면 `G/B`에도 있다. 그러므로 수축해도 답이 변하지 않는다.

**이 구현의 표현**: 그래프를 실제로 바꾸지 않고 `base[v]`(`v`가 속한 꽃의 base)만 갱신한다. 정점 `v`의 상태는

- **짝수 정점** (`is_even`): 뿌리이거나, 홀수 정점의 짝이거나, 꽃에 속했던 정점 — 큐에서 나와 간선을 확장하는 정점
- **홀수 정점**: `parent[v] != -1`이고 짝수가 아닌 정점
- 아직 닿지 않은 정점

짝수 정점 `v`에서 간선 `(v, to)`를 볼 때의 경우는 넷이다.

1. `base[v] == base[to]`: 같은 꽃 안이라 건너뛴다. (`v`의 짝은 같은 꽃 안에 있거나 이미 홀수 표가 붙어 있어서 따로 검사하지 않아도 아무 일도 일어나지 않는다.)
2. `to`도 짝수 정점 (`is_even[to]`): **홀수 사이클 발견** → `lca(v, to)`를 새 base로 정하고 경로의 정점들을 모두 이 base로 합친다. 경로 위 *홀수였던 정점도 이제 짝수가 되어* 큐에 들어간다 (꽃 안에서는 어느 쪽으로든 도달할 수 있으니까)
3. `to`에 아직 아무 표도 없고 짝이 없다: **증가 경로 발견**
4. `to`에 아무 표도 없고 짝이 있다: `to`를 홀수(`parent[to] = v`), 그 짝을 짝수로 큐에 넣는다

증가 경로를 찾으면 끝점에서 `parent`와 `mate`를 번갈아 따라 올라가며 짝을 뒤집는다. 꽃 안에서는 `mark_path`가 `parent`를 *맞은편 방향* 으로 고쳐 놓아서, 같은 규칙으로 올라가면 꽃을 알맞은 쪽으로 돌아 나간다.

**복잡도**: 정점마다 탐색 한 번. 탐색 하나에서 꽃 수축은 최대 `V`번이고(수축할 때마다 서로 다른 base가 줄어든다), 한 번에 `O(V)`(lca, 표시, base 갱신)이므로 `O(V²)`, 간선 확인이 `O(E)` → 탐색 하나가 `O(V² + E)`, 전체 `O(V³)`. 탐욕으로 초기 매칭을 만들어 탐색 횟수를 줄인다.

**최적성의 증명서 — 투테–버지 공식**: 정점 집합 `U`를 지웠을 때 홀수 크기의 연결 성분이 `odd(G − U)`개라고 하자. 홀수 성분 안의 정점은 성분 안에서만 짝을 지어서는 한 정점이 남으므로, 그 정점은 `U`의 정점과 짝이 되거나 짝이 없어야 한다. `U`의 정점 하나는 성분 하나만 구해 줄 수 있으니 짝이 없는 정점은 최소 `odd(G − U) − |U|`개이다. 그래서 모든 `U`에 대해 `ν ≤ (V + |U| − odd(G − U)) / 2`이고, **등호가 되는 `U`가 있다** (`ν = min_U (V + |U| − odd(G − U)) / 2`). 더 이상 증가 경로가 없을 때의 교대 숲에서 그런 `U`(= 홀수 정점 전체, `A`)를 읽을 수 있다. 짝 없는 정점 *모두* 를 뿌리로 한 번에 탐색해서 짝수 정점이 된 정점의 집합이 `D`(어떤 최대 매칭에서 짝이 없을 수 있는 정점), 홀수 정점이 `A = N(D) \ D`, 나머지가 `C` — 이것이 **갈라이–에드먼즈 분해**. 구조 정리:

- `D`의 연결 성분은 모두 홀수 크기의 *인수-임계* 그래프 (어느 한 정점을 지워도 완전 매칭이 생긴다)
- `C`는 완전 매칭을 가진다
- 모든 최대 매칭에서 `A`의 정점은 `D`의 *서로 다른* 성분의 정점과 하나씩 짝이 되고, `D`의 각 성분은 (그렇게 `A`와 짝이 된 정점 하나를 빼고) 성분 안에서 완전 매칭을 이루며, `C`는 `C` 안에서 완전 매칭을 이룬다

## 3. 손으로 따라가기

정점 6개, 간선 `0–1, 1–2, 2–3, 3–4, 2–4, 3–5`. 현재 매칭 `M = {1–2, 3–4}`, 짝 없는 정점은 `0`과 `5`. `0`에서 증가 경로를 찾는다. (세 정점 `2, 3, 4`가 삼각형을 이룬다.)

```
0 — 1 = 2 — 3 = 4        (=: 매칭 간선)
        \_______|
              3 — 5
```

**단순 홀짝 BFS (꽃 수축 없음)**: `0`(짝수) → `1`(홀수) → 짝 `2`(짝수) → 비매칭 간선 `2–3`로 `3`을 홀수로, 그 짝 `4`를 짝수로. 간선 `4–2`는 짝수–짝수라 무시. `3`은 홀수 표가 붙었으니 `3–5`를 확장하지 않는다. → 증가 경로 없음 (**틀림**).

**블로섬 알고리즘** (`search([0])`):

| 큐에서 꺼냄 | 보는 간선 | 일어나는 일 |
|---|---|---|
| `0` | `0–1` | `1`에 표 없음, 짝 있음 → `parent[1] = 0`, `1`의 짝 `2`를 짝수로 큐에 |
| `2` | `2–1` | `1`은 `2`의 짝 → 건너뜀 |
| `2` | `2–3` | `3`에 표 없음, 짝 있음 → `parent[3] = 2`, `3`의 짝 `4`를 짝수로 큐에 |
| `2` | `2–4` | `4`는 짝수 정점(짝 `3`이 홀수 표) → **꽃 발견**. `lca(2, 4) = 2`, 꽃 = `{2, 3, 4}`, base `2`. 홀수였던 `3`이 이제 짝수가 되어 큐에 |
| `4` | `4–2`, `4–3` | 모두 같은 꽃 안 → 건너뜀 |
| `3` | `3–2`, `3–4` | 같은 꽃 안 → 건너뜀 |
| `3` | `3–5` | `5`에 표 없음, **짝이 없음** → `parent[5] = 3`, 증가 경로 발견 |

끝점 `5`에서 거슬러 올라가며 뒤집기 (`parent`와 `mate`를 번갈아): `5`의 부모 `3`과 짝지음 (`3`의 이전 짝 `4`), 이어서 `4`의 부모 `2`와 짝지음 (`2`의 이전 짝 `1`), `1`의 부모 `0`과 짝지음. 새 매칭은 **`{0–1, 2–4, 3–5}`** — 완전 매칭, 크기 3. 경로로는 `0–1–2–4–3–5`로, 꽃 안에서 `2→4→3` 쪽으로 돌았다.

실행으로 확인한 값: 이 입력에서 `_Matcher.search([0])`의 반환값은 `5`, 끝난 뒤 `parent = [-1, 0, -1, 2, 2, 3]`, `base = [0, 1, 2, 2, 2, 5]`, 짝수 정점 `{0, 2, 3, 4}`이고 `augment_from(0)` 후 `mate = [1, 0, 4, 5, 2, 3]`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def search(self, roots):                                   # 증가 경로의 끝(짝 없는 정점), 없으면 -1
    ...                                                    # parent, base, is_even 초기화, 큐에 roots
    while queue:
        v = queue.popleft()
        for to in self.adj[v]:
            if self.base[v] == self.base[to]:
                continue                                   # 같은 꽃 안
            if self.is_even[to]:
                current_base = self._lca(v, to)            # 짝수-짝수 간선: 꽃을 수축
                self.in_blossom = [False] * n
                self._mark_path(v, current_base, to)
                self._mark_path(to, current_base, v)
                for i in range(n):
                    if self.in_blossom[self.base[i]]:
                        self.base[i] = current_base
                        if not self.is_even[i]:            # 홀수였던 정점이 짝수가 된다
                            self.is_even[i] = True
                            queue.append(i)
            elif self.parent[to] == -1:                    # 아직 표가 없는 정점
                self.parent[to] = v
                if self.mate[to] == -1:
                    return to                              # 증가 경로 발견
                self.is_even[self.mate[to]] = True
                queue.append(self.mate[to])
    return -1
```

- `max_matching(n, edges)` → `(매칭의 크기, mate)`: `mate[v]`는 `v`의 짝(없으면 `-1`). 다중 간선과 자기 루프는 무시하고, 범위를 벗어난 정점 번호는 `ValueError`.
- `gallai_edmonds(n, edges)` → `{"size", "mate", "D", "A", "C"}`: 최대 매칭과 분해. 짝 없는 정점 전부를 한 번에 뿌리로 하는 탐색은 *현재 매칭이 최대일 때만* 안전하다 (서로 다른 트리의 짝수 정점이 간선으로 이어지지 않기 때문).
- 직접 실행하면 Library Checker "General Matching" 형식 — `N M`, 이어서 `M`줄의 `a b` — 를 받아 매칭 크기와 짝 지은 간선을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 시간 `O(V³)` (탐색 하나 `O(V² + E)`, 정점마다 한 번). 메모리 `O(V + E)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다 (무작위 그래프, 탐욕 초기 매칭 포함).

| 입력 | 정점 / 간선 | 시간 (탐욕 초기 매칭 포함) | 탐욕 없이 |
|---|---|---|---|
| 무작위 희소 (평균 차수 3) | 2000 / 3000 | 0.04초 | 0.06초 |
| 무작위 조밀 (확률 0.5) | 400 / 40,084 | 0.02초 | 0.11초 |
| 홀수 사이클 선인장 (꽃 속의 꽃) | 2851 / — | 0.25초 | 0.31초 |
| 별 (실패하는 탐색이 `V − 2`번) | 1000 / 999 | 0.012초 | — |
| 별 | 2000 / 1999 | 0.048초 | — |
| 별 | 4000 / 3999 | 0.20초 | — |
| 완전 이분 `K₅₀,₂₀₀₀` | 2050 / 100,000 | 0.56초 | — |
| 홀 위반 (이웃이 둘뿐인 정점이 많음) | 1500 / 39,673 | 0.26초 | — |

- 무작위 입력은 탐욕 초기 매칭이 거의 다 풀어서 증가 경로 탐색이 몇 번 안 일어납니다. **실패하는 탐색이 많은** 입력(별: 두 배가 되면 시간이 약 네 배)에서 `O(V·(V² + E))`의 성격이 드러납니다.
- 별 모양 `V = 4000`이 0.2초이므로 정점 수 `10³`~`10⁴` 안팎의 입력은 파이썬으로도 가능합니다. `V = 10⁵` 이상의 입력(일반 매칭 템플릿 문제가 요구하는 크기)은 `O(V³)` 알고리즘으로 불가능하고, 그런 입력에는 `O(√V · E)` 블로섬(마이칼리–바지라니 알고리즘)이나 랜덤 행렬 방법이 필요합니다.

## 6. 자주 하는 실수

- **꽃을 수축하지 않고 홀짝 BFS만 함**: 3절의 예처럼 증가 경로를 놓쳐서 *최대가 아닌* 매칭을 최대라고 출력합니다. 작은 그래프에서는 맞는 것처럼 보이기 쉽습니다 (이분 그래프와 홀수 사이클이 없는 그래프에서는 맞기 때문). 삼각형이나 5-사이클이 든 입력으로 꼭 확인하세요.
- **꽃에 포함된 홀수 정점을 큐에 넣지 않음**: 수축된 뒤의 홀수 정점은 짝수가 되어 간선을 확장해야 합니다. 빠뜨리면 꽃에서 나가는 간선을 못 찾습니다.
- **`mark_path`에서 `parent`를 고치지 않음**: 증가 경로를 되짚을 때 꽃 안을 잘못된 방향으로 돌아 매칭이 깨집니다. `parent[v] = child`로 맞은편을 가리키게 해야 합니다.
- **`lca`를 base가 아닌 원래 정점으로 계산**: 이미 수축한 꽃 안의 정점은 `base[]`를 거쳐야 합니다.
- **탐색마다 `base`, `parent`, `is_even`을 초기화하지 않음**: 이전 탐색의 표가 남아 엉뚱한 곳에서 꽃이 발견됩니다.
- **한 번 실패한 정점을 다시 시도**: 짝 없는 정점 `r`에서 증가 경로가 없으면 이후 다른 증가로 매칭이 바뀌어도 `r`의 증가 경로는 생기지 않습니다. 정점마다 한 번만 시도하면 됩니다.
- **자기 루프와 다중 간선**: 자기 루프는 짝이 될 수 없습니다 (이 구현이 무시). 다중 간선은 하나로 합쳐도 됩니다.
- **여러 뿌리를 한 번에 탐색할 때 매칭이 최대가 아님**: 서로 다른 트리의 짝수 정점을 잇는 간선(= 증가 경로)이 있으면 `lca`가 엉뚱한 값을 계산합니다. 분해용 다중 뿌리 탐색은 최대 매칭에서만 하세요.
- **이분 그래프에 쓰기**: 정답은 맞지만 [호프크로프트–카프](../../../lv3-advanced/03-graph-advanced/bipartite-matching/)가 훨씬 빠릅니다.

## 7. 변형과 응용

- **완전 매칭 판정**: `V`가 짝수이고 `ν = V/2`. 투테의 정리: 완전 매칭이 없으면 `odd(G − U) > |U|`인 `U`가 있다 (`gallai_edmonds`의 `A`가 그 증명서).
- **최소 간선 덮개**: 고립 정점이 없다면 `V − ν`개. 매칭 간선 + 짝 없는 정점마다 인접 간선 하나.
- **모든 최대 매칭에 들어가는 정점**: `D`의 보집합(`A ∪ C`)이 *모든* 최대 매칭에서 짝이 있는 정점이다.
- **무작위 매칭과 행렬 랭크**: 투테 행렬의 랭크로 `ν`를 구하는 확률적 방법(`O(V^ω)`, 랜덤 대입)도 있다.
- **가중치 있는 일반 매칭**: 쌍대 변수가 들어간 블로섬 알고리즘(`O(V³)`). 이 저장소는 가중치 없는 판만 다룹니다.
- **더 일반적인 구조**: 이분 매칭은 [매트로이드 교집합](../matroid-intersection/)의 특수한 경우이고, 일반 그래프 매칭은 매트로이드 *패리티* 문제의 특수한 경우입니다.
