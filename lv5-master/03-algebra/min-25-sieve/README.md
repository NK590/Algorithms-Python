# 민-25 체 (Min_25 Sieve)

> **한 줄 요약**: 곱셈적 함수 `f`의 합 `Σ_{m ≤ n} f(m)`을 `n = 10¹⁰`, `10¹¹`처럼 체로는 도저히 못 훑는 크기에서 구한다. 1단계는 **`n ÷ i` 꼴의 수 `O(√n)`개에 대해서만** "그 수 이하 소수의 `p^k`의 합" 표를 만드는 것(소수 세기 `π(n)`도 여기서 나온다), 2단계는 **가장 작은 소인수와 그 지수** 로 수를 나눠 가며 재귀하는 것이다.

## 1. 언제 쓰나 (문제 신호)

- "`n ≤ 10¹⁰`(`10¹¹`) 이하 **소수의 개수 / 합**" — 체로는 메모리와 시간이 모자란다
- "`Σ_{m≤n} φ(m)`, `Σ σ(m)`, 메르텐스 함수 `M(n) = Σ μ(m)`" 같은 **곱셈적 함수의 누적합** 을 `n ≥ 10⁹`에서
- 곱셈적 함수 `f`가 **소수에서의 값이 `p`의 저차 다항식**(`f(p) = a + b·p + c·p²`)이고 소수의 거듭제곱 `f(p^e)`는 따로 계산할 수 있다
- 합이 `n ÷ i` 꼴의 값에서만 필요하다는 구조(디리클레 곱 / 약수 합의 변형)와 짝이 되는 문제
- `n ≤ 10⁷` 정도면 선형 체/에라토스테네스의 체가 훨씬 단순하다. 곱셈적 함수의 누적합이 *디리클레 합성곱으로 쉽게 계산되는 함수와 곱해서* 풀린다면 디리클레 쌍곡선 방법(`O(n^{2/3})`)이 더 빠를 수 있다
- `f(p)`가 `p mod 4` 같은 잔여류에 의존하거나 다항식이 아니면 이 구현으로는 안 된다 (소수 테이블을 잔여류마다 나눠야 한다)

## 2. 핵심 아이디어

**`n ÷ i` 꼴의 값은 `O(√n)`개**: `⌊n/1⌋, ⌊n/2⌋, …`는 `√n` 이하의 값과 `√n` 초과의 값(`⌊n/i⌋`, `i ≤ √n`)으로 나뉘고, 어떤 `⌊n/i⌋`를 `p`로 나누고 내림해도 다시 이 꼴이다 (`⌊⌊n/i⌋ / p⌋ = ⌊n/(ip)⌋`). 그래서 표는 이 `2√n`개의 값에 대해서만 만들면 된다 (`small[v]`, `large[i]`).

**1단계 — 소수 테이블 (Lucy_Hedgehog)**: `g_k(v) = Σ_{p ≤ v, p 소수} p^k` (`k = 0` 개수, `1` 합, `2` 제곱합). 처음에는 *2 이상의 모든 수* 의 `m^k`의 합으로 시작해서 (`g_0 = v − 1`, `g_1 = v(v+1)/2 − 1`, …) 작은 소수 `p = 2, 3, 5, …`(`p² ≤ n`)를 차례로 보며 **가장 작은 소인수가 `p`인 합성수** 를 지운다. `v ≥ p²`인 모든 `v`에서

`g_k(v) ← g_k(v) − p^k · ( g_k(⌊v/p⌋) − g_k(p − 1) )`

의미: 지울 수는 `m = p · t`이고 `t`는 `p` 이상의 소수이거나 가장 작은 소인수가 `p` 이상인 수(`t ≤ v/p`). 그런 `t`의 `t^k` 합이 `g_k(⌊v/p⌋) − g_k(p−1)` (소수 `p` 미만을 뺀다)이다. 작은 `v`는 큰 `v`가 읽은 뒤에 갱신해야 하므로 **큰 `v`부터** 갱신한다. 비용은 `Σ_p (p² ≤ n 인 v 의 개수)`로 `O(n^{3/4})`.

**2단계 — 재귀**: `S(x, j)` = `2 ≤ m ≤ x`이고 `m`의 가장 작은 소인수가 `j`번째 소수 이상인 `m`의 `f(m)` 합. `m`이 소수이거나 아니거나로 나눈다.

- 소수인 `m`: `x` 이하 소수 중 `j`번째 이상 → `F(x) − F(p_{j−1})` (`F`는 소수에서의 `f` 합, 1단계 표의 선형 결합)
- 합성수인 `m`: 가장 작은 소인수 `p_k`(`k ≥ j`)와 그 지수 `e`가 정해지고 나머지가 `p_k` 초과의 소인수만 가진다: `f(p_k^e) · S(⌊x/p_k^e⌋, k+1)` (나머지 ≥ `p_{k+1}`인 부분) `+ f(p_k^{e+1})` (나머지가 1이 되는 경우). `p_k^{e+1} ≤ x`일 때만 의미가 있다.

`S(x, j) = F(x) − F(p_{j−1}) + Σ_{k ≥ j, p_k² ≤ x} Σ_{e ≥ 1, p_k^{e+1} ≤ x} ( f(p_k^e) · S(⌊x/p_k^e⌋, k+1) + f(p_k^{e+1}) )`

답은 `1 + S(n, 1)` (`f(1) = 1`). 재귀가 방문하는 `(x, j)`는 `p_j² ≤ x`인 것뿐이라 매우 적다.

### 무엇을 저장하고 어떻게 움직이나

큰 n의 약수·소수 관련 합에서 모든 수 대신 `floor(n/i)`가 서로 다른 상태들만 저장합니다. 이 몫은 O(sqrt(n))종류입니다. 작은 소수부터 합성수의 기여를 제거해 소수 관련 합을 구하고, 소수 거듭제곱 전이로 곱셈적 함수 합을 확장합니다.

### 왜 이 방법이 맞는가

합성수의 최소 소인수를 기준으로 경우를 나누면 각 수의 기여를 한 번씩 처리할 수 있습니다. 몫이 같은 연속 구간은 후속 계산에서도 같은 상태로 합쳐집니다. 사용할 함수의 소수·소수 거듭제곱 값을 빠르게 계산할 수 있어야 합니다.

### 작은 예제로 검산하기

n=10에서 `floor(10/i)`의 서로 다른 값은 10,5,3,2,1입니다. i=6~10은 모두 몫 1이라 한 상태입니다. 몫 상태 수가 적다고 모든 알고리즘이 자동으로 O(sqrt(n))인 것은 아니며 소수 순회와 재귀 전이 비용도 셉니다.

## 3. 손으로 따라가기

`n = 10`에서 `Σφ(m)` (정답: `φ(1 … 10) = 1, 1, 2, 2, 4, 2, 6, 4, 6, 4`의 합 = **32**). `⌊√10⌋ = 3`, 표에 쓰는 값은 `{10, 5, 3, 2, 1}`, `√n` 이하 소수는 `[2, 3]`.

**1단계** (소수 개수 `g_0`, 소수 합 `g_1`; 실행으로 확인한 값):

| `v` | 10 | 5 | 3 | 2 | 1 |
|---|---|---|---|---|---|
| `g_0` 처음 (`v − 1`) | 9 | 4 | 2 | 1 | 0 |
| `p = 2` 후 (`v ≥ 4`: `g_0(v) −= g_0(⌊v/2⌋) − g_0(1)`) | 5 | 3 | 2 | 1 | 0 |
| `p = 3` 후 (`v ≥ 9`: `g_0(10) −= g_0(3) − g_0(2) = 1`) | **4** | 3 | 2 | 1 | 0 |
| 최종 `g_1` (소수의 합) | 17 | 10 | 5 | 2 | 0 |

`f(p) = p − 1`이므로 소수에서의 `f` 합은 `F(v) = g_1(v) − g_0(v)`: `F(10) = 13`, `F(5) = 7`, `F(3) = 3`, `F(2) = 1`. 앞쪽 소수들의 `f` 합 `prefix = [0, f(2), f(2) + f(3)] = [0, 1, 3]`.

**2단계** (`f(p^e) = p^{e−1}(p − 1)`: `f(2) = 1`, `f(4) = 2`, `f(8) = 4`, `f(3) = 2`, `f(9) = 6`):

| 호출 | 소수 부분 | 합성수 부분 |
|---|---|---|
| `S(10, 0)` | `F(10) − prefix[0] = 13` | 아래 세 항의 합 |
| `p = 2`, `e = 1` (`2·2 ≤ 10`) | | `f(2)·S(5, 1) + f(4) = 1·6 + 2 = 8` — 여기서 `S(5, 1) = F(5) − prefix[1] = 7 − 1 = 6`이고 `3² > 5`라 더 내려가지 않는다 |
| `p = 2`, `e = 2` (`4·2 ≤ 10`) | | `f(4)·S(2, 1) + f(8) = 2·0 + 4 = 4` — `S(2, 1) = F(2) − prefix[1] = 0` |
| `p = 3`, `e = 1` (`3·3 ≤ 10`) | | `f(3)·S(3, 2) + f(9) = 2·0 + 6 = 6` — `S(3, 2) = F(3) − prefix[2] = 0` |

`S(10, 0) = 13 + 8 + 4 + 6 = 31`, 답은 `1 + 31 = 32` ✓. (`p = 2`, `e = 3`은 `8·2 = 16 > 10`이라 멈추고, `p = 3`, `e = 2`는 `9·3 = 27 > 10`이라 멈춘다.) 합성수 부분이 센 수는 `4(2), 6(2), 8(4), 9(6), 10(4)`의 `f` 값을 모아 `8 + 4 + 6`이 되는 구조다: `6 = 2·3`은 `p = 2`, `e = 1`의 `f(2)·S(5, 1)` 안의 소수 `3`으로, `10 = 2·5`는 같은 항의 소수 `5`로 들어간다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _tables(n, degree):                                  # g_0 .. g_degree, √n 이하 소수
    r = isqrt(n)
    small = [[initial(k, v) for v in range(r + 1)] for k in range(degree + 1)]
    large = [[0] + [initial(k, n // i) for i in range(1, r + 1)] for k in range(degree + 1)]
    primes = []
    for p in range(2, r + 1):
        if small[0][p] == small[0][p - 1]: continue      # 합성수
        primes.append(p)
        limit = min(r, n // (p * p))
        for k in range(degree + 1):
            before, weight = small[k][p - 1], p ** k
            for i in range(1, limit + 1):                # v = n // i 가 큰 쪽
                ip = i * p
                g[i] -= weight * ((g[ip] if ip <= r else s[n // ip]) - before)
            for v in range(r, p * p - 1, -1):            # v <= √n 인 작은 쪽, 큰 v 부터
                s[v] -= weight * (s[v // p] - before)
    return small, large, primes

def recurse(x, j):                                       # S(x, j)
    result = prime_f_total(x) - prefix[j]
    for k in range(j, len(primes)):
        p = primes[k]
        if p * p > x: break
        pe, e = p, 1
        while pe * p <= x:
            result += prime_power(p, e) * recurse(x // pe, k + 1) + prime_power(p, e + 1)
            pe *= p; e += 1
    return result
```

- `prime_count(n)`, `prime_sum(n)`: 1단계만.
- `min25_sum(n, prime_poly, prime_power, mod=None)`: 임의의 곱셈적 함수. `f(p) = Σ prime_poly[k]·p^k` (길이 1~3), `f(p^e) = prime_power(p, e)` (`e = 1`에서 `f(p)`와 일치해야 한다). 정확한 정수로 계산하고 `mod`가 있으면 마지막에 나머지.
- `sum_totient(n)`, `sum_sigma(n)`, `sum_mobius(n)`: `φ`, `σ`, `μ`의 누적합.
- 직접 실행하면 `n` 하나를 받아 소수의 개수, 소수의 합, `Σφ(m)`을 한 줄에 하나씩 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 1단계 `O(n^{3/4})`, 메모리 `O(√n)` (`2√n`개의 값 × 차수 + 1개 표). 2단계의 재귀 호출 수는 경험적으로 `n^{3/4}/log n`과 비슷하다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다 (정확한 정수, `mod` 없음).

| `n` | `π(n)` | 소수 합 | `Σ φ` | `Σ σ` | `M(n)` |
|---|---|---|---|---|---|
| `10⁷` | 0.01초 | 0.03초 | 0.09초 | 0.09초 | 0.06초 |
| `10⁸` | 0.07초 | 0.14초 | 0.42초 | 0.44초 | 0.29초 |
| `10⁹` | 0.35초 | 0.77초 | 2.30초 | 2.36초 | 1.50초 |
| `10¹⁰` | 2.05초 | 4.48초 | 12.6초 | 13.7초 | 8.60초 |
| `10¹¹` | 11.5초 | — | — | — | — |

- 알려진 값과 대조: `π(10⁹) = 50847534`, `π(10¹⁰) = 455052511`, `π(10¹¹) = 4118054813`, `M(10⁹) = −222`, `M(10¹⁰) = −33722`, `Σφ(10⁶) = 303963552392`, `Σ_{p ≤ 10⁹} p = 24739512092254535` (모두 실행 결과와 일치).
- `n` 이 10배가 될 때 시간이 약 5~6배 늘어나는 것이 `n^{3/4}` 계열과 맞습니다 (`10⁹ → 10¹⁰`: 소수 개수 0.35초 → 2.05초, `Σφ` 2.30초 → 12.6초).
- 소수 개수만 필요하면 `10¹¹`까지 파이썬으로 12초 안팎에 구할 수 있습니다. 2단계까지 쓰는 곱셈적 함수의 합은 `10¹⁰` 정도(13초 안팎)까지가 현실적입니다.

## 6. 자주 하는 실수

- **손으로 구한 `F`의 부호/차이**: `f(p) = p − 1`이면 `F = g_1 − g_0`입니다. 3절에서 일부러 남긴 것처럼 `g_1(5) − g_0(5) = 10 − 3 = 7`을 `6`으로 잘못 빼는 식의 실수가 가장 잦습니다. 구현은 항상 선형 결합 `Σ prime_poly[k]·g_k(v)`로 계산합니다.
- **표를 갱신하는 순서**: 작은 `v` 쪽을 위에서 아래로 갱신하면 이미 갱신된 값을 읽어 틀립니다. `v`가 큰 쪽부터(`range(r, p²−1, −1)`), 큰 값 `n // i` 표는 `i`가 작은 것부터(`n // i`가 큰 것부터) 갱신합니다.
- **소수 판정에 `small[0]`**: `p`가 소수인지는 `small[0][p] ≠ small[0][p−1]`로 알 수 있습니다. 이때 `p` 미만의 모든 소수를 이미 처리한 *뒤* 의 표를 봐야 합니다.
- **`n // v`의 인덱스**: `v ≤ √n`이면 `small[v]`, 아니면 `large[n // v]`. 경계(`v = √n`)에서 `<`와 `≤`를 틀리면 한 칸씩 어긋납니다. `⌊n/(ip)⌋ = ⌊(⌊n/p⌋)/i⌋` 항등식에 기대지 말고 `ip ≤ √n`이면 `large[ip]`를 읽는지 확인.
- **재귀의 조건 `p² ≤ x`, `p^{e+1} ≤ x`**: 등호를 빼면 `x = p²`, `x = p^{e+1}`에서 항이 빠집니다 (`n = p²` 근처 값을 테스트에 넣은 이유).
- **마지막 `+1`**: `f(1) = 1`을 더하는 것을 잊으면 답이 1 작습니다.
- **`f(p)` 가 다항식이 아님 / `f(p^e)`가 `e = 1`에서 `f(p)`와 불일치**: 1단계의 표와 2단계의 `prime_power(p, 1)`이 달라지면 재귀가 어긋납니다. 두 곳을 같은 식에서 만드세요.
- **C++의 오버플로**: `g_2` 초기값 `v(v+1)(2v+1)/6`은 `n = 10¹¹`에서 `10³³`에 이릅니다. C++에서는 나눗셈을 먼저 하거나 모듈러 역원을 쓰고, 모든 갱신에 `mod`를 적용합니다 (파이썬은 큰 정수라 걱정이 없다).
- **재귀 깊이**: 깊이는 `log n`이라 문제없지만 호출 수가 많아 함수 호출 오버헤드가 시간의 대부분입니다.

## 7. 변형과 응용

- **소수 세기/합**: 1단계만 (`prime_count`, `prime_sum`). Project Euler류의 큰 `n`.
- **Σφ, Σσ, 메르텐스 함수**: 2단계 (`sum_totient`, `sum_sigma`, `sum_mobius`). 메르텐스 함수는 [뫼비우스 반전](../../../lv4-expert/01-number-theory/mobius-inversion/)과 디리클레 쌍곡선으로도 `O(n^{2/3})`에 풀리지만 코드가 길다.
- **소수 거듭제곱 합에서의 일반화**: `f(p) = c_0 + c_1 p + c_2 p²`까지 지원 (`prime_poly`의 길이 3). 더 높은 차수는 `g_3, …` 표를 더 만들면 된다.
- **잔여류별 소수 세기**: `p mod 4 = 1`/`3`의 개수 등은 표를 잔여류마다 만들어 같은 방법으로 구한다 (이 저장소 범위 밖).
- **디리클레 접두사 합, 파워풀 수 체**: 곱셈적 함수의 합을 구하는 다른 방법들과 비교해 보기.
