# 오프라인 동적 연결성 (Offline Dynamic Connectivity)

> **한 줄 요약**: 간선이 **추가되고 삭제되는** 그래프에서 "지금 `u`와 `v`가 연결되어 있나?" 같은 질의에, **모든 연산을 미리 알고 있다는 점** 을 이용해 답한다. 유니온 파인드는 삭제가 안 되지만 **되돌리기(rollback)** 는 되므로, 간선의 *살아 있는 시간 구간* 을 시간 축 구간 트리에 흩어 놓고 DFS 하며 "들어갈 때 합치고 나올 때 되돌린다".

## 1. 언제 쓰나 (문제 신호)

- 연산이 시간 순으로 주어지고 간선의 **추가 / 삭제 / 연결 질의** 가 섞여 있으며, **입력을 모두 읽은 뒤 풀어도 된다** (온라인이 아님)
- 같은 틀로 풀리는 질의: 연결 성분의 수, **이분 그래프인가**(홀짝 유니온 파인드), 성분 크기·성분 합(정점 값이 있을 때), 두 점 사이의 최소 간선 값
- 온라인으로 답해야 한다면: 간선이 숲을 이루는 경우는 [링크-컷 트리](../../01-dynamic-trees/link-cut-tree/), 일반 그래프의 온라인 동적 연결성은 Holm–de Lichtenberg–Thorup 같은 별도의 복잡한 자료구조(이 저장소 범위 밖)
- 일반화: "삽입은 쉽고 삭제는 어렵지만 *되돌리기* 는 되는" 자료구조라면 무엇이든 같은 방식으로 삭제를 지원할 수 있다 (예: [리 차오 트리](../../../lv4-expert/03-advanced-data-structures/li-chao-tree/)의 롤백 + 시간 구간)

## 2. 핵심 아이디어

**삭제를 없애는 관점 전환**: 연산을 시간 순으로 처리하면 삭제가 필요하다. 대신 간선 하나를 *[추가된 시각, 삭제된 시각)* 이라는 **시간 구간** 으로 보면, 각 시각 `t`에는 "`t`를 덮는 구간의 간선들" 이 살아 있다. 삭제가 사라지고 "각 시각마다 간선 집합이 주어졌을 때 질의에 답하기" 문제가 된다.

**시간 축 구간 트리**: 시각 `[0, T)` 위에 구간 트리를 만들고, 간선의 시간 구간을 `O(log T)`개의 노드로 쪼개 그 노드에 간선을 저장한다. 시각 `t`에 살아 있는 간선은 루트에서 잎 `t`까지의 경로 위 노드들에 *정확히 한 번씩* 들어 있다.

**DFS + 롤백**: 루트에서 시작해 노드에 들어갈 때 그 노드의 간선을 모두 유니온 파인드에 합치고, 잎(시각 `t`)에서 질의가 있으면 답하고, 노드를 나올 때 합친 것을 **되돌린다**. 되돌리기가 가능하려면 유니온 파인드를 **경로 압축 없이 크기(또는 랭크)로 합치는** 방식으로 쓴다: 한 번의 합치기가 "붙은 뿌리 하나의 부모 변경과 크기 갱신" 이라 기록 한 줄로 되돌릴 수 있고, `find`는 `O(log n)`이다.

**이분 그래프 판정**: 각 정점이 부모와 같은 색인지/다른 색인지(홀짝)를 함께 들고, 간선 `(a, b)`를 합칠 때 두 정점이 *서로 다른 색* 이 되도록 한다. 이미 같은 성분인데 같은 색이면 **홀수 사이클** — 이분 그래프가 아니다. 홀수 사이클을 만든 간선의 개수도 롤백할 수 있게 기록한다.

**시간 구간의 규칙**: 연산 번호를 시각으로 쓴다. 시각 `i`의 `add`는 `i + 1`부터 살아 있고(자기 시각의 질의는 아니다), 시각 `j`의 `remove`는 `j` 직전까지 살아 있다. 끝까지 지워지지 않은 간선은 `T`까지. 같은 간선을 여러 번 추가하면 다중 간선이므로 구간이 여러 개이고, `remove`는 그중 하나(가장 최근 것)를 끝낸다.

## 3. 손으로 따라가기

정점 3개 `0, 1, 2`, 연산 7개 (시각 `0 … 6`).

```
t=0  add (0,1)
t=1  add (1,2)
t=2  connected(0,2)  ?
t=3  remove (1,2)
t=4  connected(0,2)  ?
t=5  add (1,2)
t=6  connected(0,2)  ?
```

간선의 시간 구간: `(0,1)`은 `t=0`에서 추가 → `[1, 7)`. `(1,2)`는 `t=1`에서 추가, `t=3`에서 삭제 → `[2, 3)`; `t=5`에서 다시 추가 → `[6, 7)`.

구간 트리 `[0, 7)`에 쪼개 놓은 모습 (실행해서 확인한 배치):

| 간선 | 시간 구간 | 저장된 노드 |
|---|---|---|
| `(0,1)` | `[1, 7)` | `[1, 3)`, `[3, 7)` |
| `(1,2)` | `[2, 3)` | `[2, 3)` |
| `(1,2)` | `[6, 7)` | `[6, 7)` |

DFS 순서 (들어가며 합치고, 나오며 되돌림):

| 방문한 노드 | 하는 일 |
|---|---|
| `[0, 7)`, `[0, 3)`, `[0, 1)` | 간선 없음. `t=0`은 질의가 아님 |
| `[1, 3)` | `(0,1)` 합침 |
| `[1, 2)` | 간선 없음. `t=1`은 질의가 아님 |
| `[2, 3)` | `(1,2)` 합침. **`t=2` 질의: `0`과 `2`는 연결** → `True`. 나오며 `(1,2)` 되돌림 |
| `[1, 3)` 나감 | `(0,1)` 되돌림 |
| `[3, 7)` | `(0,1)` 합침 |
| `[3, 5)` 의 잎 `[4, 5)` | **`t=4` 질의**: 살아 있는 간선은 `(0,1)`뿐이라 `False` |
| `[5, 7)` 의 잎 `[6, 7)` | `(1,2)` 합침. **`t=6` 질의** → `True` |

답: `[True, False, True]`. 간선 `(0,1)`은 두 노드에만 저장되어 *두 번* 합쳐졌고 (`[1,3)`과 `[3,7)`에서 한 번씩), 시각 하나마다 모든 살아 있는 간선을 다시 합치는 `O(T·E)`를 피했다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
class RollbackDSU:
    def find(self, v):                                   # 경로 압축 없음: O(log n)
        color = 0
        while self.parent[v] != v:
            color ^= self.parity[v]; v = self.parent[v]
        return v, color
    def union(self, a, b):                               # a, b 를 서로 다른 색으로
        (ra, ca), (rb, cb) = self.find(a), self.find(b)
        if ra == rb:                                     # 같은 성분: 같은 색이면 홀수 사이클
            ...; return False
        if self.size[ra] < self.size[rb]: ra, rb = rb, ra   # 작은 쪽을 큰 쪽 밑으로
        self.parent[rb] = ra; self.parity[rb] = ca ^ cb ^ 1
        self.size[ra] += self.size[rb]; self.components -= 1
        self._history.append((rb, ra, 0)); return True
    def snapshot(self): return len(self._history)
    def rollback(self, snapshot):                        # 기록을 거꾸로 되돌린다
        ...

def visit(node, lo, hi):                                 # 시간 구간 트리 DFS
    snapshot = dsu.snapshot()
    for a, b in tree[node]: dsu.union(a, b)              # 들어가며 합치기
    if hi - lo == 1: ...                                 # 잎: 이 시각의 질의에 답
    else: visit(2 * node, lo, mid); visit(2 * node + 1, mid, hi)
    dsu.rollback(snapshot)                               # 나오며 되돌리기
```

- `offline_dynamic_graph(n, operations)` → 질의 항목마다 하나씩 모은 답의 리스트. 연산은 `("add", u, v)`, `("remove", u, v)`, `("connected", u, v)`(`bool`), `("components",)`(`int`), `("bipartite",)`(`bool`). 없는 간선을 지우면 `ValueError`.
- `RollbackDSU`는 따로 쓸 수 있다: `union`, `find`, `snapshot`, `rollback`, 그리고 `components`, `odd_cycles`.
- 직접 실행하면 BOJ 16911 형식 — `N M`, 이어서 `M`줄의 `1 u v`(추가) / `2 u v`(삭제) / `3 u v`(연결 질의) — 을 받아 질의마다 `0` 또는 `1`을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 간선 구간 하나는 구간 트리의 노드 `O(log T)`개에 저장되고, 노드에 들어갈 때 간선마다 `union`이 한 번(`O(log n)`) 일어나므로 전체 `O((T + E) log T log n)`. 구간 트리와 저장된 간선은 `O(E log T)` 메모리.
- 이 환경에서 측정한 값입니다.

| 입력 | 연산 수 | 시간 |
|---|---|---|
| 정점 1000, 무작위 연산 (질의 5014개) | 9,998 | 0.07초 |
| 정점 2000 (질의 25,055개) | 49,992 | 0.43초 |
| 정점 10,000 (질의 49,884개) | 99,999 | 0.95초 |
| 정점 50,000 (질의 100,382개) | 200,000 | 2.07초 |
| 간선 약 2만 개를 끝까지 유지하고 질의 1000개 | 20,998 | 0.25초 |
| 간선마다 (추가, 질의, 삭제) 3연산, 2만 세트 | 59,964 | 0.48초 |

- 질의마다 현재 간선으로 유니온 파인드를 처음부터 다시 만드는 순진한 방법과 비교: 정점 1000, 연산 4,796개에서 0.028초 대 0.172초, 연산 16,028개에서 0.153초 대 2.70초 (연산이 3.3배 늘 때 순진한 방법은 약 16배, 이 구현은 약 5.5배).
- `n = 5·10⁴`, 연산 `2·10⁵`개가 약 2초이므로 대회 제한(`2·10⁵`~`3·10⁵`)에 가까운 입력도 파이썬으로 돌아가는 편입니다. 시간의 대부분은 구간 트리 구성과 `find`입니다.

## 6. 자주 하는 실수

- **경로 압축을 쓴다**: 압축은 되돌릴 수 없게 많은 부모를 바꿉니다. 롤백이 필요하면 *크기로만* 합치세요 (`find`가 `O(log n)`이 된다).
- **크기로 합치지 않는다**: 아무 쪽이나 붙이면 사슬이 만들어져 `find`가 `O(n)`이 됩니다. 테스트 `test_union_by_size_keeps_find_logarithmic`가 같은 크기끼리 합치는 최악 순서에서 깊이가 `log n` 이하임을 봅니다.
- **스냅샷을 노드 안에서 찍는다**: 노드에 *들어가기 전에* 기록 길이를 저장해야 그 노드의 간선만 정확히 되돌립니다.
- **반개구간 경계**: 이 문제는 연산마다 시각이 하나씩이라 `add`/`remove` 자신의 시각에는 질의가 없습니다. 그래서 `add`를 자기 시각부터, `remove`를 자기 시각 끝까지로 잡아도 결과는 같습니다 (이 구현은 `add`는 다음 시각부터, `remove`는 그 시각 직전까지). 한 시각에 질의와 갱신이 함께 있는 형태로 바꾸면 경계가 결과를 바꾸므로 *질의가 보는 간선 집합* 을 기준으로 다시 정해야 합니다.
- **끝까지 남은 간선을 빼먹는다**: 삭제되지 않은 간선은 `[시작, T)` 구간으로 마저 넣어야 합니다.
- **같은 간선을 여러 번 추가**: 다중 간선으로 세어야 하고, `remove` 한 번은 하나만 지웁니다 (연결성에는 어느 것을 지워도 같다). 집합으로만 두면 `add`, `add`, `remove`에서 틀립니다.
- **홀수 사이클 기록 누락**: 이분성 질의에서 `odd_cycles`도 롤백해야 합니다. 테스트가 `add (0,1), add (1,2), add (2,0)` 뒤 삭제로 이분성이 돌아오는 경우를 봅니다.
- **자기 루프**: `(u, u)`는 홀수 사이클(길이 1)이라 이분 그래프가 아닙니다 (연결성은 변하지 않음).
- **시간 `T`를 질의 수로 줄일 수 있다**: 질의가 없는 시각도 잎으로 만드는 것은 낭비입니다. 질의 시각만 좌표 압축하면 구간 트리가 작아지지만 이 구현은 단순함을 위해 연산 전체를 시각으로 씁니다.

## 7. 변형과 응용

- **이분 그래프 판정**: 이 구현이 이미 지원합니다 (홀짝 유니온 파인드).
- **성분 합/크기/최댓값**: 유니온 파인드의 루트에 값을 얹고 롤백할 때 되돌립니다 (Library Checker의 동적 그래프 정점 값 합 문제).
- **오프라인 동적 최소 신장 트리**: 시간 구간 트리 위에서 "이 구간 동안 반드시 쓰이는 간선 / 절대 안 쓰이는 간선" 을 걸러 간선 수를 줄여 가는 분할 정복 (`O(T log² T)`).
- **롤백 가능한 다른 자료구조**: 리 차오 트리 롤백으로 "시간 구간 안에서만 살아 있는 직선들의 최솟값", 몇 가지 DP(롤백 가능한 배열) 등.
- **온라인으로 바꾸려면**: 숲이라면 링크-컷 트리, 일반 그래프라면 레벨 구조의 HDLT. 오프라인 구현이 훨씬 단순하다.
