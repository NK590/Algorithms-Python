# 동적 트리 (Dynamic Trees)

트리가 **변하는** 문제를 다룹니다. 간선이 생기고 없어지거나(링크-컷), 정점의 값이 바뀌면서 트리 전체의 DP 값이 필요한 경우(탑 트리). Lv4의 [HLD](../../lv4-expert/02-tree-decomposition/heavy-light-decomposition/)와 [센트로이드 분해](../../lv4-expert/02-tree-decomposition/centroid-decomposition/)는 **고정된 트리**를 쪼갰지만, 여기서는 쪼갠 구조 자체를 갱신합니다.

## 한눈에 비교

| 개념 | 무엇이 변하나 | 핵심 | 질의 | 시간 |
|---|---|---|---|---|
| [링크-컷 트리](link-cut-tree/) | 간선(추가·삭제), 정점 값 | 선호 경로를 스플레이 트리로, `access`/`make_root` | 연결성, 경로 합·최댓값, LCA, 경로 덧셈 | 분할 상환 O(log n) |
| [탑 트리 (정적)](top-tree/) | 정점 값 (모양 고정) | rake / compress 클러스터의 이진 트리 | 트리 DP 전체 값 (최대 독립 집합, 아핀 합성 등) | 갱신 O(log n) |

두 구조의 파이썬 측정 (이 환경, `n = 10⁵`): 링크-컷 트리의 경로 합 질의 `10⁵`번 약 10초, 탑 트리의 `set_weight` `2·10⁴`번 1.5초. 탑 트리는 모양을 미리 알아 구조를 한 번 만들기 때문에 갱신이 훨씬 가볍고, 링크-컷 트리는 모양이 바뀌는 대가로 한 질의가 접근 세 번입니다.

## 문제 신호로 고르기

| 문제의 신호 | 선택 |
|---|---|
| 간선이 추가·삭제되고 **연결 여부** 질의 (숲) | [링크-컷 트리](link-cut-tree/) (질의를 미리 알면 오프라인 동적 연결성) |
| 간선이 바뀌며 **경로 합/최댓값** | [링크-컷 트리](link-cut-tree/) |
| 루트를 바꿔 가며 LCA | [링크-컷 트리](link-cut-tree/) |
| 트리 모양 고정, **정점 값만 바뀌고 트리 DP의 전체 값** | [탑 트리](top-tree/) |
| 트리 모양 고정, 경로·서브트리 질의와 갱신 | [HLD](../../lv4-expert/02-tree-decomposition/heavy-light-decomposition/) |
| 서브트리 질의가 필요하고 간선도 바뀐다 | 링크-컷 트리의 가상 서브트리 확장 / 완전한 동적 탑 트리 |

## 개념 사이의 관계

- 둘 다 **트리를 경로(체인)로 쪼개는** HLD의 발상에서 나옵니다. HLD는 고정된 무거운 경로를 쓰고, 링크-컷 트리는 접근에 따라 *바뀌는* 선호 경로를 스플레이 트리로 들고, 탑 트리는 고정된 무거운 경로 + 가벼운 서브트리를 클러스터 이진 트리로 묶습니다.
- 링크-컷 트리의 핵심 부품은 Lv4의 [스플레이 트리](../../lv4-expert/03-advanced-data-structures/splay-tree/)입니다 (지연 뒤집기, 부모 포인터, 반복형 스플레이).
- 탑 트리의 `compress`는 [행렬 거듭제곱](../../lv3-advanced/07-dp-advanced/matrix-exponentiation/)처럼 결합 법칙을 쓴 합성이고, `rake`는 교환 법칙을 쓴 합입니다.
- 이 저장소의 탑 트리는 **정적** 위상입니다. 위상이 바뀌는 탑 트리(자기 조정 탑 트리)는 구현하지 않았고, 그 역할은 링크-컷 트리가 대신합니다.

## 공통 원칙

- **순진한 숲/트리와 무작위 비교**: 두 구현 모두 인접 리스트로 DFS 하는 순진한 방법, 트리 DP 재계산과 무작위 연산 열로 맞춰 검증했습니다.
- **구조적 불변식 확인**: 링크-컷 트리는 스플레이 깊이가 줄어드는지, 탑 트리는 클러스터가 모든 정점을 한 번씩 덮는지와 깊이가 로그인지.
- **반복형 구현**: 사슬 모양 트리(깊이 `10⁵`)에서도 재귀 한도에 걸리지 않습니다.
- **파이썬의 한계를 숨기지 않기**: 두 구조 모두 상수가 커서 `10⁵` 규모가 파이썬의 한계입니다.
