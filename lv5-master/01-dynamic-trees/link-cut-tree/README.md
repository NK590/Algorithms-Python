# 링크-컷 트리 (Link-Cut Tree)

> **한 줄 요약**: **간선이 추가·삭제되는 숲**에서 두 정점의 연결 여부, **경로의 합/최댓값**, 경로 갱신, LCA를 분할 상환 `O(log n)`에 답한다. 트리를 "선호 경로"들로 쪼개 각 경로를 [스플레이 트리](../../../lv4-expert/03-advanced-data-structures/splay-tree/) 하나로 들고, 핵심 연산 `access(x)`가 "루트에서 `x`까지"를 하나의 경로로 만든다. `make_root`로 루트를 마음대로 바꿔서 `link`/`cut`이 쉬워진다.

## 1. 언제 쓰나 (문제 신호)

- "**간선이 생기고 사라지는** 숲에서 두 정점이 연결되어 있는가" (온라인)
- "경로 `u–v`의 **정점 값 합 / 최댓값 / xor**", "경로 전체에 더하기", 그리고 그 사이에 간선이 바뀐다
- "루트를 바꾸며 LCA", "`u`와 `v` 사이 간선 중 최대", **동적 최소 신장 트리**(간선을 정점으로 쪼개서)
- 트리가 아닌 일반 그래프의 연결성이 아니라 **숲(사이클이 없음)** 이어야 한다 (간선을 넣을 때 사이클이 생기지 않는다는 것이 보장되거나 직접 검사)
- 트리 모양이 고정이면 [HLD](../../../lv4-expert/02-tree-decomposition/heavy-light-decomposition/)가 더 빠르고 단순하다. 정점 값만 바뀌는 DP면 [탑 트리](../top-tree/)
- 질의를 모두 미리 알면 [오프라인 동적 연결성](../../04-offline-dynamic/offline-dynamic-connectivity/)이 더 단순할 수 있다

## 2. 핵심 아이디어

**선호 경로(preferred path)**: 루트 있는 트리에서 각 정점마다 자식 중 *최근에 접근한 자식* 하나를 **선호 자식**으로 표시하면, 정점들이 선호 간선으로 이어진 **경로**들로 나뉜다 (위에서 아래로 내려가는 직선). 각 경로를 **스플레이 트리 하나**로 표현한다 (스플레이의 중위 순회 = 경로를 위에서 아래로 훑은 순서). 경로의 맨 위 정점이 부모에게 가는 선호하지 않는 간선은 **경로 부모(path-parent) 포인터**로 두는데, 이 구현은 스플레이 루트의 `parent`가 "그 자식이 아닌 정점"을 가리키면 경로 부모라는 규칙으로 `parent` 배열 하나에 합쳤다.

**`access(x)`**: "루트에서 `x`까지의 경로를 하나의 선호 경로로 만든다." `x`부터 시작해 `x`를 자기 스플레이 트리의 루트로 올리고(`splay`), `x` 아래쪽(오른쪽 서브트리) 선호 경로를 끊고(방금 접근한 경로로 갈아 끼움) 경로 부모를 따라 한 칸 위 경로로 올라가 같은 일을 반복한다. 모든 `access` 전체가 분할 상환 `O(log n)`: 선호 자식이 바뀌는 횟수가 "가벼운 간선 + 무거운 간선" 논증으로 `O(log n)`번이고 각 스플레이는 분할 상환으로 갚아진다.

**`make_root(x)`**: `access(x)` 뒤 `x`의 스플레이 트리(= 루트에서 `x`까지의 경로) 전체를 **뒤집는다** (지연 뒤집기). 그러면 `x`가 맨 위 = 새 루트. 루트를 마음대로 바꿀 수 있어서

- `link(u, v)`: `make_root(u)` 한 뒤 `u`의 경로 부모를 `v`로 지정.
- `cut(u, v)`: `make_root(u)`, `access(v)` 하면 `v`의 스플레이에는 경로 `u..v`만 있다. 간선 `(u, v)`가 있다면 경로는 정점 두 개이고 `u`가 `v`의 왼쪽 자식이며 `u`에 자식이 없다 → `v`에서 `u`를 떼면 끝.
- `connected(u, v)`: 두 정점의 `find_root`(맨 왼쪽 정점)가 같은가.
- 경로 질의: `make_root(u)`, `access(v)` 하면 `v`의 스플레이 트리 전체가 경로 `u–v`라서 그 노드의 집계값(합, 최댓값)이 답. 경로 덧셈은 같은 서브트리에 지연 태그.
- `lca(root, u, v)`: `make_root(root)` 한 뒤 `access(u)`; 그다음 `access(v)`가 마지막으로 스플레이하는 정점이 LCA.

**간선 가중치**는 간선을 가운데 정점으로 쪼개면 정점 가중치 문제가 된다. **비가환** 집계(합성 함수 등)는 뒤집을 때 집계값도 좌우를 바꿔야 한다.

## 3. 손으로 따라가기

트리 `0–1, 1–2, 1–3, 3–4`, 정점 값 `[5, 3, 4, 2, 6]`. 루트를 `0`으로 보고 선호 경로의 변화:

| 연산 | 선호 경로 (위 → 아래) | 설명 |
|---|---|---|
| (처음) | `0`, `1`, `2`, `3`, `4` 각각 | 모든 선호 자식이 없다 |
| `access(4)` | `0–1–3–4`, `2` (경로 부모 `1`) | 루트에서 4까지가 한 경로, 2는 따로 |
| `access(2)` | `0–1–2`, `3–4` (경로 부모 `1`) | `1`의 선호 자식이 `3`에서 `2`로 바뀐다 |

**경로 합 `path_sum(2, 4)`**: `make_root(2)`로 `2`를 루트로 → 경로 `2–1–3–4`. `access(4)` 뒤 `4`의 스플레이 트리가 이 4개 정점: `4 + 3 + 2 + 6 = 15`.

**LCA**: 루트 `0`에서 `lca(0, 2, 4) = 1`. 루트를 `4`로 바꾸면 `lca(4, 2, 0)`은 `1`(`4–3–1–{0, 2}`).

**링크/컷**: `link(2, 4)`는 `2`와 `4`가 이미 연결(경로 `2–1–3–4`)이라 사이클이 생겨 `ValueError`. `cut(1, 3)` 뒤 `3–4`가 떨어지고 `connected(0, 4) = False`. `link(0, 4)`로 이으면 `2–1–0–4–3` 하나의 경로, `path_sum(2, 3) = 4 + 3 + 5 + 6 + 2 = 20`. `cut(0, 2)`처럼 경로는 있어도 간선이 아닌 쌍은 `ValueError`("그런 간선이 없습니다").

**`cut`의 확인**: `make_root(1)`, `access(3)` 후 `3`의 스플레이 트리는 경로 `1–3`: `1`이 `3`의 왼쪽 자식이고 `1`에게 자식이 없다 → 간선이 맞다. 반대로 `cut(0, 3)`이면 경로 `0–1–3`이 정점 세 개라 `0`이 `3`의 왼쪽 자식이어도 `0`에 자식(`1`)이 있어 간선이 아니라고 판정한다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _access(self, x):
    last = 0; y = x
    while y:
        self._splay(y)               # y 를 자기 스플레이 트리의 루트로
        self.right[y] = last         # y 아래 선호 경로를 방금 만든 경로(last)로 갈아 끼움
        self._pull(y)
        last, y = y, self.parent[y]  # 경로 부모를 따라 한 경로 위로
    self._splay(x)
    return last                      # 마지막으로 합쳐진 스플레이 루트 (두 번째 access 에서는 LCA)

def make_root(self, x): self._access(x); self.reversed[x] = not self.reversed[x]
def link(self, u, v):
    self._make_root(u)
    if self._find_root(v) == u: raise ValueError("이미 연결되어 있습니다")
    self.parent[u] = v
def cut(self, u, v):
    self._make_root(u); self._access(v)
    if self.left[v] != u or self.left[u] or self.right[u]: raise ValueError("그런 간선이 없습니다")
    self.left[v] = 0; self.parent[u] = 0; self._pull(v)
```

- 회전에서 조부모의 자식 포인터는 `p`가 스플레이 루트가 아닐 때만 바꿉니다 (`p`가 루트이면 조부모는 경로 부모라 자식 포인터를 건드리면 안 됩니다).
- `LinkCutTree(values)`: `link`, `cut`, `connected`, `find_root`, `make_root`, `path_sum`, `path_max`, `path_length`, `path_add(u, v, delta)`, `set_value`, `add_value`, `get_value`, `lca(root, u, v)`. 정점은 0부터. 모든 연산이 반복문이라 사슬 모양에서도 재귀 깊이 문제가 없습니다.
- 직접 실행하면 Library Checker "Dynamic Tree Vertex Add Path Sum" 형식 — `N Q`, 정점 값, 간선 `N − 1`개, 질의 `0 u v w x`(간선 `(u,v)`를 끊고 `(w,x)`를 잇는다) / `1 p x`(`a_p += x`) / `2 u v`(경로 합) — 을 처리합니다.

## 5. 복잡도와 입력 크기 가이드

- `access`/`link`/`cut`/경로 질의 모두 분할 상환 `O(log n)`, 메모리 `O(n)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다 (`n = 10⁵`).

| 작업 | 시간 |
|---|---|
| 간선 `10⁵ − 1`개 `link` (깊은 무작위 트리) | 1.67초 |
| 사슬 `link` `10⁵ − 1`번 | 0.30초 |
| `path_sum` `10⁵`번 (깊은 무작위 트리) | 10.4초 |
| 사슬에서 `path_sum(0, 임의)` `10⁵`번 | 5.45초 |
| 사슬에서 임의 두 정점 `path_sum` `10⁵`번 | 8.96초 |
| `add_value` `10⁵`번 | 4.57초 |
| `cut` + `link` 쌍 `5·10⁴`번 | 3.21초 |

- 한 경로 질의가 `make_root` + `find_root` + `access` 세 번의 접근이라 파이썬에서 질의당 약 `100`마이크로초입니다. `10⁵` 질의는 `10`초 안팎이라 **파이썬으로는 `10⁵` 규모가 한계**이고, 제한 시간이 빡빡한 대회에는 C++ 참고 구현이 필요합니다. 구현의 정확성(전수 비교 검증)과 구조를 배우는 용도로 읽어 주세요.
- 사슬(깊이 `n`)에서도 한 번의 `access`가 `O(n)`일 수 있으나 분할 상환으로 평균 `O(log n)` — 위 측정이 이를 보여 줍니다.

## 6. 자주 하는 실수

- **`push` 없이 자식 포인터를 읽음**: 지연 뒤집기 표시가 있으면 `left`/`right`가 아직 뒤바뀌기 전입니다. `splay`는 시작 전에 루트에서 `x`까지의 경로를 위에서부터 내려보내야 합니다.
- **회전에서 조부모 포인터를 무조건 수정**: 조부모가 *경로 부모*일 때(`p`가 스플레이 루트) 자식 포인터를 바꾸면 안 됩니다. `is_root(p)`를 확인하세요.
- **`access` 뒤 `x`를 스플레이 루트로 올리지 않음**: 마지막 `splay(x)`가 있어야 `x`의 서브트리가 경로 전체의 집계값이 됩니다.
- **`make_root`의 뒤집기를 빠뜨림**: `access(x)` 뒤 스플레이 전체를 뒤집어야 `x`가 맨 위(루트)가 됩니다.
- **`link`에서 사이클 검사 누락**: 같은 트리의 두 정점을 이으면 숲이 아니게 됩니다. `make_root(u)` 뒤 `find_root(v) == u`로 연결 여부를 확인합니다.
- **`cut`에서 간선인지 확인하지 않음**: 경로가 있다고 간선이 있는 것은 아닙니다. 경로가 정확히 정점 두 개(`u`가 `v`의 왼쪽 자식이고 `u`에 자식 없음)인지 확인하세요.
- **`find_root` 뒤 `splay`를 빼먹음**: 올바른 답은 나오지만 맨 왼쪽까지 내려가는 비용이 갚아지지 않아 분할 상환 `O(log n)`이 깨집니다.
- **비가환 집계의 뒤집기**: 경로의 합성 함수처럼 순서가 중요한 값은 뒤집을 때 `left`/`right`뿐 아니라 집계값 두 방향(정방향 합성, 역방향 합성)을 바꿔 줘야 합니다.
- **간선 가중치를 정점 값으로 착각**: 간선 가중치는 간선마다 가상 정점을 만들어 정점 값으로 옮깁니다 (간선 수만큼 정점이 늘어납니다).
- **루트를 고정해 두었다고 가정**: `make_root`가 루트를 바꿉니다. LCA 같은 루트 의존 값은 호출 때 루트를 명시하세요 (`lca(root, u, v)`).

## 7. 변형과 응용

- **동적 최소 신장 트리 / 간선 삭제**: 간선을 가운데 정점으로 쪼개고 정점 값을 간선 가중치로 두어, 간선을 추가할 때 사이클의 최대 간선을 뽑아 교체 (오프라인 삭제가 있으면 삭제 시각을 가중치로).
- **가상 서브트리 정보**: 경로 부모로 매달린 서브트리의 집계를 함께 유지하면 서브트리 크기·서브트리 합 같은 질의를 동적 트리에서 답합니다 ([탑 트리](../top-tree/)가 하는 일을 LCT로).
- **이분성/2-간선 연결성 증분**: 간선만 추가되는 문제에서 사이클이 생길 때 경로를 압축.
- **오일러 투어 트리**: 서브트리 질의에 특화된 다른 동적 트리 구조 (균형 트리로 오일러 투어를 유지).
- **경로 갱신 + 경로 최대 부분합**: 노드에 접두·접미·최대 부분합을 두고 뒤집을 때 접두/접미를 바꿉니다.
- **오프라인 대안**: 질의를 모두 알면 [오프라인 동적 연결성](../../04-offline-dynamic/offline-dynamic-connectivity/)(시간 구간 트리 + 롤백 유니온 파인드)이 파이썬에서 훨씬 빠릅니다.
