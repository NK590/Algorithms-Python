# 알고리즘 설계 기법 (Paradigms)

문제를 푸는 **큰 틀**인 그리디, 백트래킹, 다이나믹 프로그래밍을 다룹니다. 개별 알고리즘이 아니라 "이 문제를 어떤 방식으로 풀 것인가"에 대한 선택입니다.

## 한눈에 비교

| 설계 기법 | 핵심 | 맞을 때 | 시간 |
|---|---|---|---|
| [그리디](greedy/) | 매 단계 지금 최선을 고르고 되돌리지 않는다 | 선택이 이후를 망치지 않는다는 **증명**이 있다 | 보통 O(n log n) |
| [대표 그리디 유형](greedy-patterns/) | 정렬 / 힙 / 도달 범위 / 스택으로 최선을 빠르게 고르는 다섯 가지 틀 | 그리디 문제 중 유형이 정해진 것 | O(n log n) |
| [백트래킹](backtracking/) | 선택 → 탐색 → 취소, 안 되는 길은 일찍 자른다 | 모든 경우를 봐야 하고, 가지치기가 된다 | 경우의 수(가지치기로 감소) |
| [다이나믹 프로그래밍](dynamic-programming/) | 겹치는 부분 문제를 한 번만 풀어 저장 | 부분 문제가 겹치고 답이 부분 문제의 답으로 표현된다 | 상태 수 × 전이 수 |
| [DP 연습](dp-practice/) | 연속합·LIS·집 털기·계단·격자·삼각형 | 상태 설계 연습 | O(n) ~ O(n²) |

## 어떤 기법을 쓸까

| 문제 상황 | 선택 |
|---|---|
| 최소·최대 개수를 구하고, 정렬하면 규칙이 보인다 | **그리디** (먼저 작은 입력으로 브루트포스와 비교) |
| 모든 경우를 출력/세야 하고 N이 작다(≤ 10~20) | **백트래킹** |
| 최적값을 구하는데 그리디의 반례를 찾았다 | **DP** |
| 완전 탐색의 같은 부분 문제가 반복된다 | **DP** (메모이제이션) |
| 경우의 수를 세는데 N이 크다 | **DP** |

세 가지는 **서로를 검증하는 도구**이기도 합니다. 그리디가 맞는지는 DP나 브루트포스의 답과 비교하면 되고, DP의 점화식은 백트래킹으로 만든 전수 열거 결과와 비교하면 됩니다. 이 그룹의 테스트가 모두 그렇게 되어 있습니다.

## 읽는 순서

1. [그리디](greedy/) → [대표 그리디 유형](greedy-patterns/): 증명과 반례, 다섯 가지 틀
2. [백트래킹](backtracking/): 가지치기의 효과를 숫자로 확인
3. [다이나믹 프로그래밍](dynamic-programming/) → [DP 연습](dp-practice/): 상태 정의와 점화식
