# Greedy Algorithm (그리디 알고리즘, 탐욕적 기법)

> **한 줄 요약**: 매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌아보지 않는다. 빠르고 간단하지만 **맞다는 증명(또는 브루트포스 검증)** 없이 쓰면 틀린다.

## 1. 언제 쓰나 (문제 신호)

- "**최소 개수**, **최대 개수**, **최소 비용**"을 묻는데 정렬 기준 하나로 순서가 정해질 것 같다
- 구간(회의, 강의)을 **겹치지 않게 최대한 많이** 고르기
- 거스름돈처럼 단위가 서로 배수 관계인 **동전 문제**
- "작은 것부터", "큰 것부터", "끝나는 시간이 빠른 것부터"처럼 한 문장으로 규칙이 말해진다
- N이 10^5~10^6으로 커서 O(N²)이나 지수 시간 탐색은 불가능하다

## 2. 핵심 아이디어

그리디가 정답이 되려면 두 가지가 필요합니다.

1. **탐욕적 선택 성질**: 지금의 최선을 골라도 전체 최적해를 놓치지 않는다.
2. **최적 부분 구조**: 고르고 남은 문제가 같은 형태의 더 작은 문제이고, 그 최적해와 합치면 전체 최적해가 된다.

증명은 보통 **교환 논증**으로 합니다. "어떤 최적해가 내 선택과 다르다면, 그 최적해의 일부를 내 선택으로 바꿔도 더 나빠지지 않는다"를 보이는 것입니다.

**예: 활동 선택** (겹치지 않게 최대한 많은 구간 고르기). 규칙은 "끝나는 시간이 가장 빠른 것부터 고른다"입니다.

- 최적해의 첫 구간이 가장 빨리 끝나는 구간 `g`가 아니라고 하자.
- 그 첫 구간을 `g`로 바꾸면, `g`는 원래 첫 구간보다 빨리 (또는 같이) 끝나므로 뒤의 구간과 여전히 겹치지 않는다. 개수도 그대로다.
- 따라서 `g`를 포함하는 최적해가 있고, 남은 문제(`g`가 끝난 뒤의 구간들)도 같은 문제라 반복해서 적용된다.

**그리디가 틀리는 경우**도 꼭 기억하세요.

- 동전이 `[1, 3, 4]`이고 6원을 만들 때: 그리디는 `4 + 1 + 1`(3개), 최적은 `3 + 3`(2개).
- "가장 먼저 시작하는 구간부터"는 `[(0,10), (1,2), (3,4)]`에서 `(0,10)` 하나만 고르고, 최적은 2개.

그래서 **작은 입력에서 브루트포스와 비교**하는 습관이 중요합니다. 이 폴더의 [테스트](test_solution.py)가 바로 그렇게 합니다. (모든 부분집합을 만들어 보는 것과 비교)

### 무엇을 저장하고 어떻게 움직이나

현재 선택을 되돌리지 않고 최종 해에 확정하는 방식입니다. 중요한 부분은 가장 좋아 보이는 기준을 찾는 일이 아니라, 그 선택을 포함하는 최적해가 항상 존재함을 증명하는 일입니다. 정렬 기준을 목적함수와 연결해 설명해야 합니다.

### 왜 이 방법이 맞는가

교환 논증은 임의의 최적해의 첫 선택을 그리디 선택으로 바꿔도 나빠지지 않음을 보입니다. 이후 남은 문제에 같은 논리를 반복합니다. 동전 단위처럼 특정 조건에서만 맞는 그리디를 일반적인 경우에 확장하면 반례가 생깁니다.

### 작은 예제로 검산하기

동전 `[1,3,4]`로 6을 만들 때 큰 것부터 고르면 4+1+1의 세 개지만 3+3은 두 개입니다. 구간 선택은 끝이 가장 빠른 구간으로 바꿔도 뒤에 남는 선택 가능 시간이 줄지 않아 그리디가 성립합니다.

## 3. 손으로 따라가기

**활동 선택**: 구간 `(1,4) (3,5) (0,6) (5,7) (3,9) (5,9) (6,10) (8,11)`.
끝나는 시간 순으로 정렬한 뒤(이미 그 순서) 앞에서부터 본다. `last_end`는 마지막으로 고른 구간이 끝나는 시각입니다.

| 구간 | 시작 ≥ last_end ? | 선택 | last_end |
|---|---|---|---|
| (1,4) | 1 ≥ −∞ | O | 4 |
| (3,5) | 3 < 4 | | 4 |
| (0,6) | 0 < 4 | | 4 |
| (5,7) | 5 ≥ 4 | O | 7 |
| (3,9) | 3 < 7 | | 7 |
| (5,9) | 5 < 7 | | 7 |
| (6,10) | 6 < 7 | | 7 |
| (8,11) | 8 ≥ 7 | O | 11 |

결과 `(1,4) (5,7) (8,11)`, **3개**.

**거스름돈**: 동전 `1, 5, 10, 50, 100, 500`으로 1260원: `500×2 = 1000`, 남은 260 → `100×2`, 남은 60 → `50×1`, 남은 10 → `10×1`. 총 **6개**. 이 동전들은 큰 단위가 작은 단위의 배수라서 그리디가 맞습니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def activity_selection(intervals):
    chosen = []
    last_end = float("-inf")
    for start, end in sorted(intervals, key=lambda it: (it[1], it[0])):
        if start >= last_end:          # 끝과 시작이 같으면 겹치지 않는 것으로 본다
            chosen.append((start, end))
            last_end = end
    return chosen

def greedy_coin_change(coins, amount):
    count = 0
    for coin in sorted(coins, reverse=True):
        count += amount // coin
        amount %= coin
    return count if amount == 0 else -1
```

- 정렬 기준 `(끝, 시작)`의 두 번째 값은 `(3,3)`처럼 **길이가 0인 구간**을 놓치지 않기 위한 것입니다. (끝이 같으면 시작이 빠른 것을 먼저 본다.)
- `min_coins_dp`는 동전 체계와 상관없이 맞는 답(DP)이며, 그리디가 틀리는 경우와 비교하려고 넣었습니다.
- `fractional_knapsack`: 물건을 **쪼갤 수 있으면** 무게당 가치가 큰 것부터 담는 그리디가 맞습니다. (쪼갤 수 없는 0/1 배낭은 그리디가 틀리고 [배낭 문제](../../../lv2-intermediate/04-dynamic-programming/knapsack/)의 DP가 필요합니다.)
- `max_camping_days`: P일 중 L일만 쓸 수 있는 캠핑장을 V일 동안 쓰는 최대 일수. 직접 실행하면 `L P V`를 받아 이 값을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 대부분 **정렬이 지배**해서 **O(n log n)**, 고르는 부분은 O(n)입니다. 공간은 O(n). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- N이 10^6이어도 파이썬 정렬로 충분히 풀립니다. 그리디의 장점은 답이 맞다면 가장 빠르다는 것입니다.

## 6. 자주 하는 실수

- **증명도 검증도 없이 그럴듯해 보여서 제출**: 가장 흔하고 가장 아픈 실수입니다. 작은 입력(n ≤ 8)에서 모든 경우를 시도하는 브루트포스와 비교해 보세요.
- **정렬 기준이 틀림**: 활동 선택에서 "시작 시간이 빠른 것부터"나 "짧은 것부터"는 반례가 있습니다. 끝나는 시간이 정답입니다.
- **동점 처리**: 끝 시간이 같은 구간이나 길이가 0인 구간처럼 경계가 같은 경우를 따로 생각하세요.
- **동전 체계를 확인하지 않음**: 단위가 서로 배수 관계가 아니면(예: `[1, 3, 4]`) DP를 써야 합니다.
- **0/1 배낭에 그리디**: "무게당 가치가 큰 것부터"는 쪼갤 수 있을 때만 맞습니다.
- **`amount != 0`일 때**: 큰 동전부터 쓰다 남으면 못 만드는 것처럼 보이지만, 다른 조합으로 만들 수 있는 경우가 있습니다(`[3, 4]`로 6원은 `3+3`). 그리디의 `-1`을 믿지 마세요.

## 7. 변형과 응용

- **대표 그리디 유형**: 정렬해서 순서 정하기, 힙으로 가장 작은 둘 합치기, 가장 멀리 가는 곳 갱신, 스택으로 앞의 작은 값 지우기 → [대표 그리디 유형](../greedy-patterns/)
- **그리디가 안 될 때**: 부분 문제의 답을 저장해 두는 [다이나믹 프로그래밍](../dynamic-programming/), 모든 경우를 가지치기하며 보는 [백트래킹](../backtracking/)
- **그래프에서의 그리디**: 최소 신장 트리(크루스칼·프림), 다익스트라는 모두 "지금 가장 가까운 것부터 확정"하는 그리디입니다. → [다익스트라](../../../lv2-intermediate/01-shortest-path/dijkstra/)
