# Backtracking (백트래킹)

> **한 줄 요약**: 선택을 하나씩 쌓아 가며 DFS로 탐색하다가, 답이 될 수 없는 길은 **들어가기 전에** 잘라 내고 되돌아온다. 8-Queen은 순열 40,320가지를 모두 만들어 보는 대신, 퀸을 2,056번 놓아 보는 것만으로 92개의 해를 모두 찾는다.

## 1. 언제 쓰나 (문제 신호)

- "**모든 경우를 출력**하라", "**경우의 수**를 구하라" (N이 10~20 이하로 작다)
- 순열, 조합, 부분집합을 만들어야 한다 (N과 M 시리즈)
- 조건을 만족하는 **배치**를 찾는다 (N-Queen, 스도쿠, 좋은 수열)
- 일부만 정해도 "이미 틀렸다"고 판단할 수 있는 제약이 있다 → **가지치기**가 가능하다
- N이 크거나(≥ 25 정도) 부분 문제가 겹친다면 백트래킹이 아니라 [DP](../dynamic-programming/)를 의심하세요.

## 2. 핵심 아이디어

선택의 연속을 **트리**로 그려 봅니다. 루트에서 시작해 한 단계마다 후보 중 하나를 고르고, 마지막 단계까지 내려가면 하나의 완성된 후보 해입니다. 이 트리를 DFS로 훑되, 세 가지 동작을 짝지어 씁니다.

```
def dfs(상태):
    if 끝났다:  결과를 기록한다; return
    for 후보 in 후보들:
        if 조건에 어긋난다:  continue      # 가지치기: 들어가지 않는다
        후보를 고른다                       # 선택
        dfs(다음 상태)                      # 탐색
        후보를 취소한다                     # 되돌리기 (backtrack)
```

- **선택을 취소해야** 같은 상태에서 다음 후보를 시도할 수 있습니다. (`append`/`pop`, `add`/`remove`가 항상 짝입니다.)
- **가지치기**가 백트래킹과 단순 완전 탐색([브루트포스](../../../lv0-basics/03-brute-force/brute-force/))의 차이입니다. 일찍 자를수록 방문하는 상태가 급격히 줄어듭니다.
- 순서가 의미 있으면 **순열**(`used` 배열), 의미 없으면 **조합**(다음 후보를 `start`부터)입니다.

**N-Queen에서의 가지치기**: 행마다 퀸을 하나씩 놓는다고 정하면 "같은 행"은 신경 쓰지 않아도 됩니다. 같은 열, 같은 `/` 대각선(`row + col`이 같다), 같은 `\` 대각선(`row − col`이 같다)은 집합으로 O(1)에 검사합니다.

| N = 8 | 후보 | 볼 상태 수 |
|---|---|---|
| 각 행에 아무 열이나 | 8⁸ | 16,777,216 |
| 열이 겹치지 않게 (순열) | 8! | 40,320 |
| **백트래킹** (열·대각선 검사로 가지치기) | | **2,056** |

### 무엇을 저장하고 어떻게 움직이나

완성되지 않은 부분 해를 만들면서 후보를 하나 선택하고, 탐색 후 선택을 취소합니다. 가지치기는 현재 부분 해가 어떤 방식으로도 유효한 완성 해가 될 수 없다는 판정입니다. 단순히 지금 점수가 나쁘다는 이유만으로 버리면 정답을 놓칠 수 있습니다.

### 왜 이 방법이 맞는가

각 깊이에서 모든 허용 후보를 시도하면 모든 완성 해에 대응하는 경로가 있습니다. 되돌리기가 이전 상태를 정확히 복원하면 형제 탐색이 서로 오염되지 않습니다. 가지치기는 버린 가지에 정답이 없다는 근거가 있어야 합니다.

### 작은 예제로 검산하기

퀸을 한 행씩 놓을 때 이전 퀸과 같은 열이나 대각선이면 이후 행을 어떻게 채워도 충돌은 사라지지 않습니다. 그래서 즉시 끊어도 안전합니다. 선택한 열을 표시하고 재귀 뒤 해제하는 두 동작을 한 쌍으로 읽으세요.

## 3. 손으로 따라가기

**N과 M (1)**: 1~3에서 2개를 고른 수열(순열), `used`로 중복을 막는다.

```
dfs([])
 ├ 1 → dfs([1]) → 2 → (1,2) 기록
 │               └ 3 → (1,3) 기록
 ├ 2 → dfs([2]) → 1 → (2,1), 3 → (2,3)
 └ 3 → dfs([3]) → 1 → (3,1), 2 → (3,2)
```

출력 순서가 곧 사전 순입니다: `(1,2) (1,3) (2,1) (2,3) (3,1) (3,2)`.

**4-Queen**: 행 0의 열 0에서 시작하면 어떻게 이어 놓아도 4행까지 못 가서(해가 없음) 열 1로 넘어갑니다. 첫 번째 해는 `[1, 3, 0, 2]`(행 0은 열 1, 행 1은 열 3, 행 2는 열 0, 행 3은 열 2)이고, 해는 모두 2개(`[1,3,0,2]`, `[2,0,3,1]`)입니다. 이 과정에서 놓는 시도를 통과한 횟수는 16번입니다.

N이 커질수록 해의 수와 걸리는 시간은 다음과 같습니다. (이 환경에서 측정, `n_queens_count`)

| N | 해의 수 | 놓은 횟수 | 시간 |
|---|---|---|---|
| 4 | 2 | 16 | 0초 |
| 6 | 4 | 152 | 0초 |
| 8 | 92 | 2,056 | 0.005초 |
| 10 | 724 | 35,538 | 0.05초 |
| 12 | 14,200 | | 1.1초 |

N이 1 늘 때마다 약 5배씩 늘어납니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def n_queens_count(n):
    cols, diag1, diag2 = set(), set(), set()

    def place(row):
        if row == n:
            return 1
        count = 0
        for col in range(n):
            if col in cols or (row + col) in diag1 or (row - col) in diag2:
                continue                      # 가지치기
            cols.add(col); diag1.add(row + col); diag2.add(row - col)     # 선택
            count += place(row + 1)                                        # 탐색
            cols.remove(col); diag1.remove(row + col); diag2.remove(row - col)  # 취소
        return count

    return place(0)
```

같은 틀로 다음을 만들어 두었습니다.

| 함수 | 하는 일 |
|---|---|
| `pick_permutations(n, m)` | 1~n에서 m개를 고른 순열 (N과 M (1)) |
| `pick_combinations(n, m)` | 조합. 남은 자리를 못 채울 만큼 숫자가 남지 않으면 가지치기 |
| `all_subsets(items)` | 모든 부분집합. 각 원소를 넣는다/안 넣는다 |
| `n_queens_count`, `n_queens_first`, `n_queens_nodes` | 해의 수 / 사전 순 첫 해 / 방문한 상태 수 |
| `generate_parentheses(n)` | 올바른 괄호 문자열 (닫는 괄호는 열린 것보다 많아질 수 없다는 가지치기). 개수는 카탈란 수 |
| `solve_sudoku(grid)` | 9×9 스도쿠. 후보가 가장 적은 칸부터 채운다 |

- `n_queens_first`는 해를 하나 찾으면 **즉시 `True`를 돌려** 남은 탐색을 끝냅니다. 이때는 선택을 취소하지 않아도 됩니다.
- 표준 스도쿠 퍼즐은 이 환경에서 약 0.001초에 풀렸습니다.
- 직접 실행하면 `N`을 받아 N-Queen의 경우의 수를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 최악의 경우 시간은 **경우의 수 전체**(순열 O(n!), 부분집합 O(2ⁿ))이고, 가지치기로 얼마나 줄어드는지는 문제마다 다릅니다. 공간은 재귀 깊이 O(n)입니다.
- 경우의 수가 순열이면 N ≤ 10 안팎, 부분집합이면 N ≤ 20 안팎입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 순수 CPython으로 N-Queen은 N = 12에서 1초 정도입니다. N ≥ 14는 이 단순한 구현으로는 부담이고, 비트마스크로 열·대각선을 정수 하나씩에 담으면 훨씬 빨라집니다. ([비트마스크](../../09-bit-manipulation/bitmask/))

## 6. 자주 하는 실수

- **선택을 취소하지 않음**: `chosen.pop()`이나 `used[x] = False`를 빼면 다음 후보를 시도할 때 상태가 오염됩니다.
- **결과 리스트를 그대로 저장**: `result.append(chosen)`은 같은 리스트를 계속 가리켜서 마지막에 모두 같은 값이 됩니다. 복사(`list(chosen)`, `tuple(chosen)`)해서 저장하세요.
- **가지치기를 늦게 함**: 재귀로 들어간 뒤에 검사하면 호출만 늘어납니다. 후보를 고르기 **전에** 검사하세요.
- **조합에서 시작 위치**: `start`를 방금 고른 수 `+1`로 넘겨야 합니다. 그냥 `start`를 넘기면 같은 수를 중복해서 고릅니다.
- **대각선 식 혼동**: `/` 방향은 `row + col`, `\` 방향은 `row − col`이 같습니다.
- **재귀 깊이**: 깊이가 1000에 가까우면 `sys.setrecursionlimit`이 필요합니다. 보통 백트래킹의 깊이는 작지만, 격자 DFS는 주의하세요. ([재귀](../../../lv0-basics/06-recursion/recursion-basics/))
- **전역 변수로 결과 누적**: 함수 안에서 `nonlocal`이나 리스트로 모으세요. 여러 번 호출하면 값이 쌓입니다.

## 7. 변형과 응용

- **한 개만 찾기**: 해를 하나 찾으면 바로 `True`를 반환해 모든 호출을 빠져나옵니다. (`n_queens_first`, `solve_sudoku`)
- **가장 제약이 큰 곳부터**: 스도쿠처럼 후보가 가장 적은 칸부터 채우면 막다른 길을 일찍 발견합니다.
- **격자 위의 백트래킹**: 방문 표시를 하고 되돌리는 DFS (알파벳, 단어 찾기). → [DFS](../../05-graph-basics/dfs/)
- **가지치기를 더 강하게**: 지금까지의 합이 이미 목표를 넘으면(양수일 때) 중단, 남은 최댓값을 더해도 목표에 못 미치면 중단 같은 **한계(bound)** 가지치기. (분기 한정)
- **중간에서 만나기**: 2ⁿ을 두 개의 2^(n/2)로 나누는 방법. → [중간에서 만나기](../../../lv3-advanced/06-query-techniques/meet-in-the-middle/)
- **상태가 겹칠 때**: 같은 부분 문제가 반복되면 저장해서 [DP](../dynamic-programming/), 비트마스크로 상태를 압축해 [비트마스크 DP](../../../lv2-intermediate/04-dynamic-programming/bitmask-dp/)
