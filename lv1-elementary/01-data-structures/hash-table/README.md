# Hash Table (해시 테이블)

> **한 줄 요약**: 키를 **해시 함수**로 칸 번호로 바꿔 저장해서, 평균 O(1)에 "넣기, 찾기, 지우기"를 하는 자료구조. 파이썬의 `dict`와 `set`이 이것이다.

## 1. 언제 쓰나 (문제 신호)

- "**이미 본 값인가?**", "**몇 번 나왔는가?**", "이름으로 값을 찾는다", "중복 제거"
- 리스트에서 `x in list`를 반복해서 시간 초과가 날 때 → `set`/`dict`로 바꾸면 O(n) → O(1)
- 두 수의 합(two sum), 애너그램 묶기, 단어 빈도 세기

PS에서는 내장 `dict`/`set`/`Counter`를 쓰고, 이 문서의 구현은 **어떻게 평균 O(1)이 가능한지** 보이기 위한 것입니다. 쓰는 법은 [set과 dict 활용](../set-and-dict/)을 보세요.

## 2. 핵심 아이디어

1. **해시 함수**가 키를 큰 정수로 바꿉니다. (`hash(key)`)
2. 그 값을 칸 수로 나눈 **나머지**가 칸 번호입니다. (`hash(key) % 칸 수`) 키를 보면 곧바로 칸을 알 수 있어서 O(1)입니다.
3. 서로 다른 키가 같은 칸에 들어오는 **충돌**이 생길 수 있습니다. 이 구현은 **체이닝**으로 해결합니다. 한 칸에 `(키, 값)` 목록을 두고, 그 칸 안에서만 순서대로 비교합니다.
4. 칸이 너무 차면(평균 한 칸에 0.75개 초과, **적재율**) 칸 수를 **두 배**로 늘리고 모든 항목을 **다시 넣습니다.** 칸 수가 바뀌면 칸 번호도 바뀌기 때문입니다.

충돌이 적게 퍼지면 한 칸에 항목이 한두 개뿐이라 평균 O(1)입니다. 모든 키가 한 칸에 몰리는 최악에는 O(n)입니다.

**키는 바뀌지 않는 값**(정수, 문자열, 튜플)이어야 합니다. 리스트나 딕셔너리는 해시할 수 없어 키가 될 수 없습니다.

### 무엇을 저장하고 어떻게 움직이나

키를 해시값으로 바꿔 저장 위치를 정합니다. 서로 다른 키가 같은 위치에 도착할 수 있으므로 충돌 처리가 필요합니다. 사전은 키의 존재뿐 아니라 값·등장 횟수·위치도 함께 저장하므로 집합보다 많은 정보를 표현합니다.

### 왜 이 방법이 맞는가

충돌이 발생해도 원래 키를 비교해 구분하면 정확성은 유지됩니다. 다만 원소가 몰리면 조회 비용이 커져 평균 O(1) 조건이 깨질 수 있습니다. 투섬에서는 현재 원소의 보수를 먼저 조회하고 현재 원소를 나중에 넣어 같은 인덱스를 두 번 쓰지 않습니다.

### 작은 예제로 검산하기

`[3,3]`, 목표 합 6에서 첫 3은 사전에 저장하고, 두 번째 3을 볼 때 이전 3을 찾습니다. 값을 집합에 넣기만 하면 위치를 잃으므로 인덱스 출력이 필요한 문제에서는 키에 위치를 대응시켜야 합니다.

## 3. 손으로 따라가기

칸 수 4, 정수 키(`hash(k) = k`)를 `1, 5, 9, 2` 순서로 넣습니다. 1, 5, 9는 모두 `% 4 = 1`이라 **충돌**합니다.

| 넣는 키 | 칸 번호 | 칸 수 | 칸 내용 (칸 번호: 키들) |
|---|---|---|---|
| 1 | 1 | 4 | `1: [1]` |
| 5 | 1 | 4 | `1: [1, 5]` (충돌, 같은 칸에 이어 둠) |
| 9 | 1 | 4 | `1: [1, 5, 9]` |
| 2 | 2 | 4 → **8** | 항목이 4개가 되어 `4 > 0.75 × 4 = 3` → 칸 수를 8로 늘리고 재배치 |

재배치 후(`% 8`): `1: [1, 9]`, `2: [2]`, `5: [5]`. 1과 9는 `% 8 = 1`이라 여전히 같은 칸이지만 5는 다른 칸으로 갔습니다.

**two sum** `[2, 7, 11, 15]`, target 9: `2`를 보고 "9 − 2 = 7이 이미 있는가?" → 없음, `2`를 기록. `7`을 보고 "9 − 7 = 2가 있는가?" → 있음(위치 0) → 답은 `(0, 1)`. 한 번만 훑어 O(n)입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
class HashMap:
    LOAD_FACTOR_LIMIT = 0.75

    def __init__(self, capacity=8):
        self._buckets = [[] for _ in range(capacity)]
        self._size = 0

    def put(self, key, value):
        bucket = self._buckets[hash(key) % len(self._buckets)]
        for i, (k, _) in enumerate(bucket):
            if k == key:                       # 이미 있으면 값만 바꾼다
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
        self._size += 1
        if self._size > self.LOAD_FACTOR_LIMIT * len(self._buckets):
            self._resize(2 * len(self._buckets))   # 모든 항목을 새 칸 수로 다시 넣는다
```

`get`, `remove`, `in`, `items`와, 활용 예인 `two_sum`, `group_anagrams`가 있습니다. 직접 실행하면 카드 N장과 질문 M개를 받아 각 질문의 수를 가지고 있으면 1, 아니면 0을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 넣기·찾기·지우기가 **평균 O(1)** 입니다. 적재율을 낮게 유지하는 재배치 덕분이고, 재배치는 가끔만 일어나므로 분할 상환으로도 O(1)입니다.
- 모든 키의 해시가 같으면 O(n)입니다. 이 저장소의 테스트가 그런 키로도 올바르게 동작함을 확인합니다.
- 순서는 보장되지 않는 것이 원래 성질입니다. (파이썬 3.7 이상의 `dict`는 넣은 순서를 유지하지만 `set`은 아닙니다)
- N = 10^6 정도의 `dict`/`set`은 문제없습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **리스트에 `in`**: O(n)이라 반복하면 O(n²)입니다. 자주 확인한다면 `set`으로.
- **변하는 값(리스트)을 키로**: `TypeError: unhashable type`. 튜플로 바꾸세요.
- **없는 키 접근**: `d[key]`는 `KeyError`. `d.get(key, 기본값)`이나 `defaultdict`를 쓰세요.
- **해시 충돌 공격**: 일부 대회에서는 충돌이 많이 나는 입력을 일부러 줍니다. 정수 키가 문제일 때는 값에 임의의 수를 섞는(XOR) 방법을 씁니다. 파이썬은 문자열 해시를 무작위화해서 대부분 괜찮습니다.
- **재배치 누락**: 칸 수만 늘리고 기존 항목을 다시 넣지 않으면 찾을 수 없게 됩니다.
