# Tower of Hanoi (하노이의 탑)

> **한 줄 요약**: n개의 원판을 옮기려면 위의 n−1개를 보조 기둥으로 치우고, 가장 큰 원판을 목표로 옮기고, 치워 둔 n−1개를 그 위로 옮긴다. 최소 이동 횟수는 정확히 2ⁿ − 1이다.

## 1. 언제 쓰나 (문제 신호)

- "원판을 옮기는 **순서를 출력**", "**최소 이동 횟수**"
- 큰 문제를 **같은 모양의 더 작은 문제**로 쪼개 해결하는 연습 (재귀의 대표 예제)
- 점화식 `T(n) = 2·T(n−1) + 1` 같은 **재귀적 구조의 점화식**을 세우고 푸는 연습
- 출력이 지수 개(2ⁿ − 1줄)여서 n이 크면 **개수만** 묻는 변형 (n = 100)

## 2. 핵심 아이디어

재귀로 풀 때는 세 가지를 확인합니다.

1. **기저 조건**: 옮길 원판이 0개면 아무것도 하지 않는다.
2. **문제를 줄이기**: n개의 문제를 n−1개의 문제로 바꾼다.
3. **작은 문제를 믿기**: `n−1`개를 옮기는 함수가 맞게 동작한다고 가정하고 그것을 호출한다.

n개를 기둥 A에서 C로 옮길 때 (B는 보조):

1. 위의 `n−1`개를 A → **B**로 옮긴다. (C를 보조로)
2. 가장 큰 원판 하나를 A → C로 옮긴다.
3. B에 있는 `n−1`개를 B → **C**로 옮긴다. (A를 보조로)

**이동 횟수**: `T(n) = 2·T(n−1) + 1`, `T(0) = 0`. 양변에 1을 더하면 `T(n) + 1 = 2·(T(n−1) + 1)`이므로 `T(n) + 1 = 2ⁿ`, 즉 **`T(n) = 2ⁿ − 1`**입니다.

**최소임의 증명**: 가장 큰 원판이 움직이려면 그 위의 `n−1`개가 모두 다른 두 기둥 중 하나(목표가 아닌 보조)에 쌓여 있어야 하므로 최소 `T(n−1)`번이 먼저 필요하고, 큰 원판이 목표에 도착한 뒤 그 `n−1`개가 다시 그 위로 가야 하므로 최소 `T(n−1)`번이 더 필요합니다. 따라서 `T(n) ≥ 2·T(n−1) + 1`이고, 위의 방법이 정확히 그 값을 달성합니다. (BFS로 n ≤ 6에서 확인한 [테스트](test_solution.py)가 있습니다.)

## 3. 손으로 따라가기

n = 3, A = 1번 기둥, C = 3번 기둥, 원판은 작은 것부터 1, 2, 3. 각 기둥은 아래에서 위 순서입니다.

| 단계 | 옮기는 원판 | 이동 | 기둥 1 | 기둥 2 | 기둥 3 |
|---|---|---|---|---|---|
| 시작 | | | 3 2 1 | | |
| 1 | 1 | 1 → 3 | 3 2 | | 1 |
| 2 | 2 | 1 → 2 | 3 | 2 | 1 |
| 3 | 1 | 3 → 2 | 3 | 2 1 | |
| 4 | 3 | 1 → 3 | | 2 1 | 3 |
| 5 | 1 | 2 → 1 | 1 | 2 | 3 |
| 6 | 2 | 2 → 3 | 1 | | 3 2 |
| 7 | 1 | 1 → 3 | | | 3 2 1 |

가운데(4단계)가 가장 큰 원판입니다. 앞 3단계는 "2개를 1 → 2로", 뒤 3단계는 "2개를 2 → 3으로"입니다. 옮긴 원판 번호의 열 `1 2 1 3 1 2 1`은 **눈금자 모양**이고, k번째 이동의 원판 번호는 **k를 이진수로 썼을 때 끝에 오는 0의 개수 + 1**입니다 (`disk_moved_at`). 가장 작은 원판은 홀수 번째마다 움직입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def hanoi_moves_detailed(n, source=1, spare=2, target=3):
    moves = []

    def move(k, src, mid, dst):
        if k == 0:
            return
        move(k - 1, src, dst, mid)      # 위의 k-1 개를 보조 기둥으로
        moves.append((k, src, dst))     # 가장 큰 원판을 목표로
        move(k - 1, mid, src, dst)      # 치워 둔 k-1 개를 그 위로

    move(n, source, spare, target)
    return moves
```

- `hanoi_moves`: `(출발, 도착)`만 담은 목록. 길이 `2ⁿ − 1`.
- `hanoi_count(n) = 2ⁿ − 1`, `hanoi_count_recursive`: 점화식을 그대로 코드로 옮긴 것.
- `hanoi_kth_move(n, k)`: 전체를 만들지 않고 **k번째 이동만 O(n)에** 구합니다. 가운데(2ⁿ⁻¹번째)가 가장 큰 원판이고, 앞이면 앞 단계, 뒤면 뒷 단계로 내려가는 이분 탐색과 같은 구조입니다. n = 60에서도 즉시 답이 나옵니다.
- `hanoi_iterative(n)`: 재귀 없이 같은 이동을 만듭니다. 번갈아 ① 가장 작은 원판을 정해진 방향으로 한 칸(n이 홀수면 1→3→2→1, 짝수면 1→2→3→1) ② 작은 원판이 없는 두 기둥 사이에서 가능한 유일한 이동. 테스트가 재귀 결과와 같음을 확인합니다.
- 직접 실행하면 `N`을 받아 이동 횟수를 출력하고, N ≤ 20이면 이동 순서도 한 줄씩 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(2ⁿ)**: 이동을 모두 출력해야 하므로 이보다 줄일 수 없습니다. **공간은 O(n)**(재귀 깊이)입니다. 이동 목록을 저장하면 O(2ⁿ).
- 이 환경에서 측정한 값입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

| n | 이동 횟수 | 이동 생성 | 문자열로 만들기 |
|---|---|---|---|
| 10 | 1,023 | 0초 | 0초 |
| 16 | 65,535 | 0.02초 | 0.01초 |
| 20 | 1,048,575 | 0.6초 | 0.45초 |

- n = 25면 3천만 줄이 넘어 사실상 출력할 수 없습니다. 이동 횟수만 묻는 문제(n = 100)는 `2ⁿ − 1`을 파이썬 큰 정수로 바로 계산합니다. (2¹⁰⁰ − 1 = 1267650600228229401496703205375)
- 전설의 64개 원판이라면 2⁶⁴ − 1 = 18,446,744,073,709,551,615번입니다.

## 6. 자주 하는 실수

- **보조 기둥의 역할을 바꿔 씀**: 첫 재귀는 `(src, dst, mid)`, 둘째 재귀는 `(mid, src, dst)`입니다. 두 호출의 `mid`와 `dst` 위치를 헷갈리면 규칙 위반이 생깁니다.
- **출력마다 `print`**: 100만 줄을 `print`로 하나씩 내보내면 느립니다. 문자열로 모아 `"\n".join(...)`으로 한 번에 출력하세요.
- **n이 큰데 이동을 만들려 함**: 이동 횟수만 필요하면 공식을 쓰고, 이동은 n이 작을 때만 만드세요.
- **기저 조건**: `n == 1`에서 멈추는 코드는 `n == 0`을 입력받으면 무한 재귀입니다. 문제의 입력 범위를 확인하고 `n == 0`에서 멈추는 쪽이 안전합니다.
- **전역 카운터**: 이동 횟수를 전역 변수로 세면 여러 번 호출할 때 누적됩니다. 반환값이나 `len(moves)`를 쓰세요.
- **재귀 깊이**: 깊이는 n이라 문제없습니다. 문제가 되는 것은 호출 **횟수**(2ⁿ)입니다.
