# Euclidean Algorithm (유클리드 호제법)

> **한 줄 요약**: 두 수의 최대공약수는 `gcd(a, b) = gcd(b, a mod b)`로 계속 줄여 가다가 나머지가 0이 되면 끝난다. 10^18 크기의 수도 최악이 85번이고, 평균은 35번 안팎이다.

## 1. 언제 쓰나 (문제 신호)

- "**최대공약수**", "**최소공배수**"를 구하라
- 분수를 **약분**해야 한다 (분자와 분모를 gcd로 나눈다)
- "두 수가 **서로소**인가?" ([서로소](../relatively-prime/))
- 수가 10^9~10^18로 커서 1부터 하나씩 나눠 볼 수 없을 때
- 여러 수의 gcd, 간격이 일정한 값 찾기 (예: 모든 수를 `m`으로 나눈 나머지가 같게 하는 `m`은 차이들의 gcd의 약수)

## 2. 핵심 아이디어

`a`를 `b`로 나눈 몫을 `q`, 나머지를 `r`이라 하면 `a = b·q + r`입니다.

> **`a`와 `b`의 공약수 집합 = `b`와 `r`의 공약수 집합**

- `a`, `b`의 공약수 `d`는 `r = a − b·q`도 나눕니다. → `b`, `r`의 공약수입니다.
- 반대로 `b`, `r`의 공약수 `d`는 `a = b·q + r`도 나눕니다. → `a`, `b`의 공약수입니다.

공약수가 똑같으니 최대공약수도 같습니다: **`gcd(a, b) = gcd(b, a mod b)`**.

이 식을 반복하면 두 번째 수가 매번 더 작아지다가 `0`이 되고, `gcd(a, 0) = a`입니다. (`a`의 약수 중 가장 큰 것은 `a` 자신이고, `0`은 모든 수의 배수라서 어떤 수로도 나누어떨어집니다.)

**왜 빠른가**: 나머지를 두 번 구하면 큰 수가 **적어도 절반 이하**로 줄어듭니다. 그래서 단계 수는 O(log min(a, b))입니다. 가장 오래 걸리는 입력은 **연속한 피보나치 수**입니다. (아래 표와 테스트 참고)

**최소공배수**: `gcd(a, b) × lcm(a, b) = a × b`이므로 `lcm(a, b) = a / gcd(a, b) × b`입니다. 곱하기 전에 먼저 나누면 중간 값이 작습니다. (파이썬은 정수가 커져도 안전하지만, C++/Java로 옮길 때 오버플로를 피하는 순서입니다.)

### 무엇을 저장하고 어떻게 움직이나

두 수의 공약수는 나머지를 취해도 바뀌지 않습니다. 그래서 큰 수를 작은 수로 나눈 나머지로 대체하고, 나머지가 0이 될 때까지 반복합니다. 약수를 일일이 찾지 않고 gcd라는 요약 정보를 직접 계산합니다.

### 왜 이 방법이 맞는가

a=q*b+r에서 a와 b를 함께 나누는 수는 r도 나누고, b와 r을 함께 나누는 수는 a도 나눕니다. 따라서 `gcd(a,b)=gcd(b,r)`입니다. 0이 아닌 나머지는 b보다 작아 반복이 종료되고 마지막 양수가 최대공약수입니다.

### 작은 예제로 검산하기

`gcd(48,18)`은 `(18,12)→(12,6)→(6,0)`으로 바뀌어 6입니다. 최소공배수는 `abs(a//gcd(a,b)*b)`로 계산하되 0 입력을 처리합니다. 음수 입력에서 gcd의 부호도 양수로 정규화해야 합니다.

## 3. 손으로 따라가기

`gcd(48, 18)`:

| 단계 | a | b | a ÷ b (몫 … 나머지) | 다음 (a, b) |
|---|---|---|---|---|
| 1 | 48 | 18 | 2 … 12 | (18, 12) |
| 2 | 18 | 12 | 1 … 6 | (12, 6) |
| 3 | 12 | 6 | 2 … 0 | (6, 0) |
| 끝 | 6 | 0 | | **gcd = 6** |

그러므로 `lcm(48, 18) = 48 / 6 × 18 = 144`.

**최악의 경우**: 연속한 피보나치 수는 매 단계 몫이 1이라 가장 천천히 줄어듭니다.

| 입력 | 나머지 연산 횟수 |
|---|---|
| (89, 55) | 9 |
| (90, 55) | 5 |
| (498454011879264, 308061521170129) (약 4.9×10^14 크기의 연속 피보나치 수) | 70 |
| (679891637638612258, 420196140727489673) (10^18 이하에서 가장 큰 연속 피보나치 쌍) | 85 |
| a ≤ 1000인 모든 쌍 중 최대 | 14 (쌍 (987, 610) 하나뿐) |

[테스트](test_solution.py)가 `a ≤ 1000`의 모든 쌍을 직접 세어, 어떤 쌍도 같은 크기의 피보나치 쌍보다 오래 걸리지 않는지 확인합니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def gcd(a, b):
    while b != 0:
        a, b = b, a % b       # (a, b) → (b, a mod b)
    return abs(a)

def lcm(a, b):
    if a == 0 or b == 0:
        return 0
    return abs(a) // gcd(a, b) * abs(b)   # 먼저 나눈 뒤 곱한다
```

- `gcd_recursive`: 같은 식을 재귀로 쓴 것입니다. 깊이가 O(log)라 재귀 한도 걱정은 없습니다.
- `gcd_of_list`: 여러 수의 gcd는 앞에서부터 `gcd(지금까지의 gcd, 다음 수)`로 이어 갑니다. 처음 값은 `0`입니다(`gcd(0, x) = x`).
- `gcd_steps`: 나머지를 몇 번 구했는지 셉니다. (위 표를 만든 함수)
- 직접 실행하면 `A B`를 받아 최대공약수, 최소공배수를 한 줄씩 출력합니다.

실전에서는 `math.gcd(a, b)`, `math.lcm(a, b)`(파이썬 3.9+, 여러 인자도 가능)를 쓰면 됩니다. 이 폴더의 구현은 원리를 이해하기 위한 것입니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(log min(a, b))**, 공간 O(1).
- 1 이상 10^18 이하의 임의의 쌍 10만 개의 gcd를 구하는 데 이 환경에서 약 0.2초가 걸렸습니다(쌍마다 평균 35번 안팎의 나머지 연산). 수의 크기보다 **개수**가 비용을 정합니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- "1부터 `min(a, b)`까지 공약수를 하나씩 확인"하면 O(min(a, b))라서 10^9만 되어도 시간 초과입니다.

## 6. 자주 하는 실수

- **`lcm`을 `a * b // gcd`로 쓰고 오버플로**: 파이썬에서는 문제없지만 다른 언어에서는 `a / gcd * b`로 쓰세요.
- **`gcd(0, 0)`과 `lcm(0, x)`**: `gcd(0, 0) = 0`이라 그대로 나누면 0으로 나누기 오류가 납니다. 입력에 0이 올 수 있다면 `lcm`에서 먼저 막습니다.
- **음수**: 파이썬의 `%`는 나누는 수의 부호를 따라서 결과가 음수일 수 있습니다(`gcd(12, -18)`이 `-6`). 마지막에 `abs`를 씌우세요.
- **여러 수의 gcd 초깃값**: 곱하기처럼 `1`로 시작하면 항상 1이 됩니다. gcd의 항등원은 `0`입니다.
- **gcd로 약분 후 부호**: 분모가 음수가 되지 않게 부호를 분자로 옮깁니다. ([서로소](../relatively-prime/)의 `reduce_fraction`)
