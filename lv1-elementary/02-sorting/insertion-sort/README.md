# Insertion Sort (삽입 정렬)

> **한 줄 요약**: 앞쪽의 이미 정렬된 구간에, 다음 원소를 알맞은 자리에 끼워 넣는 일을 반복하는 정렬. 카드를 한 장씩 받아 손에 든 카드 사이에 꽂는 방식과 같다.

## 1. 언제 쓰나 (문제 신호)

실전에서는 내장 `sorted()` / `list.sort()`를 씁니다. 삽입 정렬의 아이디어가 필요한 경우는 다음과 같습니다.

- **거의 정렬된 입력**이거나 원소가 몇 개 안 되는 경우: 입력이 정렬에 가까울수록 빠릅니다.
- **데이터가 하나씩 들어오며 항상 정렬된 상태를 유지**해야 할 때(온라인 정렬)
- **정렬 과정을 묻는 문제**: "i번째 원소까지 정렬했을 때의 배열"
- 다른 정렬 알고리즘의 **작은 구간 처리**: 파이썬의 내장 정렬(Timsort)도 짧은 구간에는 삽입 정렬 계열(이진 삽입 정렬)을 씁니다.

## 2. 핵심 아이디어

배열을 **정렬된 앞부분** `arr[:i]`와 **아직 보지 않은 뒷부분**으로 나눕니다. `arr[i]`를 하나 꺼내서, 앞부분에서 자기보다 큰 값들을 한 칸씩 뒤로 밀고 생긴 빈자리에 넣습니다.

- 불변식: 단계 `i`가 끝나면 `arr[:i+1]`은 원래 있던 원소들이 **정렬된 상태**입니다. 뒷부분 원소는 아직 건드리지 않았습니다.
- 값을 꺼내 들고 큰 값들을 **밀기만** 하다가 마지막에 한 번 넣으므로, 매번 교환하는 것보다 쓰기가 적습니다.
- 자기보다 **엄격하게 큰** 값만 밀기 때문에, 같은 값은 지나치지 않습니다. 그래서 **안정 정렬**입니다.

**밀린 횟수의 합 = 역전의 수.** `i`번째 원소가 밀어내는 원소의 수는 "자기보다 앞에 있는데 자기보다 큰 원소"의 수, 즉 그 원소가 이루는 역전의 수입니다. 그래서 전체 이동 횟수는 [버블 정렬](../bubble-sort/)의 교환 횟수와 같은 **역전의 수**입니다. 시간이 O(n + 역전 수)인 이유입니다.

## 3. 손으로 따라가기

`[5, 2, 4, 6, 1, 3]`을 정렬합니다. `|` 왼쪽이 정렬된 앞부분입니다.

| 단계 i | 꺼낸 값 | 밀려난 원소 수 | 단계가 끝난 배열 |
|---|---|---|---|
| 시작 | - | - | `[5 \| 2, 4, 6, 1, 3]` |
| 1 | `2` | 1 (5) | `[2, 5 \| 4, 6, 1, 3]` |
| 2 | `4` | 1 (5) | `[2, 4, 5 \| 6, 1, 3]` |
| 3 | `6` | 0 (6이 가장 크다) | `[2, 4, 5, 6 \| 1, 3]` |
| 4 | `1` | 4 (2, 4, 5, 6) | `[1, 2, 4, 5, 6 \| 3]` |
| 5 | `3` | 3 (4, 5, 6) | `[1, 2, 3, 4, 5, 6]` |

밀린 횟수의 합은 1+1+0+4+3 = **9**로, 이 배열의 역전 수와 같습니다. 3단계처럼 이미 제자리인 원소는 비교 한 번으로 끝납니다. 이것이 정렬된 입력에서 빠른 이유입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):
        value = arr[i]                           # 끼워 넣을 값을 꺼내 든다
        j = i - 1
        while j >= 0 and arr[j] > value:         # 엄격하게 큰 값만 한 칸씩 민다
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = value                       # 빈자리에 넣는다
```

- 입력 리스트를 **제자리에서** 정렬하고 반환값은 없습니다.
- 직접 실행하면 `N`과 N개의 정수(한 줄에 하나)를 입력받아 정렬한 결과를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 최악은 역순 입력으로, 모든 원소가 앞의 전부를 밀어서 n(n−1)/2번 이동하므로 O(n²)입니다. 이미 정렬되어 있으면 이동 없이 비교만 n−1번이라 O(n)입니다. 일반적으로 O(n + 역전 수)입니다.
- **공간**: O(1)입니다. (제자리)
- **안정 정렬**입니다.
- N ≤ 10^3 정도까지가 현실적이고, N이 크면 [병합 정렬](../merge-sort/)이나 내장 정렬이 필요합니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **`>=`로 밀기**: 같은 값까지 지나쳐 버려서 안정성이 깨집니다.
- **`j >= 0` 조건 누락/오류**: 꺼낸 값이 지금까지 중 가장 작을 때 맨 앞까지 밀어야 하는데, 조건이 `j > 0`이면 `arr[0]`을 건너뛰어 틀립니다. 인덱스가 음수가 되어 `arr[-1]`을 잘못 읽는 실수도 흔합니다.
- **꺼내 들지 않고 매번 교환하기**: 답은 맞지만 대입이 3배 많아집니다.

## 7. 변형과 응용

- **이진 삽입 정렬**: 들어갈 위치를 [이분 탐색](../../03-binary-search/binary-search/)으로 찾으면 비교는 O(log n)번으로 줄지만, 칸을 미는 이동은 여전히 O(n)이라 전체는 O(n²)입니다. 비교가 비싼 경우에만 도움이 됩니다.
- **연결 리스트 정렬**: 연결 리스트에서는 밀 필요 없이 끼워 넣기만 하면 되는 형태로 삽입 정렬을 구현합니다.
- 정렬 알고리즘 사이의 비교는 [정렬 그룹 개요](../README.md)를 보세요.
