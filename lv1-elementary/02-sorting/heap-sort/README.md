# Heap Sort (힙 정렬)

> **한 줄 요약**: 배열을 최대 힙으로 만든 뒤, 가장 큰 값(루트)을 맨 뒤로 보내고 힙을 정리하는 일을 반복하는 정렬. 최악에도 O(n log n)이고 추가 메모리가 필요 없다.

## 1. 언제 쓰나 (문제 신호)

실전에서는 내장 `sorted()`를 씁니다. 힙 정렬의 아이디어가 필요한 경우는 다음과 같습니다.

- **최악의 경우에도 O(n log n)** 이어야 하면서 **추가 메모리가 없어야** 할 때. (병합 정렬은 O(n) 메모리, 퀵 정렬은 최악 O(n²))
- **힙 자료구조의 동작을 이해**하고 싶을 때. 힙 정렬은 힙의 두 핵심 연산(내려 보내기, 힙 만들기)을 그대로 보여 줍니다.
- 정렬 전체가 아니라 **가장 큰(작은) 몇 개만** 필요할 때: 힙에서 k번만 꺼내면 O(n + k log n)입니다. (`heapq.nlargest`)

실전 속도는 퀵 정렬이나 내장 정렬보다 느린 경우가 많습니다. 멀리 떨어진 칸을 오가서 캐시를 잘 쓰지 못하기 때문입니다.

## 2. 핵심 아이디어

**배열을 완전 이진 트리로 봅니다.** 0번부터 시작하는 배열에서 `i`번 원소의 부모는 `(i-1)//2`, 자식은 `2*i+1`과 `2*i+2`입니다. **최대 힙**은 모든 부모가 자식보다 크거나 같은 트리이고, 루트(`arr[0]`)가 항상 최댓값입니다.

```
        6                    인덱스:   0  1  2  3  4  5
      /   \                  값:      [6, 5, 4, 2, 1, 3]
     5     4                 (i번의 자식 = 2i+1, 2i+2)
    / \   /
   2   1 3
```

1. **힙 만들기**: 배열을 최대 힙으로 바꿉니다. 마지막 부모부터 루트까지 거꾸로 올라가며, 각 원소를 **아래로 내려 보내서**(`_sift_down`) 부모 ≥ 자식을 회복합니다.
2. **하나씩 꺼내기**: 루트(최댓값)를 힙의 **맨 뒤 원소와 바꿔** 제자리를 찾아 주고, 힙의 크기를 하나 줄입니다. 새 루트를 내려 보내 힙을 다시 정리합니다. 이를 반복하면 큰 값부터 뒤에서부터 채워져 오름차순이 됩니다.

**내려 보내기(sift down)**: 원소를 두 자식 중 더 큰 쪽과 비교해, 자식이 더 크면 바꾸고 그 자리에서 이어서 내려 보냅니다. 부모가 자식보다 크거나 자식이 없으면 멈춥니다. 한 번에 트리의 높이(log n)만큼만 내려갑니다.

**힙 만들기가 O(n)인 이유.** 힙 만들기는 n/2번 내려 보내지만 각각이 log n은 아닙니다. 높이가 h인 노드는 대략 n/2^(h+1)개이고, 이 노드는 최대 h칸만 내려가므로 비용의 합은 Σ h·n/2^(h+1) = O(n)입니다. 대부분의 노드가 리프 근처라서 거의 안 움직이기 때문입니다.

### 무엇을 저장하고 어떻게 움직이나

최대 힙에서 루트는 전체 최댓값입니다. 루트를 배열의 마지막 미정렬 칸과 교환하고 힙 크기를 하나 줄인 뒤, 새 루트가 부모≥자식 조건을 만족하도록 아래로 내립니다. 정렬된 접미 구간은 힙에서 제외합니다.

### 왜 이 방법이 맞는가

현재 힙의 최댓값을 뒤에 확정하는 과정을 반복하므로 뒤쪽부터 정렬됩니다. 아래로 내릴 때 두 자식 중 큰 쪽과 교환해야 부모≥양쪽 자식이 됩니다. 아래에서부터 힙을 만드는 비용은 높이가 큰 노드가 적어 O(n)입니다.

### 작은 예제로 검산하기

`[4,1,3]`이 최대 힙이면 루트 4를 뒤로 보내 `[3,1,4]`로 만들고 앞 두 칸만 힙으로 봅니다. 다음에 3을 확정하면 `[1,3,4]`입니다. 자식 인덱스는 0 기반에서 `2*i+1`, `2*i+2`입니다.

## 3. 손으로 따라가기

`[5, 2, 4, 6, 1, 3]`을 정렬합니다.

**1단계 — 힙 만들기** (마지막 부모 `i = 2`부터 `0`까지)

| 내려 보내는 원소 | 하는 일 | 배열 |
|---|---|---|
| `i=2` (값 4) | 자식 `3`(인덱스 5)보다 크므로 그대로 | `[5, 2, 4, 6, 1, 3]` |
| `i=1` (값 2) | 자식 `6`, `1` 중 큰 `6`과 교환 | `[5, 6, 4, 2, 1, 3]` |
| `i=0` (값 5) | 자식 `6`, `4` 중 큰 `6`과 교환 (이어서 자식 `2`, `1`보다 크므로 멈춤) | `[6, 5, 4, 2, 1, 3]` |

**2단계 — 하나씩 꺼내기** (`|` 오른쪽은 확정된 값)

| 단계 | 하는 일 | 배열 |
|---|---|---|
| 1 | 루트 `6`을 맨 뒤와 교환 → 힙 `[3, 5, 4, 2, 1]` 정리 | `[5, 3, 4, 2, 1 \| 6]` |
| 2 | 루트 `5`를 뒤로 → 힙 `[1, 3, 4, 2]` 정리 | `[4, 3, 1, 2 \| 5, 6]` |
| 3 | 루트 `4`를 뒤로 → 힙 `[2, 3, 1]` 정리 | `[3, 2, 1 \| 4, 5, 6]` |
| 4 | 루트 `3`을 뒤로 → 힙 `[1, 2]` 정리 | `[2, 1 \| 3, 4, 5, 6]` |
| 5 | 루트 `2`를 뒤로 | `[1 \| 2, 3, 4, 5, 6]` |

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def _sift_down(arr, i, size):
    while True:
        child = 2 * i + 1
        if child >= size:                              # 자식이 없으면 끝
            return
        if child + 1 < size and arr[child + 1] > arr[child]:
            child += 1                                 # 두 자식 중 더 큰 쪽
        if arr[i] >= arr[child]:                       # 부모가 더 크면 힙 성질 만족
            return
        arr[i], arr[child] = arr[child], arr[i]
        i = child

def heap_sort(arr):
    n = len(arr)
    for i in range(n // 2 - 1, -1, -1):                # 1단계: 힙 만들기 O(n)
        _sift_down(arr, i, n)
    for end in range(n - 1, 0, -1):                    # 2단계: 루트를 뒤로 보내기
        arr[0], arr[end] = arr[end], arr[0]
        _sift_down(arr, 0, end)                        # 힙 크기는 end 로 줄어든다
```

- 입력 리스트를 **제자리에서** 정렬하고 반환값은 없습니다.
- 재귀 대신 반복문으로 내려 보내서 호출 비용과 재귀 깊이 걱정이 없습니다.
- 직접 실행하면 `N`과 N개의 정수(한 줄에 하나)를 입력받아 정렬한 결과를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 힙 만들기 O(n) + 꺼내기 n−1번 × 내려 보내기 O(log n) = **O(n log n)** 입니다. 입력이 어떻게 생겼든 최선·평균·최악이 같습니다.
- **공간**: O(1)입니다. (제자리, 반복문)
- **안정 정렬이 아닙니다.** 루트와 맨 뒤 원소를 교환하기 때문입니다.
- 파이썬에서는 내장 `sorted()`가 훨씬 빠릅니다. N = 10^5 정도는 직접 구현해도 통과하지만 여유는 크지 않습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **자식 인덱스를 잘못 계산하기**: 0번부터 시작하는 배열에서는 자식이 `2*i+1`, `2*i+2`입니다. (1번부터 시작하는 배열이면 `2*i`, `2*i+1`) 이 저장소의 이전 구현은 0번 시작 배열에 `2*i`, `2*i+1`을 써서 `[1, 2, 3, 4, 5, 6, 7]`을 `[1, 2, 3, 4, 5, 7, 6]`으로 정렬하는 버그가 있었습니다.
- **최소 힙과 최대 힙 혼동**: 오름차순으로 정렬하려면 **최대 힙**을 만들어 큰 값을 뒤로 보냅니다. 이전 구현의 주석은 "min heap"이라고 되어 있었지만 실제로는 최대 힙이었습니다.
- **힙 크기를 줄이지 않기**: 꺼낸 값이 힙 안에 남아 다시 올라오지 않도록 `_sift_down`에 줄어든 크기(`end`)를 넘겨야 합니다.
- **힙 만들기를 위에서 아래로 하기**: 마지막 부모에서 **루트 방향으로** 거꾸로 내려 보내야 합니다. 루트부터 시작하면 아래가 아직 힙이 아니라서 틀립니다.

## 7. 변형과 응용

- **`heapq`로 정렬하기**: `heapq.heapify(arr)` 후 `heapq.heappop`을 n번 하면 오름차순으로 나옵니다. 파이썬의 `heapq`는 최소 힙이라 직접 만든 힙 정렬과 방향이 반대입니다. 추가 메모리는 O(n)이 필요합니다.
- **상위 k개**: `heapq.nlargest(k, arr)`, `heapq.nsmallest(k, arr)`
- **우선순위 큐**: 힙의 진짜 쓰임새입니다. [다익스트라](../../../lv2-intermediate/01-shortest-path/dijkstra/)처럼 "가장 작은 것을 반복해서 꺼내는" 문제의 핵심 도구입니다.
- 정렬 알고리즘 사이의 비교는 [정렬 그룹 개요](../README.md)를 보세요.
