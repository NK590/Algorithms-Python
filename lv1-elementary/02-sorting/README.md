# 정렬 (Sorting)

원소를 정해진 순서로 늘어놓는 알고리즘들입니다. 실전에서는 파이썬 내장 `sorted()` / `list.sort()`를 쓰면 되지만, 정렬 알고리즘은 시간 복잡도 분석, 분할 정복, 힙 같은 핵심 개념을 익히기에 좋은 재료이고, 각 알고리즘의 아이디어는 정렬이 아닌 문제(역전 수, k번째 수, 우선순위 큐)에도 그대로 쓰입니다.

## 한눈에 비교

| 알고리즘 | 최선 | 평균 | 최악 | 추가 메모리 | 안정 정렬 | 제자리 | 특징 |
|---|---|---|---|---|---|---|---|
| [버블 정렬](bubble-sort/) | O(n)† | O(n²) | O(n²) | O(1) | O | O | 가장 단순하다. 교환 횟수 = 역전 수 |
| [선택 정렬](selection-sort/) | O(n²) | O(n²) | O(n²) | O(1) | X | O | 비교는 많지만 교환이 최대 n−1번 |
| [삽입 정렬](insertion-sort/) | O(n) | O(n²) | O(n²) | O(1) | O | O | 거의 정렬된 입력과 작은 n에 빠르다. 시간 O(n + 역전 수) |
| [병합 정렬](merge-sort/) | O(n log n) | O(n log n) | O(n log n) | O(n) | O | X | 입력과 무관하게 일정하다. 역전 수 세기에 쓴다 |
| [퀵 정렬](quick-sort/) | O(n log n) | O(n log n) | O(n²) | O(log n)‡ | X | O‡ | 평균적으로 가장 빠르다. k번째 수(퀵 셀렉트)로 응용 |
| [힙 정렬](heap-sort/) | O(n log n) | O(n log n) | O(n log n) | O(1) | X | O | 최악에도 O(n log n)이면서 제자리. 캐시 효율은 낮다 |

† 한 바퀴를 도는 동안 교환이 없으면 멈추는 조기 종료를 넣었을 때의 값입니다.
‡ 이 저장소의 `quick_sort_inplace` 기준입니다. 새 리스트를 만드는 `quick_sort`는 O(n) 추가 메모리를 씁니다.

### 실제로 얼마나 걸릴까

이 저장소의 구현을 CPython 3.13에서 무작위 정수로 한 번 재 본 값입니다. 환경에 따라 달라지므로 대략적인 감각으로만 보세요.

| 입력 크기 | 병합 / 퀵 / 힙 (직접 구현) | 내장 `sorted()` | 버블 / 선택 / 삽입 |
|---|---|---|---|
| n = 1,000 | - | - | 각각 0.02~0.04초 |
| n = 3,000 | - | - | 각각 0.2~0.4초 |
| n = 100,000 | 0.25~0.35초 | 약 0.02초 | 불가능 |
| n = 500,000 | 1.5~2.5초 | 약 0.12초 | 불가능 |

O(n²) 정렬은 n이 3배 커지면 시간이 약 9배가 되므로 n = 10^4부터는 몇 초가 걸립니다. 직접 구현한 O(n log n) 정렬도 내장 정렬보다 10~20배 느립니다.

## 무엇을 고를까

1. **그냥 정렬이 필요하다 → 내장 `sorted()` / `list.sort()`.** 파이썬의 정렬(Timsort)은 O(n log n)이고 안정 정렬이며, 거의 정렬된 입력에서는 더 빠릅니다. 여러 기준은 `key=`로 줍니다.
2. **정렬이 아니라 다른 값이 필요하다.**
   - 뒤집힌 쌍의 수, 버블 정렬의 교환 횟수 → [병합 정렬](merge-sort/)의 `count_inversions`
   - k번째로 작은 값 → [퀵 셀렉트](quick-sort/)
   - 가장 큰(작은) 몇 개 → 힙(`heapq`), [힙 정렬](heap-sort/)의 아이디어
3. **같은 키의 원래 순서를 지켜야 한다 → 안정 정렬.** 버블·삽입·병합, 내장 `sorted()`가 해당합니다. 선택·퀵·힙은 안정적이지 않습니다.
4. **값의 범위가 작은 정수라면** 비교 없이 개수를 세는 계수 정렬이 O(n + 범위)로 더 빠릅니다. (이 저장소에는 아직 없습니다)
5. **직접 구현해야 하고 n이 작다 → 삽입 정렬.** 구현이 짧고 거의 정렬된 입력에서 빠릅니다.

## 세 알고리즘이 같은 숫자를 센다

`[5, 2, 4, 6, 1, 3]`처럼 `i < j`이면서 `arr[i] > arr[j]`인 쌍(**역전**)은 9개입니다. 그리고

- [버블 정렬](bubble-sort/)의 **교환 횟수**가 9
- [삽입 정렬](insertion-sort/)의 **원소를 민 횟수**가 9
- [병합 정렬](merge-sort/)이 합치면서 센 **역전의 수**가 9

입니다. 이웃한 두 원소를 바꾸는 한 번의 동작이 정확히 역전 하나를 없애기 때문입니다. 그래서 N이 큰 "버블 소트의 교환 횟수" 문제는 직접 정렬하는 대신 병합 정렬로 역전 수를 세어 푸는 것이 표준입니다.
