# Merge Sort (병합 정렬)

> **한 줄 요약**: 배열을 반으로 나눠 각각 정렬한 뒤, 정렬된 두 배열을 하나로 합치는 정렬. 입력이 어떻게 생겼든 **항상 O(n log n)** 이고 안정 정렬이다.

## 1. 언제 쓰나 (문제 신호)

내장 `sorted()`가 이미 O(n log n) 안정 정렬(Timsort)이므로, 병합 정렬 자체를 쓰는 경우는 다음과 같습니다.

- **역전의 수를 세는 문제**: "버블 정렬을 하면 몇 번 교환하는가", "i < j 이면서 a[i] > a[j] 인 쌍의 수". 내장 정렬로는 셀 수 없고, 병합 정렬의 합치는 단계에서 셉니다.
- **정렬된 두 리스트를 합치는** 연산이 필요할 때 (`merge`). 파이썬에는 `heapq.merge`가 있습니다.
- **연결 리스트**를 O(n log n)으로 정렬해야 할 때. 임의 접근이 없어도 앞에서부터 합칠 수 있습니다.
- **분할 정복**을 배우는 가장 깔끔한 예제로서

## 2. 핵심 아이디어

문제를 반으로 나눠 각각 푼 뒤 합칩니다. ([분할 정복](../../../lv2-intermediate/05-divide-and-conquer/divide-and-conquer/))

1. **분할**: 길이가 1 이하가 될 때까지 반으로 나눕니다. 길이 1 이하는 이미 정렬된 상태입니다.
2. **정복**: 나눈 두 부분을 각각 재귀로 정렬합니다.
3. **합치기**: 정렬된 두 리스트의 **맨 앞 원소끼리 비교**해서 작은 쪽을 결과에 옮기는 일을 반복합니다. 한쪽이 바닥나면 남은 쪽을 통째로 붙입니다. 각 원소를 한 번씩만 보므로 O(n)입니다.

**안정 정렬이 되려면** 합칠 때 두 값이 같으면 **왼쪽을 먼저** 꺼내야 합니다. (`left[i] <= right[j]`) 왼쪽 부분은 원래 배열에서 앞에 있던 원소들이기 때문입니다. 이 저장소의 이전 구현은 `<`로 비교해서 같은 값에서 오른쪽을 먼저 꺼냈고, 그래서 안정 정렬이 아니었습니다.

**역전 수 세기.** 합치는 도중에 **오른쪽 원소가 먼저** 나온다는 것은, 그 원소가 왼쪽에 남아 있는 **모든** 원소보다 작다는 뜻입니다. 왼쪽 원소들은 원래 배열에서 오른쪽 원소보다 앞에 있었으니, 남은 왼쪽 원소 수만큼의 역전 쌍이 한꺼번에 생깁니다. 왼쪽 안의 역전과 오른쪽 안의 역전은 재귀가 각각 세 줍니다. 이 세 가지를 더하면 전체 역전 수이고, 합치는 비용 안에서 셀 수 있어서 O(n log n)입니다.

### 무엇을 저장하고 어떻게 움직이나

큰 정렬 문제를 두 작은 정렬 문제로 나눕니다. 두 절반이 정렬된 뒤에는 각 절반의 맨 앞 미처리 원소만 비교해 더 작은 것을 결과에 붙이면 됩니다. 분할은 구조를 만들고 실제 정렬은 합치는 단계에서 일어납니다.

### 왜 이 방법이 맞는가

두 정렬된 목록의 최소 원소는 반드시 두 맨 앞 중 하나입니다. 작은 쪽을 꺼내도 남은 두 목록은 정렬돼 있으므로 같은 논리를 반복할 수 있습니다. 재귀 깊이는 O(log n), 각 깊이의 합치는 원소 수 합은 O(n)입니다.

### 작은 예제로 검산하기

`[1,4]`와 `[2,3]`을 합칠 때 1, 2, 3, 남은 4 순으로 꺼냅니다. 역전 수 계산에서 오른쪽의 2가 왼쪽 4보다 작으면 남은 왼쪽 원소 수만큼 역전이 생깁니다. 같은 키는 왼쪽을 먼저 선택해야 안정적입니다.

## 3. 손으로 따라가기

`[5, 2, 4, 6, 1, 3]`을 정렬합니다. 들여쓰기가 재귀 깊이입니다.

```
split [5, 2, 4, 6, 1, 3] -> [5, 2, 4] | [6, 1, 3]
  split [5, 2, 4] -> [5] | [2, 4]
    split [2, 4] -> [2] | [4]
    merge [2] + [4] -> [2, 4]
  merge [5] + [2, 4] -> [2, 4, 5]
  split [6, 1, 3] -> [6] | [1, 3]
    split [1, 3] -> [1] | [3]
    merge [1] + [3] -> [1, 3]
  merge [6] + [1, 3] -> [1, 3, 6]
merge [2, 4, 5] + [1, 3, 6] -> [1, 2, 3, 4, 5, 6]
```

마지막 합치기 `[2, 4, 5] + [1, 3, 6]`을 한 단계씩 보면 다음과 같습니다. (`i`, `j`는 각 리스트에서 다음에 볼 위치)

| 비교 | 꺼내는 값 | 결과 |
|---|---|---|
| 2 vs 1 | 오른쪽 `1` | `[1]` |
| 2 vs 3 | 왼쪽 `2` | `[1, 2]` |
| 4 vs 3 | 오른쪽 `3` | `[1, 2, 3]` |
| 4 vs 6 | 왼쪽 `4` | `[1, 2, 3, 4]` |
| 5 vs 6 | 왼쪽 `5` | `[1, 2, 3, 4, 5]` |
| (왼쪽이 바닥남) | 오른쪽 남은 `6`을 붙임 | `[1, 2, 3, 4, 5, 6]` |

**역전 수는 이렇게 모입니다.** 합치기마다 "오른쪽이 먼저 나올 때 왼쪽에 남은 개수"를 더합니다.

| 합치기 | 더해지는 역전 | 누적 |
|---|---|---|
| `[2]` + `[4]` | 0 | 0 |
| `[5]` + `[2, 4]` | 오른쪽 `2`가 나올 때 왼쪽에 `5` 1개, `4`가 나올 때 또 1개 → 2 | 2 |
| `[1]` + `[3]` | 0 | 2 |
| `[6]` + `[1, 3]` | `1`, `3`이 나올 때 각각 왼쪽에 `6` 1개 → 2 | 4 |
| `[2, 4, 5]` + `[1, 3, 6]` | `1`이 나올 때 왼쪽에 3개, `3`이 나올 때 왼쪽에 2개(`4`, `5`) → 5 | **9** |

총 9로, [버블 정렬](../bubble-sort/)의 교환 횟수와 같습니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def merge(left, right):
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:                  # 같을 때 왼쪽을 먼저 → 안정 정렬
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    merged.extend(left[i:])                      # 남은 쪽은 이미 정렬되어 있으니 통째로 붙인다
    merged.extend(right[j:])
    return merged

def merge_sort(arr):
    if len(arr) <= 1:
        return list(arr)
    mid = len(arr) // 2
    return merge(merge_sort(arr[:mid]), merge_sort(arr[mid:]))
```

- `merge_sort`는 **입력을 바꾸지 않고 정렬된 새 리스트**를 반환합니다.
- `count_inversions(arr)`는 합치는 단계에 `count += len(left) - i` 한 줄을 더한 같은 구조입니다.
- 직접 실행하면 `N`과 N개의 정수(한 줄에 하나)를 입력받아 정렬한 결과를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 배열을 절반씩 나누므로 깊이가 log n이고, 각 깊이에서 합치는 비용의 합이 n입니다. 점화식으로는 T(n) = 2T(n/2) + O(n) = **O(n log n)** 이며, 입력 모양과 상관없이 최악·평균·최선이 같습니다.
- **공간**: 합친 결과를 담을 리스트와 슬라이싱 복사본이 필요해서 **O(n)** 입니다. 제자리 정렬이 아닙니다.
- **안정 정렬**입니다.
- 재귀 깊이는 log n이라 깊이 제한 걱정은 없습니다. N = 10^5 정도는 CPython에서도 무난하고, 5×10^5 근처는 PyPy3가 안전합니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **`<`로 비교하기**: 같은 값에서 오른쪽을 먼저 꺼내 **안정성이 깨집니다.** `<=`여야 합니다.
- **남은 원소 붙이기 누락**: 한쪽이 바닥난 뒤 다른 쪽의 나머지를 붙이지 않으면 원소가 사라집니다.
- **역전 수에서 `len(left) - i`를 `len(left)`로 쓰기**: 왼쪽에서 이미 꺼낸 원소는 오른쪽 원소와 역전이 아닙니다. 남은 개수만 더해야 합니다.
- **같은 값은 역전이 아닙니다**: `a[i] > a[j]` (엄격하게 큼)인 쌍만 셉니다. 합칠 때 같은 값에서 왼쪽을 먼저 꺼내므로 자연스럽게 맞습니다.

## 7. 변형과 응용

- **역전 수 / 교환 횟수 세기**: 위의 `count_inversions`. N이 수십만인 문제에서 버블 정렬의 교환 횟수를 구하는 표준 풀이입니다.
- **상향식(bottom-up) 병합 정렬**: 길이 1짜리 구간을 2개씩, 4개씩 … 합쳐 올라가는 반복문 형태로, 재귀가 필요 없습니다.
- **K개 리스트 합치기**: `heapq.merge`처럼 힙을 쓰면 K개의 정렬된 리스트를 O(N log K)에 합칩니다.
- 합치기 단계에 다른 계산을 끼워 넣는 기법은 분할 정복의 대표적인 응용입니다.
