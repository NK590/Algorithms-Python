# Quick Sort (퀵 정렬)

> **한 줄 요약**: 기준값(pivot)을 하나 고르고, 그보다 작은 값과 큰 값으로 나눈 뒤, 양쪽을 같은 방식으로 정렬한다. 평균적으로 가장 빠른 비교 정렬로 알려져 있다.

## 1. 언제 쓰나 (문제 신호)

실전에서는 내장 `sorted()` / `list.sort()`를 씁니다. 퀵 정렬의 아이디어가 필요한 경우는 다음과 같습니다.

- **k번째로 작은 값 하나만** 필요할 때: 정렬하지 않고 **퀵 셀렉트**로 평균 O(n)에 구합니다. (`quick_select`)
- **기준값을 기준으로 세 부류로 나누는** 문제: 0/1/2만 있는 배열 정렬(네덜란드 국기 문제) 같은 분할 연산
- **정렬 과정을 묻는 문제**: "첫 분할이 끝났을 때의 배열"
- 비교 정렬 중 **추가 메모리가 거의 없고** 평균적으로 빠른 정렬이 필요할 때 (제자리 버전)

## 2. 핵심 아이디어

1. 기준값 `p`를 하나 고릅니다.
2. 배열을 **`p`보다 작은 값 | `p`와 같은 값 | `p`보다 큰 값** 세 구간으로 나눕니다.
3. `p`와 같은 값들은 **이미 제자리**에 있습니다. 작은 쪽과 큰 쪽만 같은 방식으로 다시 정렬합니다.

병합 정렬이 "나누기는 쉽고 합치기가 일"이라면, 퀵 정렬은 "나누기가 일이고 합치기는 공짜"입니다. 나눈 뒤에는 이어 붙이면 이미 정렬되어 있습니다.

**기준값을 무작위로 고르는 이유.** 기준값이 매번 최솟값이나 최댓값이면 한쪽이 비어서 문제 크기가 1밖에 줄지 않고, 전체가 O(n²)이 됩니다. "맨 앞 원소"나 "가운데 원소"처럼 **고정된 위치**를 기준값으로 쓰면, 이미 정렬된 입력 같은 특정 입력에서 이 최악의 경우가 생길 수 있습니다. 무작위로 고르면 어떤 입력이든 **기대 시간이 O(n log n)** 입니다.

**같은 값을 따로 모으는 이유.** 기준값과 같은 값을 작은 쪽(또는 큰 쪽)에 섞어 넣으면, 값이 전부 같은 입력에서 분할이 한쪽으로 쏠려 O(n²)이 됩니다. 같은 값 묶음을 그대로 다시 재귀 호출하면 아예 끝나지 않습니다. 이 저장소의 이전 구현이 바로 그랬습니다. 같은 값 묶음(`pivot_li`)을 다시 정렬하다가 `[5, 5]`에서 `RecursionError`가 났습니다. 같은 값은 세 번째 구간으로 빼 두고 다시 보지 않습니다.

**제자리 분할(네덜란드 국기).** 배열 안에서 네 구간을 유지하며 한 번 훑어서 세 구간으로 나눕니다.

```
 arr[lo:lt]   < p      (확정: 작은 값)
 arr[lt:i]    == p     (확정: 같은 값)
 arr[i:gt+1]  ?        (아직 안 본 구간)
 arr[gt+1:hi+1] > p    (확정: 큰 값)
```

`arr[i]`를 보고 `p`보다 작으면 `lt` 위치와 바꾸고 `lt`, `i`를 늘리고, 크면 `gt` 위치와 바꾸고 `gt`를 줄이고(바꿔 온 값은 아직 안 봤으므로 `i`는 그대로), 같으면 `i`만 늘립니다.

### 무엇을 저장하고 어떻게 움직이나

피벗보다 작은 값·같은 값·큰 값으로 구간을 나눈 뒤 작은 쪽과 큰 쪽을 정렬합니다. 병합 정렬과 달리 결합은 단순하지만 분할의 균형이 성능을 결정합니다. 중복값이 많은 입력은 같은 값들을 한 구간으로 묶는 방식이 유리합니다.

### 왜 이 방법이 맞는가

분할 후 왼쪽의 모든 값이 피벗 이하이고 오른쪽의 모든 값이 피벗 이상이면 각 부분을 정렬해 이어 붙인 결과도 정렬됩니다. 분할이 매번 균형이면 O(n log n)이지만 한 원소만 줄면 O(n²)입니다. 임의 피벗은 평균 성능을 개선합니다.

### 작은 예제로 검산하기

피벗 3으로 `[3,1,3,2,4]`를 나누면 작은 쪽 `[1,2]`, 같은 쪽 `[3,3]`, 큰 쪽 `[4]`입니다. k번째 값이 어느 구간에 있는지만 재귀하면 퀵 셀렉트가 됩니다. 반환 리스트 방식과 제자리 분할의 메모리 비용은 다릅니다.

## 3. 손으로 따라가기

`[5, 2, 4, 6, 1, 3]`에서 **기준값을 4로 정했다고 하고** 한 번 분할합니다. (코드는 무작위로 고르지만, 따라가기 위해 고정했습니다)

| 보는 값 `arr[i]` | 하는 일 | `lt` | `i` | `gt` | 배열 |
|---|---|---|---|---|---|
| 시작 | - | 0 | 0 | 5 | `[5, 2, 4, 6, 1, 3]` |
| `5` (> 4) | `gt` 위치의 값 `3`과 교환, `gt`−1 | 0 | 0 | 4 | `[3, 2, 4, 6, 1, 5]` |
| `3` (< 4) | `lt`와 교환, `lt`+1, `i`+1 | 1 | 1 | 4 | `[3, 2, 4, 6, 1, 5]` |
| `2` (< 4) | `lt`와 교환, `lt`+1, `i`+1 | 2 | 2 | 4 | `[3, 2, 4, 6, 1, 5]` |
| `4` (= 4) | `i`+1 | 2 | 3 | 4 | `[3, 2, 4, 6, 1, 5]` |
| `6` (> 4) | `gt` 위치의 값 `1`과 교환, `gt`−1 | 2 | 3 | 3 | `[3, 2, 4, 1, 6, 5]` |
| `1` (< 4) | `lt`와 교환, `lt`+1, `i`+1 | 3 | 4 | 3 | `[3, 2, 1, 4, 6, 5]` |

`i`가 `gt`를 넘었으므로 끝입니다. 결과는 `[3, 2, 1 | 4 | 6, 5]`이고, 같은 값 구간은 `arr[3:4]`입니다. 이제 `[3, 2, 1]`과 `[6, 5]`만 각각 같은 방식으로 정렬하면 됩니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 세 가지 형태를 제공합니다.

**① 새 리스트를 만드는 버전** — 가장 읽기 쉽습니다.

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return list(arr)
    pivot = arr[random.randrange(len(arr))]      # 무작위 기준값
    smaller = [x for x in arr if x < pivot]
    equal   = [x for x in arr if x == pivot]     # 같은 값은 다시 정렬하지 않는다
    larger  = [x for x in arr if x > pivot]
    return quick_sort(smaller) + equal + quick_sort(larger)
```

**② 제자리 버전** — 위의 네덜란드 국기 분할(`_partition`)을 쓰고, 재귀 대신 직접 만든 스택으로 구간을 처리해 파이썬의 재귀 깊이 제한을 피합니다.

**③ 퀵 셀렉트** — `quick_select(arr, k)`는 같은 분할을 한 뒤 **k번째가 들어 있는 쪽 구간 하나만** 다시 봅니다. 양쪽을 모두 정렬하지 않으므로 평균 O(n)입니다.

직접 실행하면 `N`과 N개의 정수(한 줄에 하나)를 입력받아 제자리 버전으로 정렬한 결과를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 기준값이 매번 구간을 비슷하게 반으로 나누면 깊이가 log n이고 각 깊이의 분할 비용이 n이라 **O(n log n)** 입니다. 무작위 기준값이면 이것이 **평균(기대)** 입니다. 최악은 분할이 계속 한쪽으로 쏠리는 O(n²)이지만, 무작위로 고르면 그런 일은 사실상 일어나지 않습니다.
- **공간**: 제자리 버전은 분할 구간을 쌓는 스택이 기대 O(log n)입니다. 새 리스트를 만드는 버전은 O(n)의 추가 메모리를 씁니다.
- **안정 정렬이 아닙니다.** 분할 중에 멀리 떨어진 원소끼리 교환하기 때문입니다.
- **퀵 셀렉트**는 평균 O(n)입니다. 정렬(O(n log n))보다 빠르지만 최악은 O(n²)입니다.
- 파이썬에서는 내장 `sorted()`가 훨씬 빠르므로, 정렬만 필요하면 직접 구현하지 않습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **같은 값을 한쪽에 섞기**: 위에서 본 것처럼 중복 입력에서 O(n²)이 되거나 `RecursionError`가 납니다.
- **고정 위치를 기준값으로 쓰기**: 이미 정렬된 입력에서 O(n²)이 되고, 재귀 구현이면 깊이가 n이 되어 파이썬의 재귀 한도(기본 1000)를 넘습니다.
- **분할에서 `i`를 잘못 올리기**: 큰 값을 `gt`와 바꿔 온 뒤 `i`를 올리면, 바꿔 온 값을 확인하지 않고 지나쳐서 틀립니다.
- **퀵 셀렉트의 구간 경계**: 찾는 인덱스 `k`와 `lt`, `gt`의 관계(작은 쪽 / 같은 값 / 큰 쪽)를 정확히 나눠야 무한 반복에 빠지지 않습니다.
- **인덱스 기준**: `quick_select`의 `k`는 0부터 셉니다. 문제의 "K번째"가 1부터라면 `k - 1`을 넘기세요.

## 7. 변형과 응용

- **퀵 셀렉트(k번째 수)**: 정렬 없이 평균 O(n)에 구합니다. 중앙값 구하기도 같은 방식입니다.
- **네덜란드 국기 문제**: 값이 0, 1, 2뿐인 배열을 한 번 훑어 정렬하는 문제는 `_partition`의 기준값을 1로 둔 것과 같습니다.
- **중앙값의 중앙값 / introsort**: 최악의 경우를 막기 위한 기준값 선택법이나, 퀵 정렬이 나빠지면 힙 정렬로 바꾸는 방식이 있습니다. (많은 C++ 표준 라이브러리의 `std::sort`가 이 방식(introsort)입니다)
- 정렬 알고리즘 사이의 비교는 [정렬 그룹 개요](../README.md)를 보세요.
