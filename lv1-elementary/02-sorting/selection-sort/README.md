# Selection Sort (선택 정렬)

> **한 줄 요약**: 남은 구간에서 가장 작은 값을 골라 맨 앞과 바꾸는 일을 반복하는 정렬. 비교는 많지만 **교환은 최대 n−1번**뿐이다.

## 1. 언제 쓰나 (문제 신호)

실전에서는 내장 `sorted()` / `list.sort()`를 씁니다. 선택 정렬이 필요한 경우는 다음과 같습니다.

- **정렬 과정을 묻는 문제**: "i번째 단계가 끝났을 때의 배열", "교환이 몇 번 일어나는가"
- **교환(쓰기) 비용이 비교 비용보다 훨씬 큰** 상황. 선택 정렬은 교환이 최대 n−1번이라서 다른 O(n²) 정렬보다 쓰기가 적습니다.
- **가장 작은 k개만** 앞에서부터 순서대로 필요할 때. k번만 반복하면 O(kn)에 얻습니다. (k가 작을 때. 보통은 [힙](../heap-sort/)이 더 좋습니다.)

## 2. 핵심 아이디어

배열을 **정렬된 앞부분**과 **아직 정렬되지 않은 뒷부분**으로 나눕니다. 매번 뒷부분에서 가장 작은 값을 찾아 뒷부분의 맨 앞과 바꾸면, 정렬된 앞부분이 한 칸씩 늘어납니다.

- 불변식: `i`번째 단계가 끝나면 `arr[:i]`는 **전체에서 가장 작은 i개**가 정렬된 상태로 들어 있습니다. 앞부분에 들어간 값은 다시 움직이지 않습니다.
- 비교로 **위치**를 찾고(최솟값의 인덱스를 기억), 교환은 단계마다 한 번만 합니다. 값을 기억하지 말고 **인덱스**를 기억해야 맞바꿀 수 있습니다.

**안정 정렬이 아닙니다.** 맨 앞과 멀리 떨어진 원소를 맞바꾸다 보면 같은 값의 순서가 뒤집힐 수 있습니다. 예를 들어 같은 값 `2` 두 개를 `2#0`, `2#1`로 구분하고 `[2#0, 2#1, 1]`을 정렬하면, `1`을 맨 앞으로 보내려고 `2#0`과 바꾸는 순간 `[1, 2#1, 2#0]`이 되어 두 `2`의 순서가 뒤집힙니다.

### 무엇을 저장하고 어떻게 움직이나

미정렬 구간을 모두 훑어 최솟값의 위치를 찾고, 그 원소를 구간의 첫 위치와 한 번 교환합니다. 매 단계에서 선택 대상과 확정할 위치를 구분합니다. 비교는 많지만 실제 교환은 최대 n-1번입니다.

### 왜 이 방법이 맞는가

i번째 단계가 끝나면 앞 i+1개는 전체에서 가장 작은 i+1개를 정렬한 결과입니다. 남은 구간의 최솟값을 고르면 다음 자리도 맞습니다. 멀리 있는 원소와 교환하므로 값이 같은 원소의 상대 순서는 보장하지 않습니다.

### 작은 예제로 검산하기

키가 같은 두 원소를 `2a,2b`로 구분하면 `[2a,2b,1]`의 첫 교환 결과는 `[1,2b,2a]`입니다. 값만 보면 정렬됐지만 안정성은 깨집니다. 정렬 여부와 안정성을 별도로 확인해야 합니다.

## 3. 손으로 따라가기

`[5, 2, 4, 6, 1, 3]`을 정렬합니다. `|` 왼쪽이 정렬이 끝난 앞부분입니다.

| 단계 i | 뒷부분 `arr[i:]`의 최솟값 | 하는 일 | 단계가 끝난 배열 |
|---|---|---|---|
| 0 | `1` (인덱스 4) | `arr[0]`(5)과 교환 | `[1 \| 2, 4, 6, 5, 3]` |
| 1 | `2` (인덱스 1) | 이미 제자리, 교환 없음 | `[1, 2 \| 4, 6, 5, 3]` |
| 2 | `3` (인덱스 5) | `arr[2]`(4)와 교환 | `[1, 2, 3 \| 6, 5, 4]` |
| 3 | `4` (인덱스 5) | `arr[3]`(6)과 교환 | `[1, 2, 3, 4 \| 5, 6]` |
| 4 | `5` (인덱스 4) | 이미 제자리, 교환 없음 | `[1, 2, 3, 4, 5, 6]` |

원소가 6개라서 5단계로 끝나고, 교환은 3번뿐입니다. 비교는 입력과 상관없이 5+4+3+2+1 = 15번입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        smallest = i                              # arr[i:] 의 최솟값 위치
        for j in range(i + 1, n):
            if arr[j] < arr[smallest]:
                smallest = j
        if smallest != i:                         # 이미 제자리면 교환을 건너뛴다
            arr[i], arr[smallest] = arr[smallest], arr[i]
```

- 입력 리스트를 **제자리에서** 정렬하고 반환값은 없습니다.
- 직접 실행하면 `N`과 N개의 정수(한 줄에 하나)를 입력받아 정렬한 결과를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 비교는 항상 n(n−1)/2번입니다. 입력이 이미 정렬되어 있어도 줄지 않으므로 최선·평균·최악이 모두 O(n²)입니다. 교환은 최대 n−1번입니다.
- **공간**: O(1)입니다. (제자리)
- **안정 정렬이 아닙니다.**
- 입력 크기 감각은 [버블 정렬](../bubble-sort/)과 같습니다. N ≤ 10^3 정도까지가 현실적입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **최솟값을 저장하고 위치를 잊기**: `smallest`를 값으로 저장하면 어디와 바꿔야 하는지 모릅니다. 인덱스를 저장하세요.
- **안정성을 기대하기**: 값만 정렬할 때는 상관없지만, `(나이, 이름)`처럼 **다른 정보를 가진 원소를 한 키로 정렬**할 때는 같은 키의 원래 순서가 바뀝니다. 이런 문제에는 [삽입 정렬](../insertion-sort/), [병합 정렬](../merge-sort/), 내장 `sorted()`를 쓰세요.
- **바깥 반복을 `range(n)`으로 쓰기**: 마지막 원소는 자동으로 제자리에 오므로 `n - 1`번이면 충분합니다. (`range(n)`도 답은 맞습니다.)

## 7. 변형과 응용

- **뒤에서부터 최댓값 선택**: 가장 큰 값을 골라 맨 뒤로 보내도 대칭입니다.
- **부분 정렬**: 바깥 반복을 k번만 돌리면 가장 작은 k개가 앞에 정렬되어 나옵니다.
- 같은 아이디어를 힙으로 빠르게 만든 것이 [힙 정렬](../heap-sort/)입니다. "남은 것 중 최솟값을 고른다"를 O(n) 대신 O(log n)에 하는 자료구조를 씁니다.
