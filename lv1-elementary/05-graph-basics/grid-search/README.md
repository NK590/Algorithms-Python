# Grid Search (격자 탐색)

> **한 줄 요약**: 격자의 칸을 정점, 상하좌우 이웃을 간선으로 보고 DFS/BFS를 한다. 덩어리 세기·채우기는 DFS, 최단 거리는 BFS.

## 1. 언제 쓰나 (문제 신호)

- "N × M 지도/미로", "상하좌우로 이동", "인접한 칸이 이어진 덩어리의 개수/크기", "최소 이동 횟수"
- 배추 밭, 섬의 개수, 단지 번호 붙이기, 영역 채우기(flood fill) → **DFS 또는 BFS로 덩어리 찾기**
- 미로 탈출, 토마토, 불 번짐 → **BFS로 최단 거리**

## 2. 핵심 아이디어

격자를 명시적인 그래프로 만들 필요가 없습니다. 칸 `(r, c)`의 이웃은 방향 배열로 즉석에서 계산합니다. ([2차원 배열](../../../lv0-basics/01-data-structures/two-dimensional-array/))

```python
DIRECTIONS = [(-1, 0), (0, 1), (1, 0), (0, -1)]
```

- **덩어리 세기**: 모든 칸을 훑다가 **아직 방문하지 않은 지나갈 수 있는 칸**을 만나면 DFS(또는 BFS)로 이어진 칸을 모두 방문 처리하고 개수를 1 늘립니다.
- **최단 거리**: 시작 칸에서 BFS를 하며 `dist[r][c]`를 채웁니다. 이동 비용이 모두 같으므로 BFS가 맞습니다.
- **방문 표시**: 별도의 `visited` 배열을 쓰거나, 방문한 칸의 값을 바꿔서(예: 1 → 0, flood fill) 표시합니다. 원본을 보존해야 하면 배열을 따로 쓰세요.
- 이동 전에 **범위 검사**(`0 <= nr < 행 and 0 <= nc < 열`)를 합니다.

### 무엇을 저장하고 어떻게 움직이나

칸을 정점으로 보고 허용되는 이웃 이동을 간선으로 봅니다. 상하좌우인지 대각선도 가능한지, 벽을 통과하는지, 이동마다 비용이 같은지부터 명확히 합니다. 위치만으로 다음 행동이 정해지지 않으면 열쇠·방향 같은 정보도 상태에 포함합니다.

### 왜 이 방법이 맞는가

좌표의 범위와 이동 조건을 검사한 뒤 방문 처리하면 격자의 유효한 경로만 탐색됩니다. 방문 배열은 실제 상태를 구분해야 합니다. 같은 칸도 열쇠가 있을 때와 없을 때 가능한 행동이 다르면 하나의 방문 표시로 합칠 수 없습니다.

### 작은 예제로 검산하기

2×3 격자에서 4방향 이웃만 허용하면 왼쪽 위의 이웃은 아래와 오른쪽 두 칸입니다. 대각선을 추가하면 연결 요소와 최단 거리가 달라집니다. 행·열의 상한을 반대로 쓰는 오류는 직사각형 예제로 확인하세요.

## 3. 손으로 따라가기

**덩어리 세기** (1이 지나갈 수 있는 칸):

```
1 1 0 0 1
0 1 0 1 1
1 0 0 0 0
1 1 0 1 0
```

위에서 아래, 왼쪽에서 오른쪽으로 훑습니다. `(0,0)`에서 시작한 DFS가 `(0,0) (0,1) (1,1)`을 방문 → 크기 3. `(0,4)`에서 `(0,4) (1,4) (1,3)` → 크기 3. `(2,0)`에서 `(2,0) (3,0) (3,1)` → 크기 3. `(3,3)`은 혼자 → 크기 1. 덩어리는 모두 **4개**, 크기는 `[1, 3, 3, 3]`입니다.

**미로 최단 거리** (`1` 지나감, `0` 벽, 시작 `(0,0)`):

```
1 0 1 1        0  -  4  5
1 1 1 0   →    1  2  3  -
0 0 1 1        -  -  4  5
```

오른쪽이 BFS로 채운 `dist`입니다. 도착점 `(2,3)`까지 **5번** 이동합니다. 벽이거나 도달할 수 없는 칸은 `-1`(`-`)입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def distances_from(grid, start):
    rows, cols = len(grid), len(grid[0])
    dist = [[-1] * cols for _ in range(rows)]
    dist[start[0]][start[1]] = 0
    queue = deque([start])
    while queue:
        r, c = queue.popleft()
        for nr, nc in _neighbors(r, c, rows, cols):         # 범위 안의 상하좌우
            if grid[nr][nc] == 1 and dist[nr][nc] == -1:    # 지나갈 수 있고 아직 안 간 칸
                dist[nr][nc] = dist[r][c] + 1
                queue.append((nr, nc))
    return dist
```

`flood_fill`(DFS로 칠하기), `region_sizes`/`count_regions`(덩어리), `shortest_path_length`도 있습니다. 직접 실행하면 `N M`과 0/1 격자를 받아 (1,1)에서 (N,M)까지 지나는 칸의 수(이동 횟수 + 1)를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 각 칸을 한 번씩, 칸마다 4방향만 보므로 **O(행 × 열)** 입니다.
- 100 × 100은 1만 칸, 1000 × 1000은 100만 칸(× 4방향)입니다. 파이썬에서는 100만 칸이 1~2초라 PyPy가 안전합니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 재귀 DFS는 큰 격자에서 깊이 제한에 걸립니다. 스택 버전이나 BFS를 쓰세요.

## 6. 자주 하는 실수

- **범위 검사 누락**: `grid[-1]`은 에러가 아니라 마지막 행이라 조용히 틀립니다.
- **행과 열 순서**: 입력 `N M`이 (행, 열)인지 확인하고 `dist[행][열]`로 일관되게 쓰세요.
- **방문 표시 시점**: BFS는 큐에 **넣을 때** 표시합니다. 꺼낼 때 하면 같은 칸이 중복해서 들어갑니다.
- **입력 파싱**: `"1011"` 같은 문자열 줄은 `list(map(int, line.strip()))`로 바꾸세요. 공백으로 구분된 입력과 다릅니다.
- **칸 수 vs 이동 횟수**: 문제가 "지나는 칸의 수"를 묻는지 "이동 횟수"를 묻는지 확인하세요. (칸 수 = 이동 횟수 + 1)
- **대각선 포함 여부**: 8방향이면 `DIRECTIONS`에 대각선을 추가합니다. (섬의 개수 같은 문제)

## 7. 변형과 응용

- **다중 시작점 BFS**: 여러 곳에서 동시에 퍼지는 문제(토마토, 불)는 시작점을 모두 큐에 넣고 시작합니다.
- **벽을 한 번 부수는 이동**: 상태에 "벽을 부쉈는가"를 추가한 `dist[r][c][부숨 여부]` ([BFS](../bfs/)의 상태 확장)
- **연결 요소**: 격자는 칸 단위의 [연결 요소](../connected-components/) 문제입니다.
- **가중치가 있는 칸**: 이동 비용이 다르면 [다익스트라](../../../lv2-intermediate/01-shortest-path/dijkstra/)
