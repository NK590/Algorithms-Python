# 분할 정복 최적화 (Divide and Conquer Optimization)

> **한 줄 요약**: "앞 `n`개를 `k`개의 연속한 묶음으로 나눠 비용의 합을 최소로" 같은 DP `dp[g][i] = min_j dp[g−1][j] + cost(j, i)`에서, 최소를 만드는 `j`(최적 분할점)가 `i`에 대해 **단조 증가**하면, 가운데 `i`의 최적 `j`를 찾은 뒤 왼쪽 절반은 그 왼쪽에서만, 오른쪽 절반은 그 오른쪽에서만 찾는 분할 정복으로 한 층을 `O(n log n)`에 계산한다. 전체가 `O(kn²)`에서 `O(kn log n)`으로 줄어든다.

## 1. 언제 쓰나 (문제 신호)

- "수열을 **정확히 `k`개의 연속 구간**으로 나눠 (구간 비용의 합) 최소화", `n ≤ 10⁴ ~ 10⁵`, `k ≤ 10² ~ 10³`
- 구간 `(j, i]`의 비용이 **누적 합으로 `O(1)`에** 계산된다: `(크기) × (합)`, `(합)²`, `|x − 중앙값|`의 합, 서로 같은 쌍의 수 …
- 점화식이 `dp[g][i] = min_j (dp[g−1][j] + cost(j, i))` 꼴로 *층*(`g`)이 있다
- 층마다 최적 분할점이 오른쪽으로만 움직이는 것을 손으로 확인했을 때
- `O(kn²)`는 느리지만 `O(kn)`까지는 필요 없는 크기

## 2. 핵심 아이디어

**점화식**: `dp[g][i]` = 앞 `i`개를 `g`개의 묶음으로 나눈 최소 비용.
```
dp[g][i] = min over j < i of ( dp[g-1][j] + cost(j, i) )     (마지막 묶음이 (j, i])
```
모든 `(g, i)`마다 `j`를 훑으면 `O(kn²)`.

**관찰**: `opt(g, i)` = 위 최솟값을 만드는 (가장 작은) `j`라고 하자. 비용이 *사각 부등식(monge)*
```
cost(a, c) + cost(b, d) ≤ cost(a, d) + cost(b, c)        (a ≤ b ≤ c ≤ d)
```
을 만족하면 `opt(g, i) ≤ opt(g, i + 1)`이다. "더 긴 prefix일수록 마지막 묶음이 시작하는 지점도 늦어진다."

(직관: `opt(i+1) < opt(i)`이면 두 최적 해를 교차시켜 *최소보다 작은* 합을 만들 수 있다는 모순이 사각 부등식에서 나온다.)

**알고리즘** `compute(lo, hi, opt_lo, opt_hi)`: `i ∈ [lo, hi]`의 최적 `j`가 `[opt_lo, opt_hi]`에 있다고 하자.
1. 가운데 `mid = (lo + hi) // 2`의 최적 `j*`를 `j ∈ [opt_lo, min(mid − 1, opt_hi)]`를 모두 훑어 찾는다.
2. 단조성에 의해 `i < mid`의 최적은 `[opt_lo, j*]`에, `i > mid`의 최적은 `[j*, opt_hi]`에 있다. 두 쪽을 재귀한다.

**왜 `O(n log n)`인가**: 같은 깊이의 노드들이 훑는 `j` 구간은 서로 거의 겹치지 않고(양 끝의 `j*`만 공유), 깊이는 `log n`이다. 한 깊이에서 훑는 `j`의 총합이 `O(n)`이라 한 층이 `O(n log n)`.

**monge가 아니면?** 단조성이 깨져 답이 틀린다. `cost`가 오목하거나(구간이 길수록 싸짐) 이상한 모양이면 사용할 수 없다. `is_monge`로 작은 `n`에서 확인해 볼 수 있다.

**비슷한 기법과 구분**: 구간 DP `dp[l][r]`의 *크누스 최적화*는 `opt[l][r−1] ≤ opt[l][r] ≤ opt[l+1][r]`로 `O(n²)`, 이 문서의 기법은 *층이 있는* DP에서 `O(kn log n)`입니다.

## 3. 손으로 따라가기

`values = [3, 1, 4, 1, 5, 9]` (`n = 6`), 비용 `cost(j, i) = (i − j) × (values[j..i−1]의 합)` (BOJ 13261의 구역 비용). 누적 합은 `[0, 3, 4, 8, 9, 14, 23]`.

### 비용 표 (`j < i`)

| `j \ i` | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 0 | 3 | 8 | 24 | 36 | 70 | 138 |
| 1 | | 1 | 10 | 18 | 44 | 100 |
| 2 | | | 4 | 10 | 30 | 76 |
| 3 | | | | 1 | 12 | 45 |
| 4 | | | | | 5 | 28 |
| 5 | | | | | | 9 |

사각 부등식 확인: `a=0, b=1, c=3, d=5`에서 `cost(0,3) + cost(1,5) = 24 + 44 = 68 ≤ cost(0,5) + cost(1,3) = 70 + 10 = 80`.

### 층별 계산

`dp[1][i] = cost(0, i)`: `[∞, 3, 8, 24, 36, 70, 138]` (인덱스 `0..6`).

`dp[2][i] = min_{1 ≤ j < i} dp[1][j] + cost(j, i)`:

| `i` | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|
| `dp[2][i]` | 4 | 12 | 18 | 36 | 64 |
| 최적 `j` | 1 | 2 | 2 | 3 | 4 |

예: `dp[2][4]`는 `j = 1`: `3 + 18 = 21`, `j = 2`: `8 + 10 = 18`, `j = 3`: `24 + 1 = 25` → 18, 최적 `j = 2`. 최적 `j`가 `1, 2, 2, 3, 4`로 **줄지 않는다**.

`dp[3][i]`: `i = 3..6`에서 `8, 13, 23, 45`, 최적 `j = 2, 3, 4, 5`.

답 `partition_cost(6, k)`는 `k = 1..6`에서 `138, 64, 45, 32, 27, 23`. (BOJ 13261에서는 구역이 많을수록 비용이 줄어듭니다.)

### 분할 정복의 계산 순서 (`dp[2]`, `i = 2..6`)

| 구간 `[lo, hi]` | `j`의 후보 `[opt_lo, opt_hi]` | `mid` | 훑은 `j` | 최적 `j*` |
|---|---|---|---|---|
| `[2, 6]` | `[1, 5]` | 4 | `1, 2, 3` (3개) | 2 |
| `[5, 6]` (오른쪽) | `[2, 5]` | 5 | `2, 3, 4` (3개) | 3 |
| `[6, 6]` | `[3, 5]` | 6 | `3, 4, 5` (3개) | 4 |
| `[2, 3]` (왼쪽) | `[1, 2]` | 2 | `1` (1개) | 1 |
| `[3, 3]` | `[1, 2]` | 3 | `1, 2` (2개) | 2 |

훑은 `j`는 합쳐서 12번이고, 그냥 모두 확인하면 `1+2+3+4+5 = 15`번입니다. `n`이 커질수록 이 차이가 `n² / (n log n)`배로 벌어집니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 구간 `(j, i]`의 비용은 `cost(j, i)`로 주어집니다.

```python
def next_layer(previous, n, cost, low):
    """previous[j] 에서 cur[i] = min_{low ≤ j < i} previous[j] + cost(j, i) 를 i = low+1..n 에 대해."""
    current = [INF] * (n + 1)
    best_j = [-1] * (n + 1)
    stack = [(low + 1, n, low, n - 1)]                 # (구하려는 i 의 구간, 최적 j 의 후보 구간)
    while stack:
        lo, hi, opt_lo, opt_hi = stack.pop()
        if lo > hi:
            continue
        mid = (lo + hi) // 2
        best_value, best_choice = INF, -1
        for j in range(opt_lo, min(mid - 1, opt_hi) + 1):
            value = previous[j] + cost(j, mid)
            if value < best_value:
                best_value, best_choice = value, j
        current[mid], best_j[mid] = best_value, best_choice
        stack.append((lo, mid - 1, opt_lo, best_choice))
        stack.append((mid + 1, hi, best_choice, opt_hi))
    return current, best_j


def partition_cost(n, k, cost):
    layer = [INF] + [cost(0, i) for i in range(1, n + 1)]     # 묶음 1 개
    for g in range(2, k + 1):
        layer, _ = next_layer(layer, n, cost, g - 1)          # g 개로 나누려면 앞의 g-1 개 묶음에 최소 g-1 개
    return layer[n]
```

- `cost_size_times_sum(values)`, `cost_square_of_sum(values)`: 누적 합으로 `O(1)`에 계산하는 비용 함수.
- `is_monge(n, cost)`: 사각 부등식을 모든 네 점에서 확인(`O(n⁴)`, 작은 `n`의 확인용).
- `naive_partition_cost(n, k, cost)`: `O(kn²)` 기준 구현.
- 직접 실행하면 BOJ 13261 형식 — `L G`와 `L`개의 위험도 — 을 받아, 감옥을 `G`개의 연속한 구역으로 나눌 때 (구역 크기 × 구역 위험도 합)의 합의 최솟값을 출력합니다 (`G > L`이면 `L`).
- 재귀 대신 스택을 쓰므로 재귀 깊이 걱정이 없습니다(깊이는 어차피 `log n`).

## 5. 복잡도와 입력 크기 가이드

- **시간 `O(k n log n)`**, **공간 `O(n)`**(층 두 개). 비용 함수가 `O(1)`일 때. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(위험도 0~10⁴ 무작위).

| 입력 | 분할 정복 최적화 | 모든 `j` 확인 (`O(kn²)`) |
|---|---|---|
| `n = 300`, `k = 10` | 0.004초 | 0.046초 |
| `n = 600`, `k = 10` | 0.008초 | 0.19초 |
| `n = 1200`, `k = 10` | 0.018초 | 0.84초 |
| `n = 2000`, `k = 20` | 0.07초 | - |
| `n = 8000`, `k = 50` | 0.83초 | - |
| `n = 8000`, `k = 100` | 1.63초 | - |

- BOJ 13261의 최대 크기(`n = 8000`, `k = 800`)는 `k = 100`의 측정값에서 8배인 **약 13초**(**추정**)이라 파이썬으로는 시간 제한을 넘기기 쉽습니다. 이 구현은 정확성 확인용으로 쓰고, 제출은 PyPy나 C++로 하는 것을 권합니다.
- 층 수 `k`가 매우 크면 [Aliens 트릭](../../../lv4-expert/) 같은 방법으로 `k` 차원을 없앨 수 있습니다(Lv4).

## 6. 자주 하는 실수

- **monge가 아닌데 적용**: 단조성이 성립하지 않으면 틀린 답이 *조용히* 나옵니다. 비용 함수가 사각 부등식을 만족하는지 작은 입력에서 `is_monge`로, 또는 `O(kn²)` 기준 구현과의 비교로 확인하세요.
- **최적 `j`의 범위 인덱스**: `j < mid`를 지키지 않으면 빈 묶음을 쓰게 되고, `k`개를 *정확히* 쓰지 못합니다. 특히 `j = mid`를 허용하면 비용 0인 빈 묶음이 생깁니다 (이 구현은 `min(mid − 1, opt_hi)`로 막습니다).
- **첫 층의 초기화**: `dp[1][i] = cost(0, i)`이고 `dp[1][0]`은 쓸 수 없는 값(`∞`)입니다.
- **불가능한 상태**: `g`개로 `i < g`개를 나눌 수는 없습니다. 이 구현은 층마다 `i`의 하한을 `g`로 둡니다.
- **동점일 때 최적 `j`**: 가장 작은 `j`를 일관되게 선택해야 단조성의 증명이 그대로 성립합니다 (`value < best_value`로 처음 만난 것을 유지).
- **`k > n`**: 비어 있지 않은 묶음 `k`개가 불가능합니다. 문제가 "최대 `k`개"를 허용하는지 읽고 `min(k, n)`으로 줄일지 결정하세요.
- **비용 계산이 `O(1)`이 아님**: 누적 합으로 `O(1)`을 만들지 못하면 전체가 `O(k n log n · 비용)`이 됩니다. 비용이 "구간 안의 서로 다른 값의 수"처럼 어려우면 모스 알고리즘 식으로 구간을 한 칸씩 옮기며 계산합니다 (CF 868F).
- **오버플로** (C++/Java): 비용이 `10¹⁸`에 가까울 수 있어 64비트 정수 필요. `∞` 값을 너무 크게 잡으면 덧셈에서 넘칩니다.
- **최대화 문제**: 최솟값 대신 최댓값을 구할 때 부등식의 방향이 바뀝니다. 비용에 `−`를 붙여 최소화로 바꾸고 monge를 다시 확인하세요.

## 7. 변형과 응용

- **크누스 최적화**: 구간 DP `dp[l][r] = min_k dp[l][k] + dp[k][r] + cost(l, r)`에서 `opt[l][r−1] ≤ opt[l][r] ≤ opt[l+1][r]`를 이용해 `O(n³)`을 `O(n²)`으로 (BOJ 11066 파일 합치기).
- **볼록 껍질 트릭**: 비용이 `(누적 합의 차)²`이고 `dp[i] = min_j dp[j] + (S_i − S_j)² + c`처럼 *층이 없으면* [CHT](../convex-hull-trick/)로 `O(n)`~`O(n log n)`. 층이 있어도 각 층에 CHT를 쓸 수 있습니다.
- **Aliens 트릭 (WQS 이분 탐색)**: 층 수 `k`가 큰 경우 묶음마다 상수 `λ`의 벌점을 매겨 층 차원을 없애고 `λ`를 이분 탐색합니다 (Lv4).
- **온라인 분할 정복**: `dp[i] = min_{j<i} dp[j] + cost(j, i)`처럼 같은 배열 안에서 자기를 참조하는 DP는 분할 정복 안에서 *왼쪽 → 오른쪽 기여 → 오른쪽* 순서로 계산합니다 (CDQ 분할 정복과 같은 틀).
- **SMAWK**: monge 행렬의 모든 행의 최소를 `O(n)`에 찾는 알고리즘으로 한 층을 `O(n)`에. 구현이 복잡합니다.
- **비용 함수의 다양화**: 중앙값에서의 거리 합(우체국/우편함 문제), 구간의 서로 다른 쌍 수, 구간 최대−최소 …
