# 자릿수 DP (Digit DP)

> **한 줄 요약**: "1 이상 `N` 이하의 수 중 **자릿수들이 만드는 조건**을 만족하는 것"을 `N`이 10¹⁸이어도 **자릿수 길이만큼의 DP**로 센다. 수를 높은 자리부터 한 자리씩 만들며 *지금까지의 상태*만 기억하고, `N`의 접두사와 같은지(`tight`)로 상한을 지키며, 이미 `N`보다 작아진 접두사들은 같은 상태끼리 묶어서 센다.

## 1. 언제 쓰나 (문제 신호)

- "`1`부터 `N`까지 숫자 `d`가 **몇 번** 나오는가" (`N ≤ 10¹⁸`), 모든 수의 자릿수 합의 총합
- "`A`부터 `B`까지의 수 중 **4가 없는**(또는 어떤 조건의) 수의 개수" — 구간은 `f(B) − f(A−1)`
- "자릿수 합이 `D`의 배수인 수", "`m`의 배수인 수", "이웃한 두 자릿수가 다른 수"
- 이진수에서 "1이 연속하지 않는 수", "1의 개수가 `k`개인 수"
- `N`이 문자열로 주어지는 경우(10¹⁰⁰⁰⁰) — 자릿수 길이가 곧 반복 횟수
- 일반 DP로 보이는데 정의역이 "수 하나"이고 상한 제약이 걸려 있을 때

## 2. 핵심 아이디어

**순진한 방법**: 1부터 `N`까지 하나씩 검사하면 `O(N)`. `N = 10¹⁸`이면 불가능.

**수를 자릿수의 열로 본다**. `N = 235`이면 `1..235`의 수는 길이 1, 2, 3인 자릿수 열이다. 높은 자리부터 한 자리씩 고르며 조건에 필요한 *상태*(자릿수 합, 나머지, 직전 숫자 …)를 갱신한다.

**상한 `N`을 지키는 방법 — tight와 free**:
- **tight**: 지금까지 고른 접두사가 `N`의 접두사와 **정확히 같다**. 다음 자리는 `N`의 그 자리 이하만 고를 수 있다. 경로가 딱 하나(`N` 자신의 접두사)라 상태도 하나.
- **free**: 접두사가 이미 `N`보다 작아졌다. 남은 자리는 `0..9`(진법 `b`면 `0..b−1`) 무엇이든 가능하다. 많은 접두사가 있지만 *같은 상태끼리 묶어서* `{상태: (수의 개수, 이득의 합)}`으로 압축한다.

tight에서 `N`의 그 자리보다 **작은** 숫자를 고르면 free로 옮겨 가고, **같은** 숫자를 고르면 tight로 남는다.

**앞쪽 0**: `007` 같은 앞쪽 0은 자릿수가 아니다. 숫자 `0`의 출현을 셀 때 틀리지 않으려면 *수가 시작된 뒤*의 숫자만 `step`에 넣어야 한다. 이 구현은 첫 자리를 `1..b−1`로 시작하고, `N`보다 짧은 수는 "두 번째 자리 이후에 새로 시작"하는 것으로 센다.

**개수와 이득의 합**: 각 상태마다 `(개수, 이득의 합)`을 같이 유지한다. 숫자 `d`의 출현 횟수를 세려면 `d`를 고를 때 이득 1을 주면 된다. free 상태에서 숫자를 하나 더 고를 때 이득의 합은 `기존 합 + 개수 × (이번 이득)`으로 갱신된다.

**구간**: `A..B`의 개수는 `f(B) − f(A−1)`.

**복잡도**: 자릿수 `L`, 상태 수 `S`, 진법 `b`면 `O(L × S × b)`. `S`는 조건마다 다르다 (자릿수 합 ≤ 162, 나머지 `m`, 직전 숫자 10 …).

### 무엇을 저장하고 어떻게 움직이나

상한 N의 자릿수를 왼쪽부터 읽으며 부분 숫자의 상태를 저장합니다. 상한과 지금까지 같은지 tight, 아직 숫자가 시작되지 않았는지 started, 자릿수 합·나머지 같은 조건을 함께 둡니다. 길이가 아니라 값 범위가 큰 수의 개수를 셀 때 유용합니다.

### 왜 이 방법이 맞는가

다음 자릿수의 허용 범위는 tight이면 N의 현재 자릿수까지, 이미 작아졌다면 0~9 전체입니다. 상태가 미래의 조건 판정에 필요한 정보를 모두 담으면 같은 상태의 접두 숫자를 합칠 수 있습니다. 선행 0은 실제 숫자의 0과 다르게 처리할 수 있습니다.

### 작은 예제로 검산하기

N=25에서 첫 자리 1을 고르면 다음 자리는 0~9가 가능하지만 첫 자리 2를 고르면 0~5만 가능합니다. `[L,R]`의 개수는 F(R)-F(L-1)로 구합니다. 숫자 0 자체를 포함할지 별도로 검산하세요.

## 3. 손으로 따라가기

### `1..235`에서 숫자 `2`가 나오는 횟수

상태가 필요 없으므로(`state = 0` 하나) free는 `(수의 개수, 이득의 합)` 한 쌍입니다. `N = 235`의 자릿수는 `2, 3, 5`.

| 위치 | `N`의 자릿수 | free `(개수, 이득의 합)` | tight의 이득 | 설명 |
|---|---|---|---|---|
| 0 | 2 | `(1, 0)` | 1 | 첫 자리가 `1`인 수 하나(`1`)가 free. 첫 자리 `2`는 tight, 이미 `2`를 하나 썼으므로 이득 1 |
| 1 | 3 | `(22, 6)` | 1 | free `10~19`(10개, `12`에 `2`가 하나), tight에서 `20, 21, 22`(`2` 자리에서 작은 수를 고름, 이득 1, 1, 2 → 합 4), 새로 시작하는 `1~9`(9개, `2`가 하나) |
| 2 | 5 | `(234, 89)` | 1 | free 22개 × 10 = 220개(이득 `6·10 + 22·1 = 82`), tight에서 `230~234`(5개, 이득 합 6), 새로 시작하는 `1~9`(9개, 이득 1) |

마지막으로 tight인 수 `235` 하나(이득 1)를 더하면 개수 `234 + 1 = 235`, 이득의 합 `89 + 1 = 90`. 즉 `1..235`에서 숫자 `2`는 90번 나옵니다. 모든 숫자를 한 번에 보면 `digit_counts(235) = [43, 154, 90, 50, 44, 44, 43, 43, 43, 43]` (`0`부터 `9`까지의 횟수)이고 직접 써 보아도 같습니다.

### 작은 예로 확인: `1..100`

| 질문 | 답 | 확인 |
|---|---|---|
| 숫자 `4`가 없는 수 | 81 | `4`를 포함하는 수는 `4, 14, …, 94`(10개)와 `40~49`(10개)에서 `44`가 겹쳐 19개 → `100 − 19` |
| 이웃한 자릿수가 같은 곳이 없는 수 | 90 | `11, 22, …, 99`(9개)와 `100`을 뺀 `100 − 10` |
| 자릿수 합이 10인 수 | 9 | `19, 28, 37, 46, 55, 64, 73, 82, 91` |
| 이진수에 `11`이 없는 수 | 33 | 길이 `L`인 수는 피보나치 `F(L)`개(1, 1, 2, 3, 5, 8, 13). 100은 7비트(`1100100`)이고 7비트의 `11` 없는 수는 최대 `1010101 = 85`라 모두 100 이하 → 1+1+2+3+5+8+13 |
| `1..11`의 `0`~`9` 출현 | `1 4 1 1 1 1 1 1 1 1` | 1부터 11까지 직접 써서 검산 |

### 닫힌 식과 맞추기

`1..10ᵏ−1`에서 `1~9`는 각각 `k·10ᵏ⁻¹`번, 자릿수 합의 총합은 `45·k·10ᵏ⁻¹`입니다. `k = 18`에서도 DP가 이 값과 정확히 같다는 것을 테스트가 확인합니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def digit_dp(upper, init, step, base=10):
    """1..upper 의 수들을 훑어 {최종 상태: (수의 개수, 이득의 합)}. step(상태, 숫자) -> (새 상태, 이득) 또는 None(금지)."""
    digits = digits_of(upper, base)
    free = {}                                        # 이미 upper 보다 작아진 접두사: 상태 -> [개수, 이득의 합]
    first = digits[0]
    for d in range(1, first):                        # 첫 자리가 upper 의 첫 자리보다 작으면 곧바로 free
        ...
    tight = step(init, first)                        # 같으면 tight 유지: (상태, 이득)
    for position in range(1, len(digits)):
        next_free = {}
        for state, (count, gain) in free.items():    # free: 남은 자리는 무엇이든
            for d in range(base):
                ...                                  # 이득의 합 += count × (이번 이득)
        ...                                          # tight 에서 upper 의 자리보다 작은 숫자 -> free
        ...                                          # 길이가 짧은 수: 이 자리에서 시작 (d = 1..base-1)
        free = next_free
    ...                                              # 마지막에 tight 인 수 upper 자신을 더한다
```

- `count_digit_occurrences(n, d)`, `digit_counts(n)`(자릿수 출현 집계 예제), `digit_sum_total(n)`.
- `count_without_digit(n, banned)`, `count_with_digit_sum(n, target)`, `count_digit_sum_divisible(n, k)`, `count_multiples(n, m)`, `count_no_adjacent_equal(n)`.
- `count_binary_without_adjacent_ones(n)`: 이진법(`base=2`) 사용 예.
- `count_in_range(f, lo, hi)`: `f(hi) − f(lo − 1)`.
- 조건을 직접 만들 때는 `step`만 바꿉니다. 예: `lambda total, d: (total + d, 0)`은 자릿수 합을 상태로, `None`을 돌려주면 그 수는 세지 않습니다.
- 직접 실행하면 `N`을 받아 `1..N`에서 `0`부터 `9`까지 각각 몇 번 나오는지 한 줄에 출력합니다 (자릿수 출현 집계 예제 형식).

## 5. 복잡도와 입력 크기 가이드

- **시간 `O(L · S · b)`**, **공간 `O(S)`**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 입력 | 시간 |
|---|---|---|
| `digit_counts` | `N = 10¹⁸` | 1.0밀리초 |
| `digit_counts` | `N = 10⁶` | 0.3밀리초 |
| 1~`10⁶`을 모두 문자열로 써서 세기 | `N = 10⁶` | 1.07초 |
| `count_multiples` | `N = 10¹⁸`, `m = 997` | 0.04초 |
| `count_digit_sum_divisible` | `N = 10¹⁸`, `k = 100` | 0.01초 미만 |

- 순진한 방법과 같은 결과를 냈음을 테스트가 `N ≤ 12345`까지 숫자를 모두 써 보며 확인합니다.
- 상태 수가 커지면(나머지 `m`이 10⁴ 이상) 시간이 `S`에 비례해 늘어납니다. 파이썬의 딕셔너리 DP는 `L·S·b ≤ 10⁷` 정도까지 몇 초입니다.

## 6. 자주 하는 실수

- **앞쪽 0을 숫자로 셈**: `0`의 출현 횟수가 틀립니다. `007`의 앞 두 `0`은 세지 않습니다.
- **`N` 자신을 빼먹음**: tight로 끝까지 남은 수가 `N` 자신입니다. 마지막에 더해야 합니다 (`≤ N`이므로).
- **`0`을 센다/안 센다**: 이 구현은 `1..N`입니다. `0`을 포함해야 하면 `f(N)`에 `0`이 조건을 만족하는지에 따라 `+1`.
- **구간 `A..B`에서 `A = 1`**: `f(0) = 0`을 정확히 정의하세요. 이 구현은 `upper < 1`이면 빈 결과입니다.
- **`tight`에서 같은 숫자를 고를 때 상태를 갱신하지 않음**: 다음 자리의 조건이 이 숫자에 의존합니다.
- **금지 숫자를 나중에 걸러냄**: `step`이 `None`을 돌려주면 그 가지를 바로 버립니다. 걸러내지 않고 끝까지 가면 개수가 틀립니다.
- **상태가 너무 큼**: 자릿수 합은 `9·L`, 나머지는 `m`. 한 번에 여러 조건이면 곱이 폭발합니다.
- **나머지 상태에서 진법**: `나머지 = (나머지 · b + d) mod m`의 `b`는 진법입니다 (10 아님).
- **`N`이 매우 클 때**: 파이썬은 큰 정수를 그대로 받으므로 `int(문자열)`로 바꿔 쓸 수 있습니다. 다만 자릿수가 10⁴쯤 되면 개수도 거대한 정수가 되므로, 나머지를 요구하는 문제는 `digit_dp`의 합산을 `% MOD`로 고쳐 써야 합니다.
- **재귀+메모로 짠 풀이의 `lru_cache` 키에 `tight`·`started`를 빼먹음**: 같은 `(위치, 상태)`가 tight일 때와 아닐 때 값이 다릅니다.

## 7. 변형과 응용

- **`k`번째 수 찾기**: 각 접두사 뒤에 올 수 있는 개수를 DP로 알면, 높은 자리부터 "이 숫자를 고르면 몇 개가 되는가"를 보며 `k`번째를 자릿수 단위로 결정합니다.
- **두 수의 쌍 조건**: `A, B ≤ N`인 쌍을 셀 때는 tight 여부를 *두 개* 유지합니다 (자릿수 DP의 일반형).
- **사용한 숫자의 집합**: 모든 자릿수가 다른 수, 서로 다른 숫자가 정확히 `k`개인 수는 사용한 숫자를 [비트마스크](../../../lv1-elementary/09-bit-manipulation/bitmask/)로 상태에 둡니다 (LeetCode 2376).
- **최소공배수 상태**: "자신의 0이 아닌 모든 숫자로 나누어떨어지는 수"는 상태에 LCM의 나머지(`2520` 약수 48개)를 둡니다 (Codeforces 55D).
- **이진수의 조건**: 1의 개수, 연속 1 금지 등은 `base=2`로 같은 코드입니다 (LeetCode 600).
- **확률/기댓값과 결합**: 무작위 수의 자릿수 합의 기댓값처럼 개수 대신 확률을 가지고 가면 [기댓값 DP](../expected-value-dp/)가 됩니다.
- **행렬 거듭제곱과의 결합**: `N`이 아니라 "길이 `L`인 모든 문자열"을 세는 문제는 상한이 없어 [행렬 거듭제곱](../matrix-exponentiation/)으로 풉니다.
