# 중간에서 만나기 (Meet in the Middle)

> **한 줄 요약**: `n`이 40~50쯤이라 모든 경우(`2ⁿ`)를 볼 수는 없고, DP 표를 만들기엔 값이 너무 큰 문제에서, **입력을 절반씩 나눠 각자 `2^(n/2)`가지를 나열한 뒤 두 목록을 정렬·이진 탐색(또는 해시)으로 맞춰 본다.** `2⁴⁰ ≈ 10¹²`이 `2 × 2²⁰ ≈ 2·10⁶`으로 줄어든다.

## 1. 언제 쓰나 (문제 신호)

- "원소 `n ≤ 40`개 중 몇 개를 골라 **합이 `C` 이하/정확히 `C`/목표에 가장 가까운** …" (`n`이 30~50, 값은 10⁹ 이상이라 합을 인덱스로 쓰는 DP는 불가능)
- 0/1 배낭인데 **무게가 너무 커서** 용량으로 DP 표를 못 만들 때 (물건 수 `n ≤ 40`)
- "네 배열에서 하나씩 골라 합이 0인 조합의 수" — 4중 반복을 `2 + 2`로
- 상태 공간을 양쪽 끝에서 탐색해 가운데에서 맞추는 문제 (격자 경로의 XOR 합, 퍼즐의 양방향 탐색)
- 제한이 이상하게 작아서(`n ≤ 40`) 완전 탐색과 `n ≤ 20`용 비트마스크 DP의 사이에 있을 때

## 2. 핵심 아이디어

**순진한 방법**: 부분집합 `2ⁿ`개를 모두 만든다. `n = 30`이면 약 10⁹, `n = 40`이면 10¹²라 불가능.

**절반으로 나누기**: 원소를 앞 절반 `L`과 뒤 절반 `R`로 나눈다. 부분집합은 `L`의 부분집합과 `R`의 부분집합의 합집합이므로, **합이 `x`인 부분집합 = (`L`의 합 `s`) + (`R`의 합 `x − s`)**.

1. `L`의 부분집합 합을 모두 나열한다 (`2^(n/2)`개).
2. `R`의 부분집합 합을 모두 나열한다.
3. `L`의 각 합 `s`에 대해 `R`에서 조건에 맞는 값을 찾는다.
   - **합이 `C` 이하인 부분집합 수**: `R`을 정렬해 두고 `C − s` 이하인 값의 수를 `bisect_right`로. 
   - **정확히 `C`인 수**: `R`의 값을 `Counter`에 넣고 `C − s`의 횟수를 찾는다.
   - **`C`에 가장 가까운 합**: `R`을 정렬해 두고 `C − s` 바로 앞/뒤의 두 후보를 비교한다.

총 비용은 나열 `O(2^(n/2))`, 정렬 `O(2^(n/2) · n)`, 탐색 `2^(n/2)`번 × `O(n)`(이진 탐색의 `log 2^(n/2) = n/2`) → **`O(2^(n/2) · n)`**.

**배낭으로 확장**: 물건이 `(무게, 가치)`이면 `R`의 부분집합 `(무게 합, 가치 합)`을 무게순으로 정렬하고 가치의 **누적 최댓값**을 만든다. `L`의 부분집합 `(w, v)`마다 남은 용량 `W − w`에 들어가는 `R`의 최선을 이진 탐색으로 찾아 `v +`한다.

**네 배열의 합이 0**: `a[i] + b[j]`의 모든 합(`n²`개)을 `Counter`에 넣고, `c[k] + d[l]`마다 `−(c[k] + d[l])`의 횟수를 더한다. 이것도 절반씩 나누는 같은 생각이다: `O(n⁴)` → `O(n²)`.

### 무엇을 저장하고 어떻게 움직이나

전체 선택을 두 절반으로 나눠 각 절반의 가능한 결과를 모두 만듭니다. 그런 다음 두 결과 목록에서 조건을 만족하는 짝을 탐색합니다. 전체 2^n 열거 대신 두 번의 2^(n/2) 열거로 후보 생성 비용을 줄입니다.

### 왜 이 방법이 맞는가

전체 부분집합 하나는 왼쪽 부분집합과 오른쪽 부분집합 한 쌍으로 유일하게 나뉩니다. 따라서 두 목록의 모든 필요한 짝을 탐색하면 해를 놓치지 않습니다. 합의 종류만 저장할지 각 합의 등장 횟수도 저장할지는 개수 질의 여부에 따라 다릅니다.

### 작은 예제로 검산하기

`[1,4]`의 합 목록은 0,1,4,5이고 `[2,3]`은 0,2,3,5입니다. 목표 6에는 1+5와 4+2가 대응합니다. 같은 합을 만드는 다른 선택들을 집합으로 합치면 경우의 수 정보가 사라집니다.

## 3. 손으로 따라가기

### 합이 10 이하인 부분집합의 수: `values = [1, 2, 3, 4, 5, 6]`, `C = 10`

앞 절반 `L = [1, 2, 3]`의 부분집합 합(정렬): `0, 1, 2, 3, 3, 4, 5, 6` (8개).  
뒤 절반 `R = [4, 5, 6]`의 부분집합 합(정렬): `0, 4, 5, 6, 9, 10, 11, 15` (8개).

| `L`의 합 `s` | `C − s` | `R`에서 `C − s` 이하인 개수 |
|---|---|---|
| 0 | 10 | 6 (`0, 4, 5, 6, 9, 10`) |
| 1 | 9 | 5 |
| 2 | 8 | 4 |
| 3 | 7 | 4 |
| 3 | 7 | 4 |
| 4 | 6 | 4 |
| 5 | 5 | 3 |
| 6 | 4 | 2 |

합계 `6 + 5 + 4 + 4 + 4 + 4 + 3 + 2 = 32`. 전체 `2⁶ = 64`개 중 절반입니다. 직접 세어도 같은 32이고, **정확히 10인** 부분집합은 5개(`{4, 6}`, `{1, 3, 6}`, `{1, 4, 5}`, `{2, 3, 5}`, `{1, 2, 3, 4}`)입니다. 빈 집합(합 0)이 포함됩니다.

### 목표에 가장 가까운 합: `values = [4, 9, 13, 22, 31]`, 목표 50

`L = [4, 9]` → 합 `0, 4, 9, 13`. `R = [13, 22, 31]` → 정렬한 합 `0, 13, 22, 31, 35, 44, 53, 66`.

| `s` | 필요한 `R`의 값 `50 − s` | 이진 탐색 위치의 앞/뒤 후보 (합계) |
|---|---|---|
| 0 | 50 | `44`, `53` |
| 4 | 46 | `48`, `57` |
| 9 | 41 | `44`, `53` |
| 13 | 37 | `48`, `57` |

가장 가까운 합계는 `48`(거리 2), 다음이 `53`(거리 3). 같은 거리가 둘이면 작은 쪽을 돌려줍니다.

### 큰 무게의 배낭: 물건 `(무게, 가치) = (5, 10), (4, 40), (6, 30), (3, 50)`, 용량 10

`L = [(5,10), (4,40)]` → 부분집합 `(0,0), (5,10), (4,40), (9,50)`.  
`R = [(6,30), (3,50)]` → 부분집합 무게순: `(0,0), (3,50), (6,30), (9,80)`, 가치의 누적 최댓값 `0, 50, 50, 80`.

| `L`의 `(w, v)` | 남은 용량 | `R`에서 들어가는 마지막 위치의 누적 최대 가치 | 합 |
|---|---|---|---|
| (0, 0) | 10 | 80 (무게 9까지) | 80 |
| (5, 10) | 5 | 50 (무게 3까지) | 60 |
| (4, 40) | 6 | 50 (무게 6까지) | **90** |
| (9, 50) | 1 | 0 | 50 |

최댓값 90 (무게 4 + 3 = 7, 가치 40 + 50).

### 네 배열의 합이 0: `a = [1, −1]`, `b = [0, 2]`, `c = [−1, 3]`, `d = [0, −2]`

`a + b`의 모든 합: `1, 3, −1, 1` → `Counter` = `{1: 2, 3: 1, −1: 1}`. `c + d`의 합: `−1, −3, 3, 1` → 각각의 부호를 바꾼 `1, 3, −3, −1`의 횟수: `2 + 1 + 0 + 1 = 4`. 4중 반복으로 세어도 `(1,0,−1,0)`, `(1,2,−1,−2)`, `(−1,0,3,−2)`, `(−1,2,−1,0)`의 4개입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def subset_sums(values):
    sums = [0]
    for v in values:
        sums += [s + v for s in sums]            # 원소를 하나 넣을 때마다 목록이 두 배
    return sums


def count_subsets_at_most(values, limit):
    middle = len(values) // 2
    right = sorted(subset_sums(values[middle:]))
    return sum(bisect_right(right, limit - s) for s in subset_sums(values[:middle]))


def closest_subset_sum(values, target):
    middle = len(values) // 2
    right = sorted(subset_sums(values[middle:]))
    best = None
    for s in subset_sums(values[:middle]):
        index = bisect_left(right, target - s)   # 목표 바로 앞/뒤의 두 후보
        for j in (index - 1, index):
            if 0 <= j < len(right):
                total = s + right[j]
                if best is None or (abs(total - target), total) < (abs(best - target), best):
                    best = total
    return best
```

- `count_subsets_with_sum(values, target)`: 정확히 `target`인 부분집합 수(`Counter` 사용).
- `knapsack_meet(items, capacity)`: 0/1 배낭(`items = [(무게, 가치), …]`).
- `four_sum_zero_count(a, b, c, d)`: 합이 0인 네 원소 조합의 수.
- 모든 함수가 음수 원소도 다룹니다. 빈 집합(합 0)을 포함해서 셉니다.
- 직접 실행하면 부분집합 무게 예제 형식 — `N C`와 `N`개의 무게 — 을 받아 무게의 합이 `C` 이하인 부분집합(빈 집합 포함)의 수를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 `O(2^(n/2) · n)`**, **공간 `O(2^(n/2))`**. `n = 40`이면 한쪽이 약 10⁶개. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(무게는 1~10⁹ 무작위).

| 작업 | 입력 | 시간 |
|---|---|---|
| `count_subsets_at_most` | `n = 30` | 0.02초 |
| `count_subsets_at_most` | `n = 36` | 0.31초 |
| `count_subsets_at_most` | `n = 40` | 1.55초 |
| `closest_subset_sum` | `n = 40` | 1.07초 |
| `knapsack_meet` | `n = 40` | 2.13초 |
| 모든 부분집합 합을 나열(`subset_sums`)만 | `n = 22` | 0.59초 |

- 마지막 줄을 `2ⁿ`으로 환산하면 `n = 30`은 약 151초, `n = 40`은 약 43시간(15만 초대)입니다(**추정**: `n = 22`의 측정값에 `2^(n−22)`를 곱함). 절반으로 나누면 같은 `n = 40`이 1.55초입니다.
- `four_sum_zero_count`(각 값 ±10⁷ 무작위): `n = 500` 0.08초, `n = 1000` 0.49초, `n = 1500` 1.34초, `n = 2000` 3.38초(메모리 약 336MB). 원래 문제(`n = 4000`)는 쌍의 합이 1600만 개라 메모리가 **약 1.3GB**(`n = 2000`의 4배, **추정**)로 순수 파이썬 딕셔너리로는 현실적이지 않습니다. 정렬된 배열과 두 포인터를 쓰는 변형이 필요합니다.
- `n ≤ 40`이 목표 크기입니다. `n = 44`면 한쪽이 4백만 개로 메모리와 시간이 4배씩 늘어납니다.

## 6. 자주 하는 실수

- **빈 집합을 셀지 말지**: 이 구현은 빈 집합(합 0)을 포함합니다. 빈 집합 제외 예제처럼 "크기가 양수인 부분수열"을 묻는 문제는 `target == 0`일 때 1을 빼야 합니다.
- **양쪽 합이 같은 경우의 중복**: 같은 합의 부분집합이 여러 개일 때 `set`으로 합치면 개수를 잃습니다. 개수를 셀 때는 리스트(정렬)나 `Counter`로.
- **이진 탐색 경계**: "이하"는 `bisect_right(limit − s)`, "미만"은 `bisect_left`입니다. 하나 바꾸면 경계값(합이 정확히 같은 경우)에서만 틀려 눈치채기 어렵습니다.
- **가장 가까운 합에서 후보 하나만 확인**: 목표 바로 *앞* 값과 *뒤* 값 둘 다 비교해야 합니다.
- **무게가 0이거나 음수**: 배낭의 누적 최댓값 방식은 무게가 0 이상일 때 맞습니다. 음수 무게가 있으면 전략이 달라집니다.
- **남은 용량이 음수**: `knapsack_meet`에서 `L`의 무게가 이미 용량을 넘으면 건너뛰어야 합니다(`bisect`가 `−1` 위치를 가리키지 않게).
- **절반을 불균형하게 나눔**: 앞 `n/3`, 뒤 `2n/3`로 나누면 큰 쪽이 `2^(2n/3)`로 이점이 사라집니다. 정확히 절반으로.
- **메모리**: `2^20`개 정수 리스트 두 개와 정렬 사본이 필요해 수백 MB가 될 수 있습니다. 필요하면 한쪽만 정렬하고 다른 쪽은 스트리밍으로 소비하세요.
- **값이 작은데 `n`도 작다면 DP**: 합의 범위가 작으면(`n ≤ 100`, 값 ≤ 1000) 일반 배낭 DP가 더 빠르고 간단합니다. 이 방법은 *값이 큰* 경우를 위한 것입니다.

## 7. 변형과 응용

- **XOR, 모듈러 합**: 합 대신 XOR이나 `(합 mod m)`을 나열하면 같은 구조. 모듈러는 정렬 후 두 포인터로 `m − 1`을 넘지 않는 최대 합을 찾습니다.
- **정렬 + 두 포인터**: 이진 탐색 대신 `L`을 오름차순으로, `R`을 내림차순으로 두 포인터로 훑으면 탐색의 `log`가 사라집니다. 부분집합 합을 만들 때 원소 하나마다 "기존 목록"과 "`+v`한 목록"(둘 다 정렬됨)을 병합하면 정렬 비용도 없어져 전체가 `O(2^(n/2))`입니다.
- **3·4개로 나누기**: 합이 0인 네 정수처럼 `k`개 목록의 합 문제는 `k/2`개씩 묶어 비교합니다.
- **격자 경로의 중간 대각선**: `n × m` 격자의 출발점에서 중간 대각선까지, 도착점에서 중간 대각선까지의 경로를 각각 나열하고 대각선의 칸마다 합쳐 비교합니다 (Codeforces 1006F).
- **양방향 BFS**: 출발점과 도착점에서 동시에 탐색을 시작해 가운데에서 만나면 탐색 노드 수가 `b^d`에서 `2·b^(d/2)`로 줄어듭니다.
- **이산 로그 (BSGS)**: `a^x ≡ b (mod p)`를 `x = i·m − j`로 쪼개 `√p`개씩 비교하는 같은 아이디어(Lv4).
- **가지치기와 비교**: 분기한정(branch and bound)은 입력에 따라 빠르기도 느리기도 하지만, 중간에서 만나기는 입력과 무관하게 `2^(n/2)`입니다.
