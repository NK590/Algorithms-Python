# 쿼리 기법 (Query Techniques)

세그먼트 트리나 펜윅 트리로 딱 떨어지지 않는 문제를 **일을 둘로(또는 `√`로) 나누어** 푸는 기법들입니다. 공통점은 "한쪽만 키우면 비용이 폭발하니 양쪽을 맞춘다"는 균형의 사고입니다: 블록 크기와 블록 수, 왼쪽 끝 이동과 오른쪽 끝 이동, 앞 절반의 나열과 뒤 절반의 나열.

## 한눈에 비교

| 개념 | 푸는 것 | 핵심 도구 | 시간 |
|---|---|---|---|
| [모스 알고리즘](mos-algorithm/) | 갱신 없는 구간 질의(서로 다른 값의 수, 최빈값 …), 오프라인 | 질의를 블록 순으로 정렬해 끝점을 한 칸씩 이동 | O(n√q) |
| [제곱근 분할](sqrt-decomposition/) | 구간 갱신·질의(온라인), 트리로 합치기 어려운 블록 정보 | 크기 √n 블록 + 조각 + lazy/정렬된 복사본 | 연산당 O(√n) |
| [중간에서 만나기](meet-in-the-middle/) | `n ≤ 40`의 부분집합·배낭·합 문제 | 절반씩 나열 + 정렬/이진 탐색/해시 | O(2^(n/2) · n) |

## 문제 신호로 고르기

| 문제의 신호 | 선택 |
|---|---|
| 수열이 안 바뀌고 질의가 10⁵개, "구간에 서로 다른 값이 몇 종류", 구간을 합치기 어렵다 | [모스 알고리즘](mos-algorithm/) (또는 오프라인 펜윅 트리) |
| 구간 갱신이 있고 값이 단순한 합/최솟값이면 | [세그먼트 트리](../01-range-query-structures/segment-tree/), [펜윅 트리](../01-range-query-structures/fenwick-tree/) |
| 갱신이 있고 구간의 "`k`보다 큰 수" 같은 정렬 정보, 합치기 규칙을 못 만들겠다 | [제곱근 분할](sqrt-decomposition/) |
| 원소가 40개쯤인데 값이 10⁹ 이상이라 배낭 표를 못 만든다 | [중간에서 만나기](meet-in-the-middle/) |
| 원소가 20개 이하 | [비트마스크 DP](../../lv2-intermediate/04-dynamic-programming/bitmask-dp/) 또는 완전 탐색 |
| 네 수열에서 하나씩 골라 합이 0 | [중간에서 만나기](meet-in-the-middle/) (`2 + 2`) |

## 개념 사이의 관계

- [모스 알고리즘](mos-algorithm/)은 질의를 `√`개 블록으로 묶는 제곱근 분할의 오프라인판입니다. 같은 `n√n`이지만 *갱신이 없고 질의를 미리 알아야* 합니다.
- [제곱근 분할](sqrt-decomposition/)은 세그먼트 트리가 못 담는 정보를 블록 안에 담을 수 있다는 점이 강점입니다. 대신 연산이 `O(√n)`이라 `n·연산 수`가 10⁷~10⁸ 이하에서 씁니다.
- [중간에서 만나기](meet-in-the-middle/)는 구조는 다르지만 같은 계산 감각입니다. 한쪽을 `2ⁿ`에서 `2^(n/2)` 둘로 쪼개는 것도 `√` 균형입니다.

## 파이썬에서의 현실

- 세 기법 모두 같은 입력에서 `O(log n)` 구조보다 느립니다. 파이썬에서는 `n = 10⁵`, 연산 `10⁵`번 정도가 한계이고 10⁶번이면 시간 제한에 걸리기 쉽습니다.
- 대신 구현이 짧고 정확성이 높아서, 큰 입력에서 정답을 확인하는 **기준 구현**으로 쓰기에 좋습니다.
