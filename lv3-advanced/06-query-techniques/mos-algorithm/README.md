# 모스 알고리즘 (Mo's Algorithm)

> **한 줄 요약**: 구간 `[l, r)`의 답을 "원소 하나를 넣기/빼기"로 갱신할 수 있으면, **질의를 읽은 순서가 아니라 알맞은 순서로 처리**하면서 구간의 양 끝을 한 칸씩 옮겨 가는 것만으로 모든 질의를 `O((n + q)√n)`에 답할 수 있다. 값을 바꾸는 갱신이 없는 **오프라인** 구간 질의에서, 세그먼트 트리로 합치기 어려운 정보(서로 다른 값의 수, 최빈값의 빈도 …)를 쉽게 다룬다.

## 1. 언제 쓰나 (문제 신호)

- "구간 `[l, r]`에 **서로 다른 값이 몇 종류** 있는가" (세그먼트 트리의 노드끼리 합칠 수 없는 값)
- "구간에서 **같은 값을 가진 두 위치 쌍**의 수", "각 값의 등장 횟수의 제곱 × 값의 합", "최빈값의 빈도"
- 질의가 10⁵개이고 **수열은 바뀌지 않는다**(갱신 없음). 질의를 한꺼번에 받아도 된다(오프라인)
- 구간에 원소를 하나 넣거나 빼는 비용이 `O(1)`이거나 작다
- 구간이 한 칸씩 움직일 때의 답 변화를 쉽게 쓸 수 있는데, 구간을 둘로 쪼개 합치는 것은 어려운 경우

## 2. 핵심 아이디어

**순진한 방법**: 질의마다 `a[l:r]`을 훑는다. 질의 `q`개, 평균 길이 `n/3`이면 `O(nq)`. `n = q = 10⁵`면 `10¹⁰`.

**구간을 재활용하기**: 현재 구간이 `[cl, cr)`일 때 다음 질의의 `[l, r)`로 가려면 양 끝을 한 칸씩 옮기면 된다. 한 칸 옮길 때마다 원소 하나를 `add` 또는 `remove`한다. 질의를 읽은 순서대로 하면 끝점이 이리저리 널뛰어 `O(nq)`이지만, **끝점이 덜 움직이도록 질의의 순서를 바꾸는 것**이 모스 알고리즘이다.

**순서 정하기**: 왼쪽 끝 `l`을 크기 `B`의 블록으로 나눈다. 질의를 `(l이 속한 블록 번호, r)`의 오름차순으로 정렬한다.

- 같은 블록 안에서는 `r`이 오름차순이라 오른쪽 끝은 **한 방향으로만** 움직이고(블록당 최대 `n`칸), 왼쪽 끝은 같은 블록 안에서만 움직이므로 질의당 최대 `B`칸.
- 블록이 바뀔 때만 오른쪽 끝이 되돌아오지만 블록 수만큼(`n/B`번)이다.
- 총 이동: 왼쪽 `q·B` + 오른쪽 `(n/B)·n`. `B = n/√q`로 두면 `q·n/√q + n·√q = 2n√q`, 즉 `O(n√q)`. `n ≈ q`면 `O(n√n)`.

**홀짝 최적화**: 블록 번호가 짝수면 `r` 오름차순, 홀수면 **내림차순**으로 정렬하면 블록이 바뀔 때 오른쪽 끝이 곧바로 이어서 되돌아가므로 오른쪽 끝의 이동이 줄어든다. 이 환경에서 `n = q = 10⁵`일 때 총 이동이 4194만 칸에서 2639만 칸으로 줄었습니다(약 37%).

**넓히기를 먼저**: 한 질의로 넘어갈 때 `cl`을 왼쪽으로 늘리고 `cr`을 오른쪽으로 늘리는 `add`를 먼저 하고, 줄이는 `remove`를 나중에 한다. 줄이기를 먼저 하면 구간 밖의 원소를 먼저 "빼게" 되어 횟수가 음수가 되는 순간이 생긴다. 합이나 종류 수는 우연히 맞아도 횟수 표를 쓰는 상태(최빈값 등)는 깨진다.

**조건**: 구간의 답이 원소들의 **다중집합**에만 의존하고(순서 무관), `add`와 `remove`가 서로 되돌릴 수 있어야 한다. 최댓값처럼 `remove`가 어려운 값은 롤백 모스를 쓴다.

### 무엇을 저장하고 어떻게 움직이나

모든 구간 질의를 미리 알고 있을 때 처리 순서를 바꿔 현재 구간의 이동량을 줄입니다. 상태는 현재 창의 빈도·서로 다른 값의 수 등이고, 왼쪽·오른쪽 원소 하나를 추가·제거하는 연산을 만듭니다. 각 질의의 원래 번호도 저장합니다.

### 왜 이 방법이 맞는가

질의 순서는 바뀌어도 각 요청의 구간을 정확히 만든 뒤 상태에서 답을 읽으면 결과는 같습니다. 블록순 정렬이 경계 이동 횟수를 줄입니다. 값 갱신이 섞인 온라인 문제에는 기본 모스 알고리즘을 그대로 적용할 수 없습니다.

### 작은 예제로 검산하기

현재 구간 `[1,4)`에서 다음 `[2,5)`로 이동하려면 인덱스 1을 제거하고 4를 추가합니다. 빈도가 0→1일 때 종류 수를 늘리고 1→0일 때 줄입니다. 질의 답은 처리 순서가 아니라 저장한 원래 번호로 출력합니다.

## 3. 손으로 따라가기

수열 `a = [1, 2, 1, 3, 2, 3, 1, 2]` (`n = 8`), 질의 4개(0부터, 반열린): `q0 = [0, 3)`, `q1 = [5, 8)`, `q2 = [2, 6)`, `q3 = [1, 4)`. 블록 크기 `B = round(8/√4) = 4`.

### 순서

| 질의 | `l` | 블록 `l // 4` | `r` |
|---|---|---|---|
| q0 | 0 | 0 | 3 |
| q3 | 1 | 0 | 4 |
| q2 | 2 | 0 | 6 |
| q1 | 5 | 1 | 8 |

블록 0은 `r` 오름차순(3, 4, 6), 블록 1은 그다음. 처리 순서는 `q0, q3, q2, q1`. 입력 순서(`q0, q1, q2, q3`)로 처리하면 끝점이 움직이는 칸 수가 21인데, 이 순서에서는 13입니다.

### 끝점 이동

`+i`는 `a[i]`를 넣기, `−i`는 빼기입니다. 현재 구간은 처음에 비어 있습니다.

| 처리하는 질의 | 구간 | 하는 일 | 구간의 값들 | 서로 다른 값 |
|---|---|---|---|---|
| q0 | `[0, 3)` | `+0 +1 +2` | `1, 2, 1` | 2 |
| q3 | `[1, 4)` | `+3` `−0` | `2, 1, 3` | 3 |
| q2 | `[2, 6)` | `+4 +5` `−1` | `1, 3, 2, 3` | 3 |
| q1 | `[5, 8)` | `+6 +7` `−2 −3 −4` | `3, 1, 2` | 3 |

각 질의에서 `+`가 먼저, `−`가 나중에 나옵니다. 원래 입력 순서로 되돌려 답을 쓰면 `[2, 3, 3, 3]`입니다.

같은 구간에서 "값이 같은 두 위치 쌍의 수"를 세려면 `add`에서 `pairs += count[v]`를 먼저 하고 `count[v] += 1`, `remove`에서 `count[v] -= 1` 한 뒤 `pairs -= count[v]`를 합니다. 위 네 질의의 답은 `[1, 0, 1, 0]` (q0의 `1, 2, 1`에서 `1`이 두 번, q2의 `3`이 두 번).

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 구간은 0부터 반열린 `[l, r)`.

```python
def mo_order(n, queries):
    q = len(queries)
    block = max(1, round(n / max(1, q) ** 0.5))

    def key(index):
        left, right = queries[index]
        b = left // block
        return (b, right if b % 2 == 0 else -right)     # 홀짝 최적화

    return sorted(range(q), key=key)


def mo(n, queries, add, remove, answer):
    result = [None] * len(queries)
    cl = cr = 0                                          # 현재 구간 [cl, cr)
    for index in mo_order(n, queries):
        left, right = queries[index]
        while cl > left:                                 # 넓히는 쪽을 먼저
            cl -= 1
            add(cl)
        while cr < right:
            add(cr)
            cr += 1
        while cl < left:
            remove(cl)
            cl += 1
        while cr > right:
            cr -= 1
            remove(cr)
        result[index] = answer()
    return result
```

- `distinct_counts(a, queries)`: 서로 다른 값의 수. 값을 먼저 `0..k−1`로 번호 매겨(어떤 해시 가능한 값이든) 횟수 배열을 씁니다.
- `equal_pair_counts(a, queries)`: 같은 값의 쌍의 수.
- `pointer_moves(order, queries)`: 어떤 순서로 처리할 때 끝점이 움직이는 총 칸 수. 순서를 비교해 볼 때 씁니다.
- 직접 실행하면 구간 종류 수 예제 형식 — `N`, 수열, `M`, `M`개의 질의(1부터, 양 끝 포함) — 을 받아 각 구간의 서로 다른 값의 수를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n√q + q log q)**(정렬 포함, `add`/`remove`가 `O(1)`일 때), **공간 O(n + q)**. 이 문서에서는 `n ≈ q`로 보고 `O(n√n)`이라고도 부릅니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 끝점 이동 칸 수입니다(무작위 구간).

| `n = q` | 읽은 순서대로 | 모스 순서 | 이론 `n√q` |
|---|---|---|---|
| 20000 | 2억 3037만 | 236만 | 283만 |
| 100000 | 57억 5004만 | 2640만 | 3162만 |

- 블록 크기를 잘못 잡으면 순서의 이점이 사라집니다. `n = q = 10⁵`에서 `B = 316`은 2639만 칸, `B = 1`은 15억 6786만 칸, `B = n`은 22억 7881만 칸이었습니다.
- 시간(`distinct_counts`, 값 범위 0~1000, 두 번 중 최소): `n = q = 10⁵`에서 3.35초, `n = q = 2·10⁵`에서 9.11초. `n = q = 5000`에서는 모스가 0.045초, 질의마다 `len(set(a[l:r]))`을 쓰면 0.196초였습니다. **파이썬에서는 `n = q = 10⁵`가 한계 근처**이고, 시간 제한이 빠듯한 문제는 통과하기 어려울 수 있습니다. 로컬에서 정확성을 확인하는 용도로는 충분합니다.

## 6. 자주 하는 실수

- **질의를 읽은 순서대로 답을 저장함**: 정렬해서 처리했으니 `result[원래 번호]`에 저장해야 합니다.
- **`remove`를 먼저 함**: 구간 밖 원소를 빼서 횟수가 음수가 됩니다. `add` 4줄을 먼저, `remove` 4줄을 나중에.
- **블록 크기**: `√n`으로 고정하면 질의 수가 `n`과 많이 다를 때 손해입니다. `n/√q`가 이론적 최적입니다. 0이 되지 않게 `max(1, …)`.
- **홀짝 최적화의 부호**: 홀수 블록에서 `r`을 `−r`로 정렬해야 합니다. 둘 다 오름차순이면 이점이 사라집니다(그래도 정답은 나옵니다).
- **구간의 열림/닫힘**: 문제의 `[l, r]`(1부터, 양 끝 포함)을 `[l − 1, r)`로 바꾸는 것을 빼먹기 쉽습니다. 이 구현은 반열린이 기준입니다.
- **`add`와 `remove`가 대칭이 아님**: 쌍의 수를 셀 때 `add`는 `count`를 올리기 *전*에, `remove`는 내린 *후*에 더해야 합니다.
- **값 범위가 큼**: 횟수 배열을 값으로 직접 색인하려면 값을 먼저 번호 매겨야 합니다(`distinct_counts`가 하는 것).
- **갱신이 섞인 문제**: 수열의 값이 바뀌면 이 알고리즘만으로는 안 됩니다(시간 축을 더한 3차원 모스).
- **같은 질의가 반복**: 정렬 키가 같아도 문제없지만 결과 배열에 모두 채워야 합니다.
- **느린 `add`/`remove`**: 이 함수들이 `O(1)`이어야 합니다. `O(log n)`이면 전체가 `O(n√n log n)`.

## 7. 변형과 응용

- **시간 축 모스**: 갱신이 있는 수열에서 질의를 `(l 블록, r 블록, 시간)`으로 정렬하고 세 번째 끝점도 움직입니다. `O(n^(5/3))`.
- **롤백 모스**: `remove`가 어려운 값(구간 최댓값, 같은 값 사이의 최대 거리)은 왼쪽 블록을 기준으로 오른쪽만 늘리고, 질의마다 왼쪽 부분을 임시로 더했다가 되돌립니다.
- **트리 위의 모스**: 오일러 투어로 트리를 일차원으로 펴면 서브트리와 경로 질의를 구간 질의로 바꿀 수 있습니다 ([LCA](../../03-graph-advanced/lca/)).
- **다른 오프라인 기법**: 서로 다른 값의 수는 질의를 `r` 순으로 정렬하고 [펜윅 트리](../../01-range-query-structures/fenwick-tree/)에 "각 값의 마지막 위치"만 1로 두는 방법으로 `O(n log n)`에 풉니다. `n√n`보다 훨씬 적은 연산이라 파이썬에서는 이쪽이 더 현실적입니다.
- **블록 분할 자료구조와의 조합**: 갱신이 `O(1)`, 질의가 `O(√n)`인 구조를 모스에 붙이면(예: 최빈값의 빈도) `add`/`remove`는 `O(1)`이고 `answer`만 `O(√n)`이어도 됩니다.
- **제곱근 분할과의 관계**: 모스 알고리즘은 "질의를 `√`로 묶는" 제곱근 분할입니다 ([제곱근 분할](../sqrt-decomposition/)).
