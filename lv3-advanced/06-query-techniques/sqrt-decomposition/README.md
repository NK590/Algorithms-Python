# 제곱근 분할 (Sqrt Decomposition)

> **한 줄 요약**: 배열을 크기 `B ≈ √n`의 **블록**으로 나누고, 구간 질의를 "온전히 덮이는 블록들 + 양 끝에 걸친 조각"으로 처리한다. 온전한 블록은 블록마다 미리 계산해 둔 값(합, 정렬된 복사본, lazy 태그 …)으로 한 번에, 조각은 원소를 하나씩 본다. 연산 하나가 `O(√n)`이라 세그먼트 트리보다 느리지만, **구현이 짧고 블록에 무엇이든 담을 수 있어서** 트리로 합치기 어려운 정보에도 쓴다.

## 1. 언제 쓰나 (문제 신호)

- 구간 합·구간 더하기 같은 연산인데 세그먼트 트리를 짜기엔 귀찮고 `n ≤ 10⁵` 정도라 `O(√n)`으로 충분할 때
- "구간에서 `k`보다 큰 원소의 수", "구간의 정렬된 순서가 필요" + **한 원소 갱신** — 노드를 합치기 어려운 정보(정렬된 목록)를 블록 안에 둘 때
- 연산이 이상해서 세그먼트 트리의 합치기 규칙을 만들기 어려울 때(블록 안에서는 마음대로 처리)
- 질의를 `√q`개씩 모아서 한꺼번에 처리하는 **배치(재구성)** 기법
- 값의 빈도가 `√` 이상인 것/이하인 것을 나누는 "무거운/가벼운" 분할

## 2. 핵심 아이디어

**블록**: 길이 `n`의 배열을 길이 `B`의 블록 `⌈n/B⌉`개로 자른다. 인덱스 `i`의 블록은 `i // B`.

구간 `[l, r)` 질의는 세 부분으로 갈라진다.

```
idx:    0 1 2 | 3 4 5 | 6 7 8        B = 3, 구간 [2, 7)
block:    0   |   1   |   2
          .  .[#]|[# # #]|[# .  .]
              ^      ^       ^
         왼쪽 조각  온전한 블록  오른쪽 조각
```

- **조각**: 블록 하나를 다 덮지 못하는 양 끝은 원소를 직접 훑는다 — 최대 `2B`개.
- **온전한 블록**: 블록의 요약 값을 쓴다 — 최대 `n/B`개.
- 비용 `B + n/B`가 `B = √n`에서 최소: **질의당 `O(√n)`**.

**구간 더하기 + 구간 합** (`SqrtSum`): 블록마다 두 값을 둔다.
- `total[b]`: 블록 안 원소의 합(더해진 값까지 반영)
- `lazy[b]`: 블록의 모든 원소에 **아직 `a`에는 더하지 않고** 얹어 둔 값

구간 더하기는 조각의 원소에는 `a[i] += v`와 `total` 갱신, 온전한 블록에는 `lazy[b] += v`와 `total[b] += v·B`만 한다. 합 질의는 조각은 `a[i] + lazy[블록]`을 더하고, 온전한 블록은 `total[b]`를 더한다. 세그먼트 트리의 [지연 전파](../../01-range-query-structures/lazy-propagation/)와 같은 생각이지만 "내려보내기" 없이 태그가 블록에 머문다.

**한 원소 갱신 + 구간에서 `k`보다 큰 원소의 수** (`SqrtCountGreater`): 블록마다 **정렬된 복사본**을 둔다.
- 갱신: 옛 값을 복사본에서 찾아 지우고(`bisect`) 새 값을 제자리에 넣는다(`insort`). 리스트 한 번 밀기라 `O(B)`지만 C 속도다.
- 질의: 조각은 직접 센다. 온전한 블록은 `bisect_right`로 `k` 이하의 개수를 구해 `len − 그 값`.

**블록 크기**: 한쪽 연산이 훨씬 자주 나오면 `B`를 달리 잡을 수 있다. 질의가 비싸고 갱신이 싼 구조에서는 `B`를 작게 해 블록 수(`n/B`)를 늘리고 싶을 수도 있지만, 아래 측정에서는 `√n` 근처가 가장 빨랐다.

### 무엇을 저장하고 어떻게 움직이나

배열을 대략 sqrt(n) 크기의 블록으로 나누고 블록별 요약을 저장합니다. 질의의 양 끝 불완전 블록은 원소를 직접 보고 가운데 완전 블록은 요약값으로 처리합니다. 구현 단순성과 갱신·질의 균형을 얻는 방법입니다.

### 왜 이 방법이 맞는가

블록 크기 B에서 경계 직접 순회는 O(B), 전체 블록 수는 O(n/B)입니다. 두 비용을 합친 B+n/B를 균형 잡으면 B가 sqrt(n) 정도입니다. 어떤 요약을 갱신할 수 있는지에 따라 점 갱신과 구간 갱신 설계가 달라집니다.

### 작은 예제로 검산하기

길이 10 배열을 크기 3 블록으로 나누고 `[2,8)`을 묻는다면 인덱스 2와 6·7은 직접, 3~5는 블록 합으로 처리합니다. 마지막 블록은 더 짧을 수 있으므로 항상 B개라고 가정하면 범위를 벗어납니다.

## 3. 손으로 따라가기

### 구간 더하기·구간 합: `a = [1, 2, 3, 4, 5, 6, 7, 8, 9]`, `B = 3`

| | 블록 0 (`1 2 3`) | 블록 1 (`4 5 6`) | 블록 2 (`7 8 9`) |
|---|---|---|---|
| `total` | 6 | 15 | 24 |
| `lazy` | 0 | 0 | 0 |

**`add(2, 7, 10)`** (`[2, 7)`, 블록 0의 끝 1칸 + 블록 1 전체 + 블록 2의 앞 1칸):
- 왼쪽 조각: 인덱스 2 → `a[2] = 13`, `total[0] += 10·1`.
- 온전한 블록 1: `lazy[1] += 10`, `total[1] += 10·3`.
- 오른쪽 조각: 인덱스 6 → `a[6] = 17`, `total[2] += 10·1`.

| | 블록 0 | 블록 1 | 블록 2 |
|---|---|---|---|
| `a` | `1 2 13` | `4 5 6` (원래 값) | `17 8 9` |
| `total` | 16 | 45 | 34 |
| `lazy` | 0 | 10 | 0 |

**`sum(2, 7)`**: 왼쪽 조각 `a[2] + lazy[0]·1 = 13`, 온전한 블록 `total[1] = 45`, 오른쪽 조각 `a[6] + lazy[2]·1 = 17` → `13 + 45 + 17 = 75`. 직접 더해도 `13+14+15+16+17 = 75`. 전체 `sum(0, 9) = 16 + 45 + 34 = 95`. 블록 1의 실제 값은 `a[i] + lazy[1]`이므로 `get(3) = 4 + 10 = 14`.

### 세기: `a = [3, 1, 4, 1, 5, 9, 2, 6, 5]`, `B = 3`

정렬된 복사본: 블록 0 `[1, 3, 4]`, 블록 1 `[1, 5, 9]`, 블록 2 `[2, 5, 6]`.

**`count_greater(1, 8, 4)`** (`[1, 8)`에서 4보다 큰 것):
- 왼쪽 조각 인덱스 1, 2 (`1, 4`): 4보다 큰 것 0개.
- 온전한 블록 1: `[1, 5, 9]`에서 `bisect_right(4) = 1`이므로 `3 − 1 = 2`개.
- 오른쪽 조각 인덱스 6, 7 (`2, 6`): 1개.
- 합계 3 (`5, 9, 6`).

**`update(4, 0)`**: 블록 1의 복사본에서 옛 값 5를 지우고(`[1, 9]`) 0을 넣는다(`[0, 1, 9]`). 같은 질의를 다시 하면 블록 1에서 `[0, 1, 9]`의 4보다 큰 것은 1개 → 합계 2.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 구간은 0부터 반열린 `[l, r)`.

```python
class SqrtSum:
    def __init__(self, a, block=None):
        self.n = len(a)
        self.block = block or max(1, isqrt(self.n))
        self.a = list(a)
        count = (self.n + self.block - 1) // self.block
        self.lazy = [0] * count
        self.total = [sum(self.a[b * self.block:(b + 1) * self.block]) for b in range(count)]

    def add(self, left, right, value):
        ...
        first, last = left // block, (right - 1) // block
        if first == last:                                    # 한 블록 안: 직접
            for i in range(left, right): self.a[i] += value
            self.total[first] += value * (right - left)
            return
        for i in range(left, (first + 1) * block): self.a[i] += value   # 왼쪽 조각
        self.total[first] += value * ((first + 1) * block - left)
        for b in range(first + 1, last):                                # 온전한 블록: lazy 만
            self.lazy[b] += value
            self.total[b] += value * block
        for i in range(last * block, right): self.a[i] += value         # 오른쪽 조각
        self.total[last] += value * (right - last * block)
```

- `SqrtSum.sum(l, r)`, `SqrtSum.get(i)`.
- `SqrtCountGreater.update(i, value)`, `SqrtCountGreater.count_greater(l, r, k)`.
- 구간이 범위를 벗어나면 `ValueError`. 빈 구간은 아무 일도 하지 않습니다.
- 직접 실행하면 구간 빈도 갱신 예제 형식 — `N`, 수열, `M`, 질의 `1 i v`(`A[i] = v`) 또는 `2 l r k`(`A[l..r]`에서 `k`보다 큰 원소의 수, 모두 1부터·양 끝 포함) — 을 처리해 2번 질의의 답을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **연산 하나 `O(√n)`**(`SqrtCountGreater`의 질의는 `O(B + (n/B)·log B)`), **공간 `O(n)`**. 구축 `O(n)` 또는 `O(n log B)`(정렬). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(`n = 10⁵`, 연산 5만 번).

| 구조 | 연산 | 시간 |
|---|---|---|
| `SqrtSum` (`B = 316`) | 구간 더하기 5만 번 | 1.69초 |
| `SqrtSum` (`B = 316`) | 구간 합 5만 번 | 0.35초 |
| `SqrtCountGreater` (`B = 316`) | 갱신 5만 번 | 0.08초 |
| `SqrtCountGreater` (`B = 316`) | 질의 5만 번 | 2.14초 |
| 단순하게 `a[l:r]`을 훑기 | 질의 100번 → 5만 번 환산 | 약 49.5초 (**추정**) |

- 구간 더하기가 합보다 느린 이유는 조각과 온전한 블록을 모두 파이썬 `for` 문으로 훑기 때문입니다(합은 슬라이스의 `sum`이 C 속도).
- 블록 크기에 따른 `SqrtCountGreater` 시간(질의 5만 번): `B = 100` 3.42초, **`B = 316` 2.14초**, `B = 1000` 3.38초, `B = 3000` 7.72초. 갱신은 어느 쪽이든 0.08~0.11초로 거의 같았습니다. `√n` 근처가 가장 빠르고 너무 작거나 크면 한쪽이 병목이 됩니다.
- `n ≤ 10⁵`, 연산 `10⁵`번까지는 파이썬에서도 몇 초 안에 됩니다. 연산이 `10⁶`번이면 세그먼트 트리나 펜윅 트리로 가야 합니다.

## 6. 자주 하는 실수

- **한 블록 안에 구간이 들어가는 경우를 빼먹음**: `first == last`일 때 왼쪽 조각과 오른쪽 조각이 같은 블록이라 따로 처리하지 않으면 두 번 더합니다.
- **`lazy`를 조각에 반영하지 않음**: 조각을 직접 훑을 때 `a[i]`에 블록의 `lazy`를 더해야 실제 값이 됩니다. 반대로 조각을 갱신할 때는 `a[i]`에만 더하고 `lazy`는 건드리지 않습니다.
- **마지막 블록이 짧음**: `n`이 `B`의 배수가 아니면 마지막 블록은 `B`보다 짧습니다. 이 구현은 구간의 양 끝 블록을 항상 "조각"으로 처리하므로 안전하지만, 끝 블록을 온전한 블록으로 취급하는 구현에서 `value * B`처럼 크기를 `B`로 가정하면 틀립니다.
- **반열린/닫힌 구간**: 오른쪽 조각이 `range(last·B, right)`(반열림). 문제의 `[l, r]`(1부터)이면 `[l − 1, r)`로 바꿉니다.
- **블록 크기 0**: `n = 0`이나 1에서 `isqrt`가 0을 줄 수 있어 `max(1, …)`.
- **정렬된 복사본의 동기화**: 갱신할 때 `a[i]`와 블록의 복사본을 **둘 다** 바꾸지 않으면 질의가 틀립니다. 같은 값으로 두 번 갱신해도 복사본이 어긋나면 안 됩니다.
- **옛 값을 찾을 때 `bisect_left`**: 같은 값이 여럿이어도 그중 하나를 지우면 되므로 `bisect_left`로 찾은 위치를 지웁니다.
- **너무 많은 연산에 사용**: `10⁶`번 이상은 `O(log n)` 구조를 쓰세요.
- **정수 범위**: C++/Java에서는 구간 합이 `int`를 넘을 수 있습니다(파이썬은 해당 없음).

## 7. 변형과 응용

- **질의 배치 처리**: 연산을 `√q`개씩 모아, 모은 동안은 "변경 목록"을 따로 두고 질의에서 보정하며, 한 묶음이 끝나면 전체를 다시 계산합니다(재구성). 동적 변경이 있는 정적 알고리즘을 쓸 때 유용합니다.
- **블록 안에 연결 리스트**: 삽입/삭제가 있는 "리스트의 `k`번째" 문제는 블록마다 파이썬 리스트를 두고, 블록이 너무 커지면 반으로 쪼갭니다.
- **블록 요약의 다양화**: 합 대신 최솟값(조각은 직접), 해시, 비트셋, 최빈값 등을 블록에 둘 수 있습니다. 정적 구간 최빈값은 블록 쌍(`i`부터 `j`까지의 블록)마다 답을 전처리합니다.
- **무거운/가벼운 분할**: 빈도가 `√n` 이상인 값은 최대 `√n`종류라 따로 표를 만들고, 나머지는 직접 훑습니다.
- **세그먼트 트리와의 비교**: 세그먼트 트리는 `O(log n)`이지만 합치기 규칙이 필요합니다. "정렬된 복사본" 같은 정보를 트리로 하려면 머지 소트 트리·웨이블릿 트리가 필요합니다(Lv4).
- **오프라인 질의**: 갱신이 없고 질의를 미리 안다면 [모스 알고리즘](../mos-algorithm/)이 같은 `√` 분할의 다른 모양입니다.
