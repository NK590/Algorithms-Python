# 접미사 배열과 LCP 배열 (Suffix Array, LCP Array)

> **한 줄 요약**: 문자열의 **모든 접미사를 사전순으로 정렬한 순서**(접미사 배열 `sa`)와, 사전순으로 이웃한 두 접미사의 **최장 공통 접두사 길이**(LCP 배열 `lcp`)를 만든다. 부분 문자열은 모두 어떤 접미사의 접두사이므로, 이 두 배열만 있으면 **서로 다른 부분 문자열의 수, 가장 긴 반복 부분 문자열, 두 문자열의 가장 긴 공통 부분 문자열, 패턴 검색**이 정렬된 배열 위의 계산으로 바뀐다.

## 1. 언제 쓰나 (문제 신호)

- "**서로 다른 부분 문자열의 개수**" (길이 10⁵~10⁶)
- "두 번 이상 나오는 **가장 긴 부분 문자열**", "`k`번 이상 나오는 가장 긴 부분 문자열"
- "두 문자열의 **가장 긴 공통 부분 문자열**" (길이 10⁵)
- 본문은 고정이고 **패턴이 계속 바뀌는** 검색 — 본문을 한 번 정리해 두고 패턴마다 `O(m log n)`
- "사전순으로 `k`번째 부분 문자열", "임의의 두 접미사의 공통 접두사 길이"를 `O(1)`에
- 부분 문자열을 모두 비교해야 해서 [해시](../../../lv2-intermediate/07-strings/rabin-karp/)의 충돌이 부담스러운 경우

## 2. 핵심 아이디어

**접미사 배열**: `s = "banana"`의 접미사는 `s[0:]`, `s[1:]`, …, `s[5:]` 6개. 이를 사전순으로 정렬하고 **시작 위치**만 적은 것이 `sa`다. `sa = [5, 3, 1, 0, 4, 2]`는 `a < ana < anana < banana < na < nana`의 시작 위치다.

**왜 유용한가**: 같은 접두사를 가진 접미사들은 정렬된 배열에서 **연속된 구간**을 이룬다. 그래서 "어떤 문자열 `t`로 시작하는 접미사 = `t`가 나타나는 모든 위치" 는 `sa` 위의 구간이고, 이진 탐색으로 찾는다.

**순진한 구축**: 접미사를 직접 잘라 `sorted(range(n), key=lambda i: s[i:])`. 슬라이스를 `n`개 한꺼번에 만들어 메모리가 `O(n²)`(길이 10⁵면 약 5GB, **추정**)라 큰 입력에는 못 쓴다.

**접두사 배가법 (prefix doubling)**: 길이 `2^k`의 접두사만 보고 정렬한 **순위** `rank`가 있으면, 길이 `2^(k+1)`의 순위는 `(rank[i], rank[i + 2^k])` 쌍으로 정렬하면 나온다. 앞 절반과 뒤 절반이 각각 이미 순위로 요약되어 있기 때문이다. 길이 1(글자 하나)에서 시작해 모든 접미사의 순위가 서로 달라질 때까지 `k = 1, 2, 4, …`로 반복한다. 뒤 절반이 문자열 밖이면 가장 작은 순위(0)로 둔다("빈 문자열은 어떤 글자보다 작다"). 라운드는 `O(log n)`번, 라운드마다 정렬 `O(n log n)` → **O(n log² n)**.

**LCP 배열**: `lcp[i]` = `sa[i−1]`과 `sa[i]`의 최장 공통 접두사 길이(`lcp[0] = 0`). 각 쌍을 처음부터 비교하면 `O(n²)`이지만 **카사이(Kasai) 알고리즘**은 접미사를 *순위순이 아니라 위치순*으로 보면서 푼다. 접미사 `i`의 사전순 직전 접미사 `j`와의 공통 길이가 `h`이면, 접미사 `i+1`의 직전 접미사와의 공통 길이는 **적어도 `h − 1`**이다. (`s[i]`를 떼어 내도 `s[j+1:]`이 `s[i+1:]` 바로 앞쪽에 있는 접미사이면서 `h−1`만큼 일치하기 때문.) 그래서 `h`는 한 번에 1씩만 줄고 늘기만 하는 동안은 총 `n`번 이하 → **O(n)**.

**LCP 배열로 풀리는 것들**
- 서로 다른 부분 문자열의 수: 접미사 `sa[i]`가 새로 만드는 접두사는 `n − sa[i] − lcp[i]`개(앞 이웃과 겹치는 `lcp[i]`개는 이미 셌다). 합하면 `n(n+1)/2 − Σ lcp`.
- 가장 긴 반복 부분 문자열: `max(lcp)`와 그 위치의 접미사 접두사.
- 임의의 두 접미사의 LCP: 순위 사이 구간의 `lcp` 최솟값 ([희소 배열](../../01-range-query-structures/sparse-table/)로 `O(1)`).
- 두 문자열의 가장 긴 공통 부분 문자열: 사이에 구분자를 끼워 이어 붙인 뒤, **서로 다른 문자열에서 온 이웃**의 `lcp` 최댓값.

### 무엇을 저장하고 어떻게 움직이나

접미사 배열은 문자열의 모든 시작 위치를 접미사 사전순으로 정렬한 인덱스 목록입니다. LCP는 인접한 두 접미사가 공유하는 접두 길이입니다. 원문 전체를 복사하지 않고 인덱스·순위로 비교하는 것이 핵심입니다.

### 왜 이 방법이 맞는가

같은 접두사를 가진 접미사들은 정렬 순서에서 연속합니다. 새 접미사가 만드는 부분 문자열 중 바로 앞 접미사와 겹치는 접두 LCP개를 빼면 새로운 문자열의 수를 셀 수 있습니다. 임의 두 접미사의 LCP는 사이 구간의 인접 LCP 최솟값입니다.

### 작은 예제로 검산하기

`aba`의 접미사 순서는 `a`, `aba`, `ba`, 즉 인덱스 `[2,0,1]`입니다. 새 부분 문자열 수는 1+(3-1)+2=5입니다. 문자열 끝에 센티널을 넣는 구현이라면 그 접미사를 최종 답에서 제외합니다.

## 3. 손으로 따라가기: `s = "banana"`

### 접미사 배열과 LCP

| 순위 `i` | `sa[i]` | 접미사 | `lcp[i]` (바로 위 접미사와) |
|---|---|---|---|
| 0 | 5 | `a` | 0 |
| 1 | 3 | `ana` | 1 (`a`) |
| 2 | 1 | `anana` | 3 (`ana`) |
| 3 | 0 | `banana` | 0 |
| 4 | 4 | `na` | 0 |
| 5 | 2 | `nana` | 2 (`na`) |

`sa = [5, 3, 1, 0, 4, 2]`, `lcp = [0, 1, 3, 0, 0, 2]`.

### 접두사 배가법으로 만들기

글자 순위 `a=0, b=1, n=2` → `rank = [1, 0, 2, 0, 2, 0]` (길이 1의 접두사 순위).

**라운드 `k = 1`** (길이 2의 접두사): 키 = `(rank[i], rank[i+1])`, 문자열 밖이면 `−1`.

| `i` | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 접두사 | `ba` | `an` | `na` | `an` | `na` | `a` |
| 키 | (1, 0) | (0, 2) | (2, 0) | (0, 2) | (2, 0) | (0, −1) |

정렬하면 `a < an = an < ba < na = na`. `sa = [5, 1, 3, 0, 2, 4]`(동점은 임의 순서), 새 `rank = [2, 1, 3, 1, 3, 0]`. 아직 `an`끼리, `na`끼리 같다.

**라운드 `k = 2`** (길이 4): 키 = `(rank[i], rank[i+2])`.

| `i` | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 접두사 | `bana` | `anan` | `nana` | `ana` | `na` | `a` |
| 키 | (2, 3) | (1, 1) | (3, 3) | (1, 0) | (3, −1) | (0, −1) |

모두 다르다. 정렬해 `sa = [5, 3, 1, 0, 4, 2]`, `rank = [3, 2, 5, 1, 4, 0]`. 순위가 모두 달라졌으니 끝(2 라운드).

### 카사이로 LCP 구하기

`rank = [3, 2, 5, 1, 4, 0]` (접미사 `i`의 순위). `h`는 현재 이어 가는 공통 길이.

| `i` | 접미사 | 순위 | 사전순 직전 `j` | 시작 `h` | 늘린 뒤 `h` | `lcp[순위]` | 다음으로 넘길 `h` |
|---|---|---|---|---|---|---|---|
| 0 | `banana` | 3 | 1 (`anana`) | 0 | 0 (`b`≠`a`) | `lcp[3] = 0` | 0 |
| 1 | `anana` | 2 | 3 (`ana`) | 0 | 3 (`ana`=`ana`, 직전이 끝남) | `lcp[2] = 3` | 2 |
| 2 | `nana` | 5 | 4 (`na`) | 2 | 2 (직전이 끝남) | `lcp[5] = 2` | 1 |
| 3 | `ana` | 1 | 5 (`a`) | 1 | 1 (직전이 끝남) | `lcp[1] = 1` | 0 |
| 4 | `na` | 4 | 0 (`banana`) | 0 | 0 (`n`≠`b`) | `lcp[4] = 0` | 0 |
| 5 | `a` | 0 | 없음 | - | - | - | - |

직접 비교한 글자는 `i = 1`의 3개뿐입니다. `i = 2, 3`은 `h`를 이어받아 추가 비교가 없었습니다.

### 활용

- **서로 다른 부분 문자열 수**: `6·7/2 − (0+1+3+0+0+2) = 21 − 6 = 15`.
- **가장 긴 반복 부분 문자열**: `lcp`의 최댓값 3이 순위 2에 있고 그 접미사는 `anana`이므로 `ana` (`banana`에서 1번과 3번 위치에서 겹쳐 나옴).
- **패턴 `"ana"` 찾기**: `sa` 위에서 `ana`로 시작하는 접미사는 순위 1(`ana`, 위치 3)과 순위 2(`anana`, 위치 1) → 위치 `[1, 3]`. 이진 탐색 두 번으로 순위 구간 `[1, 3)`을 구한다.
- **두 접미사의 LCP**: 접미사 1(`anana`, 순위 2)과 3(`ana`, 순위 1) → 순위 사이 `lcp[2..2] = 3`. 접미사 0(`banana`, 순위 3)과 2(`nana`, 순위 5) → `min(lcp[4], lcp[5]) = min(0, 2) = 0`.
- **공통 부분 문자열**: `"xabcdy"`와 `"zabcdw"` → 합친 배열에서 서로 다른 문자열의 이웃 쌍의 `lcp` 최댓값 4, `abcd`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 입력은 문자열이어도 정수 리스트여도 됩니다.

```python
def suffix_array(s):
    n = len(s)
    if n == 0:
        return []
    rank = _compress(s)                          # 글자 -> 0..(종류 수 - 1)
    sa = list(range(n))
    k = 1
    while True:
        base = n + 1
        key = [rank[i] * base + (rank[i + k] + 1 if i + k < n else 0) for i in range(n)]   # (앞, 뒤) 순위 쌍을 정수 하나로
        sa.sort(key=key.__getitem__)
        new_rank = [0] * n
        for position in range(1, n):
            new_rank[sa[position]] = new_rank[sa[position - 1]] + (key[sa[position]] != key[sa[position - 1]])
        rank = new_rank
        if rank[sa[-1]] == n - 1:                # 모든 접미사의 순위가 달라졌다
            return sa
        k *= 2


def lcp_array(s, sa):
    n = len(s)
    rank = [0] * n
    for position, start in enumerate(sa):
        rank[start] = position
    lcp = [0] * n
    h = 0
    for i in range(n):                           # 접미사를 위치 순으로 본다
        if rank[i] > 0:
            j = sa[rank[i] - 1]                  # 사전순으로 바로 앞 접미사
            while j + h < n and s[i + h] == s[j + h]:
                h += 1
            lcp[rank[i]] = h
            if h > 0:
                h -= 1                           # 다음 위치의 lcp 는 적어도 h - 1
    return lcp
```

- `count_distinct_substrings(s)`, `longest_repeated_substring(s)`, `longest_common_substring(a, b)`: 위의 활용. 같은 길이면 사전순으로 앞서는 것을 돌려줍니다.
- `find_occurrences(s, sa, pattern)`: `bisect`에 `key=`를 주어 접미사를 패턴 길이로 잘라 비교하는 이진 탐색 두 번. 시작 위치를 오름차순으로 돌려줍니다.
- `LcpQuery(s)`: 임의의 두 접미사의 LCP를 `O(1)`에 (`lcp` 배열 위의 희소 배열). 전처리 `O(n log n)`.
- 직접 실행하면 문자열 하나를 받아 접미사 배열(1부터)과, 첫 칸이 `x`인 LCP 배열을 출력합니다 (접미사 배열 출력 예제 형식).
- 정수 키 하나로 쌍을 합친 것(`rank·(n+1) + 뒤 순위`)이 속도에 중요합니다. 튜플 리스트로 정렬하면 몇 배 느립니다.

## 5. 복잡도와 입력 크기 가이드

- **접미사 배열 O(n log² n)** (이 구현: 라운드 `O(log n)`번 × 정렬 `O(n log n)`), 기수 정렬로 라운드를 `O(n)`으로 줄이면 `O(n log n)`, SA-IS는 `O(n)`. **카사이 LCP: O(n)**. **공간 O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 입력 | `suffix_array` | `lcp_array` |
|---|---|---|
| 무작위 `a`/`b` 20만 글자 | 0.71초 | 0.11초 |
| 무작위 영소문자 20만 글자 | 0.40초 | 0.14초 |
| `"a" * 200000` | 0.95초 | 0.06초 |
| 무작위 `a`/`b` 50만 글자 | 2.34초 | 0.41초 |
| `"a" * 500000` | 2.5초 | - |

- 같은 글자가 이어지는 입력이 가장 오래 걸립니다(순위가 늦게 갈라져 라운드가 많음). 무작위 입력은 몇 라운드 만에 끝납니다.
- 접미사를 슬라이스로 잘라 정렬하는 방법과 비교하면, 무작위 `a`/`b` 5000글자에서는 슬라이스 정렬이 0.004초, 배가법이 0.007초로 비슷하고, `"a" * 20000`에서는 슬라이스 정렬 0.117초, 배가법 0.068초였습니다. 이 크기까지는 어느 쪽이든 되지만, 슬라이스 방식은 메모리가 `O(n²)`이라 10⁵ 근처부터 못 씁니다.
- 파이썬에서 길이 5·10⁵까지 2.8초 정도이므로 문제의 시간 제한이 빠듯하면 통과하기 어려울 수 있습니다. 로컬에서 정확성을 확인하는 용도로는 충분합니다.

## 6. 자주 하는 실수

- **뒤 절반이 문자열 밖일 때의 값**: 가장 작은 순위보다 **더 작은** 값이어야 합니다. 이 구현은 순위에 1을 더하고 밖은 0으로 둡니다. 순위 0과 같게 두면 `"aa"`에서 `a`와 `aa`가 같다고 판단하고, 순위가 영영 갈라지지 않아 반복이 끝나지 않습니다.
- **쌍을 정수 하나로 합칠 때의 기수**: `rank[i]·base + 뒤`에서 `base`는 뒤 값의 최댓값보다 커야 합니다(`n + 1`). 같게 하면 다른 쌍이 같은 정수로 뭉칩니다.
- **끝나는 조건**: 순위가 모두 달라졌는지 확인합니다. 라운드를 `log n`번 고정 반복해도 되지만 같은 글자 하나로만 이루어진 문자열은 끝까지 가야 하고, 무작위는 일찍 끝납니다.
- **글자를 순위로 압축하지 않고 `ord` 값을 그대로 씀**: `base = n + 1`은 "뒤 순위가 `n` 이하"라는 가정에 기대고 있어서, 큰 `ord` 값(예: 유니코드 글자)은 서로 다른 쌍을 같은 정수로 뭉치게 합니다. 먼저 `0..종류 수−1`로 압축하세요.
- **LCP 배열의 인덱스**: `lcp[i]`는 `sa[i−1]`과 `sa[i]`의 공통 길이입니다. `lcp[i]`가 `sa[i]`와 `sa[i+1]`의 것이라고 쓰면 모든 응용이 한 칸씩 밀립니다.
- **카사이에서 `h`를 줄이는 것을 빼먹음**: `h`를 0으로 되돌리거나 줄이지 않으면 `O(n²)`이거나 틀린 답이 나옵니다. 순위가 0인 접미사(사전순 첫째)는 앞 이웃이 없습니다.
- **카사이에서 "바로 앞 접미사"**: 문자열에서 바로 앞 위치가 아니라 **사전순 바로 앞**(`sa[rank[i] − 1]`)입니다.
- **공통 부분 문자열에서 구분자**: 두 문자열 사이에 **어떤 글자보다 작고 한 번만 나오는** 값을 끼우지 않으면 공통 접두사가 경계를 넘어갑니다. 이 구현은 `ord` 값에 1을 더하고 구분자를 0으로 둡니다.
- **서로 다른 문자열에서 온 이웃만 보기**: 공통 부분 문자열은 같은 문자열 안의 이웃 쌍(예: 둘 다 첫 번째 문자열)의 `lcp`를 세면 안 됩니다.
- **출력 형식**: 접미사 배열 출력 예제은 접미사 배열을 1부터 출력하고, LCP 줄의 첫 칸은 `x`입니다.

## 7. 변형과 응용

- **`k`번째 부분 문자열**: 접미사 `sa[i]`가 새로 만드는 부분 문자열이 `n − sa[i] − lcp[i]`개이므로, 이를 누적하며 `k`가 속하는 접미사를 찾고 그 접두사를 자른다.
- **`k`번 이상 나오는 가장 긴 부분 문자열**: `lcp` 위에서 길이 `k−1`의 슬라이딩 윈도우 최솟값의 최댓값 (단조 큐, [슬라이딩 윈도우](../../../lv2-intermediate/08-search-techniques/sliding-window/)).
- **여러 문자열의 공통 부분 문자열**: 구분자로 이어 붙이고 모든 문자열이 포함된 `lcp` 윈도우를 이동한다.
- **접미사 자동자·접미사 트리**: 같은 구조를 다른 모양으로 담은 것. 접미사 자동자는 `O(n)`에 구축되고 부분 문자열 질의에 유연하지만 구현이 길다 (Lv4).
- **해시 + 이진 탐색**: "가장 긴 반복 부분 문자열" 같은 단조 문제는 길이를 이진 탐색하고 해시로 검사해 `O(n log n)`에 푼다. 구현은 쉽지만 충돌 가능.
- **Z 알고리즘과의 관계**: Z는 *전체 문자열의 접두사*와의 공통 길이만 주고, 접미사 배열은 *임의의 두 접미사*의 공통 길이를 준다 ([Z 알고리즘](../z-algorithm/)).
- **버로우즈-휠러 변환(BWT)**: 접미사 배열 순서대로 각 접미사 바로 앞 글자를 모은 것. 압축과 FM-index의 기초.
- **정수 수열**: 값이 크면 먼저 [좌표 압축](../../../lv2-intermediate/08-search-techniques/coordinate-compression/)해서 같은 코드를 씁니다.
