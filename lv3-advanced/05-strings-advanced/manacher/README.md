# 매내처 알고리즘 (Manacher's Algorithm)

> **한 줄 요약**: 문자열의 **모든 중심에서 가장 긴 회문의 반지름**을 `O(n)`에 구한다. 중심마다 양쪽으로 넓혀 보면 `aaaa…a`에서 `O(n²)`이지만, **지금까지 찾은 가장 큰 회문 안에서는 거울에 비친 위치의 답을 그대로 가져와** 시작하면 경계를 벗어날 때만 글자를 비교하므로 전체가 선형이다. 반지름 배열 하나로 가장 긴 회문 부분 문자열, 회문 부분 문자열의 개수, "구간 `[l, r)`이 회문인가"라는 질의를 모두 풀 수 있다.

## 1. 언제 쓰나 (문제 신호)

- "가장 긴 **회문 부분 문자열**" (길이 10⁵ 이상)
- "회문인 부분 문자열의 **개수**" (위치가 다르면 따로 센다)
- 구간 `[l, r]`이 회문인지 묻는 질의가 **10⁶개** — 전처리 `O(n)` 후 질의당 `O(1)`
- "문자열을 회문 조각으로 **최소 몇 번 잘라** 나눌 수 있나" 같은 DP에서 "`s[j:i]`가 회문인가"를 `O(1)`로 알아야 할 때
- "각 위치에서 끝나는(시작하는) 가장 긴 회문" 같은 모든 중심에 대한 정보

## 2. 핵심 아이디어

**반지름 배열 두 개**. 홀수 길이와 짝수 길이 회문의 중심이 다르기 때문에 따로 둔다.

- `odd[i]` = `i`를 **한가운데**로 하는 홀수 길이 회문의 수(= 반지름, 자기 자신 포함). 가장 긴 것의 길이는 `2·odd[i] − 1`.
- `even[i]` = `s[i−1]`과 `s[i]` **사이**를 가운데로 하는 짝수 길이 회문의 수. 가장 긴 것의 길이는 `2·even[i]`(`s[i−1] ≠ s[i]`이면 0).

**순진한 방법**: 중심마다 양쪽으로 넓힌다. `"aaaa…a"`면 모든 중심에서 끝까지 가므로 `O(n²)`.

**거울 아이디어**: 지금까지 찾은 회문 중 **가장 오른쪽 끝**까지 간 것을 `[l, r]`이라 하자. 새 중심 `i`가 `l ≤ i ≤ r` 안에 있으면, `[l, r]`이 회문이므로 `i`의 거울 위치 `j = l + r − i`의 모양이 `i` 주변에 똑같이 비친다.

```
idx:  0 1 2 3 4 5 6
s:    a b a c a b a        박스 [l, r] = [0, 6], 가운데 c = 3
i = 5 의 거울 위치: j = l + r − i = 1   →   odd[1] = 2 가 odd[5] 의 출발점
```

- `j`의 회문이 `[l, r]` 안에 **완전히 들어가면**(`odd[j]`가 `r − i + 1`보다 작으면) `i`의 반지름도 정확히 `odd[j]`다. 넓혀 볼 필요도 없다.
- `j`의 회문이 `l`을 넘거나 딱 닿으면 `i`의 반지름은 **적어도** `r − i + 1`(경계까지)이고, 그 바깥은 아직 모르니 직접 비교하며 넓힌다.

그래서 `k = min(odd[j], r − i + 1)`에서 시작해 `s[i−k] == s[i+k]`인 동안 `k`를 늘린다. 넓히기에 성공할 때마다 `[l, r]`의 오른쪽 끝이 밀리므로(`r`은 줄어들지 않음), **성공한 비교는 합쳐서 `n`번 이하**. 전체 `O(n)`.

짝수 길이도 같은 방식으로 한 번 더 돌린다(거울 위치가 `l + r − i + 1`로 한 칸 달라진다).

**회문 개수**: 반지름이 `k`이면 같은 중심의 회문이 길이 순서로 `k`개 있다(가장 큰 것에서 양 끝을 한 글자씩 떼어 내도 회문). 그래서 개수는 `sum(odd) + sum(even)`.

**구간 회문 질의**: `s[l:r]`(반열린)의 길이가 `L = r − l`일 때
- `L`이 홀수면 중심 `c = l + L//2`, `odd[c] ≥ L//2 + 1`이면 회문
- `L`이 짝수면 중심 `c = l + L//2`, `even[c] ≥ L//2`이면 회문

## 3. 손으로 따라가기

### 홀수 반지름: `s = "abacaba"` (`n = 7`)

`[l, r]`은 가장 오른쪽까지 간 홀수 회문(양 끝 포함). `거울 j = l + r − i`.

| `i` | 시작 `[l, r]` | 거울 `j`, `odd[j]` | 시작 `k` | 직접 넓힘 | 최종 `odd[i]` | 갱신 후 `[l, r]` |
|---|---|---|---|---|---|---|
| 0 | 없음 | 박스 밖 | 1 | 없음 (왼쪽이 끝) | 1 | `[0, 0]` |
| 1 | `[0, 0]` | 박스 밖 (`i > r`) | 1 | `a`=`a` 성공 → 2 | 2 | `[0, 2]` |
| 2 | `[0, 2]` | 0, 1 | `min(1, 1) = 1` | `b`≠`c` 실패 | 1 | `[0, 2]` |
| 3 | `[0, 2]` | 박스 밖 | 1 | `a`=`a`, `b`=`b`, `a`=`a` 성공 → 4 | 4 | `[0, 6]` |
| 4 | `[0, 6]` | 2, 1 | `min(1, 3) = 1` | `c`≠`b` 실패 | 1 | `[0, 6]` |
| 5 | `[0, 6]` | 1, 2 | `min(2, 2) = 2` | 오른쪽이 끝 | 2 | `[0, 6]` |
| 6 | `[0, 6]` | 0, 1 | `min(1, 1) = 1` | 오른쪽이 끝 | 1 | `[0, 6]` |

`odd = [1, 2, 1, 4, 1, 2, 1]`. 가운데 `c`(인덱스 3)의 반지름이 4이므로 가장 긴 회문은 길이 `2·4 − 1 = 7`, 문자열 전체입니다. 직접 넓힌 성공 비교는 `i = 1`에서 1번, `i = 3`에서 3번뿐이고, `i = 4, 5, 6`은 거울 값을 그대로 쓰고 끝났습니다.

### 거울 값이 경계에서 잘리는 경우: `s = "abab"`

`odd = [1, 2, 2, 1]`. `i = 2`(두 번째 `a`)가 `b a b`를 만들어 `[1, 3]`이 됩니다. `i = 3`의 거울은 `j = 1 + 3 − 3 = 1`이고 `odd[1] = 2`(`a b a`)인데, 박스 오른쪽 끝까지는 `r − i + 1 = 1`칸뿐이라 `k = min(2, 1) = 1`로 **잘라서** 시작해야 합니다. 거울의 반지름 2를 그대로 쓰면 박스 오른쪽 바깥, 아직 확인하지 않은 영역까지 이미 일치한 것으로 믿게 됩니다.

### 짝수 반지름: `s = "abaaba"`

`even[i]`는 `s[i−1]`과 `s[i]` 사이가 가운데입니다. `even = [0, 0, 0, 3, 0, 0]`.

- `i = 3`: `s[2] = a`, `s[3] = a`가 같고, 바깥 `b`=`b`, 그 바깥 `a`=`a` → 반지름 3, 길이 6 회문 `abaaba`. 구간 `[0, 5]`.
- `i = 4`: 거울 위치 `l + r − i + 1 = 2`의 `even[2] = 0`, 직접 보니 `s[3] = a`≠`s[4] = b`. 0.
- `i = 5`: 거울 `1`의 `even[1] = 0`. 0.

홀수 쪽은 `odd = [1, 2, 1, 1, 2, 1]`이므로 가장 긴 회문은 짝수 쪽의 길이 6입니다.

### 개수와 구간 질의

- `"abaaba"`의 회문 부분 문자열 수 = `sum(odd) + sum(even) = 8 + 3 = 11`: 한 글자 6개, `aba` 2개, `aa` 1개, `baab` 1개, `abaaba` 1개.
- `is_palindrome(1, 4)`: `s[1:4] = "baa"`, `L = 3`, `c = 1 + 1 = 2`, `odd[2] = 1 ≥ 3//2 + 1 = 2`? 아니오 → 회문이 아님.
- `is_palindrome(0, 6)`: `L = 6`, `c = 3`, `even[3] = 3 ≥ 6//2 = 3` → 회문.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def manacher(s):
    n = len(s)
    odd = [0] * n
    left, right = 0, -1                          # 가장 오른쪽까지 간 홀수 회문 [left, right]
    for i in range(n):
        k = 1 if i > right else min(odd[left + right - i], right - i + 1)   # 거울에서 출발
        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1
        odd[i] = k
        if i + k - 1 > right:
            left, right = i - k + 1, i + k - 1
    even = [0] * n
    left, right = 0, -1
    for i in range(n):
        k = 0 if i > right else min(even[left + right - i + 1], right - i + 1)
        while i - k - 1 >= 0 and i + k < n and s[i - k - 1] == s[i + k]:
            k += 1
        even[i] = k
        if i + k - 1 > right:
            left, right = i - k, i + k - 1
    return odd, even
```

- `longest_palindromic_substring(s)`: 가장 긴 회문(같은 길이면 가장 앞). `count_palindromic_substrings(s)`: 개수.
- `PalindromeChecker(s).is_palindrome(l, r)`: 반열린 구간 `s[l:r]`이 회문인지 `O(1)`.
- `min_palindrome_cuts(s)`: 회문 조각으로 나누는 최소 자르는 횟수(`O(n²)`, 판정은 `O(1)`).
- 입력은 문자열이어도 리스트여도 됩니다. 직접 실행하면 문자열 하나를 받아 가장 긴 회문 부분 문자열의 **길이**를 출력합니다.
- 글자 사이에 구분자를 끼워 홀수·짝수를 하나로 합치는 구현도 흔하지만(`#a#b#a#`), 이 파일은 두 배열을 따로 둡니다. 인덱스 변환 실수가 줄어듭니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n)**, **공간 O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 작업 | 입력 | 시간 |
|---|---|---|
| `manacher` | 무작위 `a`/`b` 10⁶ 글자 | 0.68초 |
| `manacher` | `"a" * 10⁶` | 0.68초 |
| 중심마다 넓히기 | 무작위 `a`/`b` 3000 글자 | 0.004초 |
| 중심마다 넓히기 | `"a" * 3000` | 0.85초 |
| `manacher` | `"a" * 3000` | 0.002초 |

- 무작위 문자열에서는 회문이 짧아서 단순한 넓히기도 빠릅니다. **같은 글자가 길게 이어지면** 단순한 방법은 `O(n²)`로 터지고(3000글자에서 0.85초, 3만 글자면 약 100배인 **추정** 85초), 매내처는 입력과 무관하게 일정합니다.
- 길이 `n ≤ 1000` 정도면 단순한 방법도 충분하고, 10⁵ 이상이면 매내처가 필요합니다.

## 6. 자주 하는 실수

- **거울 값을 경계에서 자르지 않음**: `min(odd[j], r − i + 1)`의 `min`을 빼먹으면 박스 밖의 값을 믿게 됩니다 (`abab`의 `i = 3`).
- **홀수와 짝수를 하나의 배열로 섞고 인덱스를 틀림**: 이 구현은 `even[i]`를 "`s[i−1]`과 `s[i]` 사이"로 정의하므로 가장 긴 짝수 회문은 `[i − even[i], i + even[i])`입니다.
- **거울 위치 공식**: 홀수는 `l + r − i`, 짝수는 `l + r − i + 1`. 짝수에서 한 칸 차이가 나는 이유는 가운데가 글자 사이에 있기 때문입니다.
- **구간을 갱신하는 조건**: `i + k − 1 > right`일 때만 `[l, r]`을 바꿉니다. 매번 바꾸면 박스가 줄어들 수 있습니다.
- **반지름과 길이를 혼동**: 홀수 길이는 `2·odd − 1`, 짝수는 `2·even`. 개수는 반지름 그대로.
- **질의에서 중심 계산**: 반열린 구간 `[l, r)`의 홀수 길이는 `c = l + L//2`, 짝수 길이도 같은 식 `c = l + L//2`지만 비교 기준이 다릅니다(`odd[c] ≥ L//2 + 1` vs `even[c] ≥ L//2`).
- **1부터 vs 0부터**: 문제의 구간이 1부터 양 끝 포함이면 `is_palindrome(l − 1, r)`.
- **같은 길이 중 어느 것**: 문제가 "가장 앞" 또는 "사전순 최소"를 요구하면 비교를 `>`로 둘지 `>=`로 둘지에 따라 답이 달라집니다.

## 7. 변형과 응용

- **회문 분할 DP**: `cuts[i] = min(cuts[j] + 1)` (`s[j:i]`가 회문인 `j`). 판정이 `O(1)`이라 전체 `O(n²)`이고 `n ≤ 2500`에서 충분합니다. 더 빠르게 하려면 회문 트리(eertree)와 시리즈 링크를 쓰는 `O(n log n)` 방법이 있습니다(Lv4).
- **각 위치에서 끝나는 가장 긴 회문**: 반지름 배열을 차분 배열로 퍼뜨려 `O(n)`에 구합니다. 서로 겹치지 않는 두 회문 길이의 곱 최대화(LeetCode 1960) 같은 문제의 재료입니다.
- **접두사/접미사 회문**: `odd[i] == i + 1`이면 `s[0..2i]`가 회문 접두사입니다 ([Z 알고리즘](../z-algorithm/)으로도 `s + # + reverse(s)`에서 구함).
- **리스트·정수 수열의 회문**: 원소를 `==`로 비교할 수 있으면 같은 코드입니다 (BOJ 11046).
- **그 밖의 회문 도구**: 해시로 앞뒤를 비교하는 방법(충돌 가능, `O(n log n)`에 가장 긴 회문), 접미사 배열 + LCP로 구하는 방법(느림), 회문 트리. 매내처는 가장 짧고 확실합니다.
- **문자열 전체를 회문으로 만들기**: 앞이나 뒤에 글자를 최소로 붙여 전체를 회문으로 → 가장 긴 회문 접두사/접미사.
