# Z 알고리즘 (Z-algorithm)

> **한 줄 요약**: 문자열 `s`의 **모든 위치 `i`에서 "`s[i:]`가 `s` 자신의 접두사와 몇 글자 일치하는가"(`z[i]`)를 `O(n)`에 구한다.** 지금까지 찾은 가장 오른쪽 일치 구간 `[l, r)`을 기억해 두고, 새 위치가 그 안에 있으면 이미 계산한 `z` 값을 재활용하기 때문에 구간 밖으로 나갈 때만 글자를 직접 비교한다. 이 배열 하나로 **문자열 찾기, 최소 주기, 모든 테두리(border)**를 풀 수 있다.

## 1. 언제 쓰나 (문제 신호)

- "본문 `T`에서 패턴 `P`가 나오는 **모든 위치**" — 패턴 + 구분자 + 본문을 이어 붙인 뒤 `z` 값이 `|P|`인 곳
- "문자열이 어떤 조각의 **반복**으로 이루어졌는가", "가장 짧은 반복 단위(주기)"
- "접두사이면서 접미사인 부분 문자열(**테두리**)의 길이 전부", 광고판·비밀번호 류 문제
- "**각 접두사가 문자열 안에 몇 번** 나오는가", "모든 위치에서 접두사와의 공통 길이의 합"
- 입력이 문자열이 아니라 **숫자 리스트**여도 되는 일치 판정 (원소끼리 `==` 비교만 되면 된다)
- KMP를 쓰려는데 "접두사 함수가 헷갈린다"고 느껴질 때 — Z 배열은 정의가 더 직접적이다

## 2. 핵심 아이디어

**정의**: `z[i] = lcp(s, s[i:])`, 즉 `s`와 `s[i:]`의 최장 공통 접두사의 길이. 관례로 `z[0] = n`.

**순진한 방법**: 위치마다 처음부터 비교하면 `s = "aaaa…a"`에서 `O(n²)`.

**재활용**: 지금까지 계산한 위치들 중 **가장 오른쪽까지 간 일치 구간** `[l, r)`을 기억한다. 이 구간은 `s[l:r] == s[0:r−l]`, 즉 접두사의 복사본이다.

```
idx:     0 1 2 3 4 5 6 7 8
s:       a b c a b c a b x
prefix:  # # # # # . . . .     s[0:5]  = "abcab"
box:     . . . # # # # # .     s[3:8]  = "abcab"   ← 박스 [l, r) = [3, 8), 접두사의 복사본
```

새 위치 `i`가 `l ≤ i < r` 안에 있으면, `s[i:r]`은 접두사 안의 `s[i−l : r−l]`과 같은 글자다. 그러므로 `z[i]`는 이미 아는 `z[i−l]`에서 출발할 수 있다.

- `z[i−l] < r − i`이면 일치가 박스 안에서 끝나므로 `z[i] = z[i−l]`이 **정확한 값**이다.
- 그렇지 않으면 박스 끝(`r − i`)까지는 확실히 일치하고, 그 뒤부터 직접 비교해 늘린다.

코드는 둘을 한 줄로 합친다: `z[i] = min(r − i, z[i − l])`로 시작한 뒤 `while` 루프로 더 늘려 본다. 첫 경우에는 `while`이 곧바로 실패한다.

**왜 `O(n)`인가**: 직접 비교로 **성공한** 글자마다 `r`이 오른쪽으로 한 칸 이상 밀리고(`i + z[i] > r`이면 `r`을 갱신), `r`은 줄어들지 않으며 `n`을 넘지 않는다. 실패한 비교는 위치당 한 번뿐이다. 합쳐서 비교는 많아야 `2n`번.

**문자열 찾기로 바꾸기**: 패턴 `P`, 본문 `T`에 대해 `P + [구분자] + T`의 Z 배열을 만든다. 구분자가 `P`와 `T`에 없는 글자이므로 `z` 값은 `|P|`를 넘을 수 없고, 본문 쪽 위치에서 `z[i] == |P|`이면 거기서 `P`가 시작한다.

## 3. 손으로 따라가기

### Z 배열 만들기: `s = "aabxaab"` (`n = 7`)

`[l, r)`은 지금까지 가장 오른쪽까지 간 일치 구간입니다(처음엔 `[0, 0)`).

| `i` | 시작 `[l, r)` | 재활용 | 직접 늘린 글자 수 | `z[i]` | 갱신 후 `[l, r)` |
|---|---|---|---|---|---|
| 1 | `[0, 0)` | 박스 밖이라 0에서 시작 | 1 (`a`=`a`, 다음 `a`≠`b`) | 1 | `[1, 2)` |
| 2 | `[1, 2)` | 박스 밖 (`i ≥ r`) | 0 (`b`≠`a`) | 0 | `[1, 2)` |
| 3 | `[1, 2)` | 박스 밖 | 0 (`x`≠`a`) | 0 | `[3, 3)` (빈 구간으로 갱신) |
| 4 | `[3, 3)` | 박스 밖 | 3 (`aab`=`aab`, 끝) | 3 | `[4, 7)` |
| 5 | `[4, 7)` | `min(r−i, z[i−l]) = min(2, z[1]=1) = 1` | 0 (`a`≠`b`) | 1 | `[4, 7)` |
| 6 | `[4, 7)` | `min(1, z[2]=0) = 0` | 0 | 0 | `[4, 7)` |

결과 `z = [7, 1, 0, 0, 3, 1, 0]` (`z[0] = n = 7`). 직접 늘린 글자는 모두 `1 + 3 = 4`개로 `n`보다 작습니다.

`i = 5`가 핵심입니다. `s[5:7] = "ab"`가 박스 `s[4:7] = "aab"` 안에 있으므로 접두사 안의 같은 위치 `s[1:3]`의 `z[1] = 1`을 그대로 가져옵니다.

### 문자열 찾기: `T = "ababa"`, `P = "aba"`

`P + [구분자] + T`를 만들면 `a b a # a b a b a` (인덱스 0~8, `#`은 구분자).

| 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 글자 | a | b | a | # | a | b | a | b | a |
| `z` | 9 | 0 | 1 | 0 | **3** | 0 | **3** | 0 | 1 |

`z[i] == 3`인 `i = 4, 6` → 본문에서의 시작 위치는 `i − |P| − 1 = 0, 2`. 즉 `aba`는 `ababa`의 0번과 2번(겹침 포함)에서 시작합니다.

### 주기와 테두리: `s = "abcabcab"` (`n = 8`)

`z = [8, 0, 0, 5, 0, 0, 2, 0]`.

- **최소 주기**: `z[p] == n − p`인 가장 작은 `p ≥ 1`. `z[3] = 5 = 8 − 3`이므로 `p = 3` (`abc`를 반복하고 마지막은 일부만 써서 `abcabcab`). 이런 `p`가 없으면 주기는 `n`.
- **테두리**: 길이 `k`가 테두리 ⟺ `z[n − k] == k` (끝에서 `k`칸 앞 위치의 접미사가 통째로 접두사와 일치). `k = 2` (`z[6] = 2`), `k = 5` (`z[3] = 5`) → 테두리 `ab`, `abcab`.

### 각 접두사의 출현 횟수: `s = "aabaab"`

`z = [6, 1, 0, 3, 1, 0]`. 길이 `k`인 접두사는 `z[i] ≥ k`인 위치 `i`마다 한 번씩 나옵니다. `z` 값이 정확히 `v`인 위치의 수를 센 뒤 큰 쪽부터 누적하면 `[0, 4, 2, 2, 1, 1, 1]` (`a`는 4번, `aa`와 `aab`는 2번, …).

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 입력은 문자열이어도 리스트여도 됩니다.

```python
def z_function(s):
    n = len(s)
    z = [0] * n
    if n:
        z[0] = n
    left = right = 0                              # 가장 오른쪽까지 간 일치 구간 [left, right)
    for i in range(1, n):
        if i < right:
            z[i] = min(right - i, z[i - left])    # 이미 알고 있는 일치를 재활용
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > right:
            left, right = i, i + z[i]
    return z


def z_search(text, pattern):
    m = len(pattern)
    if m == 0:
        return []
    combined = list(pattern) + [None] + list(text)    # None 은 어떤 글자와도 같지 않다
    z = z_function(combined)
    return [i - m - 1 for i in range(m + 1, len(combined)) if z[i] == m]
```

- `smallest_period(s)`, `all_borders(s)`, `prefix_occurrence_counts(s)`가 위 예제의 주기·테두리·출현 횟수를 계산합니다.
- 구분자로 `None`을 쓰면 문자열이든 숫자 리스트든 같은 코드로 됩니다. 문자열만 다룬다면 `pattern + "\0" + text`처럼 입력에 나올 수 없는 글자를 써도 됩니다.
- 직접 실행하면 두 줄(본문 `T`, 패턴 `P`)을 받아 `P`가 `T`에 나오는 횟수와 시작 위치(1부터)를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **Z 배열**: 시간 **O(n)**, 공간 **O(n)**. 비교는 합쳐서 많아야 `2n`번입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- **문자열 찾기**: `O(|P| + |T|)` 시간, 이어 붙인 리스트만큼의 `O(|P| + |T|)` 공간.
- 이 환경에서 측정한 값입니다(두 번 중 최소).

| 작업 | 입력 | 시간 |
|---|---|---|
| `z_function` | 무작위 `a`/`b` 10⁶ 글자 | 0.25초 |
| `z_function` | `"a" * 10⁶` | 0.27초 |
| `z_search` | 본문 10⁶ 글자(무작위 `a`/`b`), 패턴 12글자 | 0.3초 |
| `z_search` | 본문이 정수 리스트 10⁶개, 패턴 12개 | 0.29초 |

- **파이썬에서 문자열 하나를 찾는 것이 목적이면 내장 `str.find`가 훨씬 빠릅니다.** 같은 10⁶ 글자 본문에서 `startswith`로 위치마다 검사하는 단순 반복문도 0.06초로 `z_search`(0.3초)보다 빨랐고, `"a"*200000` 본문에 `"a"*50000 + "b" + "a"*50000` 패턴을 찾는 최악 입력에서 `z_search` 0.12초, 위치마다 `startswith` 0.14초, `str.find` 0.0007초였습니다. Z 알고리즘이 빛나는 곳은 내장 함수가 없는 **숫자 리스트**, 그리고 **`z` 배열 자체**(주기·테두리·출현 횟수)가 필요한 문제입니다.
- 입력이 10⁶ 글자 정도면 파이썬에서도 1초 안쪽입니다. 구분자를 끼운 리스트를 새로 만들기 때문에 메모리는 입력의 몇 배가 됩니다.

## 6. 자주 하는 실수

- **구분자를 빼먹음**: `pattern + text`만 이으면 `z` 값이 `|P|`를 넘어 본문으로 흘러 들어가 의미가 사라집니다. 구분자는 입력에 나올 수 없는 값이어야 합니다.
- **`z[0]`을 `0`으로 두고 `n`으로 기대함(또는 반대)**: 이 구현은 `z[0] = n`입니다. 테두리를 셀 때 `k < n`만 보고(`z[0]`은 문자열 전체이므로), 최소 주기는 `p ≥ 1`부터 찾습니다.
- **`min(r − i, …)`을 빼먹음**: `z[i − l]`이 박스 끝을 넘어갈 수 있는데 그대로 쓰면 틀립니다. 박스 밖의 글자는 아직 확인한 적이 없습니다.
- **박스 조건을 `i <= right`로 씀**: 반열린 구간 `[l, r)`이므로 `i < r`입니다. (`i == r`이면 `r − i = 0`이라 결과는 같지만, 헷갈리면 `z[i − l]`을 읽으며 인덱스가 어긋납니다.)
- **슬라이스로 비교함**: `s[i:] == s[:n−i]`나 `os.path.commonprefix`를 루프 안에 넣으면 위치마다 `O(n)`이라 다시 `O(n²)`입니다.
- **Z 배열과 접두사 함수(KMP의 `π`)를 섞음**: `z[i]`는 "`i`에서 **시작**하는 접미사가 접두사와 일치하는 길이", `π[i]`는 "`i`에서 **끝나는** 접두사가 접미사와 일치하는 길이"입니다. 둘은 서로 변환할 수 있지만 같은 배열이 아닙니다.
- **0부터 vs 1부터**: 출력 위치가 1부터면 `+ 1`.
- **빈 패턴**: 구분자만 남아 모든 위치가 일치하는 것처럼 보입니다. 이 구현은 빈 패턴이면 빈 목록을 돌려줍니다.

## 7. 변형과 응용

- **최소 주기와 완전한 반복**: `p = smallest_period(s)`가 `n`의 약수이면 `s`는 `n / p`번 반복된 문자열입니다. (`abab`은 `p = 2`, `n % 2 == 0` → 2번 반복. `abcab`은 `p = 3`이지만 5는 3의 배수가 아니므로 완전한 반복이 아님.)
- **테두리의 출현 횟수**: 각 테두리가 문자열 안에 몇 번 나오는지 `prefix_occurrence_counts`로 한 번에 구한다 (CF 432D).
- **뒤집어서 한 번 더**: `s`의 Z 배열과 `reverse(s)`의 Z 배열을 함께 쓰면 "접두사와 접미사가 동시에 일치하는" 조각, "위치 `i`에서 끝나는 부분 문자열과 `s`의 접미사의 공통 길이" 같은 질의를 풉니다.
- **원형 문자열 일치**: `T + T`에서 `P`를 찾는다 (두 원형 배열이 회전해서 같은지).
- **모든 접미사의 LCP 합**: `sum(z)`. 각 접미사와 전체 문자열의 공통 접두사 길이의 합입니다.
- **KMP와의 관계**: 둘 다 `O(n)`이고 서로 변환할 수 있습니다. 문자열 한 개를 순서대로 읽으면서 처리하는 온라인 문제는 [KMP](../../../lv2-intermediate/07-strings/kmp/)가, 위치마다 접두사와의 공통 길이가 필요하면 Z가 편합니다.
- **해시와의 관계**: [라빈-카프](../../../lv2-intermediate/07-strings/rabin-karp/)의 롤링 해시는 구현이 짧지만 충돌 가능성이 있고, Z는 결정적입니다.
- **서로 다른 접미사 사이의 LCP**: Z는 "전체 문자열의 접두사와의 LCP"만 줍니다. 임의의 두 접미사의 LCP는 [접미사 배열 + LCP 배열](../suffix-array-lcp/)이 필요합니다.
