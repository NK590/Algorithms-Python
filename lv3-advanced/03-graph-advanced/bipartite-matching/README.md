# Bipartite Matching (이분 매칭)

> **한 줄 요약**: 이분 그래프에서 **정점을 겹치지 않게 짝지을 수 있는 간선의 최대 개수**를 구한다. 이미 정한 짝을 필요하면 바꿔 가며 "짝 없는 정점에서 시작해 짝 없는 정점으로 끝나는 **증가 경로**"를 찾아 매칭을 하나씩 키운다(쿠온/Kuhn, `O(VE)`). 증가 경로를 한 단계에 여러 개 찾으면 호프크로프트-카프(`O(E√V)`)이다. 최대 매칭은 쾨니그의 정리로 **최소 정점 덮개, 최대 독립 집합, DAG의 최소 경로 덮개**까지 알려 준다.

## 1. 언제 쓰나 (문제 신호)

- "**한쪽 집합의 각 원소를 다른 쪽 집합의 서로 다른 원소에 배정**할 수 있는 최대 수" (직원 ↔ 일, 소 ↔ 축사, 학생 ↔ 자리)
- 가능한 배정이 "어떤 쪽과 어떤 쪽 사이의 연결"로 주어지고 한 원소는 **하나만** 가질 수 있다
- 격자에서 **서로 공격하지 않는 말의 최대 개수**, 칸을 덮는 **최소 개수**, 서로 영향을 주지 않는 **독립 집합** (격자를 체스판 색으로 나누면 이분 그래프)
- "DAG의 정점을 **겹치지 않는 경로 몇 개**로 모두 덮을 수 있는가"
- 용량이 있는 일반적인 흐름이면 [디닉](../dinic/), 이분 그래프에서 간선 가중치가 없으면 이 방법이 더 가볍고 빠르다

## 2. 핵심 아이디어

**매칭**: 어느 두 간선도 정점을 공유하지 않는 간선의 집합. 왼쪽 정점 `u`와 짝지어진 오른쪽 정점을 `match_left[u]`, 반대를 `match_right[v]`로 둔다 (없으면 `-1`).

**증가 경로**: 짝 없는 왼쪽 정점 `u₀`에서 시작해 **매칭에 속하지 않는 간선**으로 오른쪽 `v₀`로 가고, `v₀`의 현재 짝 `u₁`로 **매칭 간선**을 따라 돌아와 다시 매칭에 속하지 않는 간선으로 `v₁`로…, 마지막에 **짝 없는 오른쪽 정점**에 닿는 경로. 경로를 따라 매칭 여부를 뒤집으면 매칭이 **하나 늘어난다**. 증가 경로가 더는 없을 때 매칭이 최대이다 (베르주의 정리).

**쿠온(Kuhn)**: 왼쪽 정점 `u`를 하나씩 보며 DFS로 증가 경로를 찾는다. 오른쪽 정점 `v`를 시도할 때 (이번 탐색에서 아직 안 봤다면) `v`가 비어 있거나 `v`의 현재 짝이 **다른 곳으로 옮겨 갈 수 있으면** `v`를 가져온다. 한 번의 탐색에서 각 오른쪽 정점은 한 번만 시도한다 → 탐색 하나가 `O(E)`, 전체 `O(VE)`.

**호프크로프트-카프**: 쿠온을 한 번에 증가 경로 하나씩 찾는 대신 한 **단계(phase)**마다
1. BFS로 짝 없는 왼쪽 정점들에서 층(거리)을 매기고,
2. 층이 1씩 늘어나는 간선만 써서 DFS로 **서로 겹치지 않는 증가 경로를 가능한 한 많이** 찾는다.

단계는 `O(√V)`번이라 전체 `O(E√V)`.

**쾨니그의 정리**: 이분 그래프에서 **최대 매칭의 크기 = 최소 정점 덮개의 크기**. 정점 덮개는 모든 간선의 적어도 한 끝점을 포함하는 정점 집합. 복원 방법: 최대 매칭에서 **짝 없는 왼쪽 정점**들로부터 `왼쪽 → 오른쪽`은 아무 간선, `오른쪽 → 왼쪽`은 매칭 간선만으로 도달할 수 있는 정점 집합 `Z`를 구하면

```
최소 정점 덮개 = (왼쪽 정점 중 Z 에 없는 것) ∪ (오른쪽 정점 중 Z 에 있는 것)
최대 독립 집합 = 덮개의 여집합   (크기 = L + R - 최대 매칭)
```

**DAG의 최소 경로 덮개**: 정점 서로소 경로 최소 개수 = `n − (최대 매칭)`. 각 정점을 왼쪽 복사본(나가는 간선)과 오른쪽 복사본(들어오는 간선)으로 쪼개 이분 그래프를 만들면, 매칭 간선 하나가 경로를 한 칸 이어 주기 때문에 경로 수가 하나 줄어든다. (정점을 공유해도 되는 경로 덮개는 먼저 전이적 폐쇄를 한다.)

### 무엇을 저장하고 어떻게 움직이나

왼쪽·오른쪽 정점의 짝을 저장하고 아직 짝이 없는 왼쪽 정점에서 증가 경로를 찾습니다. 경로는 미선택 간선과 선택 간선을 번갈아 사용합니다. 오른쪽 정점이 이미 짝을 가졌다면 기존 짝을 다른 곳으로 옮길 수 있는지 탐색합니다.

### 왜 이 방법이 맞는가

증가 경로의 간선 선택을 뒤집으면 내부 정점의 짝 개수는 그대로이고 양 끝의 미매칭 정점이 새로 연결돼 크기가 1 늘어납니다. 증가 경로가 없으면 현재 매칭이 최대입니다. 한 번 실패한 탐색의 방문 상태는 다음 출발에 그대로 재사용하지 않습니다.

### 작은 예제로 검산하기

왼쪽 A가 1·2에, B가 1에 연결돼 있다고 합시다. A-1을 먼저 골랐어도 B-1-A-2로 뒤집으면 B-1과 A-2의 크기 2 매칭을 얻습니다. 단순히 비어 있는 이웃만 고르는 그리디는 크기 1에서 멈춥니다.

## 3. 손으로 따라가기

### 쿠온: 소 5마리와 축사 5개

소(왼쪽) `0..4`가 들어갈 수 있는 축사(오른쪽): `0: {1, 4}`, `1: {1, 2, 3}`, `2: {0, 4}`, `3: {0, 1, 4}`, `4: {4}`.

| 소 | 시도 | 결과 | `match_left` |
|---|---|---|---|
| 0 | 축사 1이 비어 있다 | 0→1 | `[1, -, -, -, -]` |
| 1 | 축사 1을 시도: 소 0이 다른 곳(축사 4)으로 옮길 수 있다 | 0→4, 1→1 | `[4, 1, -, -, -]` |
| 2 | 축사 0이 비어 있다 | 2→0 | `[4, 1, 0, -, -]` |
| 3 | 축사 0 시도 → 소 2가 축사 4 시도 → 소 0이 축사 1 시도 → 소 1이 축사 2(비어 있음)로 옮김 | **증가 경로 발견** (경로는 아래에서 풀어 씀) | `[1, 2, 4, 0, -]` |
| 4 | 축사 4 시도 → 소 2 → (축사 0 → 소 3 → …) 모두 막힘 | 실패 | 그대로 |

소 3의 증가 경로를 풀어 쓰면: `소3 —축사0— (소2) —축사4— (소0) —축사1— (소1) —축사2(비어 있음)`. 경로를 따라 뒤집으면 `소3→0`, `소2→4`, `소0→1`, `소1→2`. 최종 `match_left = [1, 2, 4, 0, -1]`, **최대 매칭 4** (소 4는 축사 4밖에 못 가는데 축사 4는 소 2에게 필요해서 짝이 없다). 호프크로프트-카프도 크기 4를 구하지만 다른 매칭 `[1, 2, 0, 4, -1]`을 줄 수 있습니다. 최대 매칭은 유일하지 않습니다.

### 쾨니그: 같은 그래프의 최소 정점 덮개

최대 매칭 크기 4 → 최소 정점 덮개의 크기도 4. 구해진 덮개(이 환경에서 확인): **왼쪽 `{1}`**, **오른쪽 `{0, 1, 4}`**. 모든 간선이 덮이는지 확인하면:
- 소 0 `{1,4}`: 오른쪽 1, 4 ✓ / 소 1: 왼쪽 1 ✓ / 소 2 `{0,4}`: 오른쪽 0, 4 ✓ / 소 3 `{0,1,4}`: ✓ / 소 4 `{4}`: 오른쪽 4 ✓.

최대 독립 집합(서로 간선으로 이어지지 않은 정점들)은 왼쪽 `{0, 2, 3, 4}`, 오른쪽 `{2, 3}`로 크기 `5 + 5 − 4 = 6`.

### DAG의 최소 경로 덮개

간선 `0→1, 0→2, 1→3, 2→3` (마름모): 최대 매칭 2 (`0→1`, `2→3`) → `4 − 2 = 2`개의 경로 (예: `0→1→3`, `2`). 별 모양 `0→1, 0→2, 0→3`: 정점 `0`이 나가는 간선을 하나만 쓸 수 있어 최대 매칭 1 → `4 − 1 = 3`개.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 왼쪽 `0..left_n-1`, 오른쪽 `0..right_n-1`, `adjacency[u]` = `u`와 이어진 오른쪽 정점들. 모든 DFS가 반복문입니다.

```python
def kuhn_matching(left_n, right_n, adjacency):
    match_left = [-1] * left_n
    match_right = [-1] * right_n
    visited_by = [-1] * right_n            # 오른쪽 정점을 마지막으로 시도한 탐색의 번호: 배열을 매번 새로 만들지 않는다
    size = 0
    for root in range(left_n):
        stack, chosen, pointer = [root], [], {root: 0}
        found = False
        while stack:
            u = stack[-1]
            if pointer[u] == len(adjacency[u]):    # u 로는 더 길을 못 찾는다: 물러난다
                stack.pop()
                if chosen:
                    chosen.pop()
                continue
            v = adjacency[u][pointer[u]]
            pointer[u] += 1
            if visited_by[v] == root:
                continue
            visited_by[v] = root
            chosen.append(v)
            if match_right[v] == -1:               # 짝 없는 오른쪽 정점: 경로를 따라 뒤집는다
                for a, b in zip(stack, chosen):
                    match_left[a] = b
                    match_right[b] = a
                found = True
                break
            nxt = match_right[v]                   # v 의 짝에게 다른 자리를 찾아 주러 내려간다
            pointer[nxt] = 0
            stack.append(nxt)
        size += found
    return size, match_left, match_right
```

- `hopcroft_karp(left_n, right_n, adjacency)`: 같은 반환값. BFS로 층을 매기고 층이 1씩 늘어나는 간선만 따라 DFS.
- `minimum_vertex_cover(...)`, `maximum_independent_set(...)`: 쾨니그의 정리. `min_path_cover(n, edges)`: DAG의 정점 서로소 경로 덮개의 최소 경로 수.
- 직접 실행하면 `N M`과 `N`개의 줄(각 줄은 `k`와 `k`개의 오른쪽 정점 번호, 1부터)을 받아 최대 매칭의 크기를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **쿠온 O(VE)**, **호프크로프트-카프 O(E√V)**, 공간 `O(V + E)`. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(반복문 구현, 무작위 이분 그래프, 두 번 중 최소; 마지막 줄만 한 번 측정).

| 입력 | 쿠온 | 호프크로프트-카프 |
|---|---|---|
| 3000 × 3000, 정점당 간선 3개 | 0.42초 | 0.012초 |
| 2000 × 2000, 정점당 간선 5개 | 0.11초 | 0.011초 (같은 입력을 디닉으로 풀면 0.06초) |
| 사다리 모양 50,000 × 50,000 | 0.03초 | 0.03초 |
| 10⁵ × 10⁵, 정점당 간선 4개 (한 번 측정) | 618초 | 1.36초 |

- 마지막 줄이 보여 주듯 입력이 커지면 쿠온은 **시간 제한에 걸릴 수 있습니다**. 정점이 수천 개를 넘으면 호프크로프트-카프를 쓰세요. 입력이 작거나 다루기 쉬운 구조(정렬된 순서)에서는 쿠온도 충분히 빠릅니다.
- 정점이 10⁵개, 간선이 4·10⁵개여도 호프크로프트-카프는 파이썬에서 1~2초대입니다.

## 6. 자주 하는 실수

- **재귀 DFS**: 증가 경로가 길어지면(예: 사다리 모양 입력) 파이썬의 재귀 깊이 제한에 걸립니다. 명시적 스택을 씁니다.
- **탐색마다 `visited`를 새로 할당**: `O(L · R)`가 됩니다. 시도한 탐색의 번호를 기록하는 방식(`visited_by[v] == root`)으로 초기화 없이 처리합니다.
- **왼쪽/오른쪽 번호를 섞음**: 왼쪽 정점 번호와 오른쪽 정점 번호는 별개의 번호 공간입니다. 하나의 그래프로 주어지면 먼저 두 집합으로 나눕니다.
- **이분 그래프인지 확인하지 않음**: 일반 그래프의 최대 매칭은 이분 매칭으로 풀 수 없습니다 ([블로섬 알고리즘](../../../lv5-master/02-matching-matroid/blossom/)). 격자 문제는 칸의 색(`(r + c) % 2`)으로 두 집합이 자연스럽게 나뉩니다.
- **쿠온의 느린 입력을 방치**: 위의 618초 같은 경우를 만나기 전에 호프크로프트-카프나 [디닉](../dinic/)을 고려하세요.
- **DAG 경로 덮개에서 간선 방향**: 왼쪽 = 나가는 쪽, 오른쪽 = 들어오는 쪽. `min_path_cover`는 방향을 반대로 해도 같은 결과이긴 하지만 정의를 지키세요.
- **경로가 정점을 공유할 수 있는 문제**: 정점 서로소 덮개가 아니라 전이적 폐쇄 위에서 풀어야 합니다 (`u → v → w`에서 `u → w`를 추가).
- **쾨니그의 정리를 일반 그래프에 적용**: 이분 그래프에서만 성립합니다.
- **매칭 결과가 문제의 출력과 다른 매칭**: 최대 매칭이 여러 개라 특정한 매칭을 요구하면 사전순 최소 등을 별도로 구해야 합니다.

## 7. 변형과 응용

- **홀 정리**: 왼쪽의 모든 정점을 짝지을 수 있다 ⟺ 왼쪽의 모든 부분집합 `S`에 대해 `|N(S)| ≥ |S|`.
- **정점 덮개/독립 집합**: 격자에서 서로 인접하지 않게 놓을 수 있는 최대 개수(컨닝, 체스 말), 줄/열 단위로 덮는 최소 개수(룩, 게시판).
- **DAG의 최소 경로 덮개 / 딜워스의 정리**: 최소 사슬 덮개 = 최대 반사슬의 크기.
- **용량이 있는 매칭**: 한 사람이 일을 둘 맡을 수 있으면 소스에서 용량 2인 간선을 쓰는 유량으로 → [디닉](../dinic/).
- **가중치 있는 이분 매칭**: 헝가리안 알고리즘 또는 최소 비용 최대 유량 (Lv4).
- **이분 그래프 판정**: 먼저 BFS 이색칠로 확인. → [이분 그래프](../../../lv2-intermediate/02-graph-algorithms/bipartite-graph/)
