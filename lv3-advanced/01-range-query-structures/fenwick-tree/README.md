# Fenwick Tree (펜윅 트리, Binary Indexed Tree)

> **한 줄 요약**: 배열의 **한 칸 값을 바꾸고(점 갱신) 앞에서부터의 합(접두사 합)을 구하는** 두 연산을 모두 `O(log n)`에 처리하는 자료구조. 인덱스의 이진 표현(`i & -i`)만으로 동작해서 코드가 10줄 남짓이고 세그먼트 트리보다 짧고 빠르다. 구간 합, 역순쌍 세기, "k번째 수 찾기"의 표준 도구다.

## 1. 언제 쓰나 (문제 신호)

- "수열의 한 값을 **바꾸는** 질의와 **구간 합**을 묻는 질의가 섞여 있다" (질의 10⁵~10⁶개)
- [누적 합](../../../lv1-elementary/04-range-techniques/prefix-sum/)을 쓰고 싶은데 값이 **바뀐다** (누적 합은 갱신이 `O(n)`)
- **역순쌍의 개수**, "내 뒤에 나보다 작은 수가 몇 개" — 값을 [좌표 압축](../../../lv2-intermediate/08-search-techniques/coordinate-compression/)한 뒤 개수를 센다
- "동적 집합에서 **k번째로 작은 수**" 삽입·삭제와 함께
- 2차원 격자의 점 갱신과 직사각형 합
- 구간에 값을 더하고 구간 합을 묻는 문제 (트리 두 개로 처리, [느리게 갱신되는 세그먼트 트리](../lazy-propagation/)의 가벼운 대안)

합 이외의 연산(최솟값, 최댓값, gcd)이나 구간 갱신이 복잡하면 [세그먼트 트리](../segment-tree/)를 쓴다.

## 2. 핵심 아이디어

**누적 합의 두 가지 극단**: 배열 그대로이면 갱신 `O(1)`, 구간 합 `O(n)`. 누적 합 배열이면 구간 합 `O(1)`, 갱신 `O(n)`. 펜윅 트리는 중간을 잡아 **둘 다 `O(log n)`**이다.

**`tree[i]`가 맡는 구간**: 1부터 세는 인덱스 `i`에 대해 `lowbit(i) = i & -i`(이진수에서 가장 낮은 1 비트)라 하면, `tree[i]`는 **`i`에서 끝나는 길이 `lowbit(i)`인 구간의 합**이다.

| `i` | 이진수 | `lowbit` | `tree[i]`가 맡는 구간 |
|---|---|---|---|
| 1 | 001 | 1 | `[1, 1]` |
| 2 | 010 | 2 | `[1, 2]` |
| 3 | 011 | 1 | `[3, 3]` |
| 4 | 100 | 4 | `[1, 4]` |
| 5 | 101 | 1 | `[5, 5]` |
| 6 | 110 | 2 | `[5, 6]` |
| 7 | 111 | 1 | `[7, 7]` |
| 8 | 1000 | 8 | `[1, 8]` |

**접두사 합**: `prefix(i)`는 `i`에서 시작해 `lowbit`만큼 계속 빼며(`i -= i & -i`) 만나는 `tree` 칸을 더한다. 맡은 구간이 겹치지 않고 이어 붙어 `[1, i]`를 정확히 덮는다. 예를 들어 `7 → 6 → 4 → 0`이면 `tree[7] + tree[6] + tree[4]` = `[7,7] + [5,6] + [1,4]`. 걸음 수는 `i`의 1 비트의 개수라 많아야 `log n`.

**점 갱신**: `a[i]`가 바뀌면 `i`를 포함하는 구간을 맡은 칸을 모두 고친다. `i`에서 시작해 `lowbit`만큼 계속 더하며(`i += i & -i`) 올라간다. `3 → 4 → 8`이면 `tree[3]`, `tree[4]`, `tree[8]`이 `a[3]`를 포함한다.

**구간 합**: `sum(l..r) = prefix(r) − prefix(l−1)`.

**`O(n)`에 만들기**: 값을 하나씩 `add`하면 `O(n log n)`이지만, `tree[i]`를 채운 뒤 자기를 포함하는 바로 위 칸 `i + lowbit(i)`에 한 번만 밀어 올리면 `O(n)`이다.

**k번째 수 찾기** (`find_kth`): 각 칸이 "개수"를 저장하고 있으면, 큰 2의 거듭제곱 간격부터 "이만큼 건너뛰어도 아직 `k`에 모자란가"를 보며 내려가 `O(log n)`에 `k`번째 위치를 찾는다. 이진 탐색을 트리 위에서 한다고 보면 된다.

**구간 갱신 + 구간 합**: 차분 배열 `d`에 대해 앞의 `x`개의 합은 `x · Σ d[j] − Σ d[j]·j` (`j < x`). 그래서 `d[j]`를 저장한 트리와 `d[j]·j`를 저장한 트리, 두 개면 구간에 값을 더하는 것(`d` 두 곳 갱신)과 구간 합이 모두 `O(log n)`이다.

## 3. 손으로 따라가기

### 접두사 합과 점 갱신: `a = [3, 2, -1, 6, 5, 4, -3, 3]`

`from_list`로 만든 트리 (`tree[1..8]`):

| `i` | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 맡은 구간 | `[1,1]` | `[1,2]` | `[3,3]` | `[1,4]` | `[5,5]` | `[5,6]` | `[7,7]` | `[1,8]` |
| `tree[i]` | 3 | 5 | -1 | 10 | 5 | 9 | -3 | 19 |

- **`prefix(7)`**: `7 → 6 → 4 → 0`이므로 `tree[7] + tree[6] + tree[4] = -3 + 9 + 10 = 16`. 직접 더해도 `3+2-1+6+5+4-3 = 16`.
- **구간 합 `a[3..6]`** (1부터): `prefix(6) − prefix(2) = 19 − 5 = 14`. (`-1 + 6 + 5 + 4 = 14`)
- **`a[3]`에 +5** (`i = 3`): `3 → 4 → 8`. `tree[3]`: -1→4, `tree[4]`: 10→15, `tree[8]`: 19→24. 나머지 칸은 그대로 (이 환경에서 변한 칸이 정확히 3, 4, 8).

### 개수 트리와 k번째: 집합 `{1, 3, 3, 6, 7}`

값 `v`의 개수를 위치 `v`에 저장한 배열 `[0, 1, 0, 2, 0, 0, 1, 1]`(0부터), 트리는 `tree[1..8] = [0, 1, 0, 3, 0, 0, 1, 5]`. `find_kth(4)`:

| 간격 | 후보 `position + step` | `tree[후보]` | 판단 | `position`, `k` |
|---|---|---|---|---|
| 8 | 8 | 5 | `5 < 4`? 아니오, 건너뛰지 않음 | 0, 4 |
| 4 | 4 | 3 | `3 < 4`? 예 → 건너뜀 | 4, 1 |
| 2 | 6 | 0 | `0 < 1`? 예 | 6, 1 |
| 1 | 7 | 1 | `1 < 1`? 아니오 | 6, 1 |

결과 위치 `6` → 4번째로 작은 값은 6. `k = 1..5`이면 `1, 3, 3, 6, 7`.

### 구간 더하기 + 구간 합 (`n = 6`)

`range_add(1, 4, +5)` (위치 1, 2, 3에 5를 더함): 차분 `d[1] = +5`, `d[4] = -5`. `coefficient`에는 `d`, `weighted`에는 `d[j]·j` (`5·1 = 5`, `-5·4 = -20`)가 들어간다. 각 칸의 값은 `[0, 5, 5, 5, 0, 0]`이고 `range_sum(2, 5) = 10`. 앞 3개의 합은 `3 · 5 − 5 = 10` (`x · Σd − Σ(d·j)`)으로 `[0, 5, 5]`의 합과 같다.

### 역순쌍: `[2, 4, 1, 3, 5]`

앞에서부터 보며 "지금까지 본 것 중 나보다 큰 것의 개수"를 더한다. `2`: 0, `4`: 0, `1`: 2(2, 4), `3`: 1(4), `5`: 0 → 합계 **3**. `count_inversions([3, 1, 2]) = 2`. `count_smaller_after([5, 2, 6, 1]) = [2, 1, 1, 0]`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 파이썬 인터페이스는 0부터 시작하고 구간은 반열린 `[left, right)`이며, 안쪽 `tree` 배열만 1부터 씁니다.

```python
class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (size + 1)

    def add(self, index, delta):          # a[index] += delta
        i = index + 1
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i                    # 이 칸을 포함하는 바로 위 칸으로

    def prefix_sum(self, count):          # 앞의 count 개의 합
        total = 0
        i = count
        while i > 0:
            total += self.tree[i]
            i -= i & -i                    # 맡은 구간 바로 앞으로
        return total

    def range_sum(self, left, right):     # [left, right)
        return self.prefix_sum(right) - self.prefix_sum(left)
```

- `FenwickTree.from_list(values)`: `O(n)`에 구축.
- `set(index, value)`, `point_value(index)`, `find_kth(k)`: 개수를 센 트리에서 `k`번째 위치.
- `RangeAddFenwick(size)`: `range_add(left, right, delta)`, `range_sum`.
- `Fenwick2D(rows, cols)`: `add`, `rect_sum(r1, c1, r2, c2)`.
- `count_inversions(numbers)`, `count_smaller_after(numbers)`: 좌표 압축 + 개수 세기.
- 직접 실행하면 `N M K`, `N`개의 수, `M + K`개의 질의(`1 b c`: `b`번째 수를 `c`로, `2 b c`: `b`부터 `c`번째까지의 합)를 받아 합 질의의 결과를 출력합니다 (1부터).

## 5. 복잡도와 입력 크기 가이드

- **시간**: 점 갱신·접두사 합·구간 합·`find_kth` 모두 **O(log n)**, 구축은 `O(n)`(`from_list`). 2차원은 **O(log R · log C)**. **공간 O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(무작위 값, 세 번 중 최소).

| 작업 | 크기 | 시간 |
|---|---|---|
| `from_list` | n = 2·10⁵ | 0.037초 |
| `add`를 하나씩 | n = 2·10⁵ | 0.22초 |
| 점 갱신 + 구간 합 (Fenwick) | 질의 10⁵쌍, n = 2·10⁵ | 0.43초 |
| 같은 질의 (세그먼트 트리) | 질의 10⁵쌍, n = 2·10⁵ | 0.91초 |
| `count_inversions` | n = 10⁵ | 0.26초 |

- 합을 다루는 문제라면 펜윅 트리가 세그먼트 트리보다 약 2배 빠르고 코드도 짧습니다. 파이썬에서 질의 `10⁶`개는 몇 초 단위라 `sys.stdin.buffer`로 입력을 읽고 한 번에 출력해야 합니다.
- 한계: 합처럼 **역연산이 있는** 연산에 편합니다. 최솟값·최댓값·gcd는 `prefix(r) − prefix(l)`이 불가능해서 세그먼트 트리를 씁니다.

## 6. 자주 하는 실수

- **0부터 시작하는 인덱스에 그대로 사용**: `i = 0`이면 `i & -i = 0`이라 `add`가 무한 루프에 빠집니다. 안쪽에서 `index + 1`로 바꿔 씁니다.
- **구간 합의 경계**: `prefix(r) − prefix(l − 1)`(닫힌 구간, 1부터)과 `prefix(right) − prefix(left)`(반열린, 0부터)을 섞지 마세요.
- **`set`을 `add`로 착각**: 값을 바꾸는 질의에는 `새 값 − 현재 값`을 더해야 합니다 (`fenwick.set`).
- **크기 부족**: 압축한 값의 종류 수나 `max(a) + 1`만큼의 칸이 필요합니다. 값이 0부터 시작하면 +1.
- **압축 없이 큰 값을 인덱스로**: 값이 10⁹이면 트리를 만들 수 없습니다. → [좌표 압축](../../../lv2-intermediate/08-search-techniques/coordinate-compression/)
- **오버플로(C++/Java)**: 구간 합과 역순쌍의 수는 `int`를 넘어갑니다 (`n = 10⁶`이면 약 5·10¹¹). `long long`.
- **`find_kth`에 음수 값**: 값이 모두 0 이상일 때만 의미가 있습니다 (단조성 필요).
- **`find_kth`의 시작 간격**: 2의 거듭제곱 중 `n` 이하의 최댓값부터 시작해야 합니다. 작게 시작하면 큰 `k`를 못 찾습니다.
- **구간 갱신에 트리 하나만**: `d`만 저장하면 점 질의는 되지만 구간 합이 안 됩니다. 두 번째 트리(`d·j`)가 필요합니다.

## 7. 변형과 응용

- **역순쌍·"뒤에 있는 더 작은 수"**: 압축 + 개수 세기. 버블 정렬의 교환 횟수가 역순쌍의 수입니다.
- **k번째 수 / 삽입·삭제하는 순위 통계**: `find_kth`. 원소의 순위는 `prefix_sum`으로 구합니다.
- **2차원**: `Fenwick2D`. 점 갱신 + 직사각형 합. 오프라인으로 점을 정렬하고 스위핑하면 직사각형 안의 점 세기가 1차원 펜윅 트리로 줄어듭니다. → [스위핑](../../../lv2-intermediate/08-search-techniques/sweeping/)
- **구간 최댓값 (접두사 최댓값)**: 값이 증가하기만 하면 `max`로도 쓸 수 있습니다 (역연산이 필요 없는 경우). 일반적으로는 세그먼트 트리.
- **오프라인 질의**: 질의를 끝점으로 정렬하고 펜윅 트리로 "구간 안의 서로 다른 수의 개수" 같은 문제를 푼다.
- **LIS**: 압축한 값을 인덱스로 `prefix_max`를 관리하면 `O(n log n)`.
