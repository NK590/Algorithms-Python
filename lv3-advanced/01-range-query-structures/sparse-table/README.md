# Sparse Table (희소 배열)

> **한 줄 요약**: **값이 바뀌지 않는 배열**에서 구간 최솟값·최댓값·gcd를 **질의마다 `O(1)`**에 답하는 표. 길이가 `2^k`인 모든 구간의 답을 미리 구해 두고(`O(n log n)`), 질의 구간을 길이 `2^k`짜리 두 구간으로 **겹쳐서** 덮는다. 겹쳐도 답이 변하지 않는 연산(`min`, `max`, `gcd`, `and`, `or`)에서만 쓸 수 있고, 합은 **분리 희소 배열**로 `O(1)`에 풀 수 있다.

## 1. 언제 쓰나 (문제 신호)

- "배열이 **고정**되어 있고 구간 최솟값(최댓값, gcd) 질의가 10⁵~10⁶개" (RMQ, Range Minimum Query)
- LCA를 **오일러 투어 + 구간 최솟값**으로 `O(1)`에 구할 때, 접미사 배열의 LCP 질의
- "구간의 최댓값과 최솟값 차이가 `K` 이하인 가장 긴 구간" 같은 투 포인터 조건 검사
- 값이 **바뀌면** 쓸 수 없다 → [세그먼트 트리](../segment-tree/). 합 질의만이면 [누적 합](../../../lv1-elementary/04-range-techniques/prefix-sum/)이면 충분.

| 상황 | 선택 |
|---|---|
| 정적 + 최솟값/최댓값/gcd | **희소 배열** (질의 `O(1)`) |
| 정적 + 합 | 누적 합 (`O(1)`), 합이 아닌 비멱등 연산이면 **분리 희소 배열** |
| 점 갱신 + 질의 | [세그먼트 트리](../segment-tree/), 합이면 [펜윅 트리](../fenwick-tree/) |
| 구간 갱신 + 질의 | [느리게 갱신되는 세그먼트 트리](../lazy-propagation/) |

## 2. 핵심 아이디어

**표**: `table[k][i]` = 구간 `[i, i + 2^k)`의 답. `table[0]`은 원소 자신이고,

```
table[k][i] = f( table[k-1][i], table[k-1][i + 2^(k-1)] )
```

즉, 길이 `2^k` 구간은 반으로 나눈 길이 `2^(k-1)` 구간 두 개의 답을 합친 것입니다. `k`는 `log₂ n`까지이고 `table[k]`의 길이는 `n − 2^k + 1`이므로 칸의 총 수는 `O(n log n)`입니다.

**질의 `[left, right)`**: 길이 `len = right − left`에 대해 `2^k ≤ len < 2^(k+1)`인 `k`(= `len.bit_length() − 1`)를 고릅니다. 구간을 `[left, left + 2^k)`와 `[right − 2^k, right)` 두 조각으로 덮습니다(두 조각은 겹칠 수 있다).

```
답 = f( table[k][left], table[k][right − 2^k] )
```

**왜 겹쳐도 되는가**: `f(x, x) = x`(멱등)이기 때문입니다. `min`, `max`, `gcd`, `and`, `or`가 그렇고 **합과 곱은 아닙니다**(겹친 부분이 두 번 더해진다).

**비멱등 연산: 분리 희소 배열** (Disjoint Sparse Table): 겹침 없이 쪼개는 방식으로 합·곱·문자열 이어 붙이기도 `O(1)`입니다. 수준 `h`마다 배열을 길이 `2^(h+1)`의 블록으로 나누고, 각 블록의 가운데에서 왼쪽 절반은 **왼쪽 방향**의 접미사 결과를, 오른쪽 절반은 **오른쪽 방향**의 접두사 결과를 저장합니다. 질의 `[l, r]`(닫힌)에서 `l`과 `r`의 이진수가 처음으로 갈라지는 비트가 `h`이면 둘은 수준 `h`의 한 블록 안에서 가운데를 사이에 두고 있으므로 `op(table[h][l], table[h][r])` 한 번으로 끝납니다.

## 3. 손으로 따라가기

### 표 만들기: `a = [5, 2, 4, 7, 6, 3, 1, 8]`

| `k` (구간 길이) | `table[k][0], table[k][1], …` |
|---|---|
| 0 (1) | `5, 2, 4, 7, 6, 3, 1, 8` |
| 1 (2) | `2, 2, 4, 6, 3, 1, 1` |
| 2 (4) | `2, 2, 3, 1, 1` |
| 3 (8) | `1` |

예: `table[1][3] = min(7, 6) = 6`, `table[2][1] = min(table[1][1], table[1][3]) = min(2, 6) = 2`.

### 질의 `[1, 6)`의 최솟값 (원소 `2, 4, 7, 6, 3`)

길이 5 → `k = 2` (`4 ≤ 5 < 8`). 두 조각: `[1, 5)`와 `[2, 6)`.

| 조각 | 구간 | 표에서 | 값 |
|---|---|---|---|
| 왼쪽 | `[1, 5)` = `2, 4, 7, 6` | `table[2][1]` | 2 |
| 오른쪽 | `[2, 6)` = `4, 7, 6, 3` | `table[2][2]` | 3 |

`min(2, 3) = 2`. 가운데 `4, 7, 6`이 두 번 포함되지만 최솟값이라서 상관없습니다. `query(0, 8)`은 `k = 3`이라 `table[3][0] = 1`, 길이 1인 `query(2, 3)`은 `k = 0`이라 `table[0][2] = 4`.

### 합은 왜 안 되는가

`a = [1, 2, 3]`에서 `f = +`인 희소 배열로 `query(0, 3)`: `k = 1`, `table[1][0] + table[1][1] = (1+2) + (2+3) = 8`. 진짜 합 6보다 2(가운데 원소)만큼 크다. [테스트](test_solution.py)의 `test_sum_is_not_idempotent_so_sparse_table_double_counts`가 이를 확인합니다.

### 분리 희소 배열: `[1, 2, 3, 4, 5, 6, 7, 8]`의 합

| 수준 `h` (블록 크기) | 저장된 값 (인덱스 0..7) |
|---|---|
| 0 (2) | `1, 2, 3, 4, 5, 6, 7, 8` |
| 1 (4) | `3, 2, 3, 7, 11, 6, 7, 15` |
| 2 (8) | `10, 9, 7, 4, 5, 11, 18, 26` |

수준 2에서 가운데는 인덱스 4 앞뒤: 왼쪽 절반은 오른쪽 끝(인덱스 3)부터 왼쪽으로 `4, 4+3 = 7, 7+2 = 9, 9+1 = 10`, 오른쪽 절반은 인덱스 4부터 오른쪽으로 `5, 11, 18, 26`.

질의 `[1, 7)` = 인덱스 1..6의 합: `1 ^ 6 = 7`(이진 `111`)의 최상위 비트가 2 → `h = 2`. `table[2][1] + table[2][6] = 9 + 18 = 27` (`2+3+4 = 9`, `5+6+7 = 18`). 직접 더한 `2+3+4+5+6+7 = 27`과 같습니다.

### 구간 최솟값의 위치

`RangeArgmin([3, 1, 4, 1, 5]).query(0, 5) = 1` (같은 최솟값 `1`이 위치 1과 3에 있을 때 가장 왼쪽), `query(2, 5) = 3`. `(값, 위치)` 쌍의 최솟값을 구하면 되고 튜플 비교는 값이 같을 때 위치가 작은 쪽을 고릅니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 구간은 0부터 시작하는 반열린 `[left, right)`이고 비어 있지 않아야 합니다.

```python
class SparseTable:
    def __init__(self, values, func=min):
        self.func = func
        self.n = len(values)
        self.table = [list(values)]
        k = 1
        while (1 << k) <= self.n:
            previous = self.table[-1]
            half = 1 << (k - 1)
            self.table.append([func(previous[i], previous[i + half])
                               for i in range(self.n - (1 << k) + 1)])
            k += 1

    def query(self, left, right):
        k = (right - left).bit_length() - 1          # 2^k ≤ 길이 < 2^(k+1)
        return self.func(self.table[k][left], self.table[k][right - (1 << k)])
```

- `RangeArgmin(values)`: 구간 최솟값의 위치. `range_gcd_table(values)`: 구간 gcd.
- `DisjointSparseTable(values, op)`: 결합 법칙만 성립하면 되는 연산(합, 곱 mod, 문자열 이어 붙이기)의 구간 질의를 `O(1)`로.
- 직접 실행하면 `N M`, `N`개의 수, 질의 `M`개(`a b`, 1부터)를 받아 각 구간의 최솟값을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간**: 구축 **O(n log n)**, 질의 **O(1)**. **공간 O(n log n)** (2·10⁵개에서 18층, 총 3,337,875칸). 갱신은 지원하지 않습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(무작위 값, 두 번 중 최소).

| 작업 | 크기 | 시간 |
|---|---|---|
| `SparseTable` 구축 | n = 2·10⁵ | 0.21초 |
| `SparseTable` 질의 | 2·10⁵개 | 0.08초 |
| 세그먼트 트리 질의 (같은 질의) | 2·10⁵개 | 0.66초 |
| `DisjointSparseTable` (합) 구축 | n = 2·10⁵ | 1.4초 |
| `DisjointSparseTable` 질의 | 2·10⁵개 | 0.11초 |

- 질의가 많을수록 유리합니다. 위에서 질의는 세그먼트 트리보다 약 8배 빠릅니다.
- 메모리가 `n log n`이라 `n = 10⁶`이면 약 2천만 칸입니다 (파이썬 리스트의 포인터만 세어도 약 160MB). 그 이상은 세그먼트 트리나 오프라인 처리를 고려하세요.
- 분리 희소 배열은 구축이 느립니다(위 표). 질의가 많지 않다면 세그먼트 트리가 낫습니다.

## 6. 자주 하는 실수

- **합에 쓰기**: 멱등이 아닌 연산에서는 겹친 부분이 두 번 계산됩니다. 합은 누적 합, 일반 연산은 분리 희소 배열.
- **`k` 계산**: `k = floor(log₂(길이))`. `math.log2`는 부동소수점이라 경계에서 틀릴 수 있어 `bit_length() − 1`을 씁니다.
- **두 번째 조각의 시작**: `right − 2^k`입니다(`left + len − 2^k`). `right − 2^k − 1`로 쓰면 한 칸 밀립니다.
- **구간 규칙**: 이 구현은 반열린 `[left, right)`입니다. 문제의 닫힌 `[a, b]`(1부터)는 `query(a − 1, b)`.
- **빈 구간 질의**: `len = 0`이면 `k`가 −1이 되어 의미 없는 값이 나옵니다. 이 구현은 `ValueError`를 냅니다.
- **갱신이 있는 문제에 사용**: 값이 바뀌면 표 전체를 다시 만들어야 합니다.
- **층 수 부족**: `while (1 << k) <= n`. `<`로 쓰면 `n`이 2의 거듭제곱일 때 가장 위층이 빠집니다.
- **분리 희소 배열의 단일 원소 질의**: `l == r`이면 `l ^ r = 0`이라 비트가 없으므로 따로 처리해야 합니다.

## 7. 변형과 응용

- **LCA**: 트리를 오일러 투어한 배열에서 두 정점 사이의 최소 깊이 정점이 LCA입니다. 구축 `O(n log n)`, 질의 `O(1)`. → [최소 공통 조상](../../03-graph-advanced/lca/)
- **접미사 배열의 LCP 질의**: 두 접미사의 최장 공통 접두사는 인접 LCP 배열의 구간 최솟값. → [접미사 배열과 LCP](../../05-strings-advanced/suffix-array-lcp/)
- **정적 구간 gcd**: `gcd`는 멱등입니다.
- **투 포인터 + RMQ**: "구간의 최댓값 − 최솟값 ≤ K" 같은 조건을 두 포인터마다 `O(1)`에 확인.
- **점프 표(binary lifting)**: `up[k][v]` = `v`에서 `2^k`칸 위의 조상. 같은 "2의 거듭제곱 표" 아이디어이지만 구간이 아니라 이동을 합성합니다 (`f(f(x))`).
- **구간의 두 번째 최솟값, 최빈값** 등은 별도의 자료구조가 필요합니다.
