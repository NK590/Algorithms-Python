# Divide and Conquer (분할 정복)

> **한 줄 요약**: 문제를 같은 모양의 **더 작은 문제**로 나누고(divide), 각각을 풀고(conquer), 결과를 **합친다**(combine). 합치는 비용이 O(n)이고 반으로 나누면 전체가 O(n log n)이다.

## 1. 언제 쓰나 (문제 신호)

- 입력을 **반으로 나눠도** 같은 문제이고, 두 절반의 답을 합치면 전체의 답이 나온다
- 정답이 **구간의 가운데를 걸치는** 경우만 따로 처리하면 된다 (구간 합 최대, 가장 가까운 두 점)
- 정렬 도중에 **쌍의 개수**를 센다 (역전 쌍)
- 2^k × 2^k 영역을 4등분하는 **재귀적 패턴** (Z 순서, 쿼드 트리)
- 지수/거듭제곱을 반으로 줄이기 → [빠른 거듭제곱](../fast-exponentiation/)

## 2. 핵심 아이디어

세 단계입니다.

1. **분할**: 문제를 `a`개의 `n/b` 크기 문제로 나눈다.
2. **정복**: 각각을 재귀로 푼다. 충분히 작으면(기저) 직접 푼다.
3. **결합**: 작은 문제들의 답에서 원래 문제의 답을 만든다.

비용은 점화식 `T(n) = a·T(n/b) + f(n)`입니다. 반으로 나눠(`a = b = 2`) 합치는 비용이 `O(n)`이면 `T(n) = 2T(n/2) + O(n) = O(n log n)`입니다. (재귀의 깊이 `log n`층, 각 층에서 합치는 비용 합이 `n`)

| 점화식 | 결과 | 예 |
|---|---|---|
| `T(n) = 2T(n/2) + O(n)` | O(n log n) | 병합 정렬, 구간 합 최대, 역전 쌍, 가장 가까운 두 점 |
| `T(n) = T(n/2) + O(1)` | O(log n) | 이분 탐색, 빠른 거듭제곱 |
| `T(n) = 2T(n/2) + O(1)` | O(n) | 배열 전체를 한 번 훑는 재귀 |
| `T(n) = 2T(n-1) + O(1)` | O(2ⁿ) | 하노이의 탑 (문제가 절반이 아니라 1만 줄어든다) |

**합치는 단계가 알고리즘의 핵심**입니다. 아래 세 문제는 모두 "양쪽을 각각 풀면 가운데를 걸치는 경우가 남는다"는 구조입니다.

### 구간 합의 최댓값

구간은 ① 왼쪽 절반 안, ② 오른쪽 절반 안, ③ **가운데를 걸침** 중 하나입니다. ③은 가운데에서 왼쪽으로 뻗은 최대 합과 오른쪽으로 뻗은 최대 합을 더하면 O(n)에 구해집니다.

### 역전 쌍 세기

병합 정렬의 합치는 단계에서, **오른쪽 절반의 원소가 왼쪽보다 먼저 나올 때마다** 왼쪽에 남은 원소 수만큼 역전 쌍이 있습니다(남은 왼쪽 원소는 모두 더 크므로).

### 가장 가까운 두 점

x 좌표로 정렬해 반으로 나누고, 양쪽의 최소 거리 `d`를 구합니다. 가운데 선에서 `d` 이내의 **띠(strip)** 안의 점만 y 순으로 보면 각 점에서 뒤로 상수 개만 비교하면 됩니다.

### Z 순서와 쿼드 트리

2ⁿ × 2ⁿ 배열을 네 사분면으로 나눠, 어느 사분면에 속하는지에 따라 앞선 칸 수(`사분면 번호 × 4ⁿ⁻¹`)를 더하고 그 사분면 안에서 같은 문제를 풉니다.

## 3. 손으로 따라가기

### 구간 합 최대 `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`

가운데(`index 4`)를 기준으로 왼쪽 `[-2, 1, -3, 4]`, 오른쪽 `[-1, 2, 1, -5, 4]`.

- 왼쪽 안의 최댓값: 4
- 오른쪽 안의 최댓값: 4 (`[2, 1]`이 3, `[4]`가 4)
- 가운데를 걸침: 왼쪽 끝에서 뻗은 최대 합 4(`[4]`) + 오른쪽 시작에서 뻗은 최대 합 `-1 + 2 + 1 = 2`(`[-1, 2, 1]`) = **6**

세 값 중 최대 **6** (`[4, -1, 2, 1]`).

### Z 순서 (4×4)

```
 0  1  4  5
 2  3  6  7
 8  9 12 13
10 11 14 15
```

`(r, c) = (3, 1)`의 번호를 구합니다. 크기 4: 아래쪽(`r ≥ 2`), 왼쪽(`c < 2`)이므로 사분면 번호 2 → `2 × 4 = 8` 더하고, 안쪽 좌표 `(1, 1)`로 내려갑니다. 크기 2: 아래쪽(`r ≥ 1`), 오른쪽(`c ≥ 1`) → 사분면 3 → `3 × 1 = 3`. 합 **11**.

### 쿼드 트리 압축

`["01", "11"]` → 모두 같지 않으므로 `(왼위 오른위 왼아래 오른아래)` = `(0111)`. 모두 같은 영역은 그 값 하나만 씁니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def max_subarray_dc(numbers):
    def solve(lo, hi):                       # [lo, hi)
        if hi - lo == 1:
            return numbers[lo]
        mid = (lo + hi) // 2
        left, right = solve(lo, mid), solve(mid, hi)
        # 가운데를 걸치는 구간: 가운데에서 왼쪽/오른쪽으로 뻗은 최대 합
        running, best_left = 0, float("-inf")
        for i in range(mid - 1, lo - 1, -1):
            running += numbers[i]
            best_left = max(best_left, running)
        running, best_right = 0, float("-inf")
        for i in range(mid, hi):
            running += numbers[i]
            best_right = max(best_right, running)
        return max(left, right, best_left + best_right)
    return solve(0, len(numbers))
```

- `count_inversions_dc`: 병합 정렬을 하며 역전 쌍을 센다. 입력을 바꾸지 않습니다.
- `closest_pair_squared(points)`: 가장 가까운 두 점의 거리의 **제곱**(정수 비교로 오차를 피함).
- `z_order_index(n, r, c)`: Z 순서에서의 번호. 직접 실행하면 `N r c`를 받아 출력합니다.
- `quad_tree(grid)`, `count_uniform_regions(grid)`: 쿼드 트리 압축, 9등분 후 같은 값 영역 세기.

## 5. 복잡도와 입력 크기 가이드

- 대부분 **시간 O(n log n)**, **공간 O(log n) ~ O(n)** (재귀 깊이와 합치기 버퍼). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 n = 10⁵으로 측정한 값입니다.

| 알고리즘 | 시간 |
|---|---|
| 가장 가까운 두 점 (`closest_pair_squared`) | 0.44초 |
| 역전 쌍 세기 (`count_inversions_dc`) | 0.27초 |
| 구간 합 최대 (`max_subarray_dc`) | 0.21초 |

- 구간 합 최대는 분할 정복(O(n log n))보다 [카데인 알고리즘](../../../lv1-elementary/07-algorithm-paradigms/dp-practice/)(O(n))이 더 빠릅니다. 여기서는 합치는 단계를 연습하기 위한 예제입니다.
- 재귀 깊이는 `log n`이라 작지만, 파이썬 함수 호출 비용이 커서 n ≥ 10⁶에서는 느립니다.

## 6. 자주 하는 실수

- **합치는 단계를 놓침**: 가운데를 걸치는 경우를 빼면 답이 작게 나옵니다.
- **기저 조건**: 구간 길이 1(또는 2, 3)에서 멈추지 않으면 무한 재귀입니다.
- **인덱스 경계(`mid`)**: 반열린 구간 `[lo, hi)`로 일관되게 쓰면 실수가 줄어듭니다.
- **리스트 슬라이싱의 비용**: `solve(arr[:mid])`처럼 자르면 복사 비용 O(n)이 매 층 들어 전체 O(n log n)이 되기도 하지만, 인덱스로 구간을 표현하는 것이 안전합니다.
- **역전 쌍에서 같은 값**: `a[i] <= a[j]`이면 왼쪽을 먼저 내보내 같은 값은 역전으로 세지 않습니다. `<`로 쓰면 틀립니다.
- **가까운 두 점의 띠 폭**: 거리의 제곱으로 비교한다면 폭도 제곱으로 맞춰야 합니다. 같은 점이 두 번 나오면 답은 0입니다.
- **분할이 균등하지 않음**: 한쪽이 거의 비어 있으면 O(n²)이 됩니다. (퀵 정렬의 최악)
