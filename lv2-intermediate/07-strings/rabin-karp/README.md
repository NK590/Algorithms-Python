# Rabin-Karp Algorithm (라빈-카프 알고리즘)

> **한 줄 요약**: 문자열을 **다항 해시** 하나의 정수로 바꿔 비교한다. 창을 한 칸 밀 때 앞 글자를 빼고 뒤 글자를 붙여(롤링 해시) 해시를 `O(1)`에 갱신하므로 `n`개의 부분 문자열을 `O(n)`에 비교한다. 접두사 해시를 만들어 두면 **임의의 두 부분 문자열이 같은지를 `O(1)`에** 확인할 수 있어서, 이분 탐색과 결합하는 문제(가장 긴 반복 부분 문자열)에 강력하다.

## 1. 언제 쓰나 (문제 신호)

- "본문 `T`에서 패턴 `P`가 나오는 위치" — [KMP](../kmp/)로도 되지만 해시로 간단히 풀 수 있다
- "두 부분 문자열 `s[a..b]`와 `s[c..d]`가 같은가"를 **여러 번** 묻는다 (질의 `10⁵~10⁶`번)
- "**두 번 이상 나오는** 가장 긴 부분 문자열", "길이 `L`의 부분 문자열 중 중복이 있는가" → 길이를 이분 탐색하고 해시로 검사
- **같은 길이**의 여러 패턴을 동시에 찾기, 길이 `L`의 모든 부분 문자열을 집합에 넣기 (예: DNA 서열 중 10글자 반복)
- 2차원 격자에서 패턴 찾기, 회문 판정(앞에서 읽은 해시 = 뒤에서 읽은 해시)

## 2. 핵심 아이디어

**다항 해시**: 문자열 `s[0..L−1]`을 `B`진법 수처럼 읽어서 `M`으로 나눈 나머지를 해시로 삼습니다.

```
H(s) = (s[0]·B^(L−1) + s[1]·B^(L−2) + … + s[L−1]) mod M
```

같은 문자열은 항상 같은 해시를 가집니다. 해시가 **다르면 문자열이 다르다**는 것이 확실하고, 해시가 같으면 "아마 같다" 정도입니다(충돌 가능).

**롤링 해시**: 창이 `text[i..i+m−1]`에서 `text[i+1..i+m]`로 밀릴 때

```
H_new = ((H_old − text[i]·B^(m−1)) · B + text[i+m]) mod M
```

맨 앞 글자의 기여분 `text[i]·B^(m−1)`을 빼고, 나머지 전체를 한 자리씩 올린(`·B`) 뒤 새 글자를 붙입니다. `B^(m−1)`은 한 번만 계산해 둡니다.

**충돌 처리**: 해시가 같을 때 **실제 문자열을 비교**하면 결과는 언제나 정확하고, 충돌이 많으면 느려질 뿐입니다(최악 `O(nm)`). `M`이 큰 소수(여기서는 `2⁶¹ − 1`)이면 충돌이 거의 없어 평균 `O(n + m)`입니다. 해시만 믿고 비교를 생략하면 아주 작은 확률로 틀립니다. 충돌 확률은 대략 `(비교 횟수 × 문자열 길이) / M`으로 보면 됩니다.

**접두사 해시**: `prefix[i] = H(s[:i])`로 두면 `s[l:r]`의 해시는

```
H(s[l:r]) = prefix[r] − prefix[l] · B^(r−l)    (mod M)
```

`prefix[l]`은 `s[l:r]` 앞에 붙은 부분이라 `B^(r−l)`만큼 올라가 있으므로 그만큼 뺍니다. 한 번 `O(n)`에 만들어 두면 이후 모든 부분 문자열의 해시가 `O(1)`입니다.

**가장 긴 반복 부분 문자열**: 길이 `L`인 부분 문자열이 두 번 나온다면 길이 `L − 1`인 것도 두 번 나옵니다(잘라낸 것이므로). 단조성이 있으니 길이를 **이분 탐색**하고, 각 길이는 모든 부분 문자열의 해시를 집합에 넣어 중복을 찾습니다. `O(n log n)`.

### 무엇을 저장하고 어떻게 움직이나

문자열을 다항식처럼 정수 값에 대응시키고 부분 문자열의 해시를 빠르게 계산합니다. 누적 해시와 밑의 거듭제곱을 저장하면 같은 길이의 두 구간 해시를 O(1)에 비교할 수 있습니다. 해시 같음은 후보 일치이며 문자열 같음을 항상 보장하지 않습니다.

### 왜 이 방법이 맞는가

같은 문자열은 같은 해시를 갖지만 모듈러 나머지로 많은 문자열을 작은 값에 압축해 충돌이 가능합니다. 정확성이 필수이면 원문을 비교하고, 충돌 확률을 낮추려면 독립적인 두 해시 등을 씁니다. 이러한 검증 비용도 최악 시간 분석에 포함합니다.

### 작은 예제로 검산하기

밑 10으로 숫자 문자열 `1234`를 표현하면 길이 2의 `23`은 접두 값에서 앞부분을 제거해 계산합니다. 실제 문자에는 더 큰 밑과 모듈러를 사용합니다. 다른 길이의 문자열을 길이 확인 없이 같은 해시만으로 비교하지 마세요.

## 3. 손으로 따라가기

### 롤링 해시: `text = XABAB`, `pattern = AB`

손으로 계산할 수 있게 `B = 5`, `M = 101`로 줄입니다(`ord('A') = 65`, `ord('B') = 66`, `ord('X') = 88`). `B^(m−1) = 5`.

`H("AB") = 65·5 + 66 = 391 mod 101 = 88` — 이것이 `target`입니다. 첫 창 `XA`의 해시는 `88·5 + 65 = 505 mod 101 = 0`.

| `i` | 창 | 해시 | `target`(88)과 | 실제 비교 | 한 칸 밀어서 얻은 다음 창의 해시 |
|---|---|---|---|---|---|
| 0 | `XA` | 0 | 다름 | | `((0 − 88·5)·5 + 66) mod 101 = 88` (`X`를 빼고 `B`를 붙여 창 `AB`) |
| 1 | `AB` | 88 | **같음** | `AB == AB` → **등장** | `((88 − 65·5)·5 + 65) mod 101 = 92` (`A`를 빼고 `A`를 붙여 창 `BA`) |
| 2 | `BA` | 92 | 다름 | | `((92 − 66·5)·5 + 66) mod 101 = 88` (`B`를 빼고 `B`를 붙여 창 `AB`) |
| 3 | `AB` | 88 | **같음** | `AB == AB` → **등장** | (끝) |

밀어서 얻은 해시(`88`, `92`, `88`)는 다음 창 `AB`, `BA`, `AB`를 `polynomial_hash`로 처음부터 다시 계산한 값과 모두 같습니다. 등장 위치는 `[1, 3]`입니다.

### 충돌이 일어나도 결과는 정확하다

`mod`를 일부러 작게 줄여서 실험합니다. 무작위 2000글자(`a, b, c`)에서 패턴 `abcab`를 찾을 때, 진짜 일치가 10곳입니다.

| `mod` | 해시는 같지만 문자열은 다른 위치(거짓 충돌) | `rabin_karp`의 결과 |
|---|---|---|
| 7 | 277곳 | 10곳 (정확) |
| 101 | 0곳 | 10곳 |
| 10007 | 0곳 | 10곳 |
| 2⁶¹ − 1 | 0곳 | 10곳 |

`mod = 7`에서는 거짓 충돌이 277번 일어나 매번 실제 비교를 하지만 결과는 정확합니다. 큰 `mod`에서는 거짓 충돌이 없어 실제 비교가 일치하는 곳에서만 일어납니다.

### 접두사 해시: `s = abcabc` (`B = 257`, `M = 2⁶¹ − 1`)

`prefix = [0, 97, 25027, 6432038, 1653033863, 424829702889, 109181233642572]`. 예를 들어 `prefix[3] = 97·257² + 98·257 + 99 = 6432038`이 `H("abc")`입니다. `substring_hash(0, 3)`와 `substring_hash(3, 6)`은 둘 다 `H("abc")`라서 같고, 두 부분 문자열이 같다고 `O(1)`에 판단됩니다.

### 가장 긴 반복 부분 문자열: `banana`

| 단계 | 구간 `[lo, hi]` | 시험 길이 `mid` | 길이 `mid`인 부분 문자열 | 두 번 나오나 | 결과 |
|---|---|---|---|---|---|
| 1 | `[0, 5]` | 3 | `ban, ana, nan, ana` | `ana`가 두 번 (위치 1, 3, **겹쳐도 됨**) | `lo = 3` |
| 2 | `[3, 5]` | 4 | `bana, anan, nana` | 없음 | `hi = 3` |

답은 `3`입니다. 다른 예: `abracadabra → 4`(`abra`), `aaaa → 3`, `abcd → 0`.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
BASE = 257
MOD = (1 << 61) - 1                       # 큰 소수: 충돌 확률이 매우 낮다

def polynomial_hash(s, base=BASE, mod=MOD):
    value = 0
    for ch in s:
        value = (value * base + ord(ch)) % mod
    return value

def rabin_karp(text, pattern, base=BASE, mod=MOD):
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return []
    high = pow(base, m - 1, mod)           # 맨 앞 글자의 자릿수 B^(m-1)
    target = polynomial_hash(pattern, base, mod)
    window = polynomial_hash(text[:m], base, mod)
    positions = []
    for i in range(n - m + 1):
        if window == target and text[i:i + m] == pattern:   # 해시가 같을 때만 실제 비교
            positions.append(i)
        if i + m < n:                      # 창을 한 칸 민다
            window = ((window - ord(text[i]) * high) * base + ord(text[i + m])) % mod
    return positions

class PrefixHash:
    def __init__(self, s, base=BASE, mod=MOD):
        self.mod = mod
        self.prefix = [0] * (len(s) + 1)
        self.power = [1] * (len(s) + 1)
        for i, ch in enumerate(s):
            self.prefix[i + 1] = (self.prefix[i] * base + ord(ch)) % mod
            self.power[i + 1] = self.power[i] * base % mod

    def substring_hash(self, left, right):  # s[left:right]
        return (self.prefix[right] - self.prefix[left] * self.power[right - left]) % self.mod
```

- `has_repeated_substring(s, length)`: 길이 `length`인 부분 문자열이 두 번 이상 나오는가. 해시를 모아 두고 같은 해시가 나오면 실제 문자열로 확인합니다.
- `longest_repeated_substring_length(s)`: 위를 이분 탐색한 `O(n log n)`.
- 직접 실행하면 두 줄(본문, 패턴)을 받아 패턴이 나오는 횟수를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **롤링 해시 검색**: 평균 **O(n + m)**, 최악 **O(nm)** (해시 충돌이 계속 나고 실제 비교가 매번 길게 이어지는 경우). 공간 **O(1)**.
- **접두사 해시**: 전처리 **O(n)**, 질의 **O(1)**, 공간 **O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(세 번 중 최소, 가장 긴 반복 부분 문자열은 한 번 측정).

| 작업 | 크기 | 시간 |
|---|---|---|
| `rabin_karp` (2글자 알파벳, 길이 20 패턴) | n = 10⁶ | 0.25초 |
| 같은 입력의 `kmp_search` | n = 10⁶ | 0.098초 |
| 같은 입력의 `str.find` 반복 | n = 10⁶ | 0.0067초 |
| `longest_repeated_substring_length` (무작위 10글자 알파벳) | n = 10⁵ | 1.7초 |
| `longest_repeated_substring_length` (`"a" * 20000`) | n = 2·10⁴ | 0.09초 |

- 단순한 검색이라면 내장 `str.find`가 가장 빠르고 KMP가 다음입니다. 롤링 해시는 파이썬에서 글자마다 곱셈·나머지를 해야 해서 KMP보다 느리지만, **부분 문자열의 비교를 `O(1)`로 만들어 준다**는 점이 다른 알고리즘에는 없는 장점입니다.
- 가장 긴 반복 부분 문자열을 `O(n log n)`에 푸는 방법은 해시 + 이분 탐색 외에 접미사 배열 + LCP가 있습니다. 해시 쪽이 구현이 짧습니다. → [접미사 배열과 LCP](../../../lv3-advanced/05-strings-advanced/suffix-array-lcp/)

## 6. 자주 하는 실수

- **해시가 같다고 같은 문자열로 단정**: 확률적으로 틀립니다. 정확해야 하면 실제 비교로 확인하세요(이 구현의 방식). 확률적 풀이를 쓸 때는 `mod`를 두 개 쓰는 이중 해시나 `2⁶¹ − 1` 같은 큰 소수를 씁니다.
- **고정된 `base`와 작은 `mod`**: 출제자가 같은 해시를 내는 반례를 만들 수 있습니다(안티 해시). `base`를 `random.randrange(256, mod - 1)`로 무작위로 정하세요. `mod = 2⁶⁴`(C++의 자연 오버플로)는 Thue-Morse 문자열로 깨지는 것으로 유명합니다.
- **글자 값 `0`**: 글자를 `a → 0`처럼 0부터 매기면 `"a"`와 `"aa"`의 해시가 같아집니다. `ord(ch)`처럼 1 이상의 값을 씁니다.
- **빼기 후 음수**: `window − ord(text[i]) · high`가 음수가 될 수 있습니다. 파이썬의 `%`는 음수에도 0 이상을 주지만 C++/Java에서는 `+ mod`를 더해야 합니다.
- **접두사 해시 공식에서 `power`를 빼먹음**: `prefix[r] − prefix[l]`만 하면 틀립니다. `B^(r−l)`을 곱해야 합니다.
- **길이가 다른 문자열의 해시를 비교**: 길이가 달라도 해시가 같을 수 있습니다. 길이가 같은지는 따로 확인합니다.
- **창이 본문보다 긴 경우**: `m > n`이면 빈 결과를 먼저 돌려줍니다.
- **느린 해시 계산**: 매 위치에서 `polynomial_hash(text[i:i+m])`를 새로 구하면 `O(nm)`입니다. 롤링으로 `O(1)` 갱신.

## 7. 변형과 응용

- **이중 해시**: `(base₁, mod₁)`와 `(base₂, mod₂)` 두 쌍의 해시를 묶어 충돌 확률을 곱으로 낮춥니다.
- **회문 판정**: 앞에서 읽은 해시와 뒤에서 읽은 해시(역방향 접두사 해시)가 같은지로 `O(1)`에. 가장 긴 회문은 이분 탐색과 결합하면 `O(n log n)`입니다. → [매내처](../../../lv3-advanced/05-strings-advanced/manacher/)는 `O(n)`.
- **2차원 해시**: 행·열 방향으로 각각 롤링해서 2차원 패턴을 찾습니다.
- **두 문자열의 LCP**: 길이를 이분 탐색하고 해시로 접두사 비교를 `O(1)`에.
- **중복 제거·집합**: 길이 `L`의 모든 부분 문자열의 해시를 `set`에 넣어 서로 다른 부분 문자열의 개수를 셉니다.
- **해시로 트리·그래프를 비교**: 트리 동형 판정에서 서브트리를 해시로 표현합니다.
