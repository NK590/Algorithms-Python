# 문자열 (Strings)

문자열에서 **패턴을 찾고**, 부분 문자열을 **빠르게 비교하고**, **접두사로 묶어서** 다루는 세 가지 도구입니다. 모두 "순진하게 하면 `O(nm)`"인 문제를 `O(n + m)` 근처로 줄이는 방법입니다.

## 한눈에 비교

| 개념 | 핵심 도구 | 잘하는 것 | 시간 |
|---|---|---|---|
| [KMP](kmp/) | 실패 함수 (접두사이자 접미사인 가장 긴 부분) | 패턴 찾기, **주기·테두리** 문제 | O(n + m), 항상 |
| [라빈-카프](rabin-karp/) | 다항 해시, 롤링 해시, 접두사 해시 | **임의의 두 부분 문자열 비교**를 O(1)에, 이분 탐색과 결합 | 평균 O(n + m) |
| [트라이](trie/) | 글자별 간선의 트리 | **접두사** 질의, 자동 완성, XOR 최대 | 삽입·질의 O(L) |

## 어떤 방법을 쓸까

| 상황 | 선택 |
|---|---|
| 본문에서 패턴이 있는지/어디 있는지만 | 파이썬 내장 `in`, `str.find`가 가장 빠르다 |
| 반복 주기, "접두사=접미사" 같은 구조 | [KMP](kmp/)의 실패 함수 |
| 부분 문자열이 같은지를 여러 번 질의 | [라빈-카프](rabin-karp/)의 접두사 해시 |
| 가장 긴 반복(중복) 부분 문자열 | [라빈-카프](rabin-karp/) + 이분 탐색 |
| 같은 길이의 여러 패턴을 한꺼번에 | [라빈-카프](rabin-karp/) (해시 집합) |
| 여러 문자열의 접두사 통계, 자동 완성 | [트라이](trie/) |
| 정확히 일치하는 문자열의 존재만 | `set` (트라이보다 훨씬 빠르다) |
| 서로 다른 여러 패턴을 본문에서 동시에 | [아호-코라식](../../lv3-advanced/05-strings-advanced/aho-corasick/) (트라이 + 실패 링크) |
| 모든 접미사를 다루는 문제 | [접미사 배열과 LCP](../../lv3-advanced/05-strings-advanced/suffix-array-lcp/) |

## 주의할 점

- 파이썬은 문자열 내장 연산이 C로 구현되어 있어, 직접 짠 KMP나 롤링 해시보다 단순 검색에서 훨씬 빠릅니다. 이 세 알고리즘은 **내장이 못 하는 질문**(주기, 접두사 통계, 임의의 부분 문자열 비교)에 쓰세요.
- 해시는 충돌이 있습니다. 확실해야 하면 같은 해시일 때 실제 문자열을 비교하고, 확률적이라면 큰 소수와 무작위 `base`를 씁니다.
- 입력에 공백이 있을 수 있는 문제는 `split()` 대신 줄 단위로 읽습니다.
