# Union-Find (유니온 파인드, Disjoint Set - 서로소 집합)

> **한 줄 요약**: 원소들을 서로소인 집합으로 나누어 두고, "두 집합 합치기(union)"와 "두 원소가 같은 집합인가(find)"를 거의 상수 시간에 처리한다. 경로 압축과 크기 기준 합치기를 함께 쓴다.

## 1. 언제 쓰나 (문제 신호)

- "**같은 그룹인가?**" 질의와 "**두 그룹을 합친다**" 연산이 번갈아 나온다 (친구 관계, 네트워크 연결)
- 간선을 하나씩 추가하면서 **연결 요소의 수**를 세거나 **사이클이 처음 생기는 순간**을 찾는다
- [크루스칼](../kruskal/)의 사이클 판별 (최소 스패닝 트리)
- 합치기만 있고 **쪼개기는 없다** (쪼개는 연산이 있으면 시간을 거꾸로 돌려 합치기로 바꾸거나 다른 구조를 써야 한다)
- 정점이 10⁵~10⁶, 연산이 10⁵~10⁶개

## 2. 핵심 아이디어

각 집합을 **트리**로 표현합니다. 모든 원소는 부모를 가리키고, 부모가 자기 자신인 원소가 **루트(대표)** 입니다. 처음에는 모두 자기 자신이 루트인 크기 1의 집합입니다.

- **find(x)**: 부모를 따라 루트까지 올라간다. 두 원소가 같은 집합이면 루트가 같다.
- **union(a, b)**: `find(a)`와 `find(b)`가 다르면 한 루트를 다른 루트 밑에 붙인다.

트리가 한쪽으로 길어지면 find가 느려집니다. 두 가지 최적화로 막습니다.

1. **크기 기준 합치기(union by size)**: 항상 **작은 트리를 큰 트리 밑에** 붙입니다. 어떤 원소의 깊이는 그 원소가 속한 트리가 합쳐질 때만 1씩 늘고, 합쳐질 때마다 트리 크기가 두 배 이상 커지므로 깊이는 `log₂ n` 이하입니다.
2. **경로 압축(path compression)**: find가 지나온 모든 원소의 부모를 루트로 바로 바꿉니다. 같은 경로를 다시 올라갈 일이 없어집니다.

둘을 함께 쓰면 연산 하나의 분할 상환 비용이 역아커만 함수 `α(n)`이고, 이는 현실적인 모든 n에서 4 이하라서 사실상 **상수**입니다.

## 3. 손으로 따라가기

원소 `0 … 7`, 연산을 차례로 적용합니다. `parent`가 자기 자신이 아닌 칸만 읽으면 숲의 모양이 됩니다.

| 연산 | 결과 | `parent` | 집합들 |
|---|---|---|---|
| (시작) | | `[0,1,2,3,4,5,6,7]` | `{0}{1}{2}{3}{4}{5}{6}{7}` |
| union(1, 3) | 합쳐짐 (크기가 같으면 두 번째 루트가 첫 번째 밑으로) | `[0,1,2,1,4,5,6,7]` | `{1,3}` |
| connected(1, 7) | **아니오** | 그대로 | |
| union(7, 6) | 합쳐짐 | `[0,1,2,1,4,5,7,7]` | `{1,3}` `{6,7}` |
| connected(7, 1) | **아니오** | 그대로 | |
| union(3, 7) | 합쳐짐 (크기 2 + 2) | `[0,1,2,1,4,5,7,1]` | `{1,3,6,7}` |
| union(4, 2) | 합쳐짐 | `[0,1,4,1,4,5,7,1]` | `{1,3,6,7}` `{2,4}` |
| union(1, 1) | 이미 같은 집합 → `False` | 그대로 | |
| connected(1, 1) | **예** | 그대로 | |
| connected(6, 3) | **예**. `find(6)`이 `6 → 7 → 1`을 따라가며 **경로 압축** | `[0,1,4,1,4,5,1,1]` | |

union(3, 7)에서 `find(3) = 1`, `find(7) = 7`이고 두 집합의 크기가 모두 2이므로 둘째 루트(7)가 첫째 루트(1) 밑에 붙습니다. 이때 원소 6은 `6 → 7 → 1`로 깊이가 2가 되고, 마지막 `connected(6, 3)`에서 `find(6)`이 이 경로를 따라가며 6의 부모를 루트 1로 바로 바꿉니다(경로 압축). 압축은 **find를 한 만큼만** 일어나므로 find하지 않은 원소는 깊은 채로 남아 있을 수 있습니다.

**깊이의 차이**: 원소 2000개를 `union(i+1, i)` 순서로 한 줄씩 이어 붙이면 크기를 보지 않고 항상 "두 번째 루트를 첫 번째 밑에" 붙이는 구현은 깊이가 1999까지 자라지만, 크기 기준 합치기는 깊이가 1입니다. ([테스트](test_solution.py)의 `test_chain_of_unions_does_not_build_a_deep_tree`)

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.count = n                           # 집합의 수

    def find(self, x):
        root = x
        while self.parent[root] != root:         # 루트까지 올라간다
            root = self.parent[root]
        while self.parent[x] != root:            # 지나온 모든 원소를 루트에 직접 연결 (경로 압축)
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                         # 이미 같은 집합
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra                      # 작은 쪽을 큰 쪽 밑에
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.count -= 1
        return True
```

- `find`를 **재귀가 아닌 반복문**으로 썼습니다. 깊이가 큰 트리에서 `RecursionError`를 피합니다. (테스트가 깊이 20만 사슬에서 확인합니다)
- `connected`, `size_of`, `groups`: 같은 집합인가, 집합의 크기, 모든 집합의 목록.
- `count_components(n, edges)`: 간선을 모두 합친 뒤의 연결 요소의 수.
- `first_cycle_edge(n, edges)`: 간선을 순서대로 추가할 때 **처음으로 사이클을 만드는 간선**의 번호(1부터). 없으면 0. `union`이 `False`인 첫 순간입니다.
- 직접 실행하면 `n m`과 `0 a b`(합치기), `1 a b`(같은 집합인가)를 받아 `YES/NO`를 출력합니다.

## 6. 자주 하는 실수

- **`find` 없이 `parent[a]`로 비교**: `parent[a] == parent[b]`는 루트가 같다는 뜻이 아닙니다. 반드시 `find(a) == find(b)`.
- **union에서 `parent[a] = b`**: 루트가 아닌 원소에 직접 연결하면 두 집합이 아니라 한 원소만 옮겨 가는 것이 됩니다. 항상 루트끼리 연결합니다.
- **경로 압축 없이 재귀 `find`**: 깊은 트리에서 재귀 한도에 걸립니다. 반복문이 안전합니다.
- **크기를 루트가 아닌 곳에서 읽음**: `size`는 루트에서만 유효합니다. `size_of(x)`는 `find(x)`를 거칩니다.
- **원소 번호가 1부터인데 크기를 n으로**: 크기 `n + 1`로 만드세요. (`main`에서 그렇게 합니다)
- **문자열·튜플 원소**: 번호 대신 딕셔너리로 `parent`를 만들거나, 먼저 번호를 붙이세요.
- **쪼개기 연산에 사용**: 이 구조는 합치기만 지원합니다.

## 7. 변형과 응용

- **최소 스패닝 트리**: 간선을 가중치순으로 보며 사이클을 만드는 간선을 버린다. → [크루스칼](../kruskal/)
- **이분 그래프 판별**: 정점마다 "색 0인 노드"와 "색 1인 노드"를 두는 방식. → [이분 그래프](../bipartite-graph/)
- **사이클 판별(무방향)**: 이미 같은 집합인 두 정점을 잇는 간선이 사이클. (`first_cycle_edge`)
- **오프라인 역순 처리**: 삭제 연산이 있어도 모든 연산을 읽은 뒤 거꾸로 돌리면 삭제가 합치기가 된다.
- **가중치가 있는 유니온 파인드**: 루트까지의 상대적인 값(거리, 차이)을 함께 관리한다.
- **연결 요소 개수**: BFS/DFS로도 되지만 [연결 요소](../../../lv1-elementary/05-graph-basics/connected-components/)가 정적인 반면, 간선이 **동적으로 추가**되면 유니온 파인드가 유리하다.
