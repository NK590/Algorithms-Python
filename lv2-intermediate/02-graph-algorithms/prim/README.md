# Prim's Algorithm (프림 알고리즘, 최소 스패닝 트리)

> **한 줄 요약**: 한 정점에서 시작해, 지금까지 만든 트리에서 바깥 정점으로 뻗는 간선 중 가장 싼 것을 하나씩 붙여 나간다. 다익스트라와 같은 모양에서 힙의 키만 "시작점에서의 거리"가 아니라 "트리에 붙는 간선 하나의 가중치"다.

## 1. 언제 쓰나 (문제 신호)

- [크루스칼](../kruskal/)과 같은 문제: **모든 정점을 최소 비용으로 연결** (최소 스패닝 트리)
- 간선이 **인접 리스트**로 이미 만들어져 있다
- **밀집 그래프**(E ≈ V²): O(V²) 배열 버전이 힙 버전보다 낫다
- 정점마다 "지금 트리에서 가장 가까운 정점"을 묻는 구조가 자연스러울 때

크루스칼과 결과(가중치 합)는 같습니다. 간선이 적은 희소 그래프는 둘 다 괜찮고, 파이썬에서는 정렬이 빠른 크루스칼이 편한 경우가 많습니다.

## 2. 핵심 아이디어

> 현재 트리 `T`에 속한 정점들과 나머지 정점들 사이를 잇는 간선 중 **가장 싼 간선**은 반드시 어떤 MST에 들어간다. (절단 성질. 가장 싼 간선이 하나뿐이면 모든 MST에 들어간다.)

그래서 `T`에서 시작해 이 규칙을 반복하면 MST가 완성됩니다.

1. 시작 정점을 트리에 넣고, 거기서 나가는 간선을 모두 **힙**에 넣는다.
2. 힙에서 가장 싼 간선 `(w, v)`를 꺼낸다. `v`가 이미 트리에 있으면 버린다 (낡은 항목).
3. 아니면 `v`를 트리에 넣고 `w`를 총합에 더한다. `v`에서 나가는 간선 중 트리 밖으로 가는 것을 힙에 넣는다.
4. 힙이 빌 때까지 반복한다.

[다익스트라](../../01-shortest-path/dijkstra/)와 구조가 같지만 힙에 넣는 값이 다릅니다.

| | 다익스트라 | 프림 |
|---|---|---|
| 힙의 키 | 시작점으로부터의 **누적 거리** | 트리에 붙는 **간선 하나의 가중치** |
| 확정되는 것 | 정점의 최단 거리 | 트리에 붙는 간선 |

## 3. 손으로 따라가기

[크루스칼](../kruskal/)과 같은 여섯 도시 그래프에서 A부터 시작합니다. 힙의 항목은 `(가중치, 붙을 정점, 어느 정점에서 왔는지)`.

| 꺼낸 항목 | 판정 | 총합 | 이후 힙 |
|---|---|---|---|
| (0, A) | 채택 (시작) | 0 | (1,C←A) (4,B←A) |
| (1, C←A) | 채택 | 1 | (2,B←C) (4,B←A) (8,D←C) (10,E←C) |
| (2, B←C) | 채택 | 3 | (4,B←A) (5,D←B) (8,D←C) (10,E←C) |
| (4, B←A) | **낡은 항목** (B는 이미 트리에 있음) | | |
| (5, D←B) | 채택 | 8 | (2,E←D) (6,F←D) (8,D←C) (10,E←C) |
| (2, E←D) | 채택 | 10 | (3,F←E) (6,F←D) (8,D←C) (10,E←C) |
| (3, F←E) | 채택 | 13 | (6,F←D) (8,D←C) (10,E←C) |
| (6, F←D), (8, D←C), (10, E←C) | 모두 낡은 항목 | | |

채택한 간선 `A–C, C–B, B–D, D–E, E–F`, 총 **13**. 크루스칼과 같은 가중치 합이지만 간선이 채택되는 **순서**는 다릅니다 (크루스칼은 가중치순, 프림은 트리가 자라는 순서).

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def prim(graph, start=0):
    visited = [False] * len(graph)
    heap = [(0, start, -1)]               # (트리에 붙는 간선의 가중치, 붙을 정점, 반대쪽 끝)
    total, chosen = 0, []
    while heap:
        w, u, parent = heapq.heappop(heap)
        if visited[u]:                    # 낡은 항목
            continue
        visited[u] = True
        total += w
        if parent != -1:
            chosen.append((parent, u, w))
        for v, weight in graph[u]:
            if not visited[v]:
                heapq.heappush(heap, (weight, v, u))
    return total, chosen
```

- 그래프는 **무방향 인접 리스트** `graph[u] = [(v, w), ...]`입니다. 양방향 간선은 **양쪽에 모두** 넣어야 합니다.
- 시작 정점이 속한 연결 요소만 다룹니다. 연결되지 않은 그래프는 정점마다 `prim`을 따로 불러야 합니다(또는 [크루스칼](../kruskal/)이 편합니다).
- `prim_dense(matrix)`: 인접 행렬 `matrix[i][j]`(간선이 없으면 `inf`)로 힙 없이 O(V²)에 구합니다. 매번 "트리 밖에서 트리에 가장 가까운 정점"을 배열에서 선형으로 찾습니다.
- 직접 실행하면 `V E`와 `A B C`(E줄)를 받아 MST의 가중치 합을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **힙 버전 O(E log V)**, **행렬 버전 O(V²)**. 공간은 O(V+E) 또는 O(V²).
- 이 환경에서 측정한 값입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

| 입력 | 크루스칼 | 프림 (힙) | 프림 (행렬 O(V²)) |
|---|---|---|---|
| V = 10⁵, E = 3×10⁵ (희소) | 0.36초 | 0.97초 | 해당 없음 (행렬이 10¹⁰) |
| V = 1,500 완전 그래프 (E ≈ 110만) | 0.52초 | 5.5초 | 0.35초 |

- **희소 그래프**에서는 크루스칼이나 힙 프림. 파이썬에서는 정렬이 빠른 크루스칼이 유리한 경우가 많습니다.
- **밀집 그래프**에서는 행렬 버전이 간선을 힙에 넣고 빼는 비용이 없어 가장 빠릅니다. 단, 행렬이 메모리에 들어가야 합니다(V ≲ 5,000).

## 6. 자주 하는 실수

- **한쪽 방향만 간선을 추가**: 무방향이므로 `graph[a].append((b, w))`와 `graph[b].append((a, w))` 둘 다.
- **낡은 항목 검사 누락**: 이미 트리에 있는 정점을 다시 더하면 총합이 틀립니다. 꺼낼 때 `visited`를 확인합니다.
- **누적 거리를 힙의 키로**: 다익스트라 방식(`d + w`)으로 쓰면 최단 경로 트리가 되어 MST와 다릅니다. 키는 간선 하나의 `w`입니다.
- **연결되지 않은 그래프**: 시작 정점이 속한 요소만 다룹니다. 모든 정점이 방문되었는지 확인하세요.
- **음수 가중치**: 프림도 음수 간선이 있어도 올바르게 동작합니다(절단 성질은 부호와 무관). 다익스트라와 다릅니다.
- **행렬 버전에서 `inf` 처리**: 남은 정점에 닿을 간선이 없으면(`best == inf`) 연결 요소가 끝난 것입니다. 그대로 더하면 `inf`가 됩니다.

## 7. 변형과 응용

- **MST 위의 경로 질의**: 두 정점 사이의 경로에서 가장 큰 간선을 구하는 문제는 MST + LCA. → [LCA](../../../lv3-advanced/03-graph-advanced/lca/)
- **가상 정점 추가**: 여러 발전소 중 어디서든 전기를 받는 문제는 가상 정점 하나를 발전소와 연결.
- **최대 스패닝 트리**: 키를 `-w`로 넣습니다.
- **다익스트라와의 비교**: 같은 힙 틀이므로 둘을 함께 익히면 좋습니다. → [다익스트라](../../01-shortest-path/dijkstra/)
