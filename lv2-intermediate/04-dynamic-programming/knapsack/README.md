# Knapsack Problem (배낭 문제)

> **한 줄 요약**: 무게 한도 K인 배낭에 물건(무게, 가치)을 담아 가치의 합을 최대로. 물건을 하나씩 고려하며 `dp[w]` = "무게 한도 w에서의 최대 가치"를 갱신한다. 0/1(한 번만)이면 한도를 **큰 쪽에서 작은 쪽으로**, 무한이면 **작은 쪽에서 큰 쪽으로** 돈다.

## 1. 언제 쓰나 (문제 신호)

- "**한도**(무게, 예산, 시간) 안에서 **가치를 최대로**", 각 물건은 넣거나 말거나
- "금액을 **만드는 최소 동전 수**", "만드는 **방법의 수**"
- "일부를 골라 **합이 정확히 S**가 되는가", "합이 같은 두 묶음으로 나누기"
- 한도 K가 10³~10⁵이고 물건 수 N이 10²~10³ 정도 (NK가 10⁷ 안팎)
- 그리디(무게당 가치가 큰 것부터)는 **물건을 쪼갤 수 있을 때만** 맞습니다. ([그리디](../../../lv1-elementary/07-algorithm-paradigms/greedy/))

## 2. 핵심 아이디어

**상태**: `dp[i][w]` = 앞의 `i`개 물건만 쓰고 무게 한도가 `w`일 때의 최대 가치.

**점화식** (i번째 물건의 무게 `wt`, 가치 `v`):

```
dp[i][w] = max( dp[i-1][w]               # 안 담는다
              , dp[i-1][w-wt] + v )      # 담는다 (w ≥ wt일 때)
```

`dp[i]`는 `dp[i-1]`만 쓰므로 **1차원 표 하나**로 줄일 수 있습니다. 이때 갱신 방향이 중요합니다.

| 문제 | 반복 방향 | 이유 |
|---|---|---|
| **0/1** (물건당 1번) | `w`를 **큰 쪽 → 작은 쪽** | 아직 이번 물건이 반영되지 않은 `dp[w-wt]`를 읽어야 같은 물건을 두 번 쓰지 않는다 |
| **무한** (물건당 여러 번) | `w`를 **작은 쪽 → 큰 쪽** | 이번 물건이 이미 반영된 `dp[w-wt]`를 읽어야 같은 물건을 또 쓴다 |

**개수 제한**(물건 `i`를 최대 `c`개): `c`를 `1, 2, 4, …, 나머지`로 쪼갠 묶음을 0/1 물건으로 취급하면, 묶음의 부분집합으로 `0 ~ c`개를 모두 만들 수 있고 물건 수는 `O(log c)`입니다.

**동전 문제는 배낭의 변형**입니다.

| 질문 | 점화식 | 반복 순서 |
|---|---|---|
| 최소 동전 수 | `dp[a] = min(dp[a - coin] + 1)` | 동전 → 금액 (무한 배낭) |
| **조합**의 수 (1+2 = 2+1) | `dp[a] += dp[a - coin]` | **동전이 바깥**, 금액이 안쪽 |
| **순서**까지 구분한 수 (1+2 ≠ 2+1) | `dp[a] += dp[a - coin]` | **금액이 바깥**, 동전이 안쪽 |

같은 식인데 반복문의 순서만 바꾸면 세는 대상이 달라집니다.

**부분집합의 합**: 가치 = 무게인 0/1 배낭의 "가능한가"(`bool`) 버전입니다. `reachable[s]` = 합 `s`를 만들 수 있는가.

## 3. 손으로 따라가기

물건 `(무게, 가치)` = `(6,13) (4,8) (3,6) (5,12)`, 한도 `K = 7`. 열은 `w = 0 … 7`.

| i (물건) | w=0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 0 (없음) | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 1 (6, 13) | 0 | 0 | 0 | 0 | 0 | 0 | 13 | 13 |
| 2 (4, 8) | 0 | 0 | 0 | 0 | 8 | 8 | 13 | 13 |
| 3 (3, 6) | 0 | 0 | 0 | 6 | 8 | 8 | 13 | **14** |
| 4 (5, 12) | 0 | 0 | 0 | 6 | 8 | 12 | 13 | **14** |

`dp[3][7] = 14`는 `dp[2][4] + 6 = 8 + 6`(3번째 물건을 담음)에서 나왔고, `dp[4][7] = 14`는 `dp[3][7]` 그대로입니다. **복원**: `i = 4`에서 `dp[4][7] == dp[3][7]`이므로 담지 않았고, `i = 3`에서 `14 ≠ dp[2][7] = 13`이므로 담았으며(`w = 7 − 3 = 4`), `i = 2`에서 `dp[2][4] = 8 ≠ dp[1][4] = 0`이므로 담았습니다. 담은 물건은 `(4,8)`, `(3,6)`으로 무게 7, 가치 **14**.

**그리디가 틀리는 예**: 무게당 가치는 `2.17, 2, 2, 2.4`로 `(5,12)`가 가장 높습니다. 이것을 먼저 담으면 남은 무게 2에 아무것도 못 넣어 가치 12에 그칩니다. 최적은 14입니다. (`test_greedy_by_ratio_fails_for_01`)

**방향이 틀리면**: 물건 `(3, 4)` 하나와 한도 6에서 1차원 표를 **작은 쪽부터** 돌리면 `dp[3] = 4`, `dp[6] = dp[3] + 4 = 8`로 같은 물건을 두 번 담습니다. 큰 쪽부터 돌리면 `dp[6] = 4`.

**동전**: 동전 `[1, 2, 5]`로 5를 만드는 **조합**은 `1×5`, `1×3+2`, `1+2×2`, `5`의 **4**가지. 동전 `[1, 2]`로 3을 만드는 **순서가 있는** 방법은 `1+1+1`, `1+2`, `2+1`의 **3**가지.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def knapsack_01(items, capacity):          # items = [(무게, 가치), ...]
    dp = [0] * (capacity + 1)
    for weight, value in items:
        for w in range(capacity, weight - 1, -1):      # 큰 쪽 → 작은 쪽
            if dp[w - weight] + value > dp[w]:
                dp[w] = dp[w - weight] + value
    return dp[capacity]
```

- `knapsack_table`: 2차원 표(설명·복원용). `knapsack_01_items`가 표를 거꾸로 따라가 담은 물건의 번호를 돌려줍니다.
- `knapsack_unbounded`: 무한 배낭(작은 쪽 → 큰 쪽). `knapsack_bounded`: 개수 제한(이진 분할).
- `min_coins`, `count_coin_ways`, `count_coin_orderings`: 동전 문제 세 가지.
- `subset_sum`, `can_partition_equal`: 합이 정확히 S인 부분집합, 같은 합으로 둘로 나누기.
- 직접 실행하면 `N K`와 N개의 `W V`를 받아 가치의 최댓값을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(NK)**, **공간 O(K)** (1차원 표) 또는 O(NK) (복원이 필요한 2차원 표). K가 N에 대해 지수적으로 커질 수 있어 이 시간은 **의사 다항 시간**입니다(입력 크기에 대해서는 NP-완전).
- 이 환경에서 N = 100, K = 100,000인 0/1 배낭이 1차원 표로 **0.36초**였습니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 같은 입력에 2차원 표를 쓰면 `101 × 100,001`개의 값을 저장해야 하므로 메모리가 많이 듭니다. 복원이 필요 없다면 1차원이 정답입니다.
- K가 10⁹처럼 크고 N이 작다면(N ≤ 40) 모든 부분집합을 둘로 나눠 보는 [중간에서 만나기](../../../lv3-advanced/06-query-techniques/meet-in-the-middle/)를 고려하세요.

## 6. 자주 하는 실수

- **반복 방향 혼동**: 0/1에서 작은 쪽부터 돌면 같은 물건을 여러 번 쓰는 무한 배낭이 됩니다.
- **조합 vs 순서**: 동전의 조합 수에서 금액을 바깥 반복으로 쓰면 순서까지 세는 값이 나옵니다.
- **`dp` 초깃값**: "가치의 최댓값"은 `0`으로 시작하고, "정확히 w를 채운 최대"를 요구하면 `-∞`로 시작해 `dp[0] = 0`만 둡니다. 최소 동전 수는 `∞`로 시작합니다.
- **한도 안에서 vs 정확히**: `dp[K]`는 "무게 **이하**"의 최대(0으로 초기화한 경우)입니다. 정확히 K를 채워야 하면 달라집니다.
- **무게가 한도보다 큰 물건**: `range(capacity, weight - 1, -1)`이 비어서 자연스럽게 건너뜁니다.
- **그리디 사용**: 쪼갤 수 없으면 무게당 가치 순서가 틀립니다. 쪼갤 수 있을 때만 [그리디](../../../lv1-elementary/07-algorithm-paradigms/greedy/)가 맞습니다.
- **2차원 표를 `[[0] * (K + 1)] * (N + 1)`로 만듦**: 모든 행이 같은 리스트입니다. 리스트 컴프리헨션을 쓰세요.

## 7. 변형과 응용

- **정확히 K를 채우기**, **최소 개수**, **가능 여부**: `dp` 초깃값과 `max`/`min`/`or`만 바꿉니다.
- **여러 차원의 한도**(무게와 부피 둘 다): `dp[w1][w2]`
- **그룹 배낭**(그룹에서 하나만): 그룹을 바깥 반복으로, 안쪽에서 그룹의 각 물건을 시도
- **비트셋 최적화**: `subset_sum`을 파이썬 큰 정수 하나로 `bits |= bits << x`처럼 O(N·K/64)에
- **가치가 작고 무게가 큰 경우**: `dp[v]` = 가치 `v`를 만드는 최소 무게로 상태를 뒤집는다.
- **LIS, LCS, 구간 DP, 비트마스크 DP**: 같은 DP 그룹의 다른 틀. → [LIS](../lis/), [LCS](../lcs/), [구간 DP](../interval-dp/), [비트마스크 DP](../bitmask-dp/)
