# LIS (가장 긴 증가하는 부분 수열)

> **한 줄 요약**: `tails[k]` = 길이 `k+1`인 증가 부분 수열의 마지막 값 중 가장 작은 것. `tails`는 항상 오름차순이므로 새 수를 이분 탐색으로 끼워 넣으면 O(n log n)에 LIS의 길이가 나온다. (`tails` 자체는 LIS가 아니다.)

## 1. 언제 쓰나 (문제 신호)

- "**가장 긴 증가하는 부분 수열**의 길이", 수열에서 **일부를 지워 정렬된 상태로** 만들기 (지울 원소 수 = n − LIS)
- n이 10⁵~10⁶이라 O(n²)는 불가능하다. ([DP 연습](../../../lv1-elementary/07-algorithm-paradigms/dp-practice/)의 O(n²) LIS)
- 증가했다가 감소하는 **바이토닉** 수열, 같은 값을 허용하는 **비내림차순**
- 좌표 쌍 정렬 후 한 좌표의 LIS (전깃줄, 교차하지 않는 연결 같은 문제)

## 2. 핵심 아이디어

O(n²) 풀이는 `dp[i]` = "`i`에서 끝나는 LIS의 길이"입니다. O(n log n) 풀이는 이것을 뒤집습니다.

> **`tails[k]`** = 길이가 `k + 1`인 증가 부분 수열들의 **마지막 값 중 가장 작은 것**

같은 길이라면 마지막 값이 작을수록 뒤에 이어 붙이기 쉬우므로, 작은 쪽만 기억하면 충분합니다. 그리고 `tails`는 항상 **오름차순**입니다(길이가 긴 수열의 끝값이 더 크다). 새 수 `x`를 읽을 때:

1. `tails`에서 **`x` 이상인 첫 위치**(`bisect_left`)를 찾는다. 엄격하게 증가해야 하므로 같은 값도 대체 대상이다.
2. 그런 위치가 없으면 `x`가 모든 끝값보다 크므로 **끝에 붙여** LIS가 하나 길어진다.
3. 있으면 그 위치의 값을 `x`로 **교체**한다. 같은 길이에서 더 작은 끝값이 생긴 것이다.

최종 `tails`의 길이가 **LIS의 길이**입니다.

**`tails`는 LIS가 아닙니다.** 길이만 정확합니다. 예를 들어 `[4, 5, 1]`을 다 읽은 뒤 `tails`는 `[1, 5]`인데 실제 LIS는 `[4, 5]`입니다. 수열 자체가 필요하면 `tails_idx[k]`(그 값을 가진 원소의 위치)와 `prev[i]`(i 바로 앞에 이어지는 원소의 위치)를 함께 기록해 거슬러 올라갑니다.

**같은 값을 허용하는 경우**(비내림차순)는 `bisect_left`를 `bisect_right`로 바꾸면 됩니다. (x 이하인 값들은 대체하지 않고 그 뒤를 대체한다)

## 3. 손으로 따라가기

`[10, 20, 10, 30, 20, 50]`:

| 읽은 수 | 위치 (`bisect_left`) | 동작 | `tails` |
|---|---|---|---|
| 10 | 0 | 끝에 붙임 | `[10]` |
| 20 | 1 | 끝에 붙임 | `[10, 20]` |
| 10 | 0 | `tails[0]`을 10으로 교체 (같은 값) | `[10, 20]` |
| 30 | 2 | 끝에 붙임 | `[10, 20, 30]` |
| 20 | 1 | `tails[1]`을 20으로 교체 | `[10, 20, 30]` |
| 50 | 3 | 끝에 붙임 | `[10, 20, 30, 50]` |

길이 **4**. `prev`로 거슬러 올라가면 실제 수열 `[10, 20, 30, 50]`이 복원됩니다. 각 원소에서 **끝나는** LIS의 길이는 위치 + 1이므로 `[1, 2, 1, 3, 2, 4]`.

**바이토닉**: `[1, 5, 2, 4, 3, 2, 1]`에서 꼭대기를 `4`로 하면 앞에서 끝나는 LIS `1, 2, 4`(길이 3)와 뒤에서 시작하는 감소 수열 `4, 3, 2, 1`(길이 4)이 이어져 `3 + 4 − 1 = 6`. 뒤에서 시작하는 감소 수열은 **뒤집은 수열의 LIS**와 같습니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
from bisect import bisect_left

def lis_length(numbers):
    tails = []
    for x in numbers:
        i = bisect_left(tails, x)          # x 이상인 첫 위치
        if i == len(tails):
            tails.append(x)                # 모든 끝값보다 크면 길이가 늘어난다
        else:
            tails[i] = x                   # 같은 길이에서 더 작은 끝값으로 교체
    return len(tails)
```

- `lis_sequence`: LIS 하나를 복원합니다 (`tails_idx`, `prev` 기록).
- `longest_non_decreasing`: 같은 값을 허용(`bisect_right`).
- `lis_lengths_ending_at`: 각 원소에서 끝나는 LIS의 길이 = 이분 탐색 위치 + 1.
- `longest_bitonic`: 앞에서 끝나는 LIS + 뒤에서 시작하는 감소 수열 − 1의 최댓값.
- `min_removals_to_sort`: 엄격 오름차순으로 만들기 위해 지울 최소 원소 수 = `n − LIS`.
- 직접 실행하면 `N`과 수열을 받아 LIS의 길이를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n log n)** (각 원소마다 이분 탐색 한 번), **공간 O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다.

| 입력 | 시간 |
|---|---|
| n = 10⁶ 랜덤 수열의 LIS 길이 (결과 1,967) | 0.23초 |
| 같은 입력에서 수열 복원(`lis_sequence`) | 0.33초 |
| O(n²) DP, n = 3,000 | 0.44초 |

- O(n²)은 n ≤ 3,000~5,000이 한계이고, O(n log n)은 n = 10⁶도 1초 안에 끝납니다.

## 6. 자주 하는 실수

- **`tails`를 LIS로 출력**: 길이만 맞습니다. 수열이 필요하면 `prev`를 따라가야 합니다.
- **`bisect_left`/`bisect_right` 혼동**: 엄격 증가는 `bisect_left`, 비내림차순은 `bisect_right`.
- **`tails` 값 교체를 길이 증가와 혼동**: 교체는 길이를 바꾸지 않습니다.
- **감소 수열 / 비증가**: 부호를 뒤집거나 수열을 뒤집어 증가 수열 문제로 바꿉니다. (`-x`로 바꿔 LIS)
- **바이토닉에서 꼭대기를 두 번 셈**: `up[i] + down[i] − 1`에서 `−1`을 빠뜨리지 마세요.
- **좌표 쌍의 정렬 기준**: 한 좌표로 정렬한 뒤 다른 좌표의 LIS를 구할 때, 같은 첫 좌표가 있다면 둘째 좌표를 어느 방향으로 정렬하는지가 정답을 가릅니다.
- **복원 시 `prev`를 `tails` 위치로 착각**: `prev[i]`에는 원소의 **위치**(원래 수열의 인덱스)를 저장합니다.

## 7. 변형과 응용

- **LIS 복원**: `prev` 배열. 같은 길이의 LIS가 여럿이면 문제에서 어느 것을 출력할지 확인.
- **최소 삭제로 정렬**: `n − LIS`.
- **전깃줄 문제**: 한쪽 번호로 정렬 후 반대쪽의 LIS = 교차하지 않는 최대 전깃줄 수, 지울 전깃줄 = 전체 − LIS.
- **LIS의 개수**, **가중치가 있는 LIS**(합 최대): 구간 질의 자료구조(세그먼트 트리, 펜윅 트리)가 필요합니다. → [세그먼트 트리](../../../lv3-advanced/01-range-query-structures/segment-tree/)
- **다차원 LIS**(두 값이 모두 증가): 한 좌표로 정렬 후 다른 좌표의 LIS.
