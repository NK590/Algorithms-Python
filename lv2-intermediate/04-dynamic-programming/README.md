# 다이나믹 프로그래밍 (Dynamic Programming)

대표적인 DP 문제를 통해 **상태 정의와 점화식 세우기**를 연습합니다. [Lv1의 DP](../../lv1-elementary/07-algorithm-paradigms/dynamic-programming/)가 "저장해서 재사용한다"는 개념이었다면, 여기서는 상태의 **모양**(1차원 수열, 2차원 두 문자열, 구간, 집합)에 따라 DP를 분류합니다.

## 한눈에 비교

| 개념 | 상태 | 점화식의 뼈대 | 시간 |
|---|---|---|---|
| [배낭 문제](knapsack/) | `dp[i][무게]` (물건, 한도) | 담는다 / 안 담는다 | O(NK) |
| [LIS](lis/) | `tails[길이]` (같은 길이의 최소 끝값) | 이분 탐색으로 교체 | O(n log n) |
| [LCS와 편집 거리](lcs/) | `dp[i][j]` (두 문자열의 접두사) | 마지막 글자가 같은가 | O(nm) |
| [구간 DP](interval-dp/) | `dp[l][r]` (구간) | 분할 위치 `k`, 양 끝 | O(n³) |
| [비트마스크 DP](bitmask-dp/) | `dp[집합][마지막]` | 집합에 원소 하나 추가 | O(2ⁿ·n²) |

## 상태의 모양으로 고르기

| 문제의 구조 | 상태 | 이 그룹의 개념 |
|---|---|---|
| 물건을 고르는데 한도가 있다 | `(몇 번째 물건까지, 남은 한도)` | [배낭](knapsack/) |
| 수열에서 순서를 지키며 고른다 | `(끝나는 위치)` 또는 `(길이)` | [LIS](lis/) |
| 두 수열/문자열을 맞춘다 | `(첫 번째의 i, 두 번째의 j)` | [LCS](lcs/) |
| 연속 구간을 합치거나 쪼갠다 | `(l, r)` | [구간 DP](interval-dp/) |
| 모든 원소를 한 번씩 (n ≤ 20) | `(사용한 집합, 마지막 원소)` | [비트마스크 DP](bitmask-dp/) |
| 트리 위에서 서브트리를 합친다 | `(정점, 상태)` | [트리 DP](../03-trees/tree-dp/) |

## DP를 설계하는 순서

1. **상태**: `dp[...]`가 정확히 무엇인지 한 문장으로 쓴다.
2. **점화식**: 마지막(또는 처음) 선택으로 경우를 나눈다.
3. **초기값과 경계**: 가장 작은 상태를 직접 채운다.
4. **계산 순서**: 필요한 값이 먼저 계산되어 있게 반복문을 짠다. (배낭의 방향, 구간 DP의 길이 순서)
5. **복원이 필요하면** 선택을 기록한다 (`prev`, `split`, `came`).
6. **작은 입력에서 브루트포스와 비교한다.** 이 그룹의 테스트가 모두 그렇게 되어 있습니다.

## 읽는 순서

1. [배낭 문제](knapsack/): 한도가 있는 선택, 반복 방향의 의미
2. [LIS](lis/) → [LCS](lcs/): 수열과 문자열
3. [구간 DP](interval-dp/): 2차원 상태, 길이 순서
4. [비트마스크 DP](bitmask-dp/): 집합이 상태
