# Interval DP (구간 DP)

> **한 줄 요약**: 구간 `[l, r]`의 답을 **더 짧은 구간들의 답**으로 만든다. 상태가 `dp[l][r]`이고, 구간을 나누는 위치(`k`)나 양 끝의 처리 방식으로 점화식을 세우며, **구간의 길이가 짧은 것부터** 계산한다.

## 1. 언제 쓰나 (문제 신호)

- 연속한 구간을 **합치거나 나누는** 문제: 인접한 파일 합치기, 행렬 곱셈 순서, 구간을 쪼개 괄호 치기
- "마지막에 무엇을 하느냐"로 경우를 나누면 **양쪽이 독립된 구간**이 되는 문제 (풍선 터뜨리기)
- 구간의 **양 끝**을 보고 안쪽으로 줄이는 문제 (팰린드롬, 게임)
- n이 **수백 이하** (O(n³)을 감당할 수 있는 크기)

## 2. 핵심 아이디어

**상태**: `dp[l][r]` = 구간 `l..r`만 봤을 때의 최적값.

**점화식의 두 가지 모양**

| 모양 | 식 | 예 |
|---|---|---|
| 분할 위치 `k`를 고른다 | `dp[l][r] = min/max over k (dp[l][k] + dp[k+1][r] + 합치는 비용)` | 행렬 곱셈, 파일 합치기 |
| 양 끝을 본다 | `dp[l][r] = f(dp[l+1][r-1], dp[l+1][r], dp[l][r-1])` | 팰린드롬, 최장 팰린드롬 부분 수열 |

**계산 순서**: 구간 `[l, r]`을 계산하려면 그 안의 **더 짧은 구간**이 모두 끝나 있어야 합니다. 그래서 길이 `1 → 2 → … → n` 순서로 바깥 반복을 돌고, 안쪽에서 시작점 `l`을 정합니다.

```
for length in 2..n:
    for l in 0..n-length:
        r = l + length - 1
        dp[l][r] = ...  (더 짧은 구간들로)
```

**"마지막에 하는 일"을 기준으로 나누기**: 풍선 터뜨리기에서 `k`를 **가장 먼저** 터뜨린다고 하면 이후 이웃이 바뀌어 양쪽이 독립이 아니게 됩니다. 반대로 `k`를 **마지막**에 터뜨린다고 하면, 그때 `k`의 이웃은 구간의 양 끝 밖 풍선으로 고정되고 양쪽 구간은 서로 영향을 주지 않습니다. 이처럼 "마지막"으로 뒤집어 보는 것이 구간 DP의 단골 발상입니다.

## 3. 손으로 따라가기

### 파일 합치기 (인접한 둘만, 비용 = 합)

파일 크기 `[40, 30, 30, 50]`을 하나로. `dp[l][r]` = `l..r`을 하나로 합치는 최소 비용 = `min over k (dp[l][k] + dp[k+1][r]) + (l..r의 합)`.

| `dp[l][r]` | r=0 | r=1 | r=2 | r=3 |
|---|---|---|---|---|
| **l=0** | 0 | 70 | 160 | **300** |
| **l=1** | | 0 | 60 | 170 |
| **l=2** | | | 0 | 80 |
| **l=3** | | | | 0 |

- 길이 2: `dp[0][1] = 40 + 30 = 70`, `dp[1][2] = 60`, `dp[2][3] = 80`
- 길이 3: `dp[0][2] = min(dp[1][2], dp[0][1]) + 100 = 60 + 100 = 160`, `dp[1][3] = min(80, 60) + 110 = 170`
- 길이 4: `dp[0][3] = min(dp[1][3], dp[0][1] + dp[2][3], dp[0][2]) + 150 = min(170, 150, 160) + 150 = 300`

정답 **300** (먼저 `40+30`, `30+50`, 이어서 `70+80`: 70 + 80 + 150).

**인접 제한이 없으면** 가장 작은 둘을 계속 합치는 [그리디](../../../lv1-elementary/07-algorithm-paradigms/greedy-patterns/)(힙)가 되고 답이 더 작아집니다. 인접해야 한다는 제약 때문에 구간 DP가 필요합니다.

### 행렬 곱셈 순서

행렬의 크기 `A1: 10×30`, `A2: 30×5`, `A3: 5×60` (`dims = [10, 30, 5, 60]`).

- `(A1 A2) A3`: `10·30·5 + 10·5·60 = 1500 + 3000 =` **4500**
- `A1 (A2 A3)`: `30·5·60 + 10·30·60 = 9000 + 18000 =` 27000

`dp[i][j] = min over m (dp[i][m] + dp[m+1][j] + dims[i-1]·dims[m]·dims[j])`로 `4500`과 식 `((A1A2)A3)`가 나옵니다.

### 그 외

- 최장 팰린드롬 부분 수열 `"bbbab"` → 4 (`bbbb`). 양 끝이 같으면 `dp[l+1][r-1] + 2`, 다르면 `max(dp[l+1][r], dp[l][r-1])`.
- 풍선 `[3, 1, 5, 8]` → 167. 양 끝에 1을 붙인 열린 구간 `dp[l][r]`에서 마지막으로 터뜨릴 `k`를 고릅니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def min_merge_cost(sizes):
    n = len(sizes)
    prefix = [0]
    for s in sizes:
        prefix.append(prefix[-1] + s)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):                  # 짧은 구간부터
        for l in range(n - length + 1):
            r = l + length - 1
            best = min(dp[l][k] + dp[k + 1][r] for k in range(l, r))
            dp[l][r] = best + prefix[r + 1] - prefix[l]     # 합치는 비용은 누적 합으로 O(1)
    return dp[0][n - 1] if n else 0
```

- `matrix_chain_order(dims)`: `(최소 곱셈 횟수, 괄호 친 식)`. `split[i][j]`에 최적의 분할 위치를 기록해 식을 복원합니다.
- `min_merge_cost(sizes)`: 인접한 파일 합치기.
- `longest_palindromic_subsequence(s)`, `palindrome_table(s)`: 팰린드롬 관련. 표를 만들어 두면 `s[l..r]`이 팰린드롬인지 O(1)에 대답합니다.
- `burst_balloons(nums)`: 풍선 터뜨리기.
- 직접 실행하면 테스트 케이스 수 `T`와 케이스마다 `K`, K개의 파일 크기를 받아 최소 합치는 비용을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- 상태 `O(n²)`개, 상태당 분할 위치 `O(n)`개 → **시간 O(n³)**, **공간 O(n²)**. 양 끝만 보는 경우는 상태당 O(1)이라 O(n²).
- 이 환경에서 `min_merge_cost` 측정값입니다. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

| n | 시간 |
|---|---|
| 300 | 0.39초 |
| 500 | 2.13초 |

- 테스트 케이스가 여러 개이거나 n이 500이면 CPython에서는 빠듯합니다. PyPy3를 쓰거나 **크누스 최적화**(최적 분할 위치가 단조: `opt[l][r-1] ≤ opt[l][r] ≤ opt[l+1][r]`)로 O(n²)로 줄입니다. 이 저장소의 상위 레벨에서 일반화합니다. → [분할 정복 최적화](../../../lv3-advanced/07-dp-advanced/divide-and-conquer-optimization/)

## 6. 자주 하는 실수

- **반복 순서**: 시작점 `l`을 바깥에, `r`을 안쪽에 두면 필요한 짧은 구간이 아직 계산되지 않습니다. 반드시 **길이**가 바깥 반복입니다.
- **경계 인덱스**: `dp[l+1][r-1]`에서 `l+1 > r-1`인 길이 2 구간(`length <= 2`)의 처리를 빠뜨리면 틀립니다.
- **구간 합을 매번 더함**: 누적 합 `prefix`로 O(1)에 구해야 O(n³)이 유지됩니다.
- **인접하지 않아도 되는 문제에 구간 DP 사용**: 그리디(힙)가 O(n log n)입니다. 문제의 제약을 읽으세요.
- **"처음"을 기준으로 나눠 독립이 깨짐**: 풍선처럼 이웃이 바뀌는 문제는 "마지막"을 기준으로 뒤집습니다.
- **`inf` 초기화 누락**: `min`을 구하는 `best`를 `inf`로 시작하세요.
- **복원할 때 분할 위치 저장 누락**: 최적값만 구하고 식이 필요하면 `split`을 함께 기록합니다.

## 7. 변형과 응용

- **원형 배열**: 배열을 두 번 이어 붙여 길이 n인 구간만 본다.
- **게임 이론**(양쪽 끝에서 가져가기): `dp[l][r]` = 현재 차례의 사람이 얻는 점수 차이의 최댓값
- **괄호 문자열, 팰린드롬 분할**: `dp[l][r]` 또는 `cut[i]`
- **트리 DP로의 확장**: 구간 대신 서브트리. → [트리 DP](../../03-trees/tree-dp/)
- **크누스 최적화, 분할 정복 최적화**: 분할 위치의 단조성을 이용해 O(n³) → O(n²) 또는 O(n² log n)
