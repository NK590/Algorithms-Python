# Monotonic Stack (모노톤 스택)

> **한 줄 요약**: 스택 안의 값이 항상 **한 방향으로만 단조**(증가 또는 감소)가 되게 유지하며 배열을 한 번 훑는다. 새 원소가 들어올 때 "답이 정해지는" 맨 위 원소들을 pop하며 답을 기록하고 나서 push한다. 각 원소는 한 번 들어가고 한 번 나가므로 전체 `O(n)`이다. "오른쪽(왼쪽)에서 처음으로 더 큰(작은) 값"을 모든 원소에 대해 구하는 문제의 표준 도구다.

## 1. 언제 쓰나 (문제 신호)

- "각 원소의 **오른쪽에서 처음으로 나오는 더 큰 수**" (오큰수), 더 작은 수, 왼쪽에서 처음으로 큰/작은 수
- "**며칠 뒤에** 더 따뜻해지는가", "몇 칸 떨어진 곳에 더 높은 건물이 있는가"
- **히스토그램 안의 가장 큰 직사각형**, 이진 행렬에서 1로 이루어진 가장 큰 직사각형
- "빗물이 고이는 양" (움푹 팬 곳을 채우기)
- 각 원소가 **최댓값/최솟값인 구간의 범위**가 필요한 문제 (모든 부분 배열의 최솟값의 합)
- 순진하게 `O(n²)`로 각 원소마다 오른쪽을 훑으면 `n = 10⁵~10⁶`에서 시간 초과

## 2. 핵심 아이디어

**순진한 방법의 낭비**: 원소 `i`의 오큰수를 찾으려고 오른쪽을 훑는데, 이미 훑어 본 구간의 정보를 `i + 1`의 탐색에서 버립니다.

**스택 불변식**: 아직 답(오큰수)을 못 찾은 원소들의 **위치**를 스택에 쌓습니다. 새 원소 `x`가 들어오면

1. 스택 맨 위 원소가 `x`보다 **작으면**, 그 원소의 오큰수는 `x`입니다. 답을 기록하고 pop합니다.
2. 맨 위가 `x`보다 작지 않을 때까지 1을 반복합니다.
3. `x`의 위치를 push합니다. (이제 `x`도 오큰수를 기다립니다)

이렇게 하면 스택 안의 값은 아래에서 위로 **내려가거나 같은 순서**(내림차순)를 유지합니다. 위쪽 원소가 아래쪽보다 크다면 아래쪽은 이미 pop되었을 것이기 때문입니다.

```
수열      2  7  3  5  4  6  8
오큰수    7  8  5  6  6  8  -1
```

**왜 `O(n)`인가**: 각 원소는 정확히 한 번 push되고 많아야 한 번 pop됩니다. `while`이 도는 횟수의 합은 `n`을 넘지 않습니다(분할 상환).

**방향과 부등호에 따른 네 가지 변형**

| 구하는 것 | 스택 안의 모양 | pop 조건 | 답을 기록하는 때 |
|---|---|---|---|
| 오른쪽에서 처음으로 **큰** 값 | 내림차순 | `스택 위 < x` | pop할 때 (`x`가 답) |
| 오른쪽에서 처음으로 **작은** 값 | 오름차순 | `스택 위 > x` | pop할 때 (`x`가 답) |
| 왼쪽에서 처음으로 **작은** 값 | 오름차순 | `스택 위 ≥ x` | pop한 뒤 남은 맨 위 |
| 왼쪽에서 처음으로 **큰** 값 | 내림차순 | `스택 위 ≤ x` | pop한 뒤 남은 맨 위 |

**같은 값이 있을 때**는 부등호를 `<`로 할지 `≤`로 할지로 "같은 값을 답으로 인정하는가"가 갈립니다. 문제를 읽고 정합니다.

**히스토그램**: 막대 `i`를 높이로 하는 직사각형은 양옆으로 `i`보다 낮은 막대를 처음 만나기 직전까지 넓어집니다. 막대들을 높이 오름차순 스택에 쌓다가 자기보다 낮은 막대가 오면 pop하는데, 그때 오른쪽 경계는 새 막대이고 왼쪽 경계는 pop 후의 새 맨 위입니다. 끝에 높이 `0`인 막대를 하나 붙여 스택에 남은 막대를 모두 정리합니다.

## 3. 손으로 따라가기

### 오큰수: `[2, 7, 3, 5, 4, 6, 8]`

스택에는 **값**으로 표시합니다(실제로는 위치를 저장).

| `i` | `x` | pop하며 기록 | push 후 스택 (아래→위) |
|---|---|---|---|
| 0 | 2 | | `[2]` |
| 1 | 7 | 2의 오큰수 = 7 | `[7]` |
| 2 | 3 | | `[7, 3]` |
| 3 | 5 | 3의 오큰수 = 5 | `[7, 5]` |
| 4 | 4 | | `[7, 5, 4]` |
| 5 | 6 | 4의 오큰수 = 6, 5의 오큰수 = 6 | `[7, 6]` |
| 6 | 8 | 6의 오큰수 = 8, 7의 오큰수 = 8 | `[8]` |

끝까지 남은 `8`은 오큰수가 없으므로 `-1`. 결과 `[7, 8, 5, 6, 6, 8, -1]`.

### 히스토그램: `[2, 1, 5, 6, 2, 3]`

끝에 높이 `0`을 붙여 `[2, 1, 5, 6, 2, 3, 0]`을 처리합니다. 스택은 높이가 오름차순입니다. pop한 막대의 높이 × (`i` − 왼쪽 경계)로 넓이를 구합니다.

| `i` | 새 높이 | pop한 막대 | 폭 (오른쪽 `i` − 왼쪽) | 넓이 |
|---|---|---|---|---|
| 1 | 1 | 높이 2 | 1 − 0 = 1 | 2 |
| 4 | 2 | 높이 6 | 4 − 3 = 1 | 6 |
| 4 | 2 | 높이 5 | 4 − 2 = 2 | **10** |
| 6 | 0 | 높이 3 | 6 − 5 = 1 | 3 |
| 6 | 0 | 높이 2 | 6 − 2 = 4 | 8 |
| 6 | 0 | 높이 1 | 6 − 0 = 6 | 6 |

최대는 높이 5와 6인 두 막대가 이루는 `5 × 2 = 10`입니다. 막대 하나하나가 정확히 한 번 pop되므로 `O(n)`입니다.

### 며칠 뒤에 더 따뜻한가: `[73, 74, 75, 71, 69, 72, 76, 73]`

오큰수의 **위치 차이**입니다. 결과 `[1, 1, 4, 2, 1, 1, 0, 0]` (`75`는 `76`을 4일 뒤에, `71`은 `72`를 2일 뒤에, 끝의 `76`과 `73`은 더 따뜻한 날이 없어서 0).

### 빗물: `[0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]`

스택(높이 내림차순)에서 pop하는 막대 `bottom`이 "바닥"이고, 새 막대와 새 맨 위가 양옆 벽입니다. 한 층씩 `(min(벽, 새 막대) − 바닥) × 폭`을 더합니다.

| `i` | 새 높이 | 바닥 | 왼쪽 벽 | 폭 | 더하는 양 | 누적 |
|---|---|---|---|---|---|---|
| 3 | 2 | 0 (`i=2`) | 1 (`i=1`) | 1 | 1 | 1 |
| 6 | 1 | 0 (`i=5`) | 1 (`i=4`) | 1 | 1 | 2 |
| 7 | 3 | 1 (`i=6`) | 1 (`i=4`) | 2 | 0 | 2 |
| 7 | 3 | 1 (`i=4`) | 2 (`i=3`) | 3 | 3 | 5 |
| 10 | 2 | 1 (`i=9`) | 2 (`i=8`) | 1 | 1 | **6** |

합계 **6**.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def next_greater(numbers):
    result = [-1] * len(numbers)
    stack = []                              # 아직 오큰수를 못 찾은 원소의 위치
    for i, x in enumerate(numbers):
        while stack and numbers[stack[-1]] < x:
            result[stack.pop()] = x         # x 가 이들의 오큰수다
        stack.append(i)
    return result

def largest_rectangle_in_histogram(heights):
    best = 0
    stack = []
    for i, h in enumerate(list(heights) + [0]):     # 끝에 0 을 붙여 모두 정리
        while stack and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            left = stack[-1] + 1 if stack else 0    # 새 맨 위의 오른쪽부터
            best = max(best, height * (i - left))
        stack.append(i)
    return best
```

- `next_smaller`, `previous_smaller_index`(왼쪽에서 처음으로 작은 값의 **위치**), `days_until_warmer`, `trapped_rain_water`.
- 스택에는 **값이 아니라 위치**를 넣습니다. 거리(폭)를 계산하거나 값을 다시 꺼낼 수 있어서 항상 더 쓸모 있습니다.
- 직접 실행하면 `N`과 수열을 받아 오큰수를 출력합니다 (없으면 `-1`).

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n)**, **공간 O(n)** (스택). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(두 번 중 최소, 무작위 값).

| 작업 | 크기 | 시간 |
|---|---|---|
| `next_greater` | n = 10⁶ | 0.15초 |
| `largest_rectangle_in_histogram` | n = 10⁶ | 0.25초 |
| 순진한 `O(n²)` 오큰수 (내림차순 입력, 최악) | n = 2·10⁴ | 8.8초 |
| 같은 입력의 `next_greater` | n = 2·10⁴ | 0.0046초 |

- 순진한 방법은 `n = 2·10⁴`에서 이미 9초입니다. `n = 10⁶`이면 사실상 불가능하고 모노톤 스택은 0.15초입니다.

## 6. 자주 하는 실수

- **값을 스택에 넣음**: 거리나 폭이 필요하면 위치가 있어야 합니다. 위치를 넣고 `numbers[stack[-1]]`로 값을 읽으세요.
- **빈 스택에서 `stack[-1]`**: `while stack and …`의 `stack and`와, pop 후의 `stack[-1] if stack else …` 확인을 빠뜨리면 `IndexError`.
- **같은 값 처리**: `<`와 `≤`를 헷갈리면 중복이 있는 입력에서만 틀립니다. 히스토그램은 `≥`로 pop해도 결과는 같지만, "같은 높이를 별도 막대로 센다"는 문제(오아시스 재결합 등)에서는 개수를 따로 세야 합니다.
- **끝의 정리 누락**: 히스토그램에 센티널 `0`을 안 붙이면 끝까지 남은 막대를 계산하지 않습니다. 오큰수에서는 남은 원소가 `-1`입니다.
- **빗물에서 `break`/`left` 처리**: pop 후 스택이 비면 왼쪽 벽이 없어 물이 고이지 않습니다.
- **스캔 방향**: "왼쪽에서 처음으로"는 왼쪽→오른쪽으로 훑으면서 pop한 뒤의 맨 위, "오른쪽에서 처음으로"는 pop될 때입니다. 헷갈리면 오른쪽에서 왼쪽으로 훑는 버전을 만들어 보세요.
- **`O(n²)`로 착각해 포기**: `while` 안쪽 반복이 있어도 합이 `n`이면 선형입니다.

## 7. 변형과 응용

- **모든 부분 배열의 최솟값의 합**: 각 원소가 최솟값인 구간의 왼쪽·오른쪽 한계를 스택으로 구하고 `값 × 왼쪽 개수 × 오른쪽 개수`를 더합니다.
- **이진 행렬의 가장 큰 직사각형**: 행마다 "위로 연속한 1의 개수"를 막대 높이로 보고 히스토그램 문제를 풉니다.
- **원형 배열의 오큰수**: 수열을 두 번 훑습니다(인덱스를 `i % n`으로).
- **숫자 지우기 / k개 제거해 가장 작은 수**: 앞 자리가 뒤 자리보다 크면 pop하는 오름차순 스택.
- **카르테시안 트리 구성**: 스택으로 `O(n)`에 만들 수 있습니다.
- **모노톤 덱**: 스택 대신 덱을 쓰면 **슬라이딩 윈도우 최댓값**이 됩니다. → [슬라이딩 윈도우](../sliding-window/)
