# Coordinate Compression (좌표 압축)

> **한 줄 요약**: 값의 **크기 자체는 필요 없고 대소 관계만 중요할 때**, 값을 정렬·중복 제거한 목록에서의 순위(0, 1, 2, …)로 바꾼다. 값의 범위가 10⁹~10¹⁸이어도 서로 다른 값은 많아야 `n`개라서 순위는 `0..n−1`에 들어오고, 이제 배열·누적 합·차분 배열·펜윅 트리·세그먼트 트리의 인덱스로 쓸 수 있다.

## 1. 언제 쓰나 (문제 신호)

- 좌표·값의 범위가 10⁹ 이상인데 점·구간의 **개수는 10⁵~10⁶**이다
- "자기보다 작은 서로 다른 값이 몇 개인가" 같은 **순위** 질문
- 배열 인덱스로 값을 쓰고 싶은데 범위가 너무 크다 (개수 세기, 누적 합, 차분 배열)
- [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/)나 [세그먼트 트리](../../../lv3-advanced/01-range-query-structures/segment-tree/)로 역순쌍·구간 질의를 처리할 때의 **전처리**
- 구간들의 시작·끝 좌표만 의미가 있는 문제 (겹치는 최대 개수, 덮인 영역)

## 2. 핵심 아이디어

**순위로 바꾸기**: 값들을 정렬해서 중복을 제거한 목록 `ordered`를 만들고, 각 값을 그 목록에서의 위치로 바꿉니다.

```
값      2   4  -10   4   -9
정렬·중복 제거 → [-10, -9, 2, 4]
순위    2   3    0   3    1
```

각 값의 순위는 "자기보다 작은 **서로 다른** 값의 개수"입니다. 이진 탐색(`bisect_left`)이나 딕셔너리 `{값: 순위}`로 구합니다.

**왜 안전한가**: 순위는 **대소 관계와 같음 관계를 그대로 유지**합니다(`a < b ⟺ rank(a) < rank(b)`, `a = b ⟺ rank(a) = rank(b)`). 문제의 답이 이 관계에만 의존한다면 압축해도 답이 같습니다. 거꾸로 **값의 차이나 길이가 답에 들어가면** 압축 후의 좌표로는 구할 수 없습니다. 그럴 때는 압축한 좌표를 인덱스로만 쓰고 길이는 원래 좌표로 계산합니다.

**두 가지 순위**

| 이름 | 같은 값 | 쓰임 |
|---|---|---|
| `compress` (밀집 순위) | 같은 번호 | 값의 종류가 `m`개이면 `0..m−1`. 배열 인덱스로 사용 |
| `ordinal_ranks` (서수 순위) | 서로 다른 번호 (처음 나온 것이 앞) | 순열을 만들 때. 길이 `n`의 `0..n−1` 순열 |

**점 (x, y)**: x와 y를 **각각 따로** 압축합니다. 점들의 상대 위치(위/아래/왼쪽/오른쪽)가 유지됩니다.

**구간의 겹침**: 닫힌 구간 `[l, r]`은 `l`에서 `+1`, `r + 1`에서 `−1`인 차분으로 표현합니다. 이때 쓰이는 좌표는 구간 수의 2배 이하이므로 그 좌표들만 압축해 작은 배열의 누적 합을 구하면 최대 겹침이 나옵니다. 좌표가 10¹⁷이어도 상관없습니다.

### 무엇을 저장하고 어떻게 움직이나

실제 값들을 정렬·중복 제거하고 작은 순번으로 바꿉니다. 원래 값의 크기가 10^9여도 등장한 종류가 m개면 인덱스는 0부터 m-1입니다. 비교 순서와 동일성은 보존하지만 값 사이의 거리는 보존하지 않습니다.

### 왜 이 방법이 맞는가

정렬된 고유 값의 순번은 원래 값의 `<` 관계를 그대로 보존하므로 순위·개수 질의에 안전합니다. 면적·길이 계산은 원래 좌표 차이를 사용해야 합니다. 경계가 되는 질의 좌표도 표현해야 한다면 전처리 목록에 포함합니다.

### 작은 예제로 검산하기

좌표 `[10,1000,10,50]`은 `[0,2,0,1]`로 바뀝니다. 10과 50 사이 길이는 40이지 압축 인덱스 차이 1이 아닙니다. 반열린 구간의 오른쪽 경계 처리도 같은 좌표 규칙으로 변환해야 합니다.

## 3. 손으로 따라가기

### 값 압축: `[2, 4, -10, 4, -9]`

| 단계 | 결과 |
|---|---|
| 정렬·중복 제거 | `[-10, -9, 2, 4]` |
| 각 값의 위치 | `2 → 2`, `4 → 3`, `-10 → 0`, `4 → 3`, `-9 → 1` |
| 압축 결과 | `[2, 3, 0, 3, 1]` |
| 되돌리기 (`ordered[순위]`) | `[2, 4, -10, 4, -9]` |

`compress([1000, 999, 1000, 999, 1000, 999])`는 `[1, 0, 1, 0, 1, 0]`. 값이 얼마나 큰지는 사라지고 "999 < 1000"이라는 관계만 남습니다.

### 서수 순위: `[30, 10, 20, 10]`

값 순으로 번호를 매기되 같은 값은 앞에 나온 것이 먼저입니다: `10`(위치 1) → 0, `10`(위치 3) → 1, `20` → 2, `30` → 3. 결과 `[3, 0, 2, 1]`. `compress`는 같은 값에 같은 번호를 주므로 `[2, 0, 1, 0]`입니다.

### 점 압축: `[(100, 5), (7, 5), (100, -3)]`

- x 좌표 `{7, 100}` → `7 → 0`, `100 → 1`
- y 좌표 `{-3, 5}` → `-3 → 0`, `5 → 1`

결과 `[(1, 1), (0, 1), (1, 0)]`. 원래의 "첫째 점이 둘째 점의 오른쪽, 셋째 점이 첫째 점의 아래"라는 관계는 그대로입니다.

### 겹침의 최대: 닫힌 구간 `[10¹⁷, 10¹⁷+5]`, `[10¹⁷+3, 10¹⁷+9]`, `[10¹⁷+5, 10¹⁷+6]`, `[1, 2]`

`N = 10¹⁷`이라 쓰면, 시작 좌표에 `+1`, 끝 좌표 `+ 1`에 `−1`: `1(+1)`, `3(−1)`, `N(+1)`, `N+6(−1)`, `N+3(+1)`, `N+10(−1)`, `N+5(+1)`, `N+7(−1)`. 이 8개 좌표만 정렬해 압축하면 배열 크기가 8입니다.

| 정렬된 좌표 | 1 | 3 | N | N+3 | N+5 | N+6 | N+7 | N+10 |
|---|---|---|---|---|---|---|---|---|
| 압축된 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| 차분 | +1 | −1 | +1 | +1 | +1 | −1 | −1 | −1 |
| 누적 합 | 1 | 0 | 1 | 2 | **3** | 2 | 1 | 0 |

최대 겹침 **3** (`N+5`에서 세 구간이 겹침). `[10¹⁷+5, 10¹⁷+6]`이 시작하는 `N+5`에서 첫째 구간(`N..N+5`)은 아직 끝나지 않아 닫힌 구간이라 겹칩니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
from bisect import bisect_left

def coordinate_maps(values):
    ordered = sorted(set(values))                       # 정렬 + 중복 제거
    return ordered, {v: i for i, v in enumerate(ordered)}

def compress(values):
    ordered = sorted(set(values))
    return [bisect_left(ordered, v) for v in values]    # 자기보다 작은 서로 다른 값의 개수

def ordinal_ranks(values):                              # 같은 값도 서로 다른 번호
    order = sorted(range(len(values)), key=lambda i: values[i])   # 안정 정렬
    ranks = [0] * len(values)
    for rank, i in enumerate(order):
        ranks[i] = rank
    return ranks
```

- `decompress(compressed, ordered)`: 순위를 원래 값으로.
- `compress_points(points)`: x와 y를 따로 압축.
- `max_overlap_count(intervals)`: 닫힌 구간들의 최대 겹침. 끝 좌표는 `r + 1`에서 `−1`.
- 직접 실행하면 `N`과 수열을 받아 압축한 좌표를 공백으로 구분해 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n log n)**(정렬이 지배적, 각 값의 순위 찾기는 `bisect`로 `O(log n)`), **공간 O(n)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(무작위 값 ±10⁹, 두 번 중 최소).

| 방법 | 크기 | 시간 |
|---|---|---|
| `compress` (`bisect_left`) | n = 2·10⁵ | 0.16초 |
| 딕셔너리 `{값: 순위}`로 변환 | n = 2·10⁵ | 0.12초 |

두 방법의 결과는 같고, 딕셔너리 쪽이 조금 빠릅니다. `bisect`는 목록에 없는 값의 위치도 구할 수 있다는 장점이 있습니다(질의 값이 원래 목록에 없을 수 있을 때 "이 값 이하는 몇 개").

## 6. 자주 하는 실수

- **중복 제거 누락**: `sorted(values)`만 쓰면 `bisect_left`가 같은 값에도 첫 위치를 주지만 순위에 빈칸이 생겨 `0..m−1`이 아니게 됩니다. `sorted(set(values))`.
- **`list.index`로 순위 찾기**: 값마다 `O(n)`이라 전체 `O(n²)`. `bisect`나 딕셔너리를 쓰세요.
- **닫힌 구간의 끝**: 정수 닫힌 구간 `[l, r]`의 겹침을 차분으로 셀 때 끝 이벤트는 `r + 1`에서 일어납니다. `r`에 넣으면 끝점에서 만나는 구간이 겹치지 않는 것으로 계산됩니다.
- **길이를 압축한 좌표로 계산**: 압축하면 거리 정보가 사라집니다. 합집합의 길이나 넓이는 원래 좌표 차이로 계산하세요. → [스위핑](../sweeping/)
- **x와 y를 합쳐서 압축**: 점의 두 좌표는 서로 다른 축이라 각각 압축해야 합니다.
- **0부터 vs 1부터**: [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/)는 1부터 시작하는 인덱스를 씁니다. 압축 결과에 1을 더하세요.
- **질의 좌표를 빠뜨림**: 질의에 나오는 좌표도 함께 모아서 압축해야 합니다(오프라인 처리).
- **같은 순위를 원하는지 다른 순위를 원하는지**: 서수 순위로 배열을 만들면 같은 값도 서로 다른 칸에 들어갑니다.

## 7. 변형과 응용

- **역순쌍 개수**: 값을 순위로 바꾼 뒤 펜윅 트리로 "나보다 큰 값이 앞에 몇 개 있었나"를 센다. → [펜윅 트리](../../../lv3-advanced/01-range-query-structures/fenwick-tree/)
- **오프라인 구간 질의**: 질의 구간의 끝점들을 압축하고 정렬해서 스위핑.
- **2차원 점 세기**: x와 y를 압축한 뒤 2차원 누적 합이나 스위핑 + 펜윅 트리.
- **압축 후 DP**: 좌표가 큰 문제의 DP 상태를 압축된 좌표로 줄입니다.
- **정렬 순열**: 서수 순위 `P`는 원래 수열을 정렬하는 순열입니다(`B[P[i]] = A[i]`).
