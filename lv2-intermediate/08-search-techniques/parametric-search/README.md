# Parametric Search (매개변수 탐색)

> **한 줄 요약**: "최댓값/최솟값을 구하라"를 "**답이 `x`일 수 있는가?**"라는 예/아니오 질문으로 바꾸고, `x`가 커질수록 답이 한 번만 바뀐다는 **단조성**을 이용해 `x`를 이분 탐색한다. 판정이 `O(n)`이면 전체가 `O(n log 범위)`다. 답의 범위가 10⁹이든 10¹⁸이든 판정을 30~60번만 하면 된다.

## 1. 언제 쓰나 (문제 신호)

- "**최댓값을 최소화**하라", "**최솟값을 최대화**하라" (예: 묶음의 합의 최댓값을 최소로, 이웃한 공유기 사이 거리의 최솟값을 최대로)
- "**조건을 만족하는 가장 큰/작은** 길이·높이·시간·용량을 구하라" (랜선 길이, 절단기 높이, 심사 시간, 배의 적재량)
- 답 `x`가 주어지면 "가능한가?"를 **그리디나 단순 반복으로 `O(n)`에** 판정할 수 있다
- 답의 범위가 매우 커서 하나씩 시도할 수 없다 (10⁹ 이상)
- 입력 크기 `n`은 10⁵~10⁶이고 시간 제한은 1~2초

## 2. 핵심 아이디어

**결정 문제로 바꾸기**: 최적화 문제의 답을 직접 구하는 대신, 후보 `x`를 하나 정해 "`x`가 가능한가"만 묻습니다. 판정 함수 `ok(x)`가 **단조**이면, 즉 `x`가 커짐에 따라 `False … False True … True`(또는 반대)처럼 **한 번만 바뀌면** 이분 탐색으로 경계를 찾을 수 있습니다.

```
최솟값 구하기:   x →   F F F F F T T T T T      첫 True 를 찾는다   (first_true)
                                 ↑ 답
최댓값 구하기:   x →   T T T T T F F F F F      마지막 True 를 찾는다 (last_true)
                             ↑ 답
```

예를 들어 랜선 문제에서 "길이 `x`로 `N`개 이상 만들 수 있다"는 `x`가 작을수록 쉬우므로 `T … T F … F`이고, 우리는 가장 긴 `T`를 찾습니다.

**판정은 보통 그리디**입니다. "공유기 사이 거리를 `d` 이상으로 `C`개 놓을 수 있나"는 앞에서부터 가능한 가장 앞에 놓는 그리디, "묶음 합이 `limit` 이하로 `m`개 이하의 묶음이 되나"는 묶음에 가능한 한 많이 담는 그리디로 `O(n)`에 판정합니다.

**[이진 탐색](../../../lv1-elementary/03-binary-search/binary-search/)과의 차이**: 이진 탐색은 정렬된 배열에서 값을 찾지만, 매개변수 탐색은 배열이 없고 **답의 공간**을 이분합니다.

**범위 설정**: `lo`는 답이 될 수 있는 가장 작은 값, `hi`는 가장 큰 값으로 잡습니다. 예를 들어 배열 나누기에서 한 묶음의 최솟값은 `max(numbers)`(원소 하나는 쪼갤 수 없다), 최댓값은 `sum(numbers)`(전부 한 묶음)입니다. 범위를 너무 넉넉히 잡아도 이분 탐색이라 반복이 `log`만큼만 늘어납니다.

### 무엇을 저장하고 어떻게 움직이나

답 x가 주어졌을 때 조건을 달성할 수 있는지 판정하는 함수를 먼저 만듭니다. 판정이 x에 따라 거짓→참 또는 참→거짓으로 한 번만 바뀌면 그 경계를 이분 탐색합니다. 답을 구성하는 문제를 가능한지 묻는 문제로 바꾸는 단계가 핵심입니다.

### 왜 이 방법이 맞는가

판정 함수의 단조성이 버린 절반에 답이 없다는 근거입니다. 이분 탐색 구현보다 이 단조성을 먼저 증명해야 합니다. 가능한 답을 저장하는 방식인지 실패·성공 경계 두 개를 유지하는 방식인지 구간 계약을 고정합니다.

### 작은 예제로 검산하기

시간 t에서 생산량이 `Σ(t//기계시간)`이면 t가 늘어도 생산량은 줄지 않습니다. 목표 5개를 처음 달성하는 t를 찾습니다. 최댓값 추정이 작으면 실제 답이 처음 구간 밖에 있어 아무리 정확히 탐색해도 틀립니다.

## 3. 손으로 따라가기

### 랜선 자르기: `[802, 743, 457, 539]`, 11개 이상

`ok(length) = (각 랜선 // length 의 합) ≥ 11`, 가장 긴 `length`를 찾습니다(`last_true`).

| 단계 | `lo` | `hi` | `mid` | 조각 수 | `ok` | 다음 |
|---|---|---|---|---|---|---|
| 1 | 1 | 802 | 401 | 5 | False | `hi = 400` |
| 2 | 1 | 400 | 200 | 11 | **True** | `lo = 201` |
| 3 | 201 | 400 | 300 | 6 | False | `hi = 299` |
| 4 | 201 | 299 | 250 | 8 | False | `hi = 249` |
| 5 | 201 | 249 | 225 | 10 | False | `hi = 224` |
| 6 | 201 | 224 | 212 | 10 | False | `hi = 211` |
| 7 | 201 | 211 | 206 | 10 | False | `hi = 205` |
| 8 | 201 | 205 | 203 | 10 | False | `hi = 202` |
| 9 | 201 | 202 | 201 | 10 | False | `hi = 200` |

`lo = 201 > hi = 200`이 되어 끝나고 답은 `hi = 200`입니다. 길이 200이면 `4 + 3 + 2 + 2 = 11`개, 201이면 10개입니다. 802까지 모두 시도하는 대신 9번 만에 끝났습니다.

### 나무 자르기: `[20, 15, 10, 17]`, 7m 이상 (`last_true`, 높이 `0..20`)

`ok(h) = Σ max(0, 나무 − h) ≥ 7`. 높이가 낮을수록 많이 얻습니다.

| `lo` | `hi` | `mid` | 얻는 길이 | `ok` |
|---|---|---|---|---|
| 0 | 20 | 10 | 22 | True → `lo = 11` |
| 11 | 20 | 15 | 7 | True → `lo = 16` |
| 16 | 20 | 18 | 2 | False → `hi = 17` |
| 16 | 17 | 16 | 5 | False → `hi = 15` |

답 **15**. 높이 15에서 `5 + 0 + 0 + 2 = 7`, 16에서는 5입니다.

### 공유기 설치: 위치 `[1, 2, 4, 8, 9]`, 3개 (`last_true`)

`ok(d)`: 앞에서부터 거리 `d` 이상이 되는 첫 위치마다 놓았을 때 3개 이상 놓이는가.

| `d` | 놓은 위치 | 개수 | `ok` |
|---|---|---|---|
| 1 | 1, 2, 4, 8, 9 | 5 | True |
| 2 | 1, 4, 8 | 3 | True |
| 3 | 1, 4, 8 | 3 | **True** |
| 4 | 1, 8 | 2 | False |
| 8 | 1, 9 | 2 | False |

`d`가 커질수록 놓을 수 있는 개수가 줄어드는 단조 구조이고, 경계는 `3 → 4`라서 답은 **3**입니다(1, 4, 8에 놓으면 이웃 거리의 최솟값이 3).

### 배열 나누기: `[7, 2, 5, 10, 8]`을 2개 묶음으로 (`first_true`)

묶음 합의 최댓값을 최소화합니다. `ok(limit)`: 한 묶음의 합이 `limit`을 넘지 않게 앞에서부터 최대한 담았을 때 묶음 수가 2 이하인가. 범위는 `[max, sum] = [10, 32]`.

| `limit` | 나눈 결과 | 묶음 수 | `ok` |
|---|---|---|---|
| 10 | `[7,2] [5] [10] [8]` | 4 | False |
| 14 | `[7,2,5] [10] [8]` | 3 | False |
| 17 | `[7,2,5] [10] [8]` | 3 | False |
| **18** | `[7,2,5] [10,8]` | 2 | **True** |
| 19 | `[7,2,5] [10,8]` | 2 | True |

`False … False True … True` 모양이고 처음 `True`는 **18**입니다. 묶음 수를 3개로 늘리면 답이 14, 5개면 10(가장 큰 원소), 1개면 32(전체 합)로 바뀝니다.

### 반복 횟수

범위의 크기가 `R`이면 판정을 `⌈log₂ R⌉`번 합니다. `R = 10⁹`이면 30번, `R = 10¹⁸`이면 60번입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def first_true(lo, hi, ok):            # False…False True…True 에서 첫 True (없으면 hi + 1)
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid - 1               # mid 도 후보이므로 더 작은 쪽을 찾는다
        else:
            lo = mid + 1
    return lo

def last_true(lo, hi, ok):             # True…True False…False 에서 마지막 True (없으면 lo - 1)
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            lo = mid + 1               # mid 도 후보이므로 더 큰 쪽을 찾는다
        else:
            hi = mid - 1
    return hi

def max_cable_length(cables, need):    # 랜선 자르기
    return last_true(1, max(cables), lambda length: sum(c // length for c in cables) >= need)

def split_array_min_largest_sum(numbers, parts):    # 최댓값의 최소화
    def can_split(limit):
        groups, current = 1, 0
        for x in numbers:
            if current + x > limit:    # 더 담으면 넘으니 새 묶음
                groups += 1
                current = x
            else:
                current += x
        return groups <= parts
    return first_true(max(numbers), sum(numbers), can_split)
```

- 두 템플릿(`first_true`, `last_true`)만 외우면 됩니다. **닫힌 구간 `[lo, hi]`와 `lo <= hi` 반복**으로 통일하면 경계 실수가 줄어듭니다.
- `max_cutter_height`(나무 자르기), `max_min_distance`(공유기 설치), `min_time_to_finish`(입국 심사)도 같은 틀입니다. 직접 실행하면 `K N`과 `K`개의 랜선 길이를 받아 `N`개 이상 만들 수 있는 최대 길이를 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(C · log R)**: `C`는 판정 한 번의 비용(보통 `O(n)`), `R`은 답의 범위 크기. **공간 O(1)**. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(무작위 값 10⁹ 이하, 두 번 중 최소).

| 문제 | 크기 | 시간 |
|---|---|---|
| `max_cable_length` | 랜선 10⁵개, 목표 10⁶개 | 0.09초 |
| `max_cutter_height` | 나무 10⁵그루 | 0.11초 |

- 위 측정에서 판정 한 번은 약 3ms입니다(범위 10⁹이라 30번 반복, 0.09초 ÷ 30). `n = 10⁶`이면 한 번에 약 30ms로 늘어나고, 범위가 10¹⁸(60번)이면 약 2초로 추정됩니다(측정하지 않은 값). 파이썬에서는 판정 함수를 가볍게 쓰는 것이 중요합니다.
- 판정이 `O(n log n)`이거나 `O(n + m)`의 BFS여도 같은 틀입니다.

## 6. 자주 하는 실수

- **단조가 아닌 판정**: "정확히 `N`개"처럼 한 번만 바뀌지 않는 조건은 안 됩니다. "`N`개 **이상**"처럼 바꿀 수 있는지 먼저 확인하세요.
- **`first_true` vs `last_true` 혼동**: 최대화 문제는 마지막 `True`, 최소화 문제는 첫 `True`입니다. 반대로 쓰면 한 칸이 어긋납니다.
- **범위의 끝**: `lo`가 너무 크거나 `hi`가 너무 작으면 정답이 범위 밖입니다. 랜선은 `lo = 1`부터(`0`이면 `// 0` 오류), 배열 나누기는 `lo = max(numbers)`부터(원소 하나보다 작은 `limit`은 판정이 틀립니다).
- **답이 없는 경우**: `first_true`는 `hi + 1`, `last_true`는 `lo − 1`을 돌려줍니다. 이 값이 "없음"을 뜻함을 쓰는 쪽에서 해석합니다(`max_cutter_height`의 `-1`).
- **`while lo < hi`와 `mid` 계산 섞기**: `mid = (lo + hi) // 2`에 `lo = mid`를 쓰면 무한 루프에 빠집니다. 이 문서의 닫힌 구간 템플릿을 그대로 쓰세요.
- **합의 크기**: 랜선 `10⁵`개 × `10⁹`처럼 합이 `10¹⁴`가 되어도 파이썬은 문제없지만 C++/Java에서는 `long long`이 필요합니다.
- **실수 답**: 정수 이분 탐색이 아니라 반복 횟수를 고정(예: 100번)해서 `lo/hi`를 좁히거나 `hi − lo < ε`로 끝냅니다. `==`로 비교하면 끝나지 않습니다.
- **판정이 느림**: 판정이 `O(n²)`이면 전체가 너무 느립니다. 판정을 그리디로 바꿀 수 있는지 먼저 생각하세요.

## 7. 변형과 응용

- **배열 나누기류**: 기타 레슨, 용돈 관리, 선적 용량 모두 "묶음 합의 최댓값을 최소화"와 같은 판정입니다.
- **최소 시간**: 입국 심사, 놀이공원 — 시간 `t`를 정하면 처리한 사람 수는 `Σ t // 속도`.
- **그래프 + 이분 탐색**: "경로의 최소 간선 가중치의 최댓값(중량제한)"을 BFS/DFS나 [Union-Find](../../02-graph-algorithms/union-find/)로 판정하며 이분 탐색.
- **K번째 수**: "x 이하인 수가 몇 개인가"를 셀 수 있다면 K번째 수를 이분 탐색 (곱셈표에서 K번째).
- **삼분 탐색**: 단조가 아니라 **볼록(위로 볼록/아래로 볼록)**인 함수의 최댓값·최솟값은 구간을 3분할해 찾습니다.
- **실수 매개변수**: 크기를 고정 반복으로 줄이는 이분 탐색(예: 평균의 최대를 구하는 문제에서 평균 `x`를 가정하고 판정).
