# Sliding Window (슬라이딩 윈도우)

> **한 줄 요약**: 연속한 구간(창)을 한 칸씩 밀면서 **들어오는 원소만 더하고 나가는 원소만 뺀다**. 창 길이가 고정이면 합·개수를 `O(1)`에 갱신하고, 최댓값·최솟값은 **모노톤 덱**으로 `O(1)`에 유지한다. 창 길이가 가변이면 오른쪽 끝을 늘리다 조건이 깨지면 왼쪽 끝을 줄이는 투 포인터로 `O(n)`에 푼다.

## 1. 언제 쓰나 (문제 신호)

- "길이 `K`인 연속 구간의 합(평균)의 최댓값", "최근 `K`개의 최댓값/최솟값" (고정 길이)
- "**합이 `S` 이상**인 가장 짧은 연속 부분 배열", "**서로 다른 종류가 `K`개 이하**인 가장 긴 구간", "**중복 문자 없는** 가장 긴 부분 문자열" (가변 길이)
- "문자열 `T`의 모든 글자를 포함하는 가장 짧은 부분 문자열"
- 순진하게 모든 구간을 보면 `O(n²)`이나 `O(nk)`라 `n = 10⁵~10⁶`에서 시간 초과
- 조건이 구간을 **늘리면 깨지거나 만족**, **줄이면 반대로** 단조적으로 변한다

## 2. 핵심 아이디어

### 고정 길이 창

창이 `numbers[i−k+1 .. i]`에서 `numbers[i−k+2 .. i+1]`로 밀릴 때 바뀌는 것은 **한 원소가 나가고 한 원소가 들어오는 것**뿐입니다. 합이면 `window += numbers[i+1] − numbers[i−k+1]`로 `O(1)`입니다.

### 창 안의 최댓값: 모노톤 덱

합과 달리 최댓값은 빼기가 안 됩니다. 나가는 원소가 최댓값이었다면 다음 최댓값을 알아야 합니다. 덱에 **후보의 위치**만 남깁니다.

- 새 원소 `x`가 들어오면, 덱의 **뒤에서** `x`보다 작거나 같은 후보를 버립니다. `x`가 더 늦게까지 창에 남아 있고 더 크기 때문에 그 후보들은 **영원히 최댓값이 될 수 없습니다.**
- `x`의 위치를 덱 뒤에 넣습니다. 덱의 값은 앞에서 뒤로 **내림차순**입니다.
- 덱의 **앞** 후보의 위치가 창을 벗어났으면 버립니다.
- 창의 최댓값은 덱의 **맨 앞**입니다.

[모노톤 스택](../monotonic-stack/)과 같은 아이디어인데, 오래된 쪽(앞)에서도 버린다는 점이 다릅니다. 각 원소가 한 번 들어가고 한 번 나가므로 전체 `O(n)`입니다.

### 가변 길이 창

오른쪽 끝 `right`를 하나씩 늘리고, 조건이 깨지면 `left`를 조건이 다시 만족될 때까지 늘립니다. `left`와 `right`는 **한 방향으로만** 움직이므로 전체 `O(n)`입니다. 두 가지 모양이 있습니다.

| 모양 | 조건 | 갱신 시점 |
|---|---|---|
| 가장 **긴** 구간 | 제약을 만족해야 함 (예: 종류 ≤ K) | 만족 상태에서 `right − left + 1`의 최댓값 |
| 가장 **짧은** 구간 | 목표에 도달해야 함 (예: 합 ≥ S) | `while` 안에서 조건을 만족하는 동안 최솟값 갱신 후 `left` 이동 |

**주의**: 이 방식은 구간을 줄이면 합이 **줄기만 하는** 경우, 즉 원소가 모두 양수일 때만 맞습니다. 음수가 섞여 있으면 접두사 합과 모노톤 덱으로 풉니다(LeetCode 862).

## 3. 손으로 따라가기

### 창 안의 최댓값: `[1, 3, -1, -3, 5, 3, 6, 7]`, `k = 3`

덱에는 값으로 표시합니다(실제로는 위치). `window_max`는 `i`번째에서 끝나는 창의 최댓값을 모두 돌려주며, **완전한 창**(길이 3)은 `i ≥ 2`부터입니다.

| `i` | `x` | 뒤에서 버린 후보 | 덱 (앞→뒤) | 최댓값 |
|---|---|---|---|---|
| 0 | 1 | | `[1]` | 1 |
| 1 | 3 | 1 | `[3]` | 3 |
| 2 | -1 | | `[3, -1]` | **3** |
| 3 | -3 | | `[3, -1, -3]` | **3** |
| 4 | 5 | -3, -1, 3 | `[5]` | **5** |
| 5 | 3 | | `[5, 3]` | **5** |
| 6 | 6 | 3, 5 | `[6]` | **6** |
| 7 | 7 | 6 | `[7]` | **7** |

완전한 창의 최댓값은 `[3, 3, 5, 5, 6, 7]`, 최솟값은 `[-1, -3, -3, -3, 3, 3]`입니다.

이 입력에서는 앞쪽 후보가 창을 벗어나는 일이 없었습니다. 내림차순 입력 `[5, 4, 3, 2, 1]`, `k = 3`에서는 덱이 `[5, 4, 3]`으로 쌓이다가 `i = 3`에서 맨 앞 `5`의 위치(0)가 `i − k = 0` 이하라 앞에서 버려져 `[4, 3, 2]`(최댓값 4), `i = 4`에서 `4`가 버려져 `[3, 2, 1]`(최댓값 3)이 됩니다. 결과 `[5, 5, 5, 4, 3]`.

### 고정 길이 합: `[3, -2, 5, -1, 6, -3, 2, 7, -5, 2]`, `k = 5`

첫 창 `3 − 2 + 5 − 1 + 6 = 11`. 밀 때마다 새 원소를 더하고 오래된 원소를 뺍니다.

| 창 시작 | 합 |
|---|---|
| 0 | 11 |
| 1 | 11 − 3 + (−3) = 5 |
| 2 | 5 − (−2) + 2 = 9 |
| 3 | 9 − 5 + 7 = 11 |
| 4 | 11 − (−1) + (−5) = 7 |
| 5 | 7 − 6 + 2 = 3 |

최댓값 **11**.

### 중복 없는 가장 긴 부분 문자열: `abba`

마지막으로 본 위치 `last_seen`을 두고, 글자가 창 안에서 다시 나오면 `left`를 그 위치 바로 뒤로 옮깁니다.

| `right` | 글자 | `left` | 창 길이 | 설명 |
|---|---|---|---|---|
| 0 | a | 0 | 1 | |
| 1 | b | 0 | 2 | |
| 2 | b | 2 | 1 | `b`가 위치 1에 있었으므로 `left = 2` |
| 3 | a | 2 | 2 | `a`는 위치 0에 있었지만 `0 < left`라 창 밖이므로 `left`를 **되돌리지 않음** |

최대 **2**. 마지막 줄의 `last_seen[ch] >= left` 검사가 핵심입니다. 이 검사가 없으면 `left`가 2에서 1로 후퇴합니다.

다른 예: `abcabcbb → 3`, `pwwkew → 3`.

### 합이 `7` 이상인 가장 짧은 구간: `[2, 3, 1, 2, 4, 3]`

| `right` | 합 | 조건을 만족하는 동안 줄이기 |
|---|---|---|
| 3 | 8 | 길이 4 (`2 3 1 2`) → `left` 이동 → 합 6, 중단 |
| 4 | 10 | 길이 4 (`3 1 2 4`) → 합 7 → 길이 3 (`1 2 4`) → 합 6, 중단 |
| 5 | 9 | 길이 3 (`2 4 3`) → 합 7 → 길이 **2** (`4 3`) → 합 3, 중단 |

답 **2**. 원소가 양수라서 `left`를 줄이면 합이 줄어드는 단조 구조가 있습니다.

### 그 밖에

- 서로 다른 값이 `2`개 이하인 가장 긴 구간: `eceba → 3` (`ece`)
- `S = ADOBECODEBANC`에서 `ABC`를 모두 포함하는 가장 짧은 부분 문자열: **`BANC`**

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def window_max(numbers, k):
    result = []
    candidates = deque()                      # 후보의 위치, 값은 내림차순
    for i, x in enumerate(numbers):
        while candidates and numbers[candidates[-1]] <= x:
            candidates.pop()                  # x 보다 작은 후보는 영원히 최댓값이 못 된다
        candidates.append(i)
        if candidates[0] <= i - k:            # 창을 벗어난 맨 앞 후보
            candidates.popleft()
        result.append(numbers[candidates[0]])
    return result

def longest_unique_substring(s):              # 가변 길이
    last_seen = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= left:
            left = last_seen[ch] + 1
        last_seen[ch] = right
        best = max(best, right - left + 1)
    return best
```

- `window_min`(부등호만 반대), `max_sum_of_k_consecutive`(고정 길이 합), `longest_with_at_most_k_distinct`, `shortest_subarray_sum_at_least`(양수 원소), `min_window_covering(s, t)`.
- `window_max`/`window_min`은 `i < k − 1`인 앞부분에서는 더 짧은 창의 값을 돌려줍니다. 완전한 창만 보려면 `result[k-1:]`.
- 직접 실행하면 `N L`과 수열을 받아 각 `i`에 대해 최근 `L`개(앞부분은 더 적게)의 최솟값을 출력합니다.

## 5. 복잡도와 입력 크기 가이드

- **시간 O(n)**: 각 원소가 창에 한 번 들어가고 한 번 나갑니다. **공간 O(k)**(덱·딕셔너리 크기). ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))
- 이 환경에서 측정한 값입니다(두 번 중 최소).

| 작업 | 크기 | 시간 |
|---|---|---|
| `window_max` (덱) | n = 3·10⁵, k = 1000 | 0.06초 |
| 창마다 `max(슬라이스)` (순진한 방법) | n = 3·10⁴, k = 1000 | 0.30초 |
| 같은 입력의 `window_max` | n = 3·10⁴, k = 1000 | 0.007초 |

- 순진한 방법은 `O(nk)`라서 `n = 3·10⁵`, `k = 1000`이면 약 3초(위 측정에서 10배 입력에 선형 증가로 **추정**)이고 `k`가 `n`에 가까우면 불가능합니다. 덱은 `k`와 관계없습니다.
- 파이썬에서는 `n = 5·10⁶`(백준 11003의 입력 크기) 같은 입력은 입출력과 덱 연산만으로 시간 제한을 넘기기 쉽습니다. 풀이는 같지만 구현을 최적화해야 합니다.

## 6. 자주 하는 실수

- **창을 벗어난 후보 검사의 off-by-one**: 위치 `i`에서 창은 `[i−k+1, i]`입니다. 후보 위치가 `i − k` 이하이면 벗어난 것입니다(`≤ i − k`).
- **덱에 값을 저장**: 후보가 창을 벗어났는지 판단하려면 위치가 필요합니다. 위치를 저장하고 `numbers[위치]`로 값을 읽으세요.
- **가변 창에서 `while` 대신 `if`**: `left`를 한 칸만 옮기면 조건이 아직 깨져 있을 수 있습니다. 조건이 회복될 때까지 `while`.
- **`left`의 후퇴**: 중복 문자 문제에서 `last_seen[ch] >= left` 검사를 빠뜨리면 `abba`에서 틀립니다.
- **종류 수를 셀 때 0이 된 키를 지우지 않음**: `len(counts)`가 현재 종류의 수가 되려면 개수가 0이 된 키를 지워야 합니다.
- **음수 원소**: "합이 `S` 이상인 가장 짧은 구간"은 원소가 모두 양수일 때만 슬라이딩 윈도우로 됩니다. 음수가 있으면 접두사 합 + 모노톤 덱.
- **답이 없는 경우**: 가장 짧은 구간 문제에서 `best`의 초기값(`n + 1`)을 그대로 출력하면 안 됩니다.
- **창 크기가 배열보다 큼**: `k > n`일 때의 정의를 확인하세요 (`max_sum_of_k_consecutive`는 `0`).

## 7. 변형과 응용

- **정확히 `K`개**: `(최대 K개) − (최대 K−1개)`로 바꿔 세면 슬라이딩 윈도우로 풀립니다.
- **구간의 부분 배열 개수 세기**: 각 `right`에서 가능한 `left`의 개수(`right − left + 1`)를 더합니다.
- **중앙값**: 창 안의 중앙값은 두 개의 힙이나 정렬된 구조가 필요합니다.
- **접두사 합 + 모노톤 덱**: 음수가 있는 "합이 `K` 이상인 가장 짧은 구간"(LeetCode 862).
- **DP 최적화**: 점화식이 `dp[i] = min(dp[j]) + c` (`i − k ≤ j < i`) 모양이면 모노톤 덱으로 `O(n)`에.
- **원형 배열**: 배열을 두 배로 늘려 창을 밀거나 인덱스를 `% n`으로.
