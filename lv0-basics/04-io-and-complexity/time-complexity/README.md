# Time Complexity (시간 복잡도와 빅오)

> **한 줄 요약**: 입력 크기 n이 커질 때 연산 횟수가 **어떤 모양으로 늘어나는지**를 나타낸다. 상수와 낮은 차수는 버리고 가장 빨리 커지는 항만 본다.

## 1. 언제 쓰나 (문제 신호)

- **풀이를 짜기 전에**: 입력 크기(N ≤ 10^5 등)를 보고 허용되는 복잡도를 가늠해 풀이 후보를 좁힙니다.
- **풀이를 짠 뒤에**: 이 풀이가 시간 제한 안에 돌아갈지 계산해 봅니다.
- "O(N²)은 안 된다", "O(N log N)이어야 한다" 같은 표현을 읽고 쓸 때

## 2. 핵심 아이디어

**연산 횟수를 n의 함수로** 적고, n이 아주 커졌을 때 가장 크게 영향을 주는 항만 남깁니다. 상수 배수와 낮은 차수는 버립니다. 예를 들어 `3n² + 5n + 7`은 `O(n²)`입니다.

반복문을 읽는 법:

| 코드 모양 | 연산 횟수 | 복잡도 |
|---|---|---|
| `for i in range(n)` | n | O(n) |
| 이중 반복문 `for i … for j …` (각각 n) | n² | O(n²) |
| 안쪽이 `range(i)`인 이중 반복문 | 0 + 1 + … + (n−1) = n(n−1)/2 | O(n²) |
| `while n > 1: n //= 2` | ⌊log₂ n⌋ | O(log n) |
| `while d * d <= n: d += 1` | ⌊√n⌋ | O(√n) |
| 반복문 안에서 정렬(O(n log n))을 n번 | n × n log n | O(n² log n) |

**빠르게 느는 순서**: O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!).

## 3. 손으로 따라가기

"1초에 연산 약 10^8번"이라고 어림하고, 복잡도별로 풀 수 있는 최대 n을 구합니다. (`max_n`)

| 복잡도 | 연산 횟수가 10^8 이하인 최대 n | 계산 |
|---|---|---|
| O(n) | 10^8 | n ≤ 10^8 |
| O(n log n) | 약 450만 | 4.5×10⁶ × log₂(4.5×10⁶) ≈ 4.5×10⁶ × 22 ≈ 10^8 |
| O(n²) | 10,000 | 10⁴ × 10⁴ = 10^8 |
| O(n³) | 464 | 464³ ≈ 9.99×10^7 |
| O(2ⁿ) | 26 | 2²⁶ ≈ 6.7×10⁷, 2²⁷ ≈ 1.3×10^8 |
| O(n!) | 11 | 11! ≈ 4×10⁷, 12! ≈ 4.8×10^8 |

**입력이 N = 100,000이고 풀이가 O(n²)이면** 100,000 × 100,000 = 10^10번이라 시간 초과입니다. O(n log n)이라면 약 1.7×10^6번이라 여유롭습니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 반복 횟수를 **직접 세어 공식과 비교**하는 함수들(`count_triangle_loops` 등)과 `max_n`이 들어 있습니다.

```python
def count_triangle_loops(n):          # 안쪽 반복이 i 번인 이중 반복문
    count = 0
    for i in range(n):
        for _ in range(i):
            count += 1
    return count                       # n * (n - 1) // 2 와 같다
```

`max_n`은 연산 횟수가 n에 대해 증가하는 함수라는 점을 이용한 이분 탐색입니다.

## 5. 복잡도와 입력 크기 가이드

- 어림값 "1초 ≈ 10^8 연산"은 C++ 기준입니다. **파이썬(CPython)은 수십 배 느리므로** 위 표에서 n을 한두 단계 낮춰 생각하세요. (O(n²)이면 n ≤ 3000 ~ 5000 정도)
- 시간 복잡도는 **최악의 입력**을 기준으로 합니다. 평균이 빨라도 최악이 느리면 안 되는 경우가 많습니다.
- 공간 복잡도도 같은 방식으로 셉니다. 배열 크기가 n이면 O(n), n × n이면 O(n²).
- 더 자세한 표와 파이썬 내장 연산의 복잡도는 [복잡도 치트시트](../../../docs/complexity-cheatsheet.md)에 있습니다.

## 6. 자주 하는 실수

- **상수를 무시해도 되는 줄 알기**: O(n)이어도 반복문 안에서 무거운 일을 하면 느립니다. 특히 파이썬에서 상수 차이가 큽니다.
- **내장 함수의 비용을 놓치기**: `x in list`, `list.pop(0)`, `s + t`는 O(n)입니다. 반복문 안에서 쓰면 O(n²)이 됩니다.
- **로그의 밑을 신경 쓰기**: O(log n)에서 밑(2든 10이든)은 상수 배수 차이라 무시합니다.
- **입력 크기와 값의 크기 혼동**: 수 하나의 값이 10^9여도 그 수를 √ 까지 도는 풀이는 O(√10^9) ≈ 3×10⁴번이면 됩니다. "n"이 무엇인지 정하고 시작하세요.
- **합산 vs 곱**: 반복문이 **차례로** 있으면 더하고(O(n) + O(n²) = O(n²)), **중첩**되어 있으면 곱합니다.

## 7. 변형과 응용

- **분할 상환 분석**: 가끔 비싼 연산이 있어도 평균은 싼 경우(리스트 `append`). ([배열](../../01-data-structures/array/))
- **재귀의 복잡도**: 점화식(예: T(n) = 2T(n/2) + O(n) = O(n log n))으로 구합니다. ([병합 정렬](../../../lv1-elementary/02-sorting/merge-sort/))
