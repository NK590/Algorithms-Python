# Array (배열)

> **한 줄 요약**: 같은 종류의 값을 메모리에 연속해서 나란히 저장하고, 번호(인덱스)로 곧바로 꺼내 쓰는 가장 기본적인 자료구조.

## 1. 언제 쓰나 (문제 신호)

- "N개의 수가 주어진다", "수열", "위치(번호)로 값을 찾는다" → 거의 모든 문제의 출발점입니다.
- 값을 **번호로 자주 읽고 바꾸고**, 중간에 끼워 넣거나 빼는 일은 드문 경우에 잘 맞습니다.
- 중간 삽입·삭제가 잦다면 [연결 리스트](../../../lv1-elementary/01-data-structures/linked-list/)나 [덱](../../../lv1-elementary/01-data-structures/deque/)을 고려합니다.

파이썬의 배열은 `list`입니다. (엄밀히는 크기가 자동으로 늘어나는 동적 배열입니다)

## 2. 핵심 아이디어

원소가 연속된 칸에 있으므로 `i`번째 원소의 위치를 `시작 위치 + i × 칸 크기`로 **바로 계산**할 수 있습니다. 그래서 어느 칸이든 읽고 쓰는 데 O(1)입니다.

대신 **중간에 끼워 넣거나 지우려면 뒤의 원소를 모두 한 칸씩 밀거나 당겨야** 해서 O(n)입니다. 맨 뒤에 붙이고(`append`) 떼는 것(`pop()`)만 평균 O(1)입니다. 칸이 모자라면 더 큰 공간으로 옮기지만, 가끔 일어나는 일이라 평균은 O(1)로 봅니다(분할 상환).

인덱스는 0부터 시작하고, 음수 인덱스 `-1`은 마지막 칸입니다. 범위를 벗어난 읽기는 `IndexError`입니다.

### 무엇을 저장하고 어떻게 움직이나

리스트의 한 칸은 원소 자체가 아니라 객체를 가리키는 참조를 저장합니다. 인덱스는 그 참조가 놓인 위치입니다. 그래서 `a[i]`를 읽는 일과 값 `x`가 어디 있는지 찾는 일은 다릅니다. 후자는 정렬이나 별도 색인이 없으면 모든 칸을 확인해야 합니다.

### 왜 이 방법이 맞는가

삽입할 때 뒤에서부터 이동하면 아직 복사하지 않은 원소가 보존됩니다. 마지막 칸부터 새 위치로 옮긴 뒤 현재 칸을 덮어써도 원본은 이미 이동했습니다. 삭제는 빈자리를 앞에서부터 채워 같은 성질을 지킵니다. `append`의 O(1)은 매 호출의 최악 시간이 아니라 여러 호출을 합친 분할 상환 비용입니다.

### 작은 예제로 검산하기

`[4, 7, 9]`의 인덱스 1에 5를 넣으면 9를 한 칸, 7을 한 칸 옮겨 `[4, 5, 7, 9]`가 됩니다. `a[1]`은 5이지만 `5 in a`는 위치를 모르므로 선형 탐색입니다. 인덱스 접근과 값 검색의 비용을 따로 계산하세요.

## 3. 손으로 따라가기

`[10, 20, 30, 40]`의 `1`번 자리에 `99`를 끼워 넣습니다. (`insert_at`) 먼저 한 칸 늘리고, **뒤에서부터** 한 칸씩 밉니다.

| 단계 | 하는 일 | 배열 |
|---|---|---|
| 0 | 한 칸 늘림 | `[10, 20, 30, 40, 99]` |
| 1 | `arr[4] = arr[3]` | `[10, 20, 30, 40, 40]` |
| 2 | `arr[3] = arr[2]` | `[10, 20, 30, 30, 40]` |
| 3 | `arr[2] = arr[1]` | `[10, 20, 20, 30, 40]` |
| 4 | `arr[1] = 99` | `[10, 99, 20, 30, 40]` |

앞에서부터 밀면 아직 옮기지 않은 값을 덮어씁니다. 지울 때(`delete_at`)는 반대로 **앞에서부터** 당깁니다.

**회전**: `[1, 2, 3, 4, 5]`를 왼쪽으로 2칸 돌립니다. (`rotate_left`) 앞 2개를 뒤집고, 나머지를 뒤집고, 전체를 뒤집으면 추가 메모리 없이 끝납니다.

| 단계 | 배열 |
|---|---|
| 앞 2개 뒤집기 | `[2, 1, 3, 4, 5]` |
| 나머지 뒤집기 | `[2, 1, 5, 4, 3]` |
| 전체 뒤집기 | `[3, 4, 5, 1, 2]` |

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다. 내장 연산이 하는 일을 직접 풀어 쓴 것입니다.

```python
def insert_at(arr, index, value):
    arr.append(value)                              # 한 칸 늘린다
    for i in range(len(arr) - 1, index, -1):       # 뒤에서부터 한 칸씩 민다
        arr[i] = arr[i - 1]
    arr[index] = value
```

| 하고 싶은 일 | 파이썬 | 시간 |
|---|---|---|
| `i`번째 읽기·쓰기 | `arr[i]` | O(1) |
| 맨 뒤에 추가 / 제거 | `arr.append(x)` / `arr.pop()` | O(1) |
| 중간에 삽입 / 삭제 | `arr.insert(i, x)` / `del arr[i]` | O(n) |
| 맨 앞에서 제거 | `arr.pop(0)` | O(n) → 큐라면 `deque` |
| 최댓값·합 | `max(arr)`, `sum(arr)` | O(n) |
| 구간 복사 | `arr[a:b]` | O(b − a) |

## 5. 복잡도와 입력 크기 가이드

- 읽기·쓰기 O(1), 끝에 추가·제거 O(1), 중간 삽입·삭제 O(n), 전체 훑기 O(n)입니다.
- 값이 N = 10^6개쯤이면 CPython 리스트도 통째로 다룰 수 있습니다. 값 하나당 메모리가 꽤 크므로 더 큰 배열은 [복잡도 치트시트](../../../docs/complexity-cheatsheet.md)의 메모리 항목을 보세요.

## 6. 자주 하는 실수

- **인덱스 범위**: 길이가 `n`이면 유효한 인덱스는 `0 ~ n-1`입니다. `arr[n]`은 `IndexError`입니다. 반복문 상한을 `range(n)`으로 두는 습관을 들이세요.
- **복사**: `b = a`는 복사가 아니라 **같은 리스트를 가리키는 것**입니다. `b = a[:]` 또는 `b = list(a)`로 복사합니다.
- **반복 중 수정**: `for x in arr:`를 도는 동안 `arr`에서 지우면 원소를 건너뜁니다. 새 리스트를 만들거나 인덱스를 거꾸로 돕니다.
- **맨 앞 연산**: `pop(0)`, `insert(0, x)`는 O(n)이라 반복하면 O(n²)입니다.
