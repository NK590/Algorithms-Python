# Brute Force (브루트 포스, 완전 탐색)

> **한 줄 요약**: 가능한 모든 경우를 하나씩 전부 확인해서 답을 찾는다. 느릴 수 있지만 **정답을 놓치지 않는다.**

## 1. 언제 쓰나 (문제 신호)

- **입력이 작다**: N ≤ 10~20, 또는 경우의 수가 수백만 이하
- "모든 경우를 확인해도 시간 안에 되겠다"는 계산이 선다 — 먼저 경우의 수를 센다 (쌍이면 N², 세 개 고르면 N³, 부분집합이면 2^N, 순열이면 N!)
- **처음 떠올릴 풀이**: 더 빠른 알고리즘이 안 떠오를 때, 느리더라도 맞는 풀이를 먼저 짠다. 나중에 최적화한 풀이를 검증하는 기준(`test_solution.py`의 비교 대상)이 됩니다.

입력 크기와 허용 시간 복잡도의 관계는 [복잡도 치트시트](../../../docs/complexity-cheatsheet.md)를 보세요.

## 2. 핵심 아이디어

1. **후보를 빠짐없이 나열**한다. (반복문, 중첩 반복문, 조합/순열 나열)
2. 각 후보가 **조건을 만족하는지 확인**한다.
3. 조건을 만족하는 후보 중 문제가 원하는 것(최댓값, 최솟값, 개수, 존재 여부)을 고른다.

경우의 수가 시간 제한을 넘지 않는지 **먼저 계산**하는 것이 가장 중요합니다. 반복문이 `k`개 중첩되면 `N^k`번입니다.

경우의 수를 줄이는 흔한 방법: 같은 쌍을 두 번 보지 않기(`j`를 `i + 1`부터), 이미 답이 나오면 즉시 종료하기, 불가능한 후보를 일찍 버리기(→ [백트래킹](../../../lv1-elementary/07-algorithm-paradigms/backtracking/)).

### 무엇을 저장하고 어떻게 움직이나

먼저 후보가 무엇인지 정확히 정합니다. 두 원소를 고르는 문제는 인덱스 쌍, 연속 구간은 시작·끝, 부분집합은 각 원소의 선택 여부입니다. 후보 생성과 조건 판정을 분리하면 빠뜨린 경우와 중복된 경우를 쉽게 찾을 수 있습니다.

### 왜 이 방법이 맞는가

모든 유효한 답이 생성되는 후보 중 하나이고, 각 후보를 정확하게 평가하면 그중 최댓값·최솟값을 선택한 결과가 정답입니다. 속도보다 먼저 이 완전성을 확인하세요. 같은 값이 있어도 인덱스가 다른 원소는 문제에 따라 서로 다른 선택입니다.

### 작은 예제로 검산하기

`[2, 4, 7]`에서 합 9인 쌍을 찾는다면 `(0,1), (0,2), (1,2)`만 보면 됩니다. `i<j` 조건이 같은 원소를 두 번 쓰는 일과 같은 쌍의 중복을 막습니다. 후보가 n²개이고 판정도 n번 순회한다면 전체는 O(n³)입니다.

## 3. 손으로 따라가기

**최대 부분 구간 합** `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`: 모든 시작·끝 쌍을 보고 합이 가장 큰 구간을 고릅니다. 시작 `3`(값 4)에서 이어서 더하면 다음과 같습니다.

| 끝 | 구간 | 합 | 지금까지 최댓값 |
|---|---|---|---|
| 3 | `[4]` | 4 | 4 |
| 4 | `[4, -1]` | 3 | 4 |
| 5 | `[4, -1, 2]` | 5 | 5 |
| 6 | `[4, -1, 2, 1]` | **6** | **6** |
| 7 | `[4, -1, 2, 1, -5]` | 1 | 6 |
| 8 | `[4, -1, 2, 1, -5, 4]` | 5 | 6 |

다른 시작점에서도 6을 넘지 못하므로 답은 **6**입니다. 시작·끝 쌍이 O(n²)개이고 합을 이어서 더하면 O(n²)입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
def max_subarray_sum(arr):
    best = arr[0]                                # 모두 음수일 수 있으니 0 이 아니라 첫 원소로 시작
    for start in range(len(arr)):
        total = 0
        for end in range(start, len(arr)):
            total += arr[end]                    # 합을 이어서 더하면 O(n²)
            best = max(best, total)
    return best
```

함께 있는 예: 합이 `target`인 쌍 찾기(`has_pair_with_sum`, O(n²)), 카드 3장의 합이 한도를 넘지 않는 최댓값(`closest_triple_sum`, O(n³)), 분해합의 가장 작은 생성자(`smallest_generator`, O(n)).

## 5. 복잡도와 입력 크기 가이드

| 경우의 수 | 대략 허용되는 N |
|---|---|
| N! (순열) | N ≤ 10 |
| 2^N (부분집합) | N ≤ 20 |
| N³ | N ≤ 500 |
| N² | N ≤ 5000 |
| N | N ≤ 10^7 |

파이썬은 위 값에서 한 단계 낮춰 생각하세요. 첫 풀이는 느려도 좋지만, **제출 전에 경우의 수를 한 번 계산**하세요.

## 6. 자주 하는 실수

- **경우의 수를 안 세어 보기**: 풀리겠다 싶어 짰다가 시간 초과가 납니다. 반복문 중첩 횟수와 N을 먼저 곱해 보세요.
- **초깃값**: 최댓값을 구할 때 `best = 0`으로 시작하면 모두 음수인 입력에서 틀립니다.
- **같은 원소를 두 번 쓰기**: 쌍을 찾을 때 `j`를 `i`부터 시작하면 같은 원소를 두 번 씁니다. `i + 1`부터 시작합니다.
- **경계 포함 여부**: `range(a, b)`는 `b`를 포함하지 않습니다. 구간의 끝을 포함하는지 확인하세요.
- **불필요한 계산 반복**: 안쪽 반복마다 합을 처음부터 다시 구하면 한 단계 더 느려집니다. 이어서 더하세요.
