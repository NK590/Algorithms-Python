# Implementation and Simulation (구현·시뮬레이션)

> **한 줄 요약**: 문제에 적힌 규칙을 **그대로 코드로 옮겨** 상태가 변하는 과정을 직접 따라간다. 알고리즘이 아니라 정확성의 싸움이다.

## 1. 언제 쓰나 (문제 신호)

- 문제가 "~하면 ~한다", "명령에 따라 움직인다", "N번 반복한다"처럼 **규칙을 길게 설명**하고, 풀이 아이디어보다 **구현이 관건**일 때
- 로봇·시계·카드·구슬·격자 위의 이동, 명령어 처리
- 입력이 작아서(N ≤ 수천) 규칙대로 **그냥 돌려 봐도** 시간 안에 끝날 때

시뮬레이션 횟수(단계 수 × 단계당 비용)가 시간 제한을 넘는지 먼저 계산하세요. 넘으면 규칙에서 **패턴이나 수식**을 찾아야 합니다. (예: 요세푸스 문제의 점화식)

## 2. 핵심 아이디어

1. **상태를 정의**한다. (위치, 방향, 시각, 남은 사람 목록 …)
2. **한 단계가 상태를 어떻게 바꾸는지** 규칙을 함수로 쓴다.
3. 입력된 횟수·명령만큼 단계를 반복한다.

실수를 줄이는 방법:
- **방향은 배열로**: `MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]`처럼 순서를 정하면 회전이 인덱스 `±1`이 됩니다.
- **경계 검사는 이동 전에**: 새 좌표를 만들어 격자 안인지 확인하고 맞을 때만 갱신합니다.
- **문제의 예제를 손으로 먼저 따라가** 본 뒤 코드의 결과와 비교합니다.

## 3. 손으로 따라가기

**3 × 3 격자의 로봇** (시작 `(0, 0)` 동쪽): 명령 `FRFRFLF`

| 명령 | 하는 일 | 위치 | 방향 |
|---|---|---|---|
| 시작 | - | (0, 0) | 동 |
| `F` | 한 칸 전진 | (0, 1) | 동 |
| `R` | 오른쪽으로 90° | (0, 1) | 남 |
| `F` | 전진 | (1, 1) | 남 |
| `R` | 오른쪽 | (1, 1) | 서 |
| `F` | 전진 | (1, 0) | 서 |
| `L` | 왼쪽 | (1, 0) | 남 |
| `F` | 전진 | (2, 0) | 남 |

**요세푸스** (7명, 3번째마다 제거): 앞의 2명을 뒤로 보내고 3번째를 뺍니다.

| 단계 | 원 (맨 앞이 시작) | 제거 |
|---|---|---|
| 1 | `1 2 3 4 5 6 7` | 3 |
| 2 | `4 5 6 7 1 2` | 6 |
| 3 | `7 1 2 4 5` | 2 |
| 4 | `4 5 7 1` | 7 |
| 5 | `1 4 5` | 5 |
| 6 | `1 4` | 1 |
| 7 | `4` | 4 |

제거 순서는 `3, 6, 2, 7, 5, 1, 4`입니다.

## 4. 구현

전체 코드는 [solution.py](solution.py)에 있습니다.

```python
FACING = "NESW"
MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]    # 북 동 남 서

def simulate_robot(commands, rows, cols):
    r = c = 0
    d = 1                                     # 동쪽
    for command in commands:
        if command == "L":
            d = (d - 1) % 4
        elif command == "R":
            d = (d + 1) % 4
        elif command == "F":
            nr, nc = r + MOVES[d][0], c + MOVES[d][1]
            if 0 <= nr < rows and 0 <= nc < cols:   # 벽이면 움직이지 않는다
                r, c = nr, nc
    return r, c, FACING[d]
```

요세푸스는 `deque.rotate(-(k - 1))`로 앞의 k−1명을 뒤로 보내 시뮬레이션하고(`josephus_order`), 점화식 `J(n) = (J(n−1) + k) mod n`으로 마지막 생존자만 O(n)에 구합니다(`josephus_last`). 두 방법이 같은 답을 내는 것을 테스트가 확인합니다. 시계 계산(`add_minutes`)은 하루 1440분으로 나눈 나머지를 씁니다.

## 5. 복잡도와 입력 크기 가이드

- 시간은 **단계 수 × 단계당 비용**입니다. 로봇은 명령 수에 비례하고, 요세푸스(덱)는 O(n·k) 또는 O(n)입니다.
- 격자 시뮬레이션은 (격자 크기 × 반복 횟수)가 10^7을 넘지 않는지 먼저 계산하세요. ([복잡도 치트시트](../../../docs/complexity-cheatsheet.md))

## 6. 자주 하는 실수

- **문제 조건을 놓치기**: 시뮬레이션은 조건이 길어서 한 줄을 빼먹으면 예제만 맞고 나머지가 틀립니다. 조건을 체크리스트로 적어 두세요.
- **행/열, x/y 혼동**: [2차원 배열](../../01-data-structures/two-dimensional-array/)에서 `grid[행][열]`이고 방향 배열의 순서도 같아야 합니다.
- **상태를 도중에 덮어쓰기**: 동시에 일어나는 변화(한꺼번에 이동)는 **복사본**에 쓰고 마지막에 교체하세요.
- **경계 인덱스 / 음수 인덱스**: `grid[-1]`은 마지막 행이라 조용히 틀립니다.
- **방향 회전 방향**: 문제가 말하는 왼쪽/오른쪽이 `+1`인지 `-1`인지 방향 배열 순서와 함께 확인하세요.
